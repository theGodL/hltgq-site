# 模型接入接口文档

> 本文档供**前端开发**对接使用：生产环境路径统一加 `/hltgq-site` 前缀
> 涵盖短期来水预测、中长期来水预测、水量损失预测、需水预测、水资源配置、配水调度、墒情预测七个模块
> 计算均为**异步**：提交秒回 recordId → 前端轮询状态 → 完成后拉取详情

## 模块总览

| 模块 | 前端页面 | 提交接口 | 特殊接口 |
|------|---------|---------|---------|
| 短期来水预测 | 水量预测 · 短期 tab | `POST /water-forecast/short` | — |
| 中长期来水预测 | 水量预测 · 中长期 tab | `POST /water-forecast/long` | — |
| 水量损失预测 | 水量预测 · 损失 tab | `POST /water-forecast/loss` | — |
| 需水预测 | 水量预测 · 需水 tab | `POST /water-forecast/demand`（JSON 直传）/ `/demand/upload`（模板上传） | `GET /demand/template` 模板下载 |
| 水资源配置 | 水资源配置页 | `POST /water-allocation`（JSON）/ `/upload`（模板上传） | `GET /template` 模板下载 |
| 配水调度 | 配水调度预测页 | `POST /water-decision` | `GET /download?recordId={id}` Excel 下载 |
| 墒情预测 | 墒情预测页 | `POST /water-forecast/moisture` | — |

> 七个模块的**通用接口完全同构**：`GET /{module}/status/{id}` 轮询、`GET /{module}/list` 历史方案、`PUT /{module}/{id}/name` 重命名、`DELETE /{module}/{id}` 删除（详见 [0.3](#03-七个模块共有的-4-个通用接口)）。**例外**：墒情模块 status 为平台单选字典 `#1#`/`#2#`/`#3#`（见 [0.1](#01-异步计算流程)）。
> 模块间依赖（下拉选项来源）：水量损失依赖中长期方案（短期损失已下线）；水资源配置依赖中长期+需水方案；配水调度依赖需水+配置方案；墒情预测为独立模块（无上下游依赖）（详见 [8.1](#81-模块间依赖链下拉选项来源)）。
> 另有**模型服务健康检查** `GET /model/health`：透传模型 /health 文件状态表，files 任一为 false 表示对应链路不可用（详见 [0.4](#04-模型服务健康检查modelhealth)）。

## 〇、公共约定

### 0.1 异步计算流程

```
POST 提交（秒回 recordId）
   ↓
GET /status/{id} 轮询（建议间隔 2~3s）
   ↓
status=completed → GET /{id} 拉详情展示
status=failed    → 展示 errorMsg
```

| status 取值 | 说明 |
|------------|------|
| calculating | 计算中（多方案排队串行执行，单次最长约 310s；中长期重训练场景更久） |
| completed | 计算完成，明细与汇总已入库 |
| failed | 计算失败，`errorMsg` 有失败原因（含模型侧异常/超时），无明细数据。提交接口不受影响，仍正常秒回 recordId |

> **墒情模块例外**：status 为平台单选字典 `#1#`=计算中、`#2#`=完成、`#3#`=失败（其余 6 个模块为 calculating/completed/failed 纯值）。前端轮询时需按模块兼容两种枚举（或统一处理：`calculating` 与 `#1#` 均为进行中、`completed` 与 `#2#` 均为完成）。

### 0.2 公共响应约定

- **时间格式**：ISO `yyyy-MM-ddTHH:mm:ss`
- **布尔值**：`#1#` = 是，`#2#` = 否（数据库平台统一约定）
- **错误响应**：

| HTTP 状态 | 响应体 | 场景 |
|----------|--------|------|
| 400 | `{"message": "..."}` | 请求参数错误（含必传校验、枚举校验、引用的历史方案不存在或已删除） |
| 404 | Spring 默认错误体 | 方案不存在（status/详情/重命名/删除均会触发）；跨模块 ID 误用同样返回 404。**例外：逻辑删除（DELETE 后）的 status/详情仍返回 200**（历史可追溯设计），仅决策下载接口对已删除方案返回 404 |
| 502 | `{"code": n, "message": "..."}` | 模型服务返回错误（仅同步调用路径触发；异步计算路径的模型异常统一体现为 status=failed + errorMsg，不返回 502） |

### 0.3 七个模块共有的 4 个通用接口

所有模块（路径前缀不同）均提供以下同构接口：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/{module}/status/{id}` | GET | 轮询状态：`{"id", "status", "errorMsg"}`（墒情模块 status 为 `#1#`/`#2#`/`#3#`，其余模块 calculating/completed/failed） |
| `/{module}/list` | GET | 历史方案列表（主表全字段，与 detail 的 record 对象同构；del_flag=#2#，created_at 倒序，已删除方案不返回） |
| `/{module}/{id}/name` | PUT | 重命名：body `{"name": "新名称"}` → `{"ok": true}` |
| `/{module}/{id}` | DELETE | 逻辑删除（del_flag=#1#）→ `{"ok": true}`。**配水调度模块会同步清理该方案的 Excel 快照文件**；其余模块无附属文件 |

**list 响应元素**（主表全字段，7 个模块按各自主表扩展）：

```json
{
  "id": "9xK3mTqLvW2nRc8sYh1a",
  "schemeName": "短期预报_2026-08-27_30天",
  "status": "completed",
  "createdAt": "2026-08-27T10:00:00",
  "updatedAt": "2026-08-27T10:05:12",
  "corpCode": "hltgq",
  "createdBy": "model-service"
}
```

> **前端注意**：list 返回主表**全字段**，额外包含 `requestJson`（提交参数归档大字段，前端忽略即可）、`delFlag`（恒 `#2#`，已删除方案不返回）、`errorMsg`（failed 方案非空）。**无分页**，历史方案较多时响应体较大；元素中可能含 `status=failed` 的方案（建议下拉过滤或灰显，详见 [8.1](#81-模块间依赖链下拉选项来源)）。

### 0.4 模型服务健康检查（/model/health）

```
GET /model/health
```

> 七个模块之外的全局接口：透传模型侧 `/health`（响应**不含** `{code,msg}` 包装，由后端单独解析），供页面加载时探测模型服务及结果文件是否就绪。

**响应**（200，实测 2026-09）：

```json
{
  "ok": true,
  "status": "ok",
  "service": "花凉亭灌区模型一体化服务",
  "time": "2026-09-04 22:24:23",
  "files": {
    "bp_param": true,
    "comprehensive": true,
    "demand_input": true,
    "demand_result": true,
    "manual_comprehensive": true,
    "manual_input": true,
    "moisture_model": true,
    "short_model": true,
    "short_model_v3": true
  },
  "endpoints": ["/forecast", "/predict", "/demand", "/loss", "/allocate", "/decision", "/moisture"]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| ok | Boolean | 健康汇总：模型侧 `status=="ok"` 时为 true |
| status | String | 模型侧状态（"ok"） |
| service | String | 模型服务标识 |
| time | String | 模型侧时间 |
| files | Object | 各模型/结果文件存在性表，**任一为 false 表示对应计算链路可能无法运行**（实测 9 个文件键全部 true），前端可据此展示告警 |
| endpoints | Array | 模型侧已注册接口列表（实测 7 个：/forecast /predict /demand /loss /allocate /decision /moisture） |

**用途**：页面加载时调用一次，files 中有 false 时提示对应模块暂不可用，避免提交后才失败。
**失败**：模型服务不可达/超时返回 502 `{"code": -1, "message": "模型服务不可达或超时: ..."}`（同步调用路径，同 0.2 约定）。

### 0.5 主表公共字段

所有 `record` 对象均含以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 方案 ID（22 位短 ID，页面下拉方案值直接取此字段） |
| schemeName | String | 方案名称 |
| status | String | calculating / completed / failed（墒情模块为 `#1#`/`#2#`/`#3#`，见 0.1） |
| delFlag | String | `#1#`=已删除，`#2#`=正常 |
| errorMsg | String | 失败原因（仅 failed 时非空） |
| createdAt / updatedAt | String | 创建/更新时间（ISO） |
| createdBy / updatedBy | String | 创建/更新人（后端统一 "model-service"） |
| corpCode | String | 租户编码（统一 "hltgq"） |

> 各模块详情返回的明细数组元素（dailies / details / tendays / monthlies / scaleFactors / branchDetails 等）同样包含上述审计字段（corpCode/createdAt/createdBy/updatedAt/updatedBy）及 recordId（关联方案 ID），前端渲染忽略即可。

## 一、短期来水预测（/water-forecast/short）

> **2026-09 模型接口改造完成**：小时尺度新契约（模型 /forecast V3）。
> 起调水位**不再由用户输入**（后端自动取花凉亭坝上最新水位）；逐小时降雨**未传时后端自动拉取气象 16 天逐小时数据**（缺失小时填 0）。
> **气象清洗（会议要求，✅ 已上线）**：气象缺小时一律填 0（「杠号→0」）；序列从窗口 start 起逐小时对齐（`yyyy-MM-dd HH:mm`）；降雨保留 1 位小数（会议「精确到小数点」）。前端无需自验。
> **下泄开关（已闭环）**：模型侧确认仅 3 参数（enablePower=发电 / enableTunnel=泄洪隧洞 / enableSpillway=溢洪道），**无第 4 个开关**。会议叫法对照：「异通道」=溢洪道（谐音）；「风道」「卸闸」非独立模型参数（业务叫法，如需精确对应由业务侧说明）。**前端只传 3 开关**。
> 默认值说明：模型侧参数默认 `true`；后端按会议 2「默认全关」口径**显式传 false**——前端**不传即全关**，与会议一致。
> 旧版逐日参数（startDate / days / useTypical / floodIdx / adjustRainfall / targetTotal / initialWaterLevel / dischargeMode / customDischarge）**已全部废弃**，请勿再传。

### 1.1 提交计算

```
POST /water-forecast/short
```

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:--:|--------|------|
| schemeName | String | 否 | 自动生成 | 方案名称（默认 `短期预报_<开始时间>_<小时数>小时`，实测如 "短期预报_2026-09-04 08:00_49小时"） |
| start | String | **是** | — | 预报开始时间 `yyyy-MM-dd HH:mm`（模型 start，与气象逐小时数据对齐） |
| end | String | **是** | — | 预报结束时间 `yyyy-MM-dd HH:mm`（窗口**含端点**，跨度 1~384 小时，非法/超出返回 400） |
| enablePower | Boolean | 否 | false | 是否启用发电下泄 |
| enableTunnel | Boolean | 否 | false | 是否启用泄洪隧洞 |
| enableSpillway | Boolean | 否 | false | 是否启用溢洪道 |
| rainfall | Number[] | 否 | 自动拉取 | 逐小时降雨量(mm)；不传则后端自动取气象逐小时数据；传则长度必须等于 start→end 逐小时步数（含端点） |

**请求示例**：

```json
{
  "start": "2026-09-04 08:00",
  "end": "2026-09-06 08:00",
  "enablePower": false,
  "enableTunnel": false,
  "enableSpillway": false
}
```

**响应**：

```json
{ "recordId": "9xK3mTqLvW2nRc8sYh1a" }
```

### 1.2 轮询 / 列表 / 重命名 / 删除

```

GET    /water-forecast/short/list
PUT    /water-forecast/short/{id}/name    body {"name": "新名称"}

```

| 字段 | 类型 | 说明 |
|------|------|------|

| evaporation | Number | 蒸发损失(万方)。**实测当前模型不返回，恒 `null`**（保留列，展示 "—"） |
| inflowRate | Number | 入库流量(m³/s)。模型直出「入库流量_m3s」优先，模型未返回时按小时入库水量换算 |
| outflowRate | Number | 出库流量(m³/s)。模型直出「出库流量_m3s」优先，模型未返回时按小时出库水量换算 |

**前端展示要点**：

- 统计卡：总降雨量 totalRainfall、总入库 totalInflow、总出库 totalOutflow、期末水位 finalWaterLevel、最高水位 maxWaterLevel、峰值入库流量 peakInflowRate
- 图表：降雨量分布（柱状）、入库/出库水量（双线）、库容与水位（双轴）——数据均取 dailies[]（逐小时，前端按需聚合为日/时段）
- 明细表：逐小时列 = 时间/降雨/入库/出库/水位/库容/入库流量/出库流量，按返回顺序直接渲染（已升序）
- 表单：start/end 起止时间选择器（`yyyy-MM-dd HH:mm`）+ 三个下泄开关；降雨可留空（后端自动拉气象数据）

## 八、前端实施指引

### 8.1 模块间依赖链（下拉选项来源）

```
中长期来水 ──→ 水量损失（仅 long，sourceRecordId=中长期方案）

中长期来水 ──┐
需水预测 ────┼──→ 水资源配置（auto：中长期+需水必选，损失可选）
水量损失 ────┘

需水预测 ──┐
           ├──→ 配水调度（两个下拉必传）
水资源配置 ─┘

墒情预测（独立，无上下游依赖）
```

- 各下拉的选项列表：调对应模块 `GET /{module}/list`，选项值取 `id`，展示文本取 `schemeName`（提交时传 id 即可）
- **建议只允许选择 `status=completed` 的方案**作为参数来源（前端可自行过滤；后端仅校验方案存在且未删除——**引用 calculating/failed 方案不会报错**，参数取自其已归档的 request_json，计算可正常进行；仅当引用的方案不存在或已删除时提交才返回 400）
- 配水调度的 `tens` 参数可选（仅计算指定旬），页面无此输入时不传（null = 全部 18 个灌溉旬）

### 8.2 轮询实现建议

```javascript
async function waitCompleted(recordId, statusPath, timeoutMs = 330000) {
  const start = Date.now();
  while (Date.now() - start < timeoutMs) {
    const res = await fetch(statusPath.replace('{id}', recordId));
    if (res.status === 404) throw new Error('方案不存在');
    const { status, errorMsg } = await res.json();
    if (status === 'completed' || status === '#2#') return;
    if (status === 'failed' || status === '#3#') throw new Error(errorMsg || '计算失败');
    await sleep(3000); // 建议 3s 间隔
  }
  throw new Error('计算超时');
}
```

> 轮询终止条件需兼容两种 status 枚举：普通模块 `completed/failed`，墒情模块 `#2#/#3#`（见 [0.1](#01-异步计算流程)）。

- 超时阈值：常规计算 310s，中长期 `retrain=true` 建议放宽至 30min 以上
- **网络异常**：fetch 断网/网关抖动时不要立即报错，建议重试 2~3 次（间隔 5s）后再提示失败；同一方案避免多个页面/组件并发轮询（统一由详情页单点轮询，列表页只读 status）
- **实测经验**：多方案同时提交会排队计算，总耗时 ≈ 排队任务数 × 单任务时长，排队期间轮询一直为 calculating；常规计算单任务秒级~20s 完成（实测 2026-09-04 全模块复测：短期 49 小时、长期、损失 long、需水、配置 auto、配水调度、墒情 16 天、防洪抗旱均秒级 completed），失败任务也会很快返回 failed（提交后约 10s 首次轮询即可拿到），无需等满超时
- 页面离开后返回：直接查 `GET /list` 中该方案 status 恢复状态，无需重新轮询

### 8.3 数值与格式约定

- 数值字段统一 Number；**实测**：汇总字段已四舍五入保留 2 位，明细字段保留原始精度（如逐小时入库/墒情含水量 2 位小数、G 值 4 位小数，前端按需格式化）
- 模型评估指标（`rmse/mae/mse/r2/smape`）保留模型原始精度（实测 4 位小数），前端按需格式化；`nse` 模型不返回恒为 null
- 布尔字段统一 `#1#`/`#2#` 字符串（与平台数据库约定一致）；`isSatisfied` 展示映射：`#1#`→"满足"，`#2#`→"不满足"
- 时间统一 ISO `yyyy-MM-ddTHH:mm:ss`（仅日期字段为当日 00:00:00）
- 明细 `null` 字段展示 "—"（如模型未返回库容且库容曲线表未录入时 storage 为 null）
- 墒情 `droughtLevel` 编码映射：`#1#`无旱 / `#2#`轻旱 / `#3#`中旱 / `#4#`重旱 / `#5#`特旱

### 8.4 交互状态机

| 页面状态 | 触发 | 处理 |
|---------|------|------|
| 提交成功 | POST 返回 recordId | 保存 recordId，跳详情页/列表页，开始轮询 |
| calculating（墒情为 `#1#`） | 轮询返回 | 展示加载态（如骨架屏/进度提示"模型计算中，请稍候"） |
| completed（墒情为 `#2#`） | 轮询返回 | 拉详情接口渲染 |
| failed（墒情为 `#3#`） | 轮询返回 | 展示 errorMsg（如「模型服务不可达或超时」类错误可提示用户稍后重试），提供"删除"入口 |

| 404 | 方案不存在/已删除 | 提示"方案不存在"（决策下载接口对已删除方案也返回 404；status/详情对已删除方案仍返回 200，可追溯） |
