### 通用约定（前端必读）

| 约定 | 说明 |
|------|------|
| 鉴权 | 所有接口走登录会话（`Authorization` 头），公共库 `lib/model-api.js` 已统一处理，无需额外传参 |
| 异步轮询 | 计算类接口提交**秒回 recordId** → 轮询 status → completed 后拉详情。status 枚举：`calculating / completed / failed`；轮询可直接复用 `ModelApi.waitCompleted` |
| null 语义 | 图表序列中 `null` = 无数据：柱状图不画柱、折线断线；**不渲染为 0** |
| 百分数 | `patrolCompliance / issueCompliance` 返回 **0~100 数值**（如 `85.5` 表示 85.5%），前端拼接 `%` 展示，不做除法 |
| 数字精度 | 水位/流量 3 位小数、雨量 1 位小数；方案汇总字段（totalDemand 等）为浮点可能带小数，展示用 `fmtNum` 处理 |
| 新接口封装 | 建议在 `lib/model-api.js` 补充 floodDrought / networkDevice / engineering / decision.branches 客户端（参考现有 `operation`、`soilMoisture` 写法），或页面内直接 `getJson('/xxx')` |

```
GET /network-device/summary
```

无参数。

### 1.1 响应

```json
{
  "regionName": "花凉亭灌区",
  "total": 186,
  "summary": {
    "online":  { "count": 142, "percent": 76 },
    "offline": { "count": 32,  "percent": 17 },
    "alarm":   { "count": 0,   "percent": 0 },
    "fault":   { "count": 0,   "percent": 0 }
  },
  "categories": [
    {
      "key": "waterLevel",
      "name": "水位",
      "color": "#1E90FF",
      "icon": "waterLevel",
      "total": 28,
      "counts": { "online": 22, "offline": 4, "alarm": 0, "fault": 0 },
      "devices": [
        { "id": "设备ID", "name": "南山寺节制闸1#", "status": "online" },
        { "id": "设备ID", "name": "集岭管理所雨量计#", "status": "offline" }
      ]
    }
  ]
}
```

### 1.2 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| regionName | String | 区域名 |
| total | Number | **设备去重总数**（多类型设备只计 1 次），故 `total ≠ Σcategories[].total` 属正常 |
| summary.* | Object | 4 项**固定返回**；alarm/fault 暂不支持恒 0（设备目前只有在线/离线） |
| summary.*.percent | Number | 已按四舍五入取整，直接展示拼 `%` |
| categories[] | Array | **固定 7 项、顺序固定**：waterLevel/rainfall/flow/gate/video/soil/quality；设备表无数据时仍返回 7 项（全 0 结构，页面不会塌） |
| categories[].color / icon | String | 分类色块色值与图标键名，页面渲染**直接使用**（`cat.color`、`ICONS[cat.icon]`），不要自行映射 |
| devices[] | Array | 该类**全量**设备；`status` 仅 `online/offline` 两种取值 |
| devices[].id / name | String | 设备 ID（唯一）/ 名称（格式「站点名+闸孔号#」或「站点名+设备类型#」） |

### 1.3 前端接入要点

- 页面现有 `ICONS`（SVG 模板）与 `STATUS_COLOR`（状态色）保持不变，`color/icon` 由接口数据驱动
- 弹窗「查看全部」复用同一 `devices` 数组，前端自行截断预览列表
- 接入步骤：`getJson('/network-device/summary')` → `renderCategories(data)`，其余逻辑不动

## 二、防洪抗旱决策

页面 = 日期区间查询 + **水文关系预测分析图**（柱状：实际/预测降雨量；曲线：实测/预测水位、实测/预测流量）。**墒情分析图暂不做**（无接口，保留页面占位即可）。

### 2.1 调用流程（异步三连）

```
POST /flood-drought/hydro                 body: { "startDate": "2026-09-01", "endDate": "2026-09-05" }
      → 响应 { "recordId": "..." }（秒回）
GET  /flood-drought/hydro/status/{id}     → { "id", "status": "calculating|completed|failed", "errorMsg" }
GET  /flood-drought/hydro/{id}            → 图数据（2.3 契约），仅 completed 后调用
```

提交参数：

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| startDate | String | 是 | 起始日期 `yyyy-MM-dd`（含） |
| endDate | String | 是 | 截止日期 `yyyy-MM-dd`（含）；`endDate < startDate` → 400；区间 > 90 天 → 400 |

### 2.2 数据语义

- `dates` = 区间逐日（含首尾，自然日）
- **实测段** = 区间内 ≤ 今天的日期，**预测段** = 未来的日期；日期区间选什么给什么
- 实测段缺数据（当天无采集）→ `null`（柱状无柱/折线断线）
- 降雨实测按项目**水文日口径**（同灌区雨情统计）；水位/流量实测取**每日 8 时整点值**（当日 07:00~08:00 最后一条采集，无则回退当日最后一条）
- 流量口径：实测段取渠首进水闸（水库下总干渠渠首，约 47 m³/s 量级），预测段为模型入库流量——两者口径不同（出库 vs 入库），**分界点流量数值可能不连续**属正常
- 预测最长 16 天（天气预报上限）：未来超 16 天时**截断**，以 `forecastEndDate` 标注预测截止日期

### 2.3 图数据响应

```json
{
  "dates": ["2026-09-01", "2026-09-02", "2026-09-03", "2026-09-04", "2026-09-05"],
  "split": 2,
  "rainObs":  [8.5, 18.2, null, null, null],
  "rainPred": [null, null, 9.1, 6.4, 10.2],
  "levelObs": [72.1, 68.5, null, null, null],
  "levelPred": [null, 68.5, 67.9, 68.8, 69.2],
  "flowObs":  [42.0, 40.3, null, null, null],
  "flowPred": [null, 40.3, 39.5, 38.8, 39.9],
  "forecastEndDate": "2026-09-05"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| dates | String[] | 横轴逐日标签（等长于下面所有数组） |
| split | Number | 实测天数（下标 `< split` 为实测段）；**可为 0**（整个区间都在未来时全为预测序列） |
| rainObs / rainPred | Number?[] | 实际/预测降雨量（mm）；对方段置 null |
| levelObs / levelPred | Number?[] | 实测/预测水位（m）；**分界点（split-1 下标）两序列同时有值**保证折线视觉连续 |
| flowObs / flowPred | Number?[] | 实测/预测流量（m³/s，3 位小数）；分界点同上 |
| forecastEndDate | String | 预测截止日期；若发生 16 天截断，用它在图例/提示中标明「预测至 X」 |

### 2.4 前端接入要点

- 提交后立即轮询（复用 `ModelApi.waitCompleted`），`failed` 展示 `errorMsg`
- **图表渲染代码零改动**：现有 mock 的 6 系列（颜色/图例/双轴）与契约完全一致，仅把 `buildHydroMock()` 换成接口数据源
- 页面日期查询按钮事件：发起 POST → 轮询 → 拿详情刷新图表
- 若 `split = 0` 或预测被截断，建议在图上轻提示「预测数据至 {forecastEndDate}」

## 三、配水决策

页面 = 左侧方案列表（搜索）+ 3 汇总卡 + 支渠拓扑（每支渠「需水/配水」标签、日期切换）。

### 3.1 方案列表（复用 ✅）

```
GET /water-decision/list   → [{ "id", "schemeName", "status", "createdAt", ... }]（按创建时间倒序）
```

- 左侧列表直接渲染；关键字搜索前端按 `schemeName` 过滤即可
- 默认选中第一个，选中后调 3.2 / 3.3 刷新右侧

### 3.2 3 汇总卡（复用 ✅）

```
GET /water-decision/{id}   → { "record": {...}, "scaleFactors": [...], "branchDetails": [...] }
```

| 汇总卡 | 数据来源 | 备注 |
|--------|---------|------|
| 总需水量（万m³） | `record.totalDemand` | 浮点，展示用 `fmtNum(..., 0)` |
| 总建议供水（万m³） | `record.totalSupply` | 同上 |
| 不满足需水支渠（条） | `record.unsatisfiedCount` | 浮点，同上 |

### 3.3 拓扑按旬支渠（✅ 已上线）

拓扑每支渠只显示一个值（无旬维度），按日期切换到对应旬（**取起始日期所在旬**）：

```
GET /water-decision/{id}/branches?startDate=2027-05-01
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| startDate | String | 否 | `yyyy-MM-dd`，后端映射到对应旬；不传 = 方案首旬 |

响应：

```json
{
  "tendayLabel": "5月上旬",
  "branches": [
    { "branchName": "城关支渠", "district": "太怀灌区", "subDistrict": "腊皖分干渠", "key": "cg", "demand": 45.6, "supply": 45.6, "isSatisfied": true },
    { "branchName": "红旗支渠", "district": "太怀灌区", "subDistrict": "太宿分干渠", "key": "hq_ts", "demand": 38.2, "supply": 27.1, "isSatisfied": false },
    { "branchName": "红旗支渠", "district": "太怀灌区", "subDistrict": "中干分干渠", "key": "hq_zg", "demand": 30.5, "supply": 30.5, "isSatisfied": true }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| tendayLabel | String | 当前数据对应旬（**无年份前缀**，如 "5月上旬"） |
| branchName | String | 支渠名（**与拓扑 BRANCH_LAYOUT 的 name 对应**；不匹配的节点前端显示「—」） |
| district | String | 灌区（线上实际值如「太怀灌区」） |
| subDistrict | String | 分干渠（如「腊皖分干渠」）；**重名支渠靠它区分**（拓扑 5 处重名：红旗/朝阳/杨树等） |
| key | String? | 拓扑节点标识，**重名支渠必填**（后端按 `subDistrict` 映射生成）；非重名可省略 |
| demand / supply | Number | 需水量 / 建议供水量（万m³） |
| isSatisfied | Boolean | 是否满足（后端由明细 `is_satisfied` #1#/#2# 转换；false → 配水标签橙色「不满足」样式） |

### 3.4 前端接入要点

- 拓扑匹配逻辑不用改：`metricMap[r.key || r.branchName]`——重名支渠靠 `key` 精确命中，非重名靠 `branchName`
- 日期框初始值：方案主表**无日期字段**，由首旬/末旬 `tendayLabel` 反推（"5月上旬" → 05-01）
- 日期切换事件：把现有 `toast('可切换日期（mock）')` 改为请求 3.3 接口（带新 startDate）后 `renderTopoTags()` 刷新
- 方案提交/下载入口（需水方案 + 配置方案两下拉、Excel 下载）见《模型接入接口.md》配水调度章节；`ModelApi.decision.downloadExcel(recordId)` 已封装

## 四、旱情趋势分析（复用，零改动 ✅）

页面已对接真实接口，**无需任何修改**：

```
GET /soil-moisture/sites     → [{ "code", "name" }, ...]（有墒情数据的站点，下拉用）
GET /soil-moisture/trend?stcd={站点编号}&startTime=2026-08-01 00:00:00&endTime=2026-08-31 23:59:59
     → { "stcd", "stnm", "startTime", "endTime", "points": [{ "hour", "mten", "mtwenty", "mthirty", ...8 深度 }] }
```

- 注意：`sites` 返回 **`code`/`name`**（站点编号/名称），而 `trend` 返回 **`stcd`/`stnm`**——两个接口字段名不一致，前端取值用 `s.stcd \|\| s.code`、`s.stnm \|\| s.name` 兼容写法（现有页面已如此处理）
- 页面只用 10/20/30cm：`points[].mten / mtwenty / mthirty`
- 时间参数格式带时间（`yyyy-MM-dd HH:mm:ss`），日期选择器自行拼接 `00:00:00` / `23:59:59`
- 设备异常 `-9991` 显示 "—"；`-999` 为空/断线

## 五、运行管理决策（✅ 已上线）

页面 = 日期区间查询（不变）+ **4 指标卡** + 问题/工单两个状态分布柱状图（不变）。

```
GET /operation/decision-summary?startDate=2026-08-01&endDate=2026-08-31
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| startDate | String | 否 | 统计起始日期（含），`yyyy-MM-dd`；不传 = 不限 |
| endDate | String | 否 | 统计截止日期（含）；不传 = 不限 |

### 5.1 响应

```json
{
  "summary": {
    "patrolCount": 128,
    "patrolCompliance": 85.5,
    "issueCount": 23,
    "issueCompliance": 56.5,
    "orderCount": 9
  },
  "issueStatus": [
    { "name": "待处理",   "value": 5 },
    { "name": "处理中",   "value": 3 },
    { "name": "已转工单", "value": 7 },
    { "name": "已关闭",   "value": 6 },
    { "name": "已作废",   "value": 2 }
  ],
  "orderStatus": [
    { "name": "待处理", "value": 2 },
    { "name": "处理中", "value": 3 },
    { "name": "已关闭", "value": 4 },
    { "name": "已取消", "value": 0 }
  ]
}
```

### 5.2 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| patrolCount | Number | 巡查总次数（已提交巡检记录数，排除草稿） |
| patrolCompliance | Number | **巡查符合度**：0~100 百分数（85.5 = 85.5%）；分母为 0 时返回 0 |
| issueCount | Number | 问题上报数（**页面 4 卡不渲染**，仅供分布合计校验）；若存在未知状态编码的脏数据，合计可能与分布图之和不一致（脏数据计入 issueCount、不进分布图） |
| issueCompliance | Number | **问题符合度**：0~100 百分数；分母为 0 时返回 0 |
| orderCount | Number | 工单数（按创建时间统计，非「要求完成时间」） |
| issueStatus | Array | 问题状态分布，**固定 5 项顺序**，无记录补 0，直接按数组渲染 |
| orderStatus | Array | 工单状态分布，**固定 4 项顺序**，无记录补 0 |

符合度口径（了解即可，前端只读结果）：巡查符合度 = 区间内应完成计划中「已有已提交记录」的计划占比；问题符合度 = 已处置（已转工单 + 已关闭）问题占比。

### 5.3 前端改动清单

1. HTML 3 卡 → **4 卡**，顺序：巡查总次数、巡查符合度、工单数、问题符合度
2. 符合度卡展示：`summary.patrolCompliance + '%'`（值已是百分数，不要 `*100`）
3. 两个分布图渲染逻辑**不变**（后端已固定顺序 + 补 0）
4. 注意：工单状态 `#1#` 名称由线上旧版「待指派」统一为业务定义「**待处理**」，页面文案如有硬编码需同步
5. 日期区间不传 = 全量统计；`startDate > endDate` 时计数为 0（不报错）；传日期时含起止当天
6. 统计口径（表名、时间过滤字段、状态编码）见附录 A.1 / A.3
