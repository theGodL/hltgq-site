# 智能决策接口

> 适用 4 个决策页面：**旱情趋势分析**（drought-trend-analysis.html）、**防洪抗旱决策**（flood-drought-decision.html）、**运行管理决策**（operation-management-decision.html）、**配水决策**（water-allocation-decision.html）。
> 标注「**复用**」的接口详见《模型接入接口.md》相应章节；标注「**本次新增**」的接口本文档给出完整契约。

## 模块总览

| 页面 | 接口 | 来源 | 关键说明 |
|------|------|------|---------|
| 旱情趋势分析 | `GET /soil-moisture/sites`、`GET /soil-moisture/trend` | 复用 | 只需 10/20/30cm，支持日期区间筛选 |
| 防洪抗旱决策·短期 | `POST /water-forecast/short` + 通用 5 件套 | 复用 | 左侧结果列表/搜索用 `/short/list` |
| 防洪抗旱决策·中长期 | `POST /water-forecast/long` + 通用 5 件套 | 复用 + **新增 4 计算字段** | 见 2.3 |
| 防洪抗旱决策·需水 | `POST /water-forecast/demand` + 通用 5 件套 | 复用 | 模板下载 `GET /demand/template` |
| 运行管理决策 | `GET /operation/decision-summary` | **本次新增** | 见第三章（完整契约） |
| 配水决策 | `POST /water-allocation` + 通用 5 件套 | 复用 | 5 汇总卡 + 21 列明细全命中，见第四章 |

> 「通用 5 件套」：`GET /{module}/status/{id}` 轮询 → `GET /{module}/{id}` 详情 → `GET /{module}/list` 列表 → `PUT /{module}/{id}/name` 重命名 → `DELETE /{module}/{id}` 删除。

## 一、旱情趋势分析（复用，零新增）

### 1.1 站点下拉

```
GET /soil-moisture/sites
```

响应：`[{ "stcd": "站点编号", "stnm": "站点名称" }, ...]`（表中有墒情数据的站点，供下拉选择）

### 1.2 墒情趋势曲线

```
GET /soil-moisture/trend?stcd={站点编号}&startTime=2026-08-01 00:00:00&endTime=2026-08-31 23:59:59
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| stcd | String | **是** | 站点编号（来自 1.1） |
| startTime | String | 否 | 起始时间，格式 `yyyy-MM-dd HH:mm:ss`（注意：带时间，非纯日期），默认 7 天前整点 |
| endTime | String | 否 | 截止时间，同格式，默认当前整点 |

响应：`{ "stcd", "stnm", "startTime", "endTime", "points": [{ "hour", "mten", "mtwenty", "mthirty", ...8 深度 }, ...] }`

**前端展示要点**：

- 页面只需 10/20/30cm 三条曲线：取 `points[].mten / mtwenty / mthirty`，其余深度字段忽略
- 日期区间选择器需自行拼接 `00:00:00` / `23:59:59` 再传参
- 设备异常 `-9991` 显示 "—"；设备不存在 `-999` 为空/图表断线（曲线置 null，不断线连线）

## 二、防洪抗旱决策（复用 + 中长期 4 新字段）

页面 3 个 tab 均走「**异步轮询**」模式：提交秒回 recordId → 轮询 status → completed 后拉详情。左侧「结果列表默认选中第一个 + 关键字搜索」直接使用 `GET /{module}/list`（已按 created_at 倒序，前端自行过滤 schemeName 关键字即可）。

### 2.1 短期来水预测 tab（复用）

```
POST /water-forecast/short         提交（参数/契约见《模型接入接口.md》第一章）
GET  /water-forecast/short/status/{id}
GET  /water-forecast/short/{id}    → { record, dailies[] }
GET  /water-forecast/short/list
```

- 总览卡（最高水位/累计入库/累计出库/峰值入库流量）→ `record` 各汇总字段
- 降雨量分布柱状图 / 入库出库曲线 / 流量曲线 → `dailies[]` 逐日明细

### 2.2 需水预测 tab（复用）

```
POST /water-forecast/demand        提交（JSON 直传或 /upload 模板上传）
GET  /water-forecast/demand/template   下载需水基础数据收集表模板
GET  /water-forecast/demand/status/{id}
GET  /water-forecast/demand/{id}   → { record, branchDetails[] }
GET  /water-forecast/demand/list
```

- 总览（全灌区总需水/灌溉面积/需水高峰旬）→ `record`
- 支渠拓扑图 / 四种明细视图（支渠/分灌区/片区/总计）→ `branchDetails[]`

### 2.3 中长期来水预测 tab（复用 + **本次新增 4 计算字段**）

```
POST /water-forecast/long          提交（无时间参数，预测固定为次年起 12 个月 36 旬）
GET  /water-forecast/long/status/{id}
GET  /water-forecast/long/{id}     → { record, tendays[], monthlies[] }
GET  /water-forecast/long/list
```

**本次新增的 4 个详情计算字段**（仅详情接口返回有值，`list` 接口值为 `null`；非落库字段，由后端按 tendays 计算）：

| 字段 | 类型 | 说明 |
|------|------|------|
| maxTendayLabel | String | 最大旬水量对应旬标签（如 "7月中旬"），配 `maxTendayVolume` 展示 |
| minTendayLabel | String | 最小旬水量对应旬标签（如 "12月下旬"），配 `minTendayVolume` 展示 |
| startDate | String | 预测起始日期（tendays 首行 predictDate，ISO） |
| endDate | String | 预测结束日期（tendays 末行 predictDate，ISO） |

- 预测时间行：`startDate` — `endDate`
- 总览（全年预测水量/最大旬水量/最小旬水量）→ `record.annualPredictVolume / maxTendayVolume(+maxTendayLabel) / minTendayVolume(+minTendayLabel)`
- 逐旬来水趋势曲线 → `tendays[]`；月度来水汇总柱状图 → `monthlies[]`；详细结果表 → 同 `tendays[]` + `monthlies[]`
- 其余字段契约见《模型接入接口.md》2.3 节

## 三、运行管理决策（本次新增）

页面 = 日期区间查询 + 总览三卡 + 问题/工单两个状态分布柱状图，一次请求渲染整页。

```
GET /operation/decision-summary?startDate=2026-08-01&endDate=2026-08-31
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| startDate | String | 否 | 统计起始日期（含），格式 `yyyy-MM-dd`；不传 = 不限 |
| endDate | String | 否 | 统计截止日期（含），格式 `yyyy-MM-dd`；不传 = 不限 |

### 响应

```json
{
  "summary": {
    "patrolCount": 128,
    "issueCount": 23,
    "orderCount": 9
  },
  "issueStatus": [
    { "name": "待处理",   "value": 5 },
    { "name": "处理中",   "value": 3 },
    { "name": "已转工单", "value": 7 },
    { "name": "已关闭",   "value": 6 },
    { "name": "已作废",   "value": 2 }
  ],
  "orderStatus": [
    { "name": "待指派", "value": 2 },
    { "name": "处理中", "value": 3 },
    { "name": "已关闭", "value": 4 },
    { "name": "已取消", "value": 0 }
  ]
}
```

### 统计口径

| 字段 | 统计来源 | 时间过滤字段 | 说明 |
|------|---------|------------|------|
| patrolCount | 巡检记录表 `t_auto_hltgq_water_inspection_record` | `time`（巡检时间） | 仅统计 `status=#2#`（已提交），**排除 #1# 草稿** |
| issueCount | 问题记录表 `t_auto_hltgq_knc3g_bpzjoh` | `time`（发现时间） | 全状态计数 |
| orderCount | 工单表 `t_auto_hltgq_water_work_order` | `created_at`（创建时间） | 工单表 `time` 为"要求完成时间"，非产生时间 |
| issueStatus | 问题记录表 | 同 issueCount | 按 `status` 分组，固定 5 项，无记录补 `value=0` |
| orderStatus | 工单表 | 同 orderCount | 按 `status` 分组，固定 4 项，无记录补 `value=0` |

状态编码映射：

| 表 | #1# | #2# | #3# | #4# | #5# |
|----|-----|-----|-----|-----|-----|
| 问题 status | 待处理 | 处理中 | 已转工单 | 已关闭 | 已作废 |
| 工单 status | 待指派 | 处理中 | 已关闭 | 已取消 | — |

### 前端展示要点

- 总览三卡直接绑定 `summary.patrolCount / issueCount / orderCount`
- 柱状图直接按 `issueStatus[]`、`orderStatus[]` 数组顺序渲染（后端已固定顺序并补 0，无需前端过滤/排序）
- 日期区间不传时返回全量统计；传日期时含起止当天；`startDate > endDate` 时计数为 0（不报错）
- 「待指派」为 demo 页面文案，对应工单表 `status=#1#`（业务定义名称为"待处理"），前端无需再做编码转换
- `issueCount` 为问题表全状态计数；`issueStatus[]` 为固定 5 项分布。若表内存在未知状态编码的脏数据，两者合计可能不一致（脏数据计入 issueCount、不进分布图）

## 四、配水决策（复用，零新增）

左侧「水资源调度结果列表默认选中第一个 + 关键字搜索」使用 `GET /water-allocation/list`；右侧详情走异步轮询。

```
POST /water-allocation               提交（含 3 个水位参数，默认 startLevel=75.0/floodLimitLevel=80.0/maxLevel=82.8）
POST /water-allocation/upload        模板上传（multipart：file + 水位参数，预检严格缺列即 400）
GET  /water-allocation/template      下载配水基础数据收集表模板
GET  /water-allocation/status/{id}
GET  /water-allocation/{id}          → { record, tendays[] }
GET  /water-allocation/list
```

### 页面元素与字段映射

| 页面元素 | 数据来源 |
|---------|---------|
| 总览 5 卡（总来水/总需水/总供水/缺水量/弃水量） | `record.totalInflow / totalDemand / totalSupply / deficit / spill` |
| 来水需水对比柱状图 | `tendays[]` 的 `bpInflow` 与 `totalDemand` 逐旬对比 |
| 月末水位与库容曲线图 | `tendays[].endWaterLevel`（水位）与 `tendays[].endStorage`（库容） |
| 详情结果列表（21 列） | `tendays[]` 全字段（**必须按 `sortOrder` 排序**，`tendayLabel` 为字符串不可直接排序） |

### 前端展示要点

- `tendayLabel` 带年份前缀（如 "2027年1月上旬"），展示可自行去掉年份
- `demandGtSupply` 与 `supplyGtDemand` 互斥（一个有值另一个为 0），可合并为一列「供需差（缺/余）」
- `isSatisfied`：`#1#`=是 / `#2#`=否（模型返回"已满足/满足/未满足/不满足"等文本已由后端归一化）
- 差异提示：接口为 36 旬数据，demo 表格部分列需按 `sortOrder` 逐旬渲染；其余字段契约见《模型接入接口.md》第五章
