### 通用约定（前端必读）

| 约定 | 说明 |
|------|------|
| 鉴权 | 所有接口走登录会话（`Authorization` 头），公共库 `lib/model-api.js` 已统一处理，无需额外传参 |
| 异步轮询 | 计算类接口提交**秒回 recordId** → 轮询 status → completed 后拉详情。status 枚举：`calculating / completed / failed`；轮询可直接复用 `ModelApi.waitCompleted` |
| null 语义 | 图表序列中 `null` = 无数据：柱状图不画柱、折线断线；**不渲染为 0** |
| 百分数 | `patrolCompliance / issueCompliance` 返回 **0~100 数值**（如 `85.5` 表示 85.5%），前端拼接 `%` 展示，不做除法 |
| 数字精度 | 水位/流量 3 位小数、雨量 1 位小数；方案汇总字段（totalDemand 等）为浮点可能带小数，展示用 `fmtNum` 处理 |
| 新接口封装 | 建议在 `lib/model-api.js` 补充 floodDrought / networkDevice / engineering / decision.branches 客户端（参考现有 `operation`、`soilMoisture` 写法），或页面内直接 `getJson('/xxx')` |

## 一、网络设备监控

一次请求渲染整页：顶部汇总卡 + 7 类设备列（水位/雨量/流量/闸门/视频/墒情/水质）。

```
GET /network-device/summary
```

无参数。

### 1.1 响应

```json
{
  "regionName": "花凉亭灌区",
  "total": 186,
  "summary": {
    "online":  { "count": 142, "percent": 76 },
    "offline": { "count": 32,  "percent": 17 },
    "alarm":   { "count": 0,   "percent": 0 },
    "fault":   { "count": 0,   "percent": 0 }
  },
  "categories": [
    {
      "key": "waterLevel",
      "name": "水位",
      "color": "#1E90FF",
      "icon": "waterLevel",
      "total": 28,
      "counts": { "online": 22, "offline": 4, "alarm": 0, "fault": 0 },
      "devices": [
        { "id": "设备ID", "name": "南山寺节制闸1#", "status": "online" },
        { "id": "设备ID", "name": "集岭管理所雨量计#", "status": "offline" }
      ]
    }
  ]
}
```

### 1.2 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| regionName | String | 区域名 |
| total | Number | **设备去重总数**（多类型设备只计 1 次），故 `total ≠ Σcategories[].total` 属正常 |
| summary.* | Object | 4 项**固定返回**；alarm/fault 暂不支持恒 0（设备目前只有在线/离线） |
| summary.*.percent | Number | 已按四舍五入取整，直接展示拼 `%` |
| categories[] | Array | **固定 7 项、顺序固定**：waterLevel/rainfall/flow/gate/video/soil/quality；设备表无数据时仍返回 7 项（全 0 结构，页面不会塌） |
| categories[].color / icon | String | 分类色块色值与图标键名，页面渲染**直接使用**（`cat.color`、`ICONS[cat.icon]`），不要自行映射 |
| devices[] | Array | 该类**全量**设备；`status` 仅 `online/offline` 两种取值 |
| devices[].id / name | String | 设备 ID（唯一）/ 名称（格式「站点名+闸孔号#」或「站点名+设备类型#」） |

### 1.3 前端接入要点

- 页面现有 `ICONS`（SVG 模板）与 `STATUS_COLOR`（状态色）保持不变，`color/icon` 由接口数据驱动
- 弹窗「查看全部」复用同一 `devices` 数组，前端自行截断预览列表
- 接入步骤：`getJson('/network-device/summary')` → `renderCategories(data)`，其余逻辑不动

```
GET /flood-drought/stations
```

无参数。响应：

| 字段 | 说明 |
|------|------|

| [].stcd | 站点查询键（站点档案 iofhpi，兼容编号与 MQTT 站 site UUID）；作为 2.2 选站参数原样回传 |

### 2.2 历史实测块（同步查询，无轮询）

```
GET /flood-drought/history?startDate=2026-09-01&endDate=2026-09-05[&rainStcd=...&levelStcd=...&flowStcd=...]
```

参数：

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| startDate | String | 是 | 起始日期 `yyyy-MM-dd`（含） |
| endDate | String | 是 | 截止日期 `yyyy-MM-dd`（含）；`endDate < startDate` → 400；区间 > 90 天 → 400 |
| rainStcd / levelStcd / flowStcd | String | 否 | 选站（取 2.1 下拉的 stcd）；不传时按配置，未配置按类型自动选站（水位默认花凉亭坝上 3206400007）；无效 stcd 该序列全 null |

响应：

```json
{
  "dates": ["2026-09-01", "2026-09-02", "2026-09-03", "2026-09-04", "2026-09-05"],
  "rain":  { "stcd": "3206400001", "stnm": "周家河", "values": [8.5, 18.2, null, 0.0, 3.1] },
  "level": { "stcd": "3206400007", "stnm": "花凉亭水库(坝上)", "values": [72.102, 68.531, 67.902, null, 68.120] },
  "flow":  { "stcd": "CAYQ739MiBWMg9gQvyi", "stnm": "渠首进水闸", "values": [42.0, 40.3, null, 39.5, null] }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| dates | String[] | 横轴逐日标签（含首尾，自然日） |
| rain / level / flow | Object | 三序列各自带站点（可独立切换）；`values` 与 `dates` 等长 |
| *.stcd / *.stnm | String | 序列**实际采用**的站点（用于回显下拉选中态）；stnm 查不到时与 stcd 相同 |
| rain.values | Number?[] | 逐日降雨（mm，1 位小数）；水文日口径（D-1 08:00 ~ D 08:00）；缺数据 null（**0.0 = 当日确实无雨**） |
| level.values | Number?[] | 逐日水位（m，3 位小数）；每日 8 时整点值（07:00~08:00 最后一条，无则当日最后一条）；缺数据 null |
| flow.values | Number?[] | 逐日流量（m³/s，3 位小数）；口径同上；默认渠首进水闸（出库流量） |

### 2.3 预测块（短期预报方案）

预测块复用 `/water-forecast/short` 接口，**两种取数方式**：

**方式一：本页按参数直接计算**（对应会议「按所选日期、降雨量、开关取最新结果」，推荐）

```
POST /water-forecast/short          body: { "start": "2026-09-05 08:00", "end": "2026-09-08 08:00", "enablePower": false, "enableTunnel": false, "enableSpillway": false, "rainfall": [...] }
      → { "recordId": "..." }（秒回）
GET  /water-forecast/short/status/{id}   → { "id", "status": "calculating|completed|failed", "errorMsg" }
GET  /water-forecast/short/{id}          → { "record": {...}, "dailies": [逐小时明细] }（仅 completed 后调用）
```

| 提交参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| start / end | String | 是 | 预报窗口 `yyyy-MM-dd HH:mm`（含端点，1~384 小时，对应前端所选日期） |
| enablePower / enableTunnel / enableSpillway | Boolean | 否 | 发电/泄洪隧洞/溢洪道开关，**默认均 false**（模型参数默认 true，后端按会议「默认全关」口径显式传 false；前端不传即全关） |
| rainfall | Number[] | 否 | 与窗口等长的逐小时降雨序列（前端所选降雨量）；不传则后端自动拉气象 |
| schemeName | String | 否 | 方案名称（默认自动生成） |

**方式二：下拉历史方案**（展示既往计算结果，不再提交）

```
GET /water-forecast/short/list   → 方案列表（含 id/schemeName/status/startDate/endDate 等，最新在前）
GET /water-forecast/short/{id}   → 同上详情
```

dailies[] 常用字段：

| 字段 | 说明 |
|------|------|
| forecastDate | 小时粒度时间（模型 data[].时间） |
| rainfall | 逐小时降雨（mm，模型入参） |
| waterLevel | 逐小时水位（m，模型演算） |
| inflowRate / outflowRate | 入/出库流量（m³/s） |
| inflowVolume / outflowVolume / storage | 入/出库水量、库容（万方） |

要点：

- 预测图取 `dailies` 的 `waterLevel`/`rainfall`（逐小时绘制或按日聚合皆可），**与 2.2 历史图分开展示**
- 水位预测口径：起调水位自动取花凉亭坝上最新水位（配置 `flood-drought.obs-level-stcd`），**只盯坝上，不含下游河道站**
- 轮询可直接复用 `ModelApi.waitCompleted`；`failed` 展示 `errorMsg`

### 2.4 前端接入要点

- 历史块：`getJson('/flood-drought/stations')` 填 3 个下拉（默认选中 = 不传站参数时 2.2 返回的 `*.stcd`）→ `getJson('/flood-drought/history?...')` 渲染两图（上图雨量柱、下图水位/流量线）；切换站点带参数重新请求
- 预测块：页面「计算」按钮直接 `POST /water-forecast/short` → 轮询 → 详情渲染独立预测图；页面「历史方案」下拉接 `/water-forecast/short/list` + `/{id}`
- 原 `buildHydroMock()` 的 6 系列混拼图作废，渲染按「历史两图 + 预测图」拆分
- null 语义：null 不画柱/断线，不渲染为 0

### 2.5 抗旱模块（墒情）接口集

会议 2 纪要要求墒情拆出独立模块；**接口已全部就绪**（无需后端新增）。**产品结论（胡宇，已定稿）**：三处墒情能力不合并、应标要求在不同功能页面分别体现——本模块（智能决策·抗旱）与旱情趋势页（第四章）、水量预报·墒情预测页（《模型接入接口.md》第七章）各自独立接入。完整契约如下：

**A. 实测墒情（日期区间式查询，旱情趋势页同款，见第四章）**

```
GET /soil-moisture/sites     → [{ "code", "name" }, ...]（有墒情数据的站点，下拉用）
GET /soil-moisture/trend?stcd={站点编号}&startTime=2026-08-01 00:00:00&endTime=2026-08-31 23:59:59
     → { "stcd", "stnm", "startTime", "endTime", "points": [{ "hour", "mten", "mtwenty", "mthirty", ...8 深度 }] }
```

**B. 模型墒情预测（方案式，含国标干旱等级）**

```
POST /water-forecast/moisture          body: { "schemeName": "可选", "days": 16 }
      → { "recordId": "..." }（秒回；days 可选默认 16，范围 1~16）
GET  /water-forecast/moisture/status/{id}   → { "id", "status": "calculating|completed|failed", "errorMsg" }
GET  /water-forecast/moisture/{id}          → { "record": {...}, "details": [四站 × 逐小时] }
GET  /water-forecast/moisture/list          → 历史方案列表（最新在前）
```

details[] 字段：

| 字段 | 说明 |
|------|------|
| site | 站点 ID（**四站固定**：太湖毕岭/望江/宿松/怀宁麻塘湖；初值自动取各站最新有效数据，无需前端传） |
| tm | 小时粒度时间 |
| rainfall | 逐小时降雨（mm，后端自动拉气象） |
| mten / mtwenty / mthirty | 10/20/30cm 层含水量（%） |
| gValue | G 值（RSM 相对湿度） |
| droughtLevel | **国标干旱等级**（编码见下表，逐小时输出，前端按连续段聚合即得「某时段轻旱/重旱」标注） |

干旱等级编码：

| 编码 | 含义 |
|------|------|
| #1# | 无旱 |
| #2# | 轻旱 |
| #3# | 中旱 |
| #4# | 重旱 |
| #5# | 特旱 |

前端接入要点：

- 「干旱等级标注时段」= 前端按 `details[].droughtLevel` 连续相同编码聚合区间（后端已给逐小时等级，不重复聚合为时段）
- 与旱情趋势页（第四章）的功能关系：**已定稿不合并**（应标要求，各页面独立体现，见附录 B）

## 三、配水决策

页面 = 左侧方案列表（搜索）+ 3 汇总卡 + 支渠拓扑（每支渠「需水/配水」标签、日期切换）。

### 3.1 方案列表（复用 ✅）

```
GET /water-decision/list   → [{ "id", "schemeName", "status", "createdAt", ... }]（按创建时间倒序）
```

- 左侧列表直接渲染；关键字搜索前端按 `schemeName` 过滤即可
- 默认选中第一个，选中后调 3.2 / 3.3 刷新右侧

### 3.2 3 汇总卡（复用 ✅）

```
GET /water-decision/{id}   → { "record": {...}, "scaleFactors": [...], "branchDetails": [...] }
```

| 汇总卡 | 数据来源 | 备注 |
|--------|---------|------|
| 总需水量（万m³） | `record.totalDemand` | 浮点，展示用 `fmtNum(..., 0)` |
| 总建议供水（万m³） | `record.totalSupply` | 同上 |
| 不满足需水支渠（条） | `record.unsatisfiedCount` | 浮点，同上；口径待办（会议 2 挂周俊）：isSatisfied 取自模型返回的「是否满足」字段（后端仅归一化），确认口径后后端改聚合 |

### 3.3 拓扑按旬支渠（✅ 已上线）

拓扑每支渠只显示一个值（无旬维度），按日期切换到对应旬（**取起始日期所在旬**）：

```
GET /water-decision/{id}/branches?startDate=2027-05-01
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| startDate | String | 否 | `yyyy-MM-dd`，后端映射到对应旬；不传 = 方案首旬 |

响应：

```json
{
  "tendayLabel": "5月上旬",
  "branches": [
    { "branchName": "城关支渠", "district": "太怀灌区", "subDistrict": "腊皖分干渠", "key": "cg", "demand": 45.6, "supply": 45.6, "isSatisfied": true },
    { "branchName": "红旗支渠", "district": "太怀灌区", "subDistrict": "太宿分干渠", "key": "hq_ts", "demand": 38.2, "supply": 27.1, "isSatisfied": false },
    { "branchName": "红旗支渠", "district": "太怀灌区", "subDistrict": "中干分干渠", "key": "hq_zg", "demand": 30.5, "supply": 30.5, "isSatisfied": true }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| tendayLabel | String | 当前数据对应旬（**无年份前缀**，如 "5月上旬"） |
| branchName | String | 支渠名（**与拓扑 BRANCH_LAYOUT 的 name 对应**；不匹配的节点前端显示「—」） |
| district | String | 灌区（线上实际值如「太怀灌区」） |
| subDistrict | String | 分干渠（如「腊皖分干渠」）；**重名支渠靠它区分**（拓扑 5 处重名：红旗/朝阳/杨树等） |
| key | String? | 拓扑节点标识，**重名支渠必填**（后端按 `subDistrict` 映射生成）；非重名可省略 |
| demand / supply | Number | 需水量 / 建议供水量（万m³） |
| isSatisfied | Boolean | 是否满足（后端由明细 `is_satisfied` #1#/#2# 转换；false → 配水标签橙色「不满足」样式） |

### 3.4 前端接入要点
