# 消息发送设置

对五类消息配置「什么类型的消息发给谁」：按**部门 / 岗位 / 角色 / 人员**四个维度定向接收对象；
**告警类**可再限定**站点范围**（选择站点）。配置结果由 H5 消息中心（`/h5/message/*`）在按需同步时消费——
H5 端接口契约不变，本次为行为增强（兼容适配：值域扩展 `dutyRole=receiver`）。

- 页面：`/message-rule-setting.html`（**仅系统管理员可见**；5 个消息类型 Tab + 抽屉内双态：表单 ↔ 多选）
- 表：`"qixiao-apaas".t_auto_hltgq_water_message_rule`（本期新增 `site_id` 列，DDL 见 `message-rule-ddl.sql`）
- 规则语义分两组（与 H5 消息中心同步判定代码一致）：
  - **可见性规则**（告警 `#1#` / 举报投诉 `#2#` / 意见征集 `#3#`）：命中规则的部门/岗位/角色/人员**才可见**该类消息；
    某类型**暂无规则 = 全员可见**（与改造前行为一致）；告警再叠加**站点范围**（未选站点 = 不限站点）。
  - **附加接收人**（值班提醒 `#4#` / 模型计算 `#5#`）：**原有定向不变**——当班领导/值班人员、方案提交人**始终收到**；
    此处配置的对象为**附加接收人**，额外收到该类消息（不改变原有定向的任何行为）。

> 上线约束（必须）：**代码部署前先执行 `message-rule-ddl.sql`**（规则表增加 `site_id` 列，`IF NOT EXISTS` 幂等）。
> 若先上代码后加列，规则载入 SQL（实体 `selectList` 含 site_id）将报错，导致 H5 消息同步整体失败
> （接口自身降级可用，但所有消息停止补建，日志 `h5 message sync failed`）。

## 1. 字段口径（列现状 + 本期新增）

| 列 | 含义 | 写入 | 读取 |
|---|---|---|---|
| `message_type` | 消息类型编码 `#1#`~`#5#`（见 §2 字典） | 新增时写入；**编辑锁定** | 规则分组键 |
| `target_type` | 接收维度编码 `#org#`/`#position#`/`#role#`/`#user#` | 新增时写入；**编辑锁定** | 命中判定维度 |
| `target_id` | 目标编码，多个英文逗号分隔（部门/岗位/角色取 `code`，人员取 **`login_name`**） | 新增/编辑写入（服务层去重保序后落库） | 命中匹配键 |
| `site_id` | **本期新增**：站点范围（**仅告警 `#1#` 生效**），站点档案主键（`t_auto_hltgq_5nw74_vnqqef.id`）逗号分隔；空 = 不限站点 | 新增/编辑写入；非告警类型服务层归一化为空 | 告警补建的站点过滤键 |
| `id`/`corp_code`/`created_*`/`updated_*` | 平台标准审计列 | 新增时全部写入（会话缺失用配置兜底） | `updated_at` 作列表排序与展示 |

- `site_id` 类型为**无长度 `varchar`**（与线上 `target_id` 实测一致），205 个站点全选约 4100 字符不超限；
- **唯一性**：该表只有主键约束，**没有业务唯一索引**；判重由应用层完成，
  判重键 = 「`message_type` + `target_type` + `target_id`（逗号拼接后整串原样比较）」，**站点范围不参与判重**；
- **id 生成**：实体继承 `BaseWaterEntity`，走全局 `ShortIdGenerator` 生成 **22 位**短 ID（平台规范）；
- **存量数据**：线上原 1 行规则（`#1#`/`#user#`/两个登录名），加列后 `site_id` 为 `NULL` = 不限站点，行为与改造前完全一致。

### 2.1 接收维度与候选口径（与 H5 命中判定同源）

| 维度 | 编码 | 候选/保存值 | 说明 |
|---|---|---|---|
| 部门 | `#org#` | `t_apaas_uc_org.code`（`corp_code='hltgq'`） | 命中 = 用户所属部门编码交集非空（企业关系表 `t_apaas_uc_user_org_rel`） |
| 岗位 | `#position#` | `t_apaas_uc_position.code` | 命中 = 用户所属岗位编码交集非空（`t_apaas_uc_user_position_rel`） |
| 角色 | `#role#` | `t_apaas_auth_role.code` | 命中 = 用户**直接指派**角色编码交集非空（`field_id='USER'`，黑名单关联不参与） |
| 人员 | `#user#` | **`login_name`（登录名）** | 命中 = 登录名精确匹配（当前登录人 `login_name`） |
| 站点 | `site`（候选专用） | 站点档案主键 `id` | 仅告警规则可用；`sub` 展示站点编号 `iofhpi`，`label` 展示站名 `zzkaec` |

- 候选数据量小，`/message-rule/options` **全量返回**（部门 32 / 岗位 47 / 角色 3 / 人员 150 / 站点 205，代码注释实测口径），
  页面多选列表**本地关键词过滤**，不落分页接口；
- 人员候选 `sub` 显示登录名辅助区分重名；目标 `value` 一律为上述编码（保存进 `target_id` 的匹配键）；
- 多选保存时**去重保序**（逗号拼接），名称展示解析时档案缺失项原样回退编码。

## 3. 接口契约

统一前缀 `/message-rule`，**仅系统管理员**（类注解 `@RequireAdmin`，非管理员返回 403 JSON）；
业务校验失败返回 **HTTP 400 + `{message}`**（`GlobalExceptionHandler` 统一处理）。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/message-rule/meta` | 字典：`messageTypes[]`（value/label/siteSupported/extraReceiver/desc）+ `targetTypes[]`（value/label） |
| GET | `/message-rule/page?page=&size=&messageType=` | 规则分页，按 `updated_at` 倒序（`NULLS LAST`）；`messageType` 可选过滤（传了必须合法）；`size` 上限 200（默认 20） |
| GET | `/message-rule/options?kind=` | 多选候选：`kind` = `org` 部门 / `position` 岗位 / `role` 角色 / `user` 人员 / `site` 站点（非法值 400） |
| POST | `/message-rule` | 新增：`{messageType, targetType, targetId, siteId}`（targetId 逗号拼接；siteId 仅告警可传，空=不限站点） |
| PUT | `/message-rule/{id}` | 编辑：`{targetId, siteId}`（**消息类型与接收维度锁定**，换类型/维度=删除后重新新增） |
| DELETE | `/message-rule/{id}` | 删除（物理删除；接收记录与规则解耦，不受影响） |

列表/详情返回字段（`MessageRuleVO`）：`id, messageType, messageTypeLabel, targetType, targetTypeLabel,
targetId, targetNames, siteId, siteNames, updatedAt`。
其中 `targetNames`/`siteNames` 由服务层按维度合并去重后**批量解析**（防 N+1），顿号拼接；
`targetId`/`siteId` 为原始逗号拼接值（编辑回填用）。

**校验规则**

| 情况 | 后端行为 | 前端行为 |
|---|---|---|
| 消息类型为空 / 不在字典 | 400「messageType 仅支持 #1# 告警 / #2# 举报投诉 / #3# 意见征集 / #4# 值班提醒 / #5# 模型计算」 | 下拉只列字典内类型，不会提交非法值 |
| 接收维度为空 / 不在字典 | 400「targetType 仅支持 #org# 部门 / #position# 岗位 / #role# 角色 / #user# 人员」 | 同上 |
| 接收对象为空 | 400「请至少选择一个接收对象」 | 接收对象框标红并拦截保存 |
| 接收对象不存在（对应档案无此编码） | 400「以下部门不存在：xxx」（维度名动态） | 多选候选即档案数据，正常不会提交非法值 |
| 站点不存在 | 400「以下站点不存在：xxx」 | 同上（站点候选=站点档案） |
| 重复规则（同类型+同维度+同目标串） | 400「该类型该维度下已存在完全相同的规则，请直接编辑」（编辑时「已存在完全相同的规则」，排除自身） | 错误 toast，抽屉不关、已填内容保留 |
| 规则 id 不存在 | 400「规则不存在或已删除」 | 列表刷新后重试 |
| 非系统管理员 | 403（拦截器统一 JSON） | 页面加载时隐藏内容并展示「仅系统管理员可访问」占位 |

## 4. 规则生效与 H5 消息中心同步口径（对外约定）

1. **同步时机**：无定时任务、无后台推送；H5 端 summary/page 被调用时按需补建接收记录
   （`NOT EXISTS` 幂等、Redis 30 秒防抖）。**规则发布后无需重启，下一次同步即生效**（消息延迟 ≤ 30 秒）。
2. **前三类可见性判定**：该类无规则 = 全员可见；有规则时**任一命中即可见**——
   `#user#` 按当前登录人 `login_name` 精确匹配，`#org#`/`#position#`/`#role#` 与用户所属编码求交集（角色仅直接指派）。
3. **告警站点范围**：命中规则的 `site_id` **合并**为站点范围（`a.site IN (...)` 过滤）；
   任一命中规则 `site_id` 为空 = **不限站点**；未命中任何规则 = **不可见**（不补建）。
4. **值班附加接收人**：命中值班规则 → 额外补建**近两日**值班中排班（与定向同条件：已进入「值班中」+ 未提醒 + 日期不早于昨日），
   **不限本人班次**，列表 `dutyRole=receiver`（「接收人」）。
5. **模型附加接收人**：命中模型规则 → 额外补建**近 7 天**完成的方案（**不限提交人**，含系统自动预跑/恢复方案）；
   7 天时间窗防止首次配置把历史全量方案灌入。
6. **存量回溯边界**：前三类命中规则后**全量补建**（含历史告警/投诉/意见，受站点范围限制）；
   值班附加限近两日、模型附加限近 7 天（增量语义）。
7. **收缩不回滚**：规则收紧（删除/缩站点/缩目标）后**已建接收记录保留**（已读状态不丢失），
   仅影响后续新消息的补建；接收记录与业务表 JOIN 展示，业务数据删除时列表行自然消失。
8. **同步日志**：每次同步打印 `alertVisible/sites、complaintVisible、suggestionVisible、duty leader/staffCol/staffRel/rule、
   modelCalc/modelCalcRule` 计数，部署后据此核对规则生效情况。

## 5. 页面说明（`message-rule-setting.html`）

- **权限门**：进页调 `/auth/current-user`，`admin !== true` 时隐藏页面并展示「仅系统管理员可访问」占位
  （与雨量数据维护页同一模式；判定失败不拦截，由后端 403 兜底）。
- **布局**：Tab 白卡（上行 5 类消息 Tab + 右侧「新增规则」按钮；下行当前类型语义说明行，文案取 meta.desc）
  + 规则表格卡（全宽）。
- **列表**（5 列：接收维度 12% / 接收对象 38% / 站点范围 26% / 更新时间 12% / 操作 12%）：
  - 接收维度、接收对象为当前 Tab 类型下的规则行（名称已由后端解析，顿号拼接）；
  - 站点范围：告警类型显示站名拼接，未设置显示「不限站点」；非告警类型显示 `--`；
  - 操作列为图标按钮：编辑 / 删除（删除红色 hover + 二次确认）；
  - 分页：共 X 条 · 页码 · 条/页 · 跳至 X 页（与阈值设置页同规格）。
- **抽屉（480px 右侧滑入，内页两态）**：
  - **表单态**：消息类型（新增默认取当前 Tab，可改）、接收维度、接收对象（点击进入多选）、
    站点范围（仅告警显示，提示「未选择表示全部站点」）；
  - **多选态**：搜索框（按名称/编号/登录名本地过滤）+ 全选 / 清空已选 + 勾选列表 + 已选计数；
    底部按钮组随状态切换（表单态：取消/保存 ↔ 多选态：返回/确定）；
  - **编辑**：消息类型与接收维度**置灰锁定**（换类型/维度 = 删除后重新新增，与阈值设置页同一约定），
    接收对象与站点范围可改；
  - **联动**：切换接收维度清空已选对象；切换消息类型时站点字段按 `siteSupported` 显隐，非告警时清空站点。
- **保存反馈**：成功 → 关闭抽屉 + 刷新列表 + 该行高亮闪烁一次 + toast「保存成功」；
  失败（查重冲突等）→ 错误 toast，抽屉不关、已填内容保留。
- **删除**：二次确认文案「删除后，【告警】将不再按此规则发送给"xxx"，是否继续？」。
- **样式变量**：色值/尺寸/圆角/层级统一在 `:root` 的 `--el-*` 变量（与阈值设置页同一套平台规范）；
  Tab 为 `maint-tabs` 白卡样式（当前项主色实底），多选框为 `multi-box` + 标签（`m-tag`）形态，
  与值班管理页、雨量数据维护页同一套交互语言。

## 6. 已核对结论与注意事项

1. **H5 端兼容性（本次核心约束）**：`/h5/message/*` 四个接口的请求/响应结构**完全不变**，
   本次为行为增强：① 告警按站点范围补建；② 值班/模型增加规则附加接收人；
   ③ **`dutyRole` 值域扩展** `receiver`（「接收人」）——H5 前端如对 dutyRole 做枚举渲染需同步知晓，
   未知值兜底展示后端下发的 `dutyRoleLabel` 即可。
2. **上线顺序（必须遵守）**：
   - ① 目标库执行 `message-rule-ddl.sql`（`site_id` 列，`IF NOT EXISTS` 幂等，事务包裹）；
   - ② 部署本次代码；③ 页面 `/message-rule-setting.html` 配置规则（或保持存量 1 行规则原样）。
   - 反序后果：规则表缺 `site_id` 列时实体查询报错 → 消息同步整体失败（日志 `h5 message sync failed`），
     H5 消息中心不再补建任何新消息。
3. **KingbaseES 注意事项**（沿用项目既有结论）：字符串拼接必须用 `CONCAT`（`||` 在该库按逻辑 OR 处理）；
   自定义 SQL 列别名必须与 VO 属性同名（全局 `map-underscore-to-camel-case=false`）。
4. **编辑锁定口径**：消息类型与接收维度一经创建不可修改（与阈值设置页「换类型=删除重建」同一先例），
   避免规则语义在两侧判定代码间漂移；确实要换则删除后重新新增。
5. **判重弱点（知情接受）**：判重键为整串比较（不含站点范围、不排序归一化），
   目标集合相同但逗号顺序不同的两条规则不会被判重（行为上等价：命中判定均为包含关系）；
   站点范围不同不视为重复（属预期：同类型同维度多渠道并存）。
6. **权限**：仅系统管理员（后端 `@RequireAdmin` + 前端 `admin` 标记门控）；
   本页**不开放给普通用户**（与阈值设置页"权限全放开"策略不同，消息接收规则属敏感配置）。
7. **不在本期范围**：消息文案/模板自定义、短信/微信/钉钉等外发渠道、免打扰时段、规则启停开关、
   值班/模型"替换式"接收（不动原有定向）、动态自定义维度。
