## 〇、通用约定

### 0.1 分页响应结构

`GET /water-saving/schemes/page` 返回统一结构：

```json
{
  "total": 36,
  "page": 1,
  "size": 20,
  "pages": 2,
  "records": [ ... ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| total | number | 满足筛选条件的总行数 |
| page | number | 当前页码（请求参数收敛 1 ~ 100000） |
| size | number | 每页行数（请求参数收敛 1 ~ 100，默认 20） |
| pages | number | 总页数 = ⌈total / size⌉ |
| records | array | 当前页数据行（完整方案 VO，含指标结果行与达标链） |

> 年度水量 / 指标体系列表接口返回**全量数组**（不分页，前端自行过滤分页）。

### 0.2 错误应答格式

| HTTP | 场景 | 应答体 |
|------|------|--------|
| 400 | 参数校验失败（含状态机非法流转、目标超潜力等） | `{"message":"…具体原因…"}` |
| 401 | 未登录 / 会话过期 | `{"code":401,"message":"未登录"}` |
| 403 | 非系统管理员执行写操作 | `{"message":"…"}`（拦截器统一文案） |
| 409 | 唯一约束冲突 | `{"message":"数据已存在或不满足约束，请刷新后重试"}`（含三条专属文案，见下） |

唯一索引专属提示（GlobalExceptionHandler 已内置）：

| 约束 | 文案 |
|------|------|
| `uk_water_saving_annual_year` | 该潜力年度已存在水量记录，请刷新列表后直接编辑 |
| `uk_water_saving_scheme_year_name` | 同一年度已存在同名节水方案，请刷新列表后重试 |
| `uk_water_saving_indicator_name` | 指标名称已存在（停用指标的名称同样占用），请刷新列表后重试 |

**前端建议**：所有写操作失败时优先展示应答体 `message` 字段（后端已给出可直接上屏的中文文案）。

### 0.3 数量口径（重点）

- 水量一律 **万m³**，最多 **6 位小数**（写入 >6 位小数报 400）；
- **潜力 = 上一年实际放水量 − 上一年计划放水量**（万m³，**可为负、不截断**）；任一为空 → 潜力不可计算（null）；
- 节水目标：**0 < 目标 ≤ 潜力**（潜力 ≤ 0 不可建方案）；
- 节水量 = 实施前实际（快照）− 实施后实际（万m³）；
- 节水率(%) = 节水量 ÷ 实施前实际 × 100（实施前 = 0 → 无法计算）；
- 目标完成率(%) = 节水量 ÷ 方案目标 × 100（方案目标 = 0 → 无法计算，防御口径）；
- 比率类保留 **2 位小数**，节水量保留 **6 位小数**。

### 0.4 状态码体系（筛选参数传什么）

| 字典 | 库内码 | 取值 |
|------|--------|------|
| 方案状态 | `#1#`~`#4#` | #1# 草稿 / #2# 实施中 / #3# 已完成 / #4# 待复核 |
| 指标计算方式 | `#1#`~`#3#` | #1# 节水量(万m³) / #2# 节水率(%) / #3# 目标完成率(%) |
| 指标启停 | `#1#`/`#2#` | #1# 启用 / #2# 停用（停用后新方案不可勾选，既有关联保留） |
| 对比条件确认 | `#1#`/`#2#`/null | #1# 已确认（核验后计算）/ #2# 未确认（不计算、标记待复核）/ null 未核验 |
| 核验作废标记 | `#1#`/`#2#` | #1# 已作废（数据保留、达标强制待核验）/ #2# 有效 |
| 演示数据标记 | `#1#`/`#2#` | #1# 虚拟演示 / #2# 正式（默认） |
| 计划来源 | 文本码 | `auto_plan` 用水计划带出 / `manual` 手工录入 |
| 实际来源 | 文本码 | `manual` 手工录入 / `canal_head_meter` 渠首自动计量 |

**规则**：筛选参数与请求体状态字段一律传**库内码原值**（如 `status=%231%23`）；响应字段按库内码输出（同时提供 `xxxName` 中文名）；`GET /water-saving/meta` 返回的字典 `value` 即为应交回的形态。

### 0.5 达标优先级链与状态机（V1.4，服务端唯一实现）

**方案级达标状态（attainLevel，从高到低命中即停）：**

| 优先级 | attainLevel | 中文 | 触发条件 |
|--------|-------------|------|----------|
| 1 | pending_verify | 待核验 | 未核验 / 核验作废 / 对比条件未确认 |
| 2 | pending_target | 待设置目标 | 存在未维护目标值的关联指标（该行态 no_target） |
| 3 | pending_indicator | 待关联指标 | 未勾选评估指标（异常态，接口会强制阻断） |
| 4 | uncomputable | 待复核 | 存在无法计算的指标（分母为 0），attainReason=「指标无法计算」 |
| 5 | fail | 不达标 | 存在结果不达标（含任一 fail） |
| 6 | partial | 部分达标 | 全部可计算、部分达标 |
| 7 | pass | 达标 | 全部可计算且全部达标 |

**指标行展示态（indicators[].state）：** `pass` 达标 / `fail` 不达标 / `pending` 待核验 / `uncomputable` 无法计算 / `no_target` 待设置。

**方案状态流转（status）：**

- 新增：仅可选 `#1#` 草稿 / `#2#` 实施中；
- 编辑：**未核验**方案可在 `#1#`/`#2#` 间调整；**已核验**方案状态由核验动作驱动（提交值忽略）；
- 核验：对比条件**已确认** → `#3#` 已完成 + 复位作废标记 + 按公式计算；**未确认** → `#4#` 待复核（不计算）；
- 核验作废（方案A，依据变更）：`#4#` 待复核 + `verify_*` 数据保留 + `verify_invalid=#1#` + last_recalc 留痕；触发场景：①编辑换依据记录；②刷新对比依据；③依据记录水量被修改经保存联动。

### 0.6 对比依据快照（baselineVolume）

- 建方案时固化 `baseline_volume = 依据记录的上一年实际放水量`（快照，不随记录后续变化）；
- 编辑**换依据** → baseline 取新记录实放值；**未换依据**编辑 → baseline 保持不变；
- 「刷新对比依据」动作 → baseline 拉齐为当前记录实放值，曾核验同时作废；
- 核验页提示「依据记录现值 ≠ 快照」时，建议先刷新再核验。

### 0.7 附件口径

- 本地存储：`file-dir/saving/{yyyy-MM}/{短id}_{原文件名}`；上传即替换（旧文件提交后清理）；
- 单文件 **≤ 2MB**；白名单扩展名：`jpg / jpeg / png / gif / bmp / webp / pdf / doc / docx / xls / xlsx`；
- 下载带 `Content-Disposition`（RFC 5987 原始文件名），前端以 fetch + blob 取用。

## 二、年度水量设置（/water-saving/annual-water）

一行记录 = 一个潜力年度：`{潜力年度，依据年度（=潜力年度−1），上一年计划，上一年实际}`，潜力由服务端计算。

### 2.1 GET /water-saving/annual-water/list — 全量列表

**请求参数**：无。

**响应**：`SavingAnnualVO` 数组（潜力年度倒序）。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 记录 id |
| potentialYear | int | 潜力年度（如 2026） |
| basisYear | int | 依据年度（= 潜力年度 − 1） |
| prevPlanVolume | number\|null | 上一年计划放水量（万m³） |
| prevActualVolume | number\|null | 上一年实际放水量（万m³） |
| potential | number\|null | 潜力（服务端计算：实际 − 计划；可为负） |
| planSource / planSourceName | string | 计划来源码 / 中文名（auto_plan 用水计划带出 / manual 手工录入） |
| planId | string\|null | 来源计划 id（auto_plan 时留痕） |
| actualSource / actualSourceName | string | 实际来源码 / 中文名（manual / canal_head_meter） |
| isDemo | string | `#1#` 虚拟演示 / `#2#` 正式 |
| createdText / updatedText | string | 创建 / 更新时间文本（yyyy-MM-dd HH:mm） |

### 2.2 GET /water-saving/annual-water/prev-plan — 上一年度计划带出

**请求参数**

| 参数 | 必填 | 类型 | 说明 |
|------|------|------|------|
| year | 是 | int | 潜力年度（返回其依据年度 year−1 的年度计划；未找到 found=false） |

**响应**：`SavingPrevPlanVO`

| 字段 | 类型 | 说明 |
|------|------|------|
| found | boolean | 是否带出（false 时仅 basisYear 有效，前端提示手工录入） |
| planId | string | 计划 id（落库 plan_id 留痕） |
| planNo / planName | string | 计划编号 / 名称 |
| planVolume | number | 计划放水量（**万m³**，库内 m³ ÷ 10000） |
| createdText | string | 计划创建日期文本（yyyy-MM-dd HH:mm） |
| basisYear | int | 依据年度（= 请求年度 − 1） |

> 口径：跨读 `t_auto_hltgq_water_plan` 中 `plan_type = '#1#'`（年度）且 `status ≠ '#4#'`（已作废）的记录，多条取创建时间最新一条。

### 2.3 GET /water-saving/annual-water/detail — 详情

**请求参数**：`id`（必填，string）。

**响应**：单条 `SavingAnnualVO`（同 2.1）。

### 2.4 POST /water-saving/annual-water/save — 保存（有 id 更新 / 无 id 新增）

**请求体**（`application/json`）

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| id | 否 | string | 有 → 更新；无 → 新增 |
| potentialYear | 是 | int | 潜力年度（2000~2100；全表唯一） |
| prevPlanVolume | 否 | number | 上一年计划放水量（万m³，非负、≤6 位小数；可空） |
| prevActualVolume | 是 | number | 上一年实际放水量（万m³，非负、≤6 位小数） |
| planSource | 否 | string | `auto_plan` / `manual`（planVolume 为空时忽略） |
| planId | 否 | string | 来源计划 id（auto_plan 时） |
| isDemo | 否 | string | `#1#` 虚拟演示 / `#2#` 正式（默认） |

**规则**

- 潜力年度全表唯一（撞唯一索引 → 409 专属文案）；
- 编辑时潜力年度不可修改（前端置灰；服务端以提交值落库，异常情形按唯一约束兜底）；
- **水量变更联动**：计划/实际任一发生变化 → 引用该记录的方案**核验自动作废**（`verify_invalid=#1#`、状态强制待复核、留痕），重新保存使潜力可计算时方案恢复可核验。

**响应**：保存后的 `SavingAnnualVO`。

### 2.5 DELETE /water-saving/annual-water/delete — 删除

**请求参数**：`id`（必填，string）。

**规则**：被任一方案引用的记录**禁止删除**（400 中文文案）。

**响应**：`{"success": true}`。

**请求体**（`application/json`，`SavingSchemeSaveVO`）

| 字段 | 必填 | 类型 | 说明 |

- 目标超潜力：`节水目标不能超过潜力（X 万m³）`；
- 指标停用：`指标「名称」已停用，不可勾选`；指标不存在：`勾选的指标不存在或已删除，请刷新后重新勾选`；未勾选：`请至少勾选一个评估指标`；
- 名称撞车：`{year} 年度已存在同名方案，请更换名称`（预检；唯一索引兜底见 0.2）。

**响应**：创建后的 `SavingSchemeVO`（同 3.1，含达标链）。

### 3.4 PUT /water-saving/schemes/update — 编辑

**请求参数**：`id`（必填，string）。

**请求体**：同 3.3（`SavingSchemeSaveVO`）。

**规则**

- 名称 / 目标 / 措施 / 指标校验口径同 3.3；
- **换依据**：提交 `evidenceId` 与现值不同 → `baselineVolume` 取新记录实放值；**未换依据** → baseline 保持快照不变（拉齐走 3.6）；
- 换依据且**曾核验** → 核验数据作废（方案A）：`status=#4#` 待复核、`verify_*` 保留、`verify_invalid=#1#`、last_recalc 留痕「核验依据已变更」；
- **已核验方案**状态由核验动作驱动，提交的 `status` 忽略；未核验方案可在 `#1#`/`#2#` 间调整（其余取值 400：`状态仅可选：草稿 / 实施中（已完成与待复核由核验动作驱动）`）；
- 并发保护：状态比对失败 → `方案状态已被其他操作变更，请刷新后重试`。

**响应**：更新后的 `SavingSchemeVO`。

### 3.5 POST /water-saving/schemes/verify — 核验

**请求体**（`SavingVerifyVO`）

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| id | 是 | string | 方案 id |
| afterVolume | 是 | number | 实施后实际用水量（万m³，非负、≤6 位小数） |
| source | 是 | string | 核验资料来源（≤200 字，如台账 / 报表编号） |
| note | 否 | string | 核验说明（≤500 字） |
| comparable | 是 | string | 对比条件确认：`#1#` 已确认 / `#2#` 未确认 |

**规则**

- 草稿不可核验：`草稿方案不可核验，请先将状态改为实施中`；
- `#1#` 已确认 → 状态置 `#3#` 已完成 + **复位作废标记**（`verify_invalid=#2#`）+ 按公式计算全部关联指标；
- `#2#` 未确认 → 状态置 `#4#` 待复核（**不计算**，指标结果仍显示「待核验」）；
- 核验日期由服务端写入（当天）；重复核验 = 覆写核验数据并按上述规则重算。

**响应**：核验后的 `SavingSchemeVO`（含指标结果行与达标链）。

> 核验前建议对照「依据记录现值 vs `baselineVolume` 快照」，不一致时先调 3.6 刷新对比依据再核验。

### 3.6 POST /water-saving/schemes/refresh-basis — 刷新对比依据

**请求参数**：`id`（必填，string）。

**规则**

- `baselineVolume` 拉齐为依据记录**当前**实放值；
- 曾核验 → **同时作废核验**（方案A：`#4#` 待复核、`verify_*` 保留、`verify_invalid=#1#`、留痕）；
- 依据记录缺失：`对比依据记录不存在或已删除`；实放值缺失：`依据记录的实际放水量缺失，无法刷新对比依据`。

**响应**：刷新后的 `SavingSchemeVO`。

### 3.7 DELETE /water-saving/schemes/delete — 删除

**请求参数**：`id`（必填，string）。

**规则**：物理删除方案行；附件文件在**事务提交后**清理（回滚不丢文件）。

**响应**：`{"success": true}`。

### 3.8 GET /water-saving/schemes/document — 生成措施文档

**请求参数**：`id`（必填，string）。

**响应**

| 字段 | 类型 | 说明 |
|------|------|------|
| fileName | string | 文档文件名（`{方案名称}_节水方案措施.txt`；非法字符替换为 `_`） |
| content | string | 纯文本内容（前端另存为 .txt） |

文档结构：一、基本信息 / 二、对比依据（依据年度、计划、实放、潜力）/ 三、评估指标（逐条：方式、公式、目标值、结果、达标状态）/ 四、具体措施 / 五、核验信息（未核验显示「尚未核验」；已作废标注「核验已作废，数据保留」）+ 生成时间。

### 3.9 POST /water-saving/schemes/attachment/upload — 附件上传

**请求参数**：`id`（必填，string）。

**请求体**：`multipart/form-data`，文件字段名 `file`。

**规则**

- **上传即替换**（旧文件事务提交后清理）；
- 空文件：`上传文件不能为空`；超限：`附件大小不能超过 2MB`；
- 白名单：`jpg / jpeg / png / gif / bmp / webp / pdf / doc / docx / xls / xlsx`，否则 `不支持的文件类型（仅支持图片、PDF、Word、Excel）：{文件名}`；
- 存储路径：`file-dir/saving/{yyyy-MM}/{短id}_{原文件名}`。

**响应**：方案详情 `SavingSchemeVO`（含最新 `attachmentName`）。

### 3.10 GET /water-saving/schemes/attachment/download — 附件下载

**请求参数**：`id`（必填，string）。

**响应**：文件二进制流；`Content-Type` 按扩展名映射（图片 / PDF 对应类型，其余 `application/octet-stream`）；`Content-Disposition` 带原始文件名（RFC 5987，前端 fetch + blob 用）。

**错误**：无附件 → 400 `该方案没有附件`；文件缺失 → 400 `附件文件不存在，可能已被清理`。

### 3.11 POST /water-saving/schemes/attachment/remove — 附件移除

**请求参数**：`id`（必填，string）。

**规则**：清空附件列 + 物理删文件（失败仅告警不阻断）；无附件 → 400 `该方案没有附件`。

**响应**：方案详情 `SavingSchemeVO`。

### 3.12 GET /water-saving/schemes/export — 导出 CSV

**请求参数**

| 参数 | 必填 | 类型 | 说明 |
|------|------|------|------|
| includeDemo | 否 | boolean | 是否包含虚拟演示数据（默认 false 排除） |

**响应**：CSV 文件（UTF-8 **带 BOM**；文件名 `节水方案列表_{yyyyMMddHHmmss}.csv`）。

**表头**：`年度, 方案名称, 指标, 计算公式, 结果, 单位, 指标目标值, 指标达标状态, 方案达标状态, 资料来源, 虚拟演示`

- 方案 × 指标**展开为多行**（无指标方案输出单行、指标列留空）；
- 「方案达标状态」列 = 等级（+说明：优先无法计算说明、其次待复核原因）；
- 「资料来源」列 = 核验资料来源（未核验为空）；「虚拟演示」列 = 是 / 否；
- 单元格含逗号 / 引号 / 换行时按 CSV 规范转义。

### 4.1 GET /water-saving/indicators/list — 全量列表

**请求参数**：`keyword`（选填，名称模糊）。

| purpose | string\|null | 指标用途 |
| enabled / enabledName | string | `#1#` 启用 / `#2#` 停用 |

### 4.2 GET /water-saving/indicators/detail — 详情

**请求参数**：`id`（必填，string）。

**响应**：单个 `SavingIndicatorVO`（同 4.1）；不存在 → 400 `指标不存在或已删除`。

### 4.3 POST /water-saving/indicators/create — 新增

**请求体**（`SavingIndicatorSaveVO`）

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| name | 是 | string | 指标名称（≤200 字；**全局唯一含停用**） |
| method | 是 | string | `#1#` 节水量 / `#2#` 节水率 / `#3#` 目标完成率 |
| targetValue | 否 | number | 目标值（填写则 >0、≤6 位小数；不填 → 关联方案「待设置目标」） |
| purpose | 否 | string | 指标用途（≤200 字） |

**规则**：新增默认启用（`enabled=#1#`）；重名 → `指标名称已存在（停用指标的名称同样占用）`（唯一索引兜底见 0.2）；方式非法 → `请选择计算方式（节水量 / 节水率 / 目标完成率）`。

**响应**：创建后的 `SavingIndicatorVO`。

### 4.4 PUT /water-saving/indicators/update — 编辑

**请求参数**：`id`（必填，string）。

**请求体**：同 4.3。

**规则**

- **已关联方案的指标计算方式锁定**：`该指标已被 N 个方案关联，计算方式已锁定不可修改（可新建指标替代）`；
- 目标值变更且有关联方案 → 关联方案留痕「指标目标值变更」；目标值可编辑为清空（null）；
- 名称唯一预检排除自身。

**响应**：更新后的 `SavingIndicatorVO`。

### 4.5 POST /water-saving/indicators/toggle — 启停切换

**请求参数**：`id`（必填，string）。

**规则**：`#1#` ⇄ `#2#` 反转；停用后**新方案不可勾选**、**既有关联保留**（已关联方案照常计算展示）；关联方案留痕「指标状态变更」。

**响应**：切换后的 `SavingIndicatorVO`。

### 4.6 DELETE /water-saving/indicators/delete — 删除

**请求参数**：`id`（必填，string）。

**规则**：被方案关联禁止删除：`该指标已被 N 个方案关联，不可删除（可改为停用，既有关联与计算结果保留）`；未关联 → 物理删除。

**响应**：`{"success": true}`。

## 七、联调与待核对项

1. 全链冒烟：先建年度水量记录（组二）→ 建指标（组四）→ 建方案（组三）→ 核验（对比条件已确认）→ 观察达标链与指标结果；
2. 方案A链路：核验「未确认」→ 编辑换依据 / 刷新对比依据 → 确认回到「待复核」且核验数据保留、`verifyInvalid=#1#`；
3. 年度水量改水量联动：编辑依据记录的计划 / 实际 → 引用方案的核验应自动作废；
4. 附件链路：上传 → `attachmentName` 回显 → 下载（文件名与类型正确）→ 移除；
5. 导出 CSV 用 Excel 验证中文与 BOM、含演示数据时 `includeDemo=true` 对照行数增量；
6. 非管理员账号调用写接口应 403（前端隐藏 + 后端拦截）。
