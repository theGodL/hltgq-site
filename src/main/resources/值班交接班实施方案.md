# 值班交接班实施方案（后端）

> 版本：v1.0 ｜ 编写日期：2026-10-12
> 目标：打通「值班排班（hdbzyd）→ 值班记录（igahxz）→ 交接班记录（kwzwga）」三张低代码表，支撑两个页面的完整值班闭环。
> 配套接口文档：《值班交接班接口.md》
> 分工：后端负责接口与数据流转（本文档范围）；前端按接口文档替换页面内 mock（duty-management.html / duty-handover.html）。

## 1. 目标与流程

### 1.1 业务目标

| 页面 | 说明 | 需要的后端能力 |
| --- | --- | --- |
| duty-management.html（值班管理） | 排班的查询 / 新增 / 编辑 / 删除 + 今日值班判定与签到提醒 | 排班 CRUD、今日值班判定、下拉选项 |
| duty-handover.html（值班交接班） | 当前值班卡片、开始值班（签到）、填写值班报告、交班、今日动态 | 值班记录创建/更新、交接班记录创建、状态联动 |

### 1.2 一次值班的完整流程

```
① 创建排班（peuzwi=#1# 未开始）
      ↓ 到达班次开始时间（读时纠偏显示「待值班」）
② 开始值班（签到）
     · 生成值班记录（编号 ZBJL-YYYYMMDD-NN，ylncfw=#2# 值班中）
     · 排班状态 → #cmiu# 值班中
      ↓ 值班过程中
③ 填写值班报告（重大事件记载 / 值班情况综述，写入当前记录）
      ↓ 交班
④ 交班确认
     · 更新记录：实际交班时间、ylncfw=#3# 已完成
     · 生成交接班记录（编号 JJB-YYYYMMDD-NN）
     · 排班状态 → #qavx# 已完成
     · 同单位下一班未开始排班自动置 #zzkl# 待值班
```

### 1.3 范围界定

- **本方案范围内**：新增后端接口、SQL、状态流转、编号生成、兼容处理；升级现有 `/duty/list`（值班记录列表）读取逻辑。
- **不在范围内**：低代码平台模型/表单改动（模型已就绪，见 §2.1）；「值班内容」（bjeoos）明细；H5 端页面改动。
- **前端**：两个页面按《值班交接班接口.md》替换 mock 数据与请求（映射清单见 §6）。

### 2.3 H5 值班提醒的兼容约束（重要）

H5 消息模块（`h5/mapper/MessageQueryMapper.java`）的「值班提醒」直接读 hdbzyd 的**遗留列**，过滤与展示如下：

```sql
-- 过滤（节选）
s.corp_code='hltgq' AND s.alidpq = :当前用户
AND s.peuzwi='#cmiu#'        -- 仅值班中的排班
AND s.hfxuuk='#papu#'        -- 已发送提醒
AND s.owcvsv >= :since       -- 按值班日期（旧列）
-- 展示（节选）
s.owcvsv AS dutyDate, s.itxmyy AS shiftTime, s.ihdflq AS dutyUnit
-- 人员侧：EXISTS(hdbzyd_cogxjx_rel rel WHERE rel.biz_id=s.id AND rel.rel_id=:当前用户)
```

**结论**：排班写入必须**兼容双写** `owcvsv`（值班日期）、`itxmyy`（班次时间文本）、`ihdflq`（单位名称）、并在开始值班时写 `hfxuuk='#papu#'`，否则新排班不会出现在 H5 值班提醒中。

## 3. 总体设计

### 3.1 状态机

**排班状态 peuzwi（hdbzyd）**

| 存储值 | 名称 | 进入时机 | 可执行操作 |
| --- | --- | --- | --- |
| `#1#` | 未开始 | 新建排班 | 查看 / 编辑 / 删除 |
| `#zzkl#` | 待值班 | ① 读时纠偏（见下）② 上一班交班后自动置位 | 查看 |
| `#cmiu#` | 值班中 | 开始值班（签到）成功 | 查看 |
| `#qavx#` | 已完成 | 交班成功 | 查看 |

**读时纠偏规则**（用于所有查询接口的展示字段 `status`，不落库）：存储为 `#1#` 且 `now ≥ COALESCE(tneakp_min, owcvsv)` 时，展示为「待值班」。这样无需定时任务即可呈现「到点待值班」。

**值班记录状态 ylncfw（igahxz）**

| 存储值 | 名称 | 说明 |
| --- | --- | --- |
| `#2#` | 值班中 | 开始值班时写入；可填写报告、可交班 |
| `#3#` | 已完成 | 交班时写入 |
| `#4#` | 异常结束 | 预留（本期不产生） |

**状态联动**（交班事务内）：本班排班 → `#qavx#`；同单位下一班（时间最近且 `#1#`）→ `#zzkl#`。

### 3.2 数据读写策略

**读：新列优先 + 旧列兜底 + 关系表兜底**

| 展示项 | 取值规则 |
| --- | --- |
| 排班·值班日期 | `idjwlq`，空则 `owcvsv`（取日期部分） |
| 排班·班次时间 | `tneakp_min/max` 格式化为 `HH:mm-HH:mm`；空则不展示时间 |
| 排班·班次 | `fjyyhu` 编码 → 中文（`#1#`白班 / `#jhyu#`中班 / `#zsfh#`夜班） |
| 排班·单位 | `jepbhm` 联 `t_apaas_uc_org.name`，空则旧列 `ihdflq` |
| 排班·值班人员 | rel 表 `hdbzyd_cogxjx_rel` → 用户姓名，顿号连接 |
| 记录·班次时间（列表接口） | 新列 `egkivk_min/max` 优先（格式化为 `HH:mm-HH:mm`，跨天加「次日」前缀）；无值且旧列 `lzcjgq` 有值则直接展示旧文本（异构兜底，用 CASE WHEN 而非 COALESCE） |
| 记录·单位（列表接口） | `cfszln` 联单位表，空则旧列 `sdcgli` 文本 |
| 记录·值班人员过滤（列表接口） | 三通道：rel 表 `igahxz_ahygpx_rel`.rel_id 命中（新记录）、旧文本列 `_d_10233_ahygpx` 双路 LIKE（原文 + 解析出的用户 id）、带班领导 `atfzxl` |

**写：主写当前模型字段；兼容双写旧列（仅为保住存量读取方）**

| 表 | 写入字段 | 兼容双写 | 目的 |
| --- | --- | --- | --- |
| hdbzyd | idjwlq / tneakp_min / tneakp_max / fjyyhu / jepbhm / alidpq / peuzwi / cogxjx-rel | `owcvsv`=值班日期、`itxmyy`=班次时间文本（`HH:mm-HH:mm`，跨天含「次日」）、`ihdflq`=单位名称；开始值班时 `hfxuuk='#papu#'` | 保住 H5 值班提醒（§2.3） |
| igahxz | pttmxx / yaaebo / egkivk_min / egkivk_max / cfszln / atfzxl / jlailj / yuyitx / xggayo / rdammr / ylncfw / ahygpx-rel | `lzcjgq`=班次时间文本、`sdcgli`=单位名称 | 未升级的旧列表 SQL / 报表仍可显示新记录；`_d_10233_ahygpx` 不写 |
| kwzwga | nizxsv / tavpmi_min/max / whthxi / qwiioz / gdtjny / ezvhop-rel / igkyeu-rel | 无 | 旧列（cbmeco/tdahvq/vyyuev）读侧已有兜底，写侧不再维护（交接班列表为新开发，不含历史兼容负担） |

> 原则：**双写只加不删**。旧列均是 varchar/无约束，追加写入无风险；平台已确认从物理层不删列。

### 3.3 编号生成规则

| 编号 | 格式 | 日期基准 | 序号规则 |
| --- | --- | --- | --- |
| 值班记录编号 | `ZBJL-{yyyyMMdd}-{NN}` | 值班日期（排班的 idjwlq/owcvsv） | 查询 `pttmxx LIKE 'ZBJL-{yyyyMMdd}-%'` 取当日最大 NN + 1，两位补零 |
| 交接班编号 | `JJB-{yyyyMMdd}-{NN}` | 交班操作当天 | 查询 `nizxsv LIKE 'JJB-{yyyyMMdd}-%'` 取当日最大 NN + 1，两位补零 |

- 序号解析：取 `-` 后两段拼接串转 int，非法值跳过（如平台生成的旧值）。
- 并发说明：值班场景为单人操作、日序号空间充足；并发冲突概率极低，不引入锁（如出现，重试一次即可）。

### 3.4 事务与幂等

| 操作 | 事务内容 | 幂等/防重 |
| --- | --- | --- |
| 开始值班 | insert igahxz + insert ahygpx-rel（多行）+ update hdbzyd（状态/提醒） | 该排班已存在 `#2#` 记录 → 直接返回该记录（重复点击安全）；排班已 `#qavx#` → 409 |
| 填写报告 | update igahxz（xggayo/rdammr） | 覆盖式更新，可重复提交；记录非 `#2#` → 409 |
| 交班 | update igahxz（yuyitx/ylncfw）+ insert kwzwga + insert ezvhop-rel + insert igkyeu-rel + update hdbzyd（本班 `#qavx#`、下一班 `#zzkl#`） | 记录已 `#3#` → 409「该记录已完成交班」；整段单事务 |
| 排班保存 | insert/update hdbzyd + 重写 cogxjx-rel（先删后插） | 编辑仅限未开始（读时纠偏前 `#1#`），否则 409 |

**记录 ↔ 排班 的匹配算法**（三表间无外键，靠业务字段回查）：

```
优先：单位相同 AND 班次起止时间精确相等（实现两侧均取 to_char(...,'YYYY-MM-DD HH24:MI:SS') 定长文本比较）
  hdbzyd.jepbhm = igahxz.cfszln
  AND to_char(hdbzyd.tneakp_min) = to_char(igahxz.egkivk_min)
  AND to_char(hdbzyd.tneakp_max) = to_char(igahxz.egkivk_max)
```

- 开始值班时记录值从排班原样复制（时间戳精确相等到秒），匹配必然命中；
- 历史数据（新列为空）匹配不到时**降级处理**：交班仍成功，仅跳过排班状态联动并记录 warn 日志；
- 兜底：匹配不到时再用「同单位 + 进行态（值班中/待值班）+ 值班日期相同」条件尝试一次（`#cmiu#` 优先）。

### 3.5 鉴权 / 错误 / 审计约定（沿用现有工程约定）

| 项 | 约定 |
| --- | --- |
| 鉴权 | 全部接口要求登录会话（AuthInterceptor 全局生效）；本模块写接口仅要求登录态，**不加 @RequireAdmin**（值班员日常操作） |
| 未登录 | AJAX 返回 `401 {"code":401,"message":"未登录","redirectUrl":...}` |
| 无会话服务 | `503 {"code":503,"message":"会话服务不可用，请稍后重试"}` |
| 参数/业务校验失败 | `400 {"message":"..."}`（抛 IllegalArgumentException，由 GlobalExceptionHandler 统一处理） |
| 状态冲突 | `409 {"message":"..."}`（DataIntegrityViolationException 或业务显式抛出——实现时建议统一抛自定义冲突异常映射 409） |
| 审计列 | id=UUID；corp_code=`hltgq`；created_by/updated_by=当前用户 id（UserContextHolder.currentUser()）；created_at/updated_at=LocalDateTime.now() |
| 时间格式 | 请求/响应统一 `yyyy-MM-dd`（日期）与 `yyyy-MM-dd HH:mm`（时刻） |

### 4.1 今日值班判定（/duty/today-status）逻辑

以当前登录人视角，按顺序命中即返回：

1. 当前人参与（cogxjx-rel 含我 或 alidpq=我）且状态为 `#cmiu#` 的排班（不限时间）；
2. 否则：当前人参与、状态 `#1#/#zzkl#`、且班次时间与今日相交（开始 < 明日零点 且 结束 ≥ 今日零点；无班次时间的历史排班不参与）的排班；
3. 多条命中取一条：`#cmiu#` 优先 → `#zzkl#` → 其他，再按班次开始时间升序；
4. 命中返回 `onDuty=true` + 班次/时间/领导（签到弹窗展示）；未命中返回 `onDuty=false`。

### 4.2 当前值班四态（/duty/attendance/today）判定

| 返回 status | 判定顺序 | 数据来源 |
| --- | --- | --- |
| `ongoing` 值班中 | ① 存在我的 `#2#` 记录（rel 含我 或 atfzxl=我） | igahxz（recordNo/ID + 展示字段） |
| `notstarted` 未开始 | ② 存在我的排班（判定口径同 §4.1：`#cmiu#` 不限时间；`#1#/#zzkl#` 要求班次时间与今日相交） | hdbzyd（scheduleId + 展示字段） |
| `completed` 已完成 | ③ 今日交班的我的 `#3#` 记录（yuyitx 当天） | igahxz |
| `none` 无安排 | ④ 兜底 | — |

> 记录展示字段：记录编号、值班日期、班次时间、单位、带班领导、值班人员、摘要（rdammr）；`completed` 状态附加实际开始/实际交班。

### 4.3 交班时的接班人员默认值

交班弹窗的「接班人员」候选默认取**下一班排班的值班人员**（同单位、开始时间不早于本班结束时间的最近未开始排班），由 `/duty/attendance/today` 的 `receiverCandidates` 字段提供（仅 ongoing 态返回，格式 `[{id,name}]`；无下一班为空数组）；用户可增删（提交时传最终 `receiverIds`，允许空数组）。

```sql
SELECT s.id,
       COALESCE(s.idjwlq, s.owcvsv)          AS dutyDateRaw,   -- 应用层格式化 yyyy-MM-dd

          FROM "qixiao-apaas"."t_auto_hltgq_yn8cm_hdbzyd_cogxjx_rel" rel
          JOIN "qixiao-apaas"."t_apaas_uc_user" usr ON usr.id = rel.rel_id
         WHERE rel.biz_id = s.id)              AS members,

  LEFT JOIN "qixiao-apaas"."t_apaas_uc_user" u ON u.id = s.alidpq
 WHERE s.corp_code = 'hltgq'
 ORDER BY COALESCE(s.tneakp_min, s.owcvsv) DESC NULLS LAST, s.id DESC
```

**值班记录列表升级（/duty/list 的班次时间异构兜底）**

```sql
CASE WHEN d.egkivk_min IS NOT NULL AND d.egkivk_max IS NOT NULL
     THEN to_char(d.egkivk_min, 'HH24:MI') || '-' ||
          CASE WHEN to_char(d.egkivk_min, 'YYYY-MM-DD') != to_char(d.egkivk_max, 'YYYY-MM-DD')
               THEN '次日' ELSE '' END ||
          to_char(d.egkivk_max, 'HH24:MI')
     ELSE d.lzcjgq END            AS shift,            -- 旧列文本原样兜底；跨天加「次日」
COALESCE(o.name, d.sdcgli)        AS unit             -- 新列联单位表，空则旧文本
```

人员过滤升级为三通道：`EXISTS(igahxz_ahygpx_rel WHERE biz_id=d.id AND rel_id=:personId)` OR 旧文本列 `_d_10233_ahygpx` 双路 LIKE（原文 + 解析出的用户 id）OR 带班领导 `atfzxl`。

DELETE FROM "qixiao-apaas"."t_auto_hltgq_yn8cm_hdbzyd_cogxjx_rel" WHERE biz_id = #{bizId};

## 8. 边界与风险

| 项 | 说明 | 处理 |
| --- | --- | --- |
| 记录↔排班无外键 | 靠「单位+班次时间」匹配（§3.4） | 匹配失败降级：不阻断业务流程，记 warn 日志 |
| 历史记录无编号（pttmxx 空） | 旧 12 条不补编号 | 列表展示编号为空即可（不回溯生成） |
| 跨天班次（如 20:00-次日08:00） | tneakp_max 直接落在次日 | 时间比较全部用完整时间戳，不做「同日」假设 |
| 并发编号 | 极端并发下可能出现同序号 | 概率极低；如发生重试一次 |
| 平台侧若调整模型 | 遗留列理论上可能被清理（当前确认不会） | 若 H5 提醒模块同期下线，可移除兼容双写（届时以本方案 §2.3 为对照） |
| 值班内容（bjeoos） | 不在本期范围 | 后续如需明细扩充另立方案 |
| 值班表模型状态 | igahxz/kwzwga 当前为 MODIFY（有未发布改动） | 实现前与平台核对最终字段集不变；本方案已按当前在册字段设计 |
