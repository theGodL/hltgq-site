# 阈值设置

对监测站点按「站点 + 阈值类型」配置**单级警戒值**，供告警比对与业务页面展示使用。
本期只支持一个警戒值（`threshold`），保证值 / 设计值字段在表中保留但界面不渲染、保存也不改写。

- 页面：`/threshold-setting.html`（列表 + 新增/编辑/查看三态抽屉，单文件）
- 表：`"qixiao-apaas".t_auto_hltgq_water_threshold`
- 类型编码：与站点档案监测类型 `epjutj` **同一套编号**（`#1#` 水位 / `#2#` 雨量 / `#3#` 流量 / `#4#` 闸站·开度 / `#7#` 墒情 / `#8#` 水质）

---

## 1. 字段口径（只读核对 2026-09-24）

| 列 | 含义 | 写入 | 读取 |
|---|---|---|---|
| `site` | 站点档案主键（`t_auto_hltgq_5nw74_vnqqef.id`，19 位） | 新增时写入 | 匹配键 |
| `zvieyb` | 阈值类型编码（**权威列**，支持多值如 `#1#\|#3#`；存量 3 行已是完整多值） | **新配置一律写本列** | 优先 |
| `type` | 历史类型列（存量 3 行落**首个编码**，如 `#1#`） | 不再写入 | 仅兜底 |
| `alarmdir` | 告警方向编码 `#1#`/`#2#` | 保存时写入 | 空值按类型默认方向 |
| `threshold` | 警戒值（`numeric`，业务保留两位小数） | 写入 | 比对值 |
| `remark` | 描述（≤500 字） | 写入（可清空） | 展示 |
| `device` | 设备级阈值预留 | 不写 | 不用 |
| `guarantee` / `num` | 保证值 / 设计值（预留） | **不改写** | 水位页仍读 `guarantee` 展示保证水位 |
| `id`/`corp_code`/`created_*`/`updated_*` | 平台标准审计列（均 NOT NULL） | 新增时全部写入 | `updated_at` 作列表排序与展示 |

读取侧统一口径（**不得直接读 `type`**）：

```sql
COALESCE(NULLIF("zvieyb", ''), "type", '')
```

只读 `type` 会漏两类数据：新配置的行 `type` 为空、存量多值行（`#1#|#2#`）只落了首个编码。

**唯一性**：该表**只有主键约束，没有 `(site, zvieyb)` 唯一索引**，判重由应用层完成
（同站点同类型、多值行如 `#1#|#3#` 同样视为已配置）。

**id 生成**：实体继承 `BaseWaterEntity`，走全局 `ShortIdGenerator` 生成 **22 位**短 ID（平台规范）。

## 2. 类型字典与站点口径

| 类型 | 编码 | 单位 | 默认告警方向 | 适用站点（说明文案） | 实测站点数 |
|---|---|---|---|---|---|
| 水位 | `#1#` | m | 高于警戒值触发 | 泄洪闸、节制闸、进水闸、河道站 | 18 |
| 雨量 | `#2#` | mm | 高于警戒值触发 | 雨量站 | 18 |
| 流量 | `#3#` | m³/s | 低于警戒值触发 | 测流闸、河道站 | 135 |
| 开度 | `#4#` | % | 低于警戒值触发 | 泄洪闸、节制闸、进水闸 | 25 |
| 墒情 | `#7#` | % | 低于警戒值触发 | 墒情站 | 4 |

- 字典单一维护点：`ThresholdServiceImpl#TYPES`（新增类型只改这一处，界面经 `/threshold/meta` 自动获得，前端不写死）。
- 站点候选 = **站点档案中 `epjutj` 含该类型编码**的站点，即「站点支持哪些类型」由档案维护，不是代码里的白名单。
- 站点顺序 = **站点排序配置**（`/station-sort`，与各监测页站点下拉同一套序列）中该类型序列的顺序；
  映射关系（`ThresholdServiceImpl#sortScope`）：水位 `#1#`→`waterLevel`、雨量 `#2#`→`rainfall`、流量 `#3#`→`flow`、
  开度 `#4#`→`gate`（闸站共用闸门序列）、墒情 `#7#`→`moisture`（站点排序侧编码为 `#5#`，语义相同）；
  未配置过顺序时保持接口默认（按站名），新增/编辑抽屉的站点下拉即时反映排序结果。
- 实测水位 18 站与设计文案完全吻合（周家河、望花凉亭坝上/坝下及各类节制闸、泄洪闸、进水闸、渠道站等）。

## 3. 接口契约

统一前缀 `/threshold`，返回体为 JSON；业务校验失败返回 **HTTP 400 + `{message}`**（`GlobalExceptionHandler` 统一处理），
非管理员调用删除返回 **403**。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/threshold/meta` | 字典：`types[]`（code/name/unit/defaultAlarmDir/siteScopeDesc）+ `alarmDirs[]`（code/name） |
| GET | `/threshold/sites?type=&keyword=` | 类型下的站点候选；返回 `siteId/name/siteCode/configured`（`configured=true` 表示该站点在该类型下已配置）；顺序按该类型对应的站点排序配置 |
| GET | `/threshold/configured-sites` | 已配置阈值的站点清单（列表筛选下拉用，按站名排序，不区分类型）；只列阈值表中出现过的站点，选中后必有结果 |
| GET | `/threshold/page?page=&size=&siteId=&type=&keyword=` | 列表分页，按 `updated_at` 倒序；返回 `total/page/size/pages/records` |
| GET | `/threshold/{id}` | 详情（编辑/查看回显） |
| POST | `/threshold` | 新增：`{site, type, alarmDir, threshold, description}` |
| PUT | `/threshold/{id}` | 编辑：`{alarmDir, threshold, description}`（**站点、类型锁定**，换类型/换站点=删除后重新新增） |
| DELETE | `/threshold/{id}` | 删除（`@RequireAdmin`，仅管理员） |

列表/详情返回字段：`id, site, siteName, siteCode, thresholdType, typeName, unit, alarmDir, alarmDirName, alarmDirDefault, threshold, description, updatedAt`。

**校验规则**

| 情况 | 后端行为 | 前端行为 |
|---|---|---|
| 类型为空 / 不在字典 | 400「请选择阈值类型」/「阈值类型无效」 | 类型、站点同时标红 |
| 站点不存在 | 400「站点不存在或未在站点档案登记」 | — |
| 站点不支持该类型 | 400「该站点不支持【水位】阈值」 | 下拉空态「暂无支持【水位】阈值的站点」并拦截保存 |
| 指标值 ≤ 0 / 非数字 | 400「请输入大于 0 的数字」 | 字段下方红字，禁用负号与字母 |
| 重复配置 | 400「该站点已配置【水位】阈值，请直接编辑」 | 错误 toast，抽屉不关、内容保留 |
| 描述超 500 字 | 400「描述最多 500 字」 | 输入即截断 + 右下角字数统计 |
| 删除非管理员 | 403 | 无权限时不渲染删除入口 |

## 4. 阈值生效与告警比对口径（对外约定）

1. **比对时机**：监测数据入库时按 `site + zvieyb` 查阈值；**无配置静默跳过**（不报错、不产生噪音日志）。
2. **触发方向**（含等号）：
   - `alarmdir = #1#`（高于警戒值触发）：监测值 **≥** 警戒值 → 触发；
   - `alarmdir = #2#`（低于警戒值触发）：监测值 **≤** 警戒值 → 触发；
   - `alarmdir` 为空（如存量行）：按**类型默认方向**处理（水位/雨量=高于，流量/开度/墒情=低于）。
3. **重复告警抑制**：同站点同类型持续超限默认 **30 分钟内不重复推送**，恢复正常后重新计数；
   建议做成**系统参数**（不写死），参数项见《阈值告警比对-给hltgq-mq.md》。
4. **变更即时生效**：比对每次实时读库，编辑保存后下一次比对即用新值，**无需刷新缓存或重启服务**。
5. **预留扩展**：启用保证值/设计值时按 `警戒 < 保证 < 设计` 校验，界面在抽屉中追加两个输入框即可，表结构与交互框架无需改动。

## 5. 页面说明（`threshold-setting.html`）

- **列表**：站点、阈值类型、警戒值（带单位）、告警方向、描述、更新时间、操作（图标按钮：查看/编辑/删除）；
  顶部筛选白卡为「标签 + 控件」横排（阈值类型下拉、站点下拉），**两个下拉均选中即查**、「查询」与「重置」为同义操作，
  行尾为「查询（主）/ 重置（次）」；空格值与字典外编码显示 `--`。
  站点下拉只列**已配置阈值的站点**（可输入站名/编号过滤，占位「全部站点」，与列表数据同源、选中必有结果），
  该站点阈值全部删除后会自动从候选中移除并清空筛选值；与「阈值类型」为独立条件，同时选中即取交集。
- **抽屉三态**（480px，右侧滑入 300ms，遮罩 `rgba(0,0,0,.45)` 可点击关闭，标题栏带全屏切换）：

  | | 新增 | 编辑 | 查看 |
  |---|---|---|---|
  | 标题 | 新增 | 编辑 | 阈值详情 |
  | 类型/站点 | 可选（站点选完类型才显示） | 置灰锁定 | 纯文本 |
  | 方向/警戒值/描述 | 可编辑 | 可编辑 | 只读，空值 `--` |
  | 底部按钮 | 取消 / 保存 | 取消 / 保存 | 关闭（+ 编辑直达） |

- **联动**：选类型 → 渲染站点字段（带类型参数查候选，输入框内 16px spinner）+ 带出方向默认值 + 单位后缀；
  切换类型清空已选站点；警戒值 placeholder 随方向变化（「高于警戒值触发告警」↔「低于警戒值触发告警」）。
- **查看态**用「标签在上、值在下」的紧凑文本，不用禁用态输入框伪装只读。
- **保存反馈**：成功 → 关闭抽屉 + 刷新列表 + 该行高亮闪烁一次 + toast「保存成功」；
  失败（唯一冲突等）→ 错误 toast，抽屉不关、已填内容保留。
- **删除**：仅管理员可见；二次确认文案「删除后该站点【水位】阈值将不再告警，是否继续？」，危险按钮为红色。

## 6. 已核对结论与注意事项

1. **存量数据（3 行，`zvieyb` 均含水位）**：周家河 `98`（`#1#|#2#`）、花凉亭坝下 `43.5`（`#1#`）、花凉亭坝上 `82.8`（`#1#`）；
   三行 `type` 列落**首个编码** `#1#`、`alarmdir` 为 `NULL`（界面按类型默认方向展示，仅抽屉详情标注「默认」）；
   周家河、坝上为历史「一行多类型」（水位 + 雨量），列表按 `zvieyb` 展示为「水位、雨量」、单位取首个类型。
2. **下游读取口径已修正**（否则「配置了不生效」：新配置只写 `zvieyb`，下游只读旧列 `type` 必然查不到，
   存量多值行也会漏掉非首个类型）：
   - `StRiverRServiceImpl#queryThreshold`（河道/水库水位页、水情简报的警戒水位/保证水位）；
   - `WaterQualityMapper#selectThresholdsBySites`（水质页预警线）。
3. **KingbaseES 模糊匹配写法**：必须 `LIKE CONCAT('%', #{x}, '%')`；
   实测 `LIKE '%' || #{x} || '%'` 的绑定参数会**静默失效（退化为匹配全部行）**，全库既有 SQL 亦统一使用 `CONCAT`。
   根因（2026-09-24 补充实测）：`||` 在该库按**逻辑或**求值（`'[' || metric_type` 返回布尔 `f`），
   凡字符串拼接一律用 `CONCAT`/`COALESCE`，新增 SQL 不得使用 `||`。
4. **权限**：新增/编辑为日常配置操作（不限管理员），删除仅管理员；
   前端按 `GET /auth/current-user` 的 `admin` 标记隐藏删除入口，与后端 `@RequireAdmin` 同一判定口径。
5. **匹配键实测（2026-09-24）**：监测数据表（水位 `water_river_info`、雨量 `water_rain_info`、水质 `water_nmisp_info`）的
   `site` 列即**站点档案主键**，覆盖率 100%（无空值，水位 34622 行 / 雨量 29610 行 / 水质 1138 行）；
   档案测站编码 `iofhpi` 无重复（174 个非空），支持阈值类型的站 100% 有编码；详见《阈值告警比对-给hltgq-mq.md》。
6. **不在本期范围**：设备级阈值（`device` 列）、保证值/设计值录入、多级/分级告警、批量导入。
7. **唯一性口径（当前实现）**：同站点同类型**只能配置一条**阈值行——判重键为「站点 + 类型」（`countBySiteAndType`），
   **不含告警方向**，`alarmdir` 只是该行的属性（界面二选一），因此同一站点同一类型暂不支持「高于 + 低于」两条并存。
   若后续要支持双方向：判重键与冲突文案需加方向维度（抽屉「已配置」标记同步按方向区分），
   且下游单条读取口径必须同步改造——`StRiverRServiceImpl#queryThreshold` 以 `LIMIT 1` 取水位阈值作警戒线，
   双条并存时取哪条不确定，须改为按 `alarmdir = '#1#'`（高于）过滤再取。
