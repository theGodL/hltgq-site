# 值班交接班接口文档

> 版本：v1.0 ｜ 编写日期：2026-10-12
> 配套文档：《值班交接班实施方案.md》（数据现状、状态机、设计决策详见该文档）
> 适用页面：`static/duty-management.html`（值班管理）、`static/duty-handover.html`（值班交接班）
> 前端改造方式：按本文件替换页面内 mock 请求（对照表见 §6）。

---

## 1. 通用约定

| 项 | 约定 |
| --- | --- |
| 服务前缀 | 下文路径均省略上下文前缀 `/hltgq-site`（如 `GET /duty/schedule/list` 实际请求 `/hltgq-site/duty/schedule/list`） |
| 请求/响应编码 | UTF-8，JSON（`Content-Type: application/json`） |
| 鉴权 | 全部接口要求登录会话（浏览器同域自动携带 Cookie；或 `Authorization` 头携带 sessionId）。未登录返回：`401 {"code":401,"message":"未登录","redirectUrl":"..."}`（前端可用 redirectUrl 跳转登录页）；会话服务不可用：`503 {"code":503,"message":"会话服务不可用，请稍后重试"}` |
| 成功响应 | 直接返回数据对象/数组（无统一 `{code,data}` 包装） |
| 错误响应 | `{ "message": "错误说明" }`；`400`=参数/业务校验失败，`409`=状态冲突（如「仅未开始的排班可编辑」），`500`=服务器错误 |
| 写接口权限 | 本模块写接口仅要求登录态（不加管理员限制）；如需收紧另行通知 |
| 日期格式 | 请求/响应日期：`yyyy-MM-dd`；时刻：`yyyy-MM-dd HH:mm` |
| 分页 | 请求 `page`（默认 1，≥1）、`size`（默认 10，1~100）；响应固定结构 `{total, page, size, pages, records}` |
| 空值 | 无值字段返回 `null` 或省略（本文档示例统一为 `null`，前端按 `|| '-'` 兜底） |

## 2. 数据字典

### 2.1 班次（排班·fjyyhu）

| 编码（请求传参用） | 名称 |
| --- | --- |
| `#1#` | 白班 |
| `#jhyu#` | 中班 |
| `#zsfh#` | 夜班 |

### 2.2 排班状态（排班·peuzwi）

| 编码 | 名称 | 说明 |
| --- | --- | --- |
| `#1#` | 未开始 | 可编辑/删除（前端操作列以 `statusCode` 判断） |
| `#zzkl#` | 待值班 | 到点后由后端「读时纠偏」展示，或上一班交班后自动置位 |
| `#cmiu#` | 值班中 | 已签到 |
| `#qavx#` | 已完成 | 已交班 |

> 前端展示字段 `status` 为纠偏后的中文；`statusCode` 为库中真实编码。

### 2.3 值班记录状态（记录·ylncfw）

| 编码 | 名称 |
| --- | --- |
| `#2#` | 值班中 |
| `#3#` | 已完成 |
| `#4#` | 异常结束（预留） |

### 2.4 时间展示约定

- 班次时间文本（`shiftTime`）：`HH:mm-HH:mm`；跨天时次日部分加「次日」前缀，如 `20:00-次日08:00`。
- 列表页展示可拼接为 `白班(08:00-16:00)`（班次 + 括号时间）。

## 3. 值班管理页接口

### 3.1 今日值班判定 `GET /duty/today-status`

页面进入时判断「今天是否我值班」，用于签到提醒弹窗。以当前登录人视角。

**请求参数**：无

**响应**

```json
{
  "onDuty": true,
  "scheduleId": "47h3wCXvoYnhTr8ty5e",
  "dutyDate": "2026-10-13",
  "statusCode": "#zzkl#",
  "status": "待值班",
  "name": "张伟",
  "shift": "白班",
  "shiftTime": "08:00-16:00",
  "leader": "刘建国"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| onDuty | boolean | 是否命中我的值班安排 |
| scheduleId | string | 命中的排班 id（供跳转交接班页使用） |
| dutyDate | string | 值班日期 |
| statusCode / status | string | 排班状态编码 / 中文（纠偏后） |
| name | string | 当前登录人姓名 |
| shift | string | 班次中文（白班/中班/夜班） |
| shiftTime | string | 班次时间文本 |
| leader | string | 带班领导姓名 |

未命中时：`{"onDuty": false}`（其余字段省略）。

**判定顺序**：① 我参与（带班领导或值班人员）且 `#cmiu#` 的排班（不限时间）→ ② 我参与且 `#1#/#zzkl#`、班次时间与今日相交（开始 < 明日零点 且 结束 ≥ 今日零点，跨天班次自然覆盖；无班次时间的历史排班不参与）的排班 → ③ 无则 `onDuty=false`。

多条命中取一条：`#cmiu#` 优先 → `#zzkl#` → 其他，再按班次开始时间升序（先开班的先命中）。

**请求参数**（均为可选，Query 参数）

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| page | int | 页码，默认 1 |
| size | int | 每页条数，默认 10（1~100） |
| date | string | 值班日期 `yyyy-MM-dd`（精确到当日） |
| shift | string | 班次：传编码（`#1#` 等）或中文（白班）均可 |
| status | string | 排班状态中文（未开始/待值班/值班中/已完成） |
| org | string | 单位：单位 id 或名称模糊 |
| keyword | string | 人员关键词：值班人员/带班领导姓名模糊 |

**响应**

```json
{
  "total": 4,
  "page": 1,
  "size": 10,
  "pages": 1,
  "records": [
    {
      "id": "47h3wCXvoYnhTr8ty5e",
      "date": "2026-10-13",
      "shift": "白班",
      "shiftCode": "#1#",
      "shiftTime": "08:00-16:00",
      "timeStart": "2026-10-13 08:00",
      "timeEnd": "2026-10-13 16:00",
      "org": "花凉亭灌区怀宁县管理所",
      "orgId": "ggEKzLyMEG7nD55XjIW",
      "leader": "张三",
      "leaderId": "A9jEKZmJhcmUEK4RCZo",
      "members": "李四、王五",
      "memberIds": ["VDLqdrLqoRQkmH7tltL", "CNgiPAW3DuuLDGRQtpv"],
      "status": "未开始",
      "statusCode": "#1#"
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| date | 值班日期（新列 idjwlq 优先，历史数据回落旧列） |
| shift / shiftCode | 班次中文 / 编码；`shiftTime` 为 `HH:mm-HH:mm` 文本（历史无时间则为 `null`） |
| timeStart / timeEnd | 值班时间起止（`yyyy-MM-dd HH:mm`，编辑回显可用） |
| org / orgId | 单位名称 / 单位 id（org 空时回落旧列单位文本） |
| leader / leaderId | 带班领导姓名 / 用户 id |
| members / memberIds | 值班人员姓名（顿号连接）/ 用户 id 数组 |
| status / statusCode | 展示状态（含「待值班」纠偏）/ 存储编码 |

**排序**：按值班时间倒序（历史无时间行按旧列值班日期倒序兜底）。

### 3.5 保存排班（新增/编辑）`POST /duty/schedule/save`

**请求体**

```json
{
  "id": null,
  "dutyDate": "2026-10-13",
  "shiftCode": "#1#",
  "timeStart": "2026-10-13 08:00",
  "timeEnd": "2026-10-13 16:00",
  "orgId": "ggEKzLyMEG7nD55XjIW",
  "leaderId": "A9jEKZmJhcmUEK4RCZo",
  "memberIds": ["VDLqdrLqoRQkmH7tltL", "CNgiPAW3DuuLDGRQtpv"]
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| id | 否 | 有值=编辑，空=新增 |
| dutyDate | 是 | 值班日期 `yyyy-MM-dd` |
| shiftCode | 是 | 班次编码（`#1#`/`#jhyu#`/`#zsfh#`） |
| timeStart / timeEnd | 是 | `yyyy-MM-dd HH:mm`，结束须晚于开始（跨天允许） |
| orgId | 是 | 单位 id（须存在于单位表） |
| leaderId | 是 | 带班领导用户 id（须存在于用户表） |
| memberIds | 否 | 值班人员用户 id 数组（可空数组=不安排人员） |

**响应**：保存后的完整详情对象（结构同 §3.3）。

**错误**

| 场景 | 状态码 | message 示例 |
| --- | --- | --- |
| 必填缺失/格式错误 | 400 | `值班日期不能为空` / `值班时间格式应为 yyyy-MM-dd HH:mm` |
| 时间倒挂 | 400 | `值班结束时间必须晚于开始时间` |
| 班次编码非法 | 400 | `班次编码不合法` |
| 单位/领导不存在 | 400 | `所在单位不存在或已删除` / `带班领导不存在` |
| 编辑非未开始排班 | 409 | `仅未开始的排班可编辑` |

**写入说明**（后端行为，前端无需关心）：新增默认 `peuzwi=#1#`；同时兼容写入 H5 提醒所需的旧列（值班日期/班次时间文本/单位名称）。

---

### 3.6 删除排班 `DELETE /duty/schedule/{id}`

**路径参数**：`id` 排班 id

**响应**：`{"success": true}`

**错误**：`400`（`排班不存在或已删除`）；`409 {"message":"仅未开始的排班可删除"}`

> 删除时同步清理排班的值班人员关系数据。

## 4. 值班交接班页接口

> 以下接口均以当前登录人为操作主体（值班人/带班领导视角）。

### 4.1 当前值班 `GET /duty/attendance/today`

页面左侧「当前值班」卡片数据源。四态判定。

**请求参数**：无

**响应（ongoing 值班中）**

```json
{
  "status": "ongoing",
  "badge": "值班中",
  "scheduleId": "iR4G6Umb6z97BITVWtK",
  "recordId": "skIz0cFFclvQJRPqHwf",
  "recordNo": "ZBJL-20260920-01",
  "date": "2026-09-20",
  "shift": "白班",
  "shiftTime": "08:00-16:00",
  "org": "花凉亭灌区怀宁县管理所",
  "leader": "张三",
  "members": "李四、王五",
  "summary": "持续关注3号闸门水位变化",
  "actualStart": "2026-09-20 07:55",
  "actualEnd": null,
  "receiverCandidates": [
    { "id": "CNgiPAW3DuuLDGRQtpv", "name": "李四" }
  ]
}
```

**响应（notstarted 未开始）**：同上结构，无 `recordId/recordNo/actualStart/actualEnd`（或为 null），`summary` 为 null；`scheduleId` 供「开始值班」使用。

**响应（completed 已完成）**：带 `recordNo/recordId` 与 `actualStart/actualEnd`。

**响应（none 无安排）**

```json
{ "status": "none", "badge": "无安排" }
```

| 字段 | 说明 |
| --- | --- |
| status | `ongoing` / `notstarted` / `completed` / `none`（前端按钮规则：ongoing→填写报告/交班可点；notstarted→开始值班可点；其余全禁用） |
| badge | 中文徽标：值班中 / 未开始 / 已完成 / 无安排 |
| scheduleId | 对应排班 id（ongoing/completed 由记录反查，可能为 null） |
| recordId / recordNo | 值班记录 id / 编号（填写报告、交班提交时使用） |
| date | 值班日期（`yyyy-MM-dd`） |
| shift / shiftTime | 班次中文 / 时间文本（跨天含「次日」前缀） |
| org / leader / members | 单位 / 带班领导 / 值班人员（顿号连接） |
| summary | 值班情况综述（记录 rdammr） |
| actualStart / actualEnd | 实际开始 / 实际交班时间（`yyyy-MM-dd HH:mm`） |
| receiverCandidates | 接班人员候选（仅 ongoing）：同单位下一班（开始时间不早于本班结束时间的最近未开始排班）的值班人员 `[{id,name}]`，供交班弹窗默认选中；无下一班为空数组 |

**判定顺序**：① 我的 `#2#` 记录（rel 含我 或 带班领导=我）→ ongoing；② 我的排班 → notstarted（口径同 §3.1：`#cmiu#` 不限时间，`#1#/#zzkl#` 要求班次时间与今日相交；多条命中按值班中优先 → 待值班 → 开始时间升序取一条）；③ 今日交班的我的 `#3#` 记录（yuyitx 落在今天）→ completed；④ none。

### 4.2 开始值班（签到）`POST /duty/attendance/start`

**请求体**

```json
{ "scheduleId": "iR4G6Umb6z97BITVWtK" }
```

**响应**

```json
{ "ok": true, "recordId": "skIz0cFFclvQJRPqHwf", "recordNo": "ZBJL-20261012-01" }
```

**后端行为**：

1. 校验排班存在且未完成；
2. 幂等：若该排班已存在「值班中」记录，直接返回该记录（不重复创建）；
3. 生成记录编号 `ZBJL-{值班日期}-{NN}`（NN=同前缀当日最大序号+1，两位补零，见 §7.2）；
4. 创建值班记录：值班日期/班次时间/单位/带班领导/值班人员从排班复制，`实际开始时间=当前时间`，状态=值班中；
5. 排班状态置「值班中」，并维护 H5 提醒标记。

**错误**

| 场景 | 状态码 | message 示例 |
| --- | --- | --- |
| 参数缺失 | 400 | `排班 id 不能为空` |
| 排班不存在 | 400 | `排班不存在或已删除` |
| 排班已完成 | 409 | `该排班已完成，无法开始值班` |

### 4.3 填写值班报告 `POST /duty/attendance/report`

**请求体**

```json
{
  "recordId": "skIz0cFFclvQJRPqHwf",
  "events": "3号闸门水位短时超警，已通知巡查处理",
  "summary": "本班设备运行正常，重点关注渠道水位变化"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| recordId | 是 | 值班记录 id（来自 §4.1） |
| events | 否* | 重大事件记载 |
| summary | 否* | 值班情况综述（最长 800 字） |

\* `events` 与 `summary` 至少一项非空（前端已校验「请填写值班报告内容」，后端同步校验）。

**响应**：`{"success": true}`（按提交字段更新：未提交或为空的字段保持原值，可重复提交）

**错误**：`400`（`请填写值班报告内容` / `值班情况综述不能超过 800 字` / `值班记录不存在`）；`409 {"message":"当前记录不在值班中，无法填写报告"}`

### 4.4 交班 `POST /duty/attendance/handover`

**请求体**

```json
{
  "recordId": "skIz0cFFclvQJRPqHwf",
  "receiverIds": ["CNgiPAW3DuuLDGRQtpv", "EiCDnlpzopRMJzZKYS4"],
  "matters": "夜间注意3号闸门水位，明早8点前上报巡查记录"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| recordId | 是 | 值班记录 id |
| receiverIds | 建议必填 | 接班人员用户 id 数组（默认取下一班排班的值班人员，前端可增删）；允许空数组 |
| matters | 否 | 待办移交事项 |

**响应**

```json
{ "success": true, "handoverNo": "JJB-20261012-01" }
```

**后端行为（单事务）**：

1. 校验接班人员存在性（不存在则 400 拒绝，候选来自 `receiverCandidates` 一般为有效值）；
2. 更新值班记录：`实际交班时间=当前时间`，状态=已完成；
3. 生成交接班编号 `JJB-{交班当天}-{NN}`（口径同 §7.2），创建交接班记录：原班次时间/单位取自值班记录，交班人员=本班值班人员，下一班值班人员=receiverIds，待办移交事项=matters；
4. 本班排班置「已完成」；
5. 同单位下一班未开始排班自动置「待值班」（无下一班则跳过）。

> 排班联动前提是记录与排班匹配成功（单位 + 班次起止时间精确相等；历史数据降级为「同单位 + 进行态 + 同值班日期」）。匹配失败仅跳过联动并记日志，不影响交班结果。

**错误**

| 场景 | 状态码 | message 示例 |
| --- | --- | --- |
| 记录不存在 | 400 | `值班记录不存在` |
| 接班人员不存在 | 400 | `接班人员不存在或已删除` |
| 重复交班 | 409 | `该记录已完成交班` |
| 非值班中状态 | 409 | `当前记录不在值班中，无法交班` |

---

### 4.5 今日交接班动态 `GET /duty/attendance/timeline`（P1 可选）

页面右栏「今日交接班动态」时间线数据源。**当前页面该区域为静态内容，本期可暂不接入**；接入时按下述契约。

**请求参数**：`date`（可选，默认今天，`yyyy-MM-dd`）

**响应**

```json
{
  "date": "2026-10-12",
  "items": [
    {
      "type": "handover",
      "status": "done",
      "time": "08:00",
      "title": "夜班→白班",
      "handoverNo": "JJB-20261012-01",
      "fromUsers": ["李静"],
      "toUsers": ["张伟"]
    },
    {
      "type": "ongoing",
      "status": "active",
      "time": "10:24",
      "title": "白班",

    }

```

| 字段 | 说明 |
| --- | --- |
| type | `handover`=已交班（当日交接班记录）｜`ongoing`=值守中（当前值班中的记录，`time` 取实际开始时间，前端自行计算交班倒计时）｜`pending`=待交接（当日 `#zzkl#` 待值班或已到点未开始（读侧纠偏为待值班）的排班） |
| title | 班次标签：已交班/待交接为「上班次→下班次」，值守中为当前班次名（按班次时间点推断，无法推断时为「交接班」） |
| fromUsers / toUsers | 交班人 / 接班人姓名数组（pending 行 `fromUsers` 为 null，不推定上一班人员） |
| shiftTime | 当前班次时间文本（仅 ongoing，供倒计时计算） |

**排序**：三类行合并后按 `time` 升序（同刻保持「已交班 → 值守中 → 待交接」收集序；`time` 为空排末尾）。

### 4.6 登录值班提醒 `GET /duty/login-remind`

供人员**登录后调用**（任意页面），判断今天是否有我的值班；有则返回班次、时间段、带班领导等数据，
用于登录提醒弹窗，并可引导至值班交接班页完成签到、填写报告、交班。判定与数据复用 §4.1 四态卡片
（`notstarted` 未开始 / `ongoing` 值班中 / `completed` 已完成）。

**请求参数**：无（以当前登录人视角）

**响应（今天有值班）**

```json
{
  "hasDuty": true,
  "status": "notstarted",
  "badge": "未开始",
  "scheduleId": "47h3wCXvoYnhTr8ty5e",
  "date": "2026-10-13",
  "shift": "白班",
  "shiftTime": "08:00-16:00",
  "org": "花凉亭灌区怀宁县管理所",
  "leader": "张三",
  "members": "李四、王五"
}
```

**响应（今天无值班）**

```json
{ "hasDuty": false }
```

| 字段 | 说明 |
| --- | --- |
| hasDuty | 今天是否有我的值班（四态非 `none` 即 true，含已完成） |
| status / badge | 四态：`notstarted` 未开始 / `ongoing` 值班中 / `completed` 已完成（+中文徽标） |
| 其余字段 | 与 §4.1 响应同构（班次/时间段/单位/带班领导/值班人员/摘要/实际时间；`recordId/recordNo` 仅记录态有值，`ongoing` 含 `receiverCandidates`） |

**对接建议**：`notstarted`（或 `ongoing`）时弹提醒窗并给「去签到 / 去值班」按钮，跳转 `duty-handover.html`
完成签到、填写报告、交班；`completed` 仅轻提示或忽略；`hasDuty:false` 不弹窗。

> 与 §3.1 `/duty/today-status` 的差异：后者面向值班管理页「是否需要签到」弹窗（不含已完成态）；本接口为登录提醒，完整四态（已完成也返回 `true`，由前端决定是否提示）。

## 5. 值班记录列表（兼容升级，`GET /duty/list`）

现有「值班记录列表」页接口，**路径与参数、响应字段保持不变**，本次升级读取逻辑（前端无需改动）。

**请求参数**：`date`（yyyy-MM-dd）、`shift`（班次时间模糊）、`unit`（单位模糊）、`person`（姓名或用户 id）——均为可选。

**响应**：裸数组（现有格式）

```json
[
  {
    "id": "skIz0cFFclvQJRPqHwf",
    "dutyDate": "2026-09-20",
    "shift": "08:00-16:00",
    "unit": "花凉亭灌区怀宁县管理所",
    "leaderId": "Gx7b5Kd2Pq9wLm3RtYv",
    "leader": "张三",
    "actualStart": "2026-09-20 07:55",
    "actualEnd": null,
    "summary": "持续关注3号闸门水位变化",
    "status": "值班中",
    "statusCode": "#2#"
  }
]
```

**升级说明**：

| 项 | 升级后行为 |
| --- | --- |
| 班次时间（shift） | 新记录由班次起止时间格式化 `HH:mm-HH:mm`（跨天加「次日」前缀）；历史记录继续展示旧列原文（两种形态并存，均不报错） |
| 单位（unit） | 新记录联单位表显示名称；历史记录回落旧单位文本列 |
| 人员过滤（person） | 三通道：值班人员关系表 `rel_id`（新记录）、历史多选文本列双路 LIKE（原文 + 解析出的用户 id）、带班领导 |
| 其他字段 | 值班日期/带班领导/实际开始/实际交班/综述/状态（#2#值班中/#3#已完成/#4#异常结束）不变 |

> 新流程产生的记录（§4.2 创建）在列表中正常显示；历史 12 条记录不回归。
