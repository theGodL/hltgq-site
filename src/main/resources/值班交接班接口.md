## 1. 通用约定

| 项 | 约定 |
| --- | --- |
| 服务前缀 | 下文路径均省略上下文前缀 `/hltgq-site`（如 `GET /duty/schedule/list` 实际请求 `/hltgq-site/duty/schedule/list`） |
| 请求/响应编码 | UTF-8，JSON（`Content-Type: application/json`） |
| 鉴权 | 全部接口要求登录会话（浏览器同域自动携带 Cookie；或 `Authorization` 头携带 sessionId）。未登录返回：`401 {"code":401,"message":"未登录","redirectUrl":"..."}`（前端可用 redirectUrl 跳转登录页）；会话服务不可用：`503 {"code":503,"message":"会话服务不可用，请稍后重试"}` |
| 成功响应 | 直接返回数据对象/数组（无统一 `{code,data}` 包装） |
| 错误响应 | `{ "message": "错误说明" }`；`400`=参数/业务校验失败，`409`=状态/业务冲突（如「仅未开始或待值班的排班可编辑」「值班时间冲突：…」），`500`=服务器错误 |
| 写接口权限 | 本模块写接口仅要求登录态（不加管理员限制）；如需收紧另行通知 |
| 日期格式 | 请求/响应日期：`yyyy-MM-dd`；时刻：`yyyy-MM-dd HH:mm` |
| 分页 | 请求 `page`（默认 1，≥1）、`size`（默认 10，1~100）；响应固定结构 `{total, page, size, pages, records}` |
| 空值 | 无值字段返回 `null` 或省略（本文档示例统一为 `null`，前端按 `|| '-'` 兜底） |

## 2. 数据字典

### 2.1 班次（排班·fjyyhu）

| 编码（请求传参用） | 名称 |
| --- | --- |
| `#1#` | 白班 |
| `#jhyu#` | 中班 |
| `#zsfh#` | 夜班 |

### 2.2 排班状态（排班·peuzwi）

| 编码 | 名称 | 说明 |
| --- | --- | --- |
| `#1#` | 未开始 | 可编辑/删除（前端操作列以 `statusCode` 判断） |
| `#zzkl#` | 待值班 | 到点后由后端「读时纠偏」展示，或上一班交班后自动置位；可编辑/删除（与未开始同为未开始类） |
| `#cmiu#` | 值班中 | 本班已有在途记录（任一参与人签到时置位）；不代表本人已签到——本人签到与否按归属人判定，见 §3.1 `signed` 与 §4.1（2026-10 每人独立签到） |
| `#qavx#` | 已完成 | 已交班 |

> 前端展示字段 `status` 为纠偏后的中文；`statusCode` 为库中真实编码。

### 2.3 值班记录状态（记录·ylncfw）

| 编码 | 名称 |
| --- | --- |
| `#2#` | 值班中 |
| `#3#` | 已完成 |
| `#4#` | 异常结束（预留） |

### 2.4 时间展示约定

- 班次时间文本（`shiftTime`）：`HH:mm-HH:mm`；跨天时次日部分加「次日」前缀，如 `20:00-次日08:00`。
- 列表页展示可拼接为 `白班(08:00-16:00)`（班次 + 括号时间）。

## 3. 值班管理页接口

### 3.1 今日值班判定 `GET /duty/today-status`

登录或页面加载时判断「今天是否我值班」，用于签到提醒弹窗（弹窗由登录侧实现，不在本项目页面弹出）。以当前登录人视角。

**请求参数**：无

**响应**

```json
{
  "onDuty": true,
  "scheduleId": "47h3wCXvoYnhTr8ty5e",
  "dutyDate": "2026-10-13",
  "statusCode": "#zzkl#",
  "status": "待值班",
  "name": "张伟",
  "shift": "白班",
  "shiftTime": "08:00-16:00",
  "leader": "刘建国",
  "signed": false
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| onDuty | boolean | 是否命中我的值班安排 |
| scheduleId | string | 命中的排班 id（供跳转交接班页使用） |
| dutyDate | string | 值班日期 |
| statusCode / status | string | 排班状态编码 / 中文（纠偏后） |
| name | string | 当前登录人姓名 |
| shift | string | 班次中文（白班/中班/夜班） |
| shiftTime | string | 班次时间文本 |
| leader | string | 带班领导姓名 |
| signed | boolean | 本人是否已签到（按人判定）：仅 `statusCode=#cmiu#` 时按「该排班已存在归属本人（ahygpx=我）的在途记录」（归属人 + 单位 + 班次匹配）判定，其余状态恒 `false` |

未命中时：`{"onDuty": false}`（其余字段省略）。

**判定顺序（待签到优先）**：① 我参与（带班领导或值班人员）且 `#1#/#zzkl#`、班次时间与今日相交（开始 < 明日零点 且 结束 ≥ 今日零点，跨天班次自然覆盖；时间取新列起止，缺失时回落旧列值班日期兜底，新旧皆空的历史行不参与）的排班 → ② 我参与且 `#cmiu#` 的排班（不限时间，兜底）→ ③ 无则 `onDuty=false`。

多条命中取一条：`#zzkl#`（待值班）→ `#1#`（未开始）→ `#cmiu#`（值班中兜底），再按班次开始时间升序（先开班的先命中）。同一天多条并存（如白班值班中 + 晚班待签到）时，提醒优先指向待签到的班；**签到提醒弹窗条件**：`statusCode` 为 `#zzkl#/#1#`，或 `statusCode` 为 `#cmiu#` 且 `signed=false`（本班已有在途记录、本人尚未签到，引导签到）；`#cmiu#` 且 `signed=true` 表示本人已签到值班中，不再弹提醒。


| 字段 | 说明 |
| --- | --- |
| date | 值班日期（新列 idjwlq 优先，历史数据回落旧列） |

### 3.5 保存排班（新增/编辑）`POST /duty/schedule/save`

**请求体**

```json
{
  "id": null,
  "dutyDate": "2026-10-13",
  "shiftCode": "#1#",
  "timeStart": "2026-10-13 08:00",
  "timeEnd": "2026-10-13 16:00",
  "orgId": "ggEKzLyMEG7nD55XjIW",
  "leaderId": "A9jEKZmJhcmUEK4RCZo",
  "memberIds": ["VDLqdrLqoRQkmH7tltL", "CNgiPAW3DuuLDGRQtpv"]
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| id | 否 | 有值=编辑，空=新增 |
| dutyDate | 是 | 值班日期 `yyyy-MM-dd` |
| shiftCode | 是 | 班次编码（`#1#`/`#jhyu#`/`#zsfh#`） |
| timeStart / timeEnd | 是 | `yyyy-MM-dd HH:mm`，结束须晚于开始（跨天允许） |
| orgId | 是 | 单位 id（须存在于单位表） |
| leaderId | 是 | 带班领导用户 id（须存在于用户表） |
| memberIds | 否 | 值班人员用户 id 数组（可空数组=不安排人员） |

**响应**：保存后的完整详情对象（结构同 §3.3）。

**错误**

| 场景 | 状态码 | message 示例 |
| --- | --- | --- |
| 必填缺失/格式错误 | 400 | `值班日期不能为空` / `值班开始时间不能为空` / `值班开始时间格式应为 yyyy-MM-dd HH:mm：2026-10-13 8:00` |
| 时间倒挂 | 400 | `值班结束时间必须晚于开始时间` |
| 班次编码非法 | 400 | `班次编码不合法` |
| 单位/领导不存在 | 400 | `所在单位不存在或已删除` / `带班领导不存在` / `值班人员不存在或已删除` |
| 编辑非未开始/待值班排班 | 409 | `仅未开始或待值班的排班可编辑` |
| 人员时间冲突 | 409 | `值班时间冲突：张三 在 2026-10-13 白班（花凉亭灌区怀宁县管理所 08:00-16:00）已有值班安排` |

**人员时间唯一规则**：同一时间段，一个人（无论带班领导还是值班人员身份）只能出现在一条排班中。新增/编辑保存时校验：与其余排班（不限状态、不限单位）时间区间重叠——开始 < 对方结束 且 对方开始 < 结束（首尾相接不算重叠，如 16:00 交班、16:00 接班）——且任一所选人员在其领导/人员名单中，即拒绝并提示冲突人员与班次；编辑时排除自身。

> 保存失败只返回首个问题；提交前可先调 §3.7 校验接口一次性获取全部问题（同一套规则与文案）。

**写入说明**（后端行为，前端无需关心）：新增默认 `peuzwi=#1#`；同时兼容写入 H5 提醒所需的旧列（值班日期/班次时间文本/单位名称）。

### 3.6 删除排班 `DELETE /duty/schedule/{id}`

**路径参数**：`id` 排班 id

**响应**：`{"success": true}`

**错误**：`400`（`排班不存在或已删除`）；`409 {"message":"仅未开始或待值班的排班可删除"}`（值班中/已完成不可删除）

> 删除时同步清理排班的值班人员关系数据。

### 3.7 保存前数据校验 `POST /duty/schedule/verify`

「新增/编辑排班」提交前的数据体检（不落库）：与 §3.5 保存**同一套规则与文案**，一次性返回全部问题，供前端标记到对应输入项（前端只传数据，合规性由后端裁定）。

**请求体**：与 §3.5 相同；`id` 有值=按编辑场景校验（校验对象存在性与状态，冲突排除自身），空=按新增校验。

**响应（全部通过）**

```json
{ "valid": true }
```

**响应（存在问题）**

```json
{
  "valid": false,
  "errors": [
    { "field": "timeEnd", "message": "值班结束时间必须晚于开始时间" },
    { "field": "memberIds", "message": "值班人员不存在或已删除" }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| valid | 是否全部通过（本接口恒返回 HTTP 200，问题在 errors 中） |
| errors[].field | 定位请求字段：`dutyDate` / `timeStart` / `timeEnd` / `shiftCode` / `orgId` / `leaderId` / `memberIds` / `id`（`id`=编辑对象不存在或不可编辑；人员时间冲突定位在 `timeStart`；请求体整体问题为 null） |
| errors[].message | 问题说明（与保存失败时的 message 完全一致） |

**校验项**（按序收集，一次返回全部）：

1. 必填：值班日期 / 值班开始时间 / 值班结束时间 / 班次 / 所在单位 / 带班领导（带班领导为单值字段，结构上只有一人；值班人员为数组，可多人或空）；
2. 格式：日期 `yyyy-MM-dd`、时间 `yyyy-MM-dd HH:mm`、结束晚于开始（跨天允许）；
3. 班次编码合法（`#1#`/`#jhyu#`/`#zsfh#` 或中文）；
4. 单位 / 带班领导 / 值班人员存在性；
5. 编辑场景：排班存在且为未开始/待值班（否则不可编辑）；
6. 人员时间唯一：同一时间段一个人只能有一条排班（规则同 §3.5；基础项全部通过后才校验，避免不可靠结果）。

> 校验通过后仍建议以 §3.5 保存结果为准（保存内含同一套校验，防并发窗口）；校验接口可用于表单实时提交前预检（如失焦/下一步时调用）。

### 3.8 取号：查询下一个编号 `GET /duty/next-no`

供前端/其他项目在新增数据前获取下一个可用编号（规则见 §7.2）；与签到（§4.2）/交班（§4.4）内部编号生成**同源**（查各自数据表当日最大序号 +1）；签到/交班在数据库事务内持有编号互斥锁至提交（事务级建议锁，跨实例生效），取号接口仅查询不落库，不会与正在提交的签到/交班撞号。

**请求参数**

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| type | 否 | 编号类型：`record`=值班记录（ZBJL-，默认）/ `handover`=交接班（JJB-） |
| date | 否 | 日期 `yyyy-MM-dd`（默认今天；`record` 传值班日期口径，`handover` 传交班当天口径） |

**响应**

```json
{ "type": "record", "date": "2026-10-13", "no": "ZBJL-20261013-0001" }
```

**说明**

- 本系统签到/交班响应中已含真实编号，界面无需调用本接口；本接口面向外部系统/其他项目取号场景；
- 接口为**查询式计算**（查表最大序号 +1），不预留占用：取号后未写入数据的编号不视为已占用，会被后续取号/生成按「最大序号 +1」自然接续；
- 错误：`type` 非法 → `400`（`编号类型仅支持 record（值班记录）或 handover（交接班）：xxx`）；`date` 非法 → `400`（`日期格式应为 yyyy-MM-dd：xxx`）。

```json
  "myCheckinAt": "2026-09-20 07:55",
  "receiverCandidates": [
    { "id": "CNgiPAW3DuuLDGRQtpv", "name": "李四" }
  ]
}
```

**响应（notstarted 未开始 / 待签到）**：同一 status 两个子形态（均只带 `scheduleId`，以 `badge` 区分）——① 我的待值班排班（badge「未开始」，`scheduleId` 供「开始值班」使用）；② 在途班已有记录、本人尚未签到（badge「待签到」，`scheduleId` 供「去签到」使用；签到即生成属于我自己的值班记录）。

**响应（completed 已完成）**：带 `recordNo/recordId` 与 `actualStart/actualEnd`。

**响应（none 无安排）**

```json
{ "status": "none", "badge": "无安排" }
```

| 字段 | 说明 |
| --- | --- |
| status | `ongoing` / `notstarted` / `completed` / `none`（前端按钮规则：ongoing→填写报告/交班可点；notstarted→开始值班可点，待签到子形态（`badge==='待签到'`）按钮为「去签到」；其余全禁用） |
| badge | 中文徽标：值班中 / 未开始 / 待签到（班已在途、本人尚未签到的子形态）/ 已完成 / 无安排 |
| scheduleId | 对应排班 id（notstarted 为我的排班；ongoing/completed 由记录反查，可能为 null） |
| recordId / recordNo | **我自己的**值班记录 id / 编号（填写报告、交班提交时使用；仅 ongoing/completed 有值，每人记录互相独立） |
| date | 值班日期（`yyyy-MM-dd`） |
| shift / shiftTime | 班次中文 / 时间文本（跨天含「次日」前缀） |
| org / leader / members | 单位 / 带班领导 / 值班人员（记录按人：新记录 members 为记录归属人本人；历史记录回退本班人员聚合） |
| events / summary | 重大事件记载 / 值班情况综述（本人记录；报告弹窗回显用） |
| actualStart / actualEnd | 实际开始 / 实际交班时间（`yyyy-MM-dd HH:mm`） |
| myCheckinAt | 本人签到时间（`yyyy-MM-dd HH:mm`，仅 ongoing；即本人记录的实际开始时间 `jlailj`） |
| receiverCandidates | 接班人员候选（仅 ongoing）：同单位下一班（开始时间不早于本班结束时间的最近未开始排班）的值班人员 `[{id,name}]`，供交班弹窗默认选中；无下一班为空数组 |

**判定顺序（记录按人）**：① 我的在途 `#2#` 记录（归属人 ahygpx=我 且班次时间与今日相交）→ ongoing（附 `myCheckinAt`、`scheduleId` 反查与 `receiverCandidates`）；② 我的在途排班（`#cmiu#`、我参与、班次时间与今日相交，且我尚未生成自己的记录）→ notstarted（badge「待签到」）；③ 我的待值班排班（rel 含我 或 带班领导=我；`#1#/#zzkl#` 且班次时间与今日相交，`#zzkl#` 优先、再按开始时间升序取一条）→ notstarted（badge「未开始」）；④ 今日交班的我的 `#3#` 记录（yuyitx 落在今天；历史班记录回退「我参与」匹配）→ completed；⑤ none。

同一天多条并存（如白班在途未签 + 晚班待值班）时优先返回待签到，登录提醒先弹「去签到」；**本人未签到不显示「值班中」**——同班他人签到开启班后，其余成员各自看到「待签到」直至本人签到（签到即生成各自独立的记录）；签到后按顺序自然流转到 ongoing。在途判定限「班次时间与今日相交」的班（跨天班在结束日仍可见）：陈旧的跨日未交班记录不参与判定，不再遮挡当日状态。改造前的历史在途记录（ahygpx 为空）不参与 ①/④ 归属判定，本班参与人按排班维度回 ② 各自签到生成自己的记录；历史记录随本班任一收口一并关闭（§4.4）。

### 4.2 开始值班（签到）`POST /duty/attendance/start`

**请求体**

```json
{ "scheduleId": "iR4G6Umb6z97BITVWtK" }
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| scheduleId | 是 | 排班 id（来自 §4.1 的 `scheduleId`；签到即按我（归属人）创建我自己的值班记录，同班每人各签各的） |

**响应**

```json
{ "ok": true, "recordId": "skIz0cFFclvQJRPqHwf", "recordNo": "ZBJL-20261012-0001" }
```

**后端行为**（记录按人：**值班记录 = 一个人的值班记录**——每人签到各自生成一条归属本人（`ahygpx`）的记录，接口与响应不区分「首位签到」与「同班后来者签到」）：

1. 校验排班存在、本人为本班带班领导或值班人员（非本班人员 409）；
2. 事务级建议锁内幂等检查：若该排班已存在**归属我**的在途 `#2#` 记录（归属人 + 单位 + 班次匹配）→ 直接返回该记录 id/编号（重复点击/并发安全，不重复创建我自己的记录）；
3. 无我的记录则走状态闸门：仅 `#qavx#` 已完成拒绝（**`#cmiu#` 值班中允许同班后来者签到**）；
4. 生成记录编号 `ZBJL-{值班日期}-{NN}`（NN=同前缀当日最大序号+1，四位补零，见 §7.2）；
5. 创建**我自己的**值班记录：值班日期/班次时间/单位/带班领导/值班人员从排班复制，**归属人=本人**（带班领导本人签到时该记录的带班领导即本人），`实际开始时间=当前时间`（即本人签到时间），状态=值班中；
6. 排班状态置「值班中」，并维护 H5 提醒标记（首个签到触发，后续幂等）。

| 场景 | 状态码 | message 示例 |

| scheduleId 缺失 | 400 | `排班 id 不能为空` |
| 排班不存在 | 400 | `排班不存在或已删除` |
| 非本班人员 | 409 | `仅本班带班领导或值班人员可签到` |
| 排班已完成 | 409 | `该排班已完成，无法签到` |

### 4.4 交班 `POST /duty/attendance/handover`

**请求体**

```json
{
  "recordId": "skIz0cFFclvQJRPqHwf",
  "receiverIds": ["CNgiPAW3DuuLDGRQtpv", "EiCDnlpzopRMJzZKYS4"],
  "matters": "夜间注意3号闸门水位，明早8点前上报巡查记录"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| recordId | 是 | 我自己的值班记录 id（归属人=我；交班一次全班收口） |
| receiverIds | 建议必填 | 接班人员用户 id 数组（默认取下一班排班的值班人员，前端可增删）；允许空数组 |
| matters | 否 | 待办移交事项 |

**响应**

```json
{ "success": true, "handoverNo": "JJB-20261012-0001" }
```

**后端行为（单事务；一次交班全班收口）**：

1. 校验本人为记录归属人（非归属人 409）、记录在途（#2#）、接班人员存在性（不存在则 400 拒绝，候选来自 `receiverCandidates` 一般为有效值）；
2. **全班收口**：同单位 + 班次起止时间的在途记录组（排班无班次时间时降级「同单位 + 值班日期」；找不到单位的历史记录按单条兜底）一并置 `#3#` 已完成、写**同一实际交班时间**；组内每人的记录各自完整保留（各人报告不受影响），其余人再发起交班 409 已收口；
3. 生成交接班编号 `JJB-{交班当天}-{NN}`（口径同 §7.2），创建一条交接班记录：原班次时间/单位取自值班记录，**交班人员=本班各记录的归属人**（改造前历史记录回退其 rel 人员），下一班值班人员=receiverIds，待办移交事项=matters；
4. 本班排班置「已完成」；
5. 同单位下一班未开始排班自动置「待值班」（无下一班则跳过）。

> 排班联动前提是记录与排班匹配成功（单位 + 班次起止时间精确相等；历史数据降级为「同单位 + 进行态 + 同值班日期」）。匹配失败仅跳过联动并记日志，不影响交班结果。

**错误**

| 场景 | 状态码 | message 示例 |
| --- | --- | --- |
| 记录不存在 | 400 | `值班记录不存在` |
| 接班人员不存在 | 400 | `接班人员不存在或已删除` |
| 非记录归属人 | 409 | `仅记录归属人可发起交班` |
| 重复交班 | 409 | `该记录已完成交班` |
| 非值班中状态 | 409 | `当前记录不在值班中，无法交班` |

### 7.2 编号规则对照

| 编号 | 格式 | 示例 |
| --- | --- | --- |
| 值班记录 | `ZBJL-{值班日期 yyyyMMdd}-{NN}` | ZBJL-20261012-0001 |
| 交接班 | `JJB-{交班当天 yyyyMMdd}-{NN}` | JJB-20261012-0001 |

NN 为当日（同前缀）最大序号 +1（四位补零，如 `0001`；容量 9999/天，不会溢出）。

> 编号位数扩容为四位后，平台侧字段校验（原 `^ZBJL-\d{8}-\d{2}$` / `^JJB-\d{8}-\d{2}$`，见实施方案 §2.4）需同步放宽为 `^ZBJL-\d{8}-\d{4}$` / `^JJB-\d{8}-\d{4}$`；后端直连写入不受平台校验影响。

> 取号接口（§3.8）与签到/交班内部生成同源互斥：签到/交班在数据库事务内持有编号互斥锁（事务级建议锁）至提交，进程内再叠加方法级互斥，并发与跨实例提交均不会重号。
