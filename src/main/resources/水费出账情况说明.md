## 三、前端要怎么做才能出账（调用链）

统一前缀 `http://<host>:8081/hltgq-site`，需登录态 Cookie；数量对外一律**万m³**，金额元。

```
① GET  /water-bill/meta                 取周期/状态字典、当天日期
② GET  /water-bill/ledger               台账视图一：每户一行，看 pendingCount / dataOk / dataNote
③ GET  /water-bill/user-plans?userId=   台账明细视图二：该户逐方案，拿 records[].dispatchId
④ POST /water-bill/bills/create         出账：请求体 = 所选 dispatchId 的 JSON 数组
⑤ GET  /water-bill/page + /stats        账单列表 + 顶部统计条（出账后有数据）
⑥ GET  /water-bill/detail?id=           账单详情（含 plans[] 计费快照）
```

**第 ④ 步的 body 不是对象，是裸数组**：

```
POST /hltgq-site/water-bill/bills/create
Content-Type: application/json

["<dispatchId>", "<dispatchId>"]
```

成功响应：`{"success":true,"count":2,"bills":[WaterBillVO…]}`，`bills` 含方案快照，可直接回显或跳详情。

### 出账必须同时满足的条件（缺一条就 400）

| 条件 | 数据来源 | 不满足时的 400 文案 |
|------|----------|---------------------|
| 所选方案存在 | ③ 的 `dispatchId`，别传已删方案 / 传户 id | `部分调度方案不存在，请刷新后重试` |
| 未取消、未计费 | ③ 的 `status` ≠ 已取消、`billed=false` | `方案 DD#### 已取消，不可出账` / `已计费（账单 SF…），不可重复出账` |
| 户已配统计周期 | 户档案 `settle_cycle` | `用水户 X 未配置统计周期，无法出账` |
| 户已配计量闸口（SUM/DIFF 合法 JSON） | 户档案 `gate_config` | `用水户 X 未配置关联闸口，无法出账` |
| **每个计量闸口在执行时段内有有效累计流量数据** | 流量接入侧 | `方案 DD#### 不可出账：执行时段内该闸口无流量记录（时段 … ~ …，闸口 …）` ← **当前卡在这里** |
| 单方案计入水量 > 0 | 计量结果 | `方案 DD#### 计入水量为 0 或负值（N m³），请核对流量数据` |
| 组内净计入水量 > 0（DIFF 扣减后） | 计量结果 | `用水户 X {2026年10月} 净计入水量为 Z 万m³（≤0），不可出账…` |
| 户水价 > 0 | 户档案 `water_price` | `用水户 X 未配置有效水价，无法出账` |

> 分组拆分由后端完成：一次请求可混选多户 / 多分期，后端按 `(用水户 × 分期 key)` 自动拆成多张账单；**同一账单内的方案必须同户**，跨月/跨季会拆成多张而不是报错。

### 今天就能出账的最小准备（业务侧操作，不需改代码）

1. 用水户管理页（该页已对接）→ 编辑户，计量闸口改选**北干渠进水闸**（`4Ieu32Stnz8dTD8S8GD`，有数据：累计 4120 行、覆盖 2026-08-07 至今），策略选「指定闸口累加」；DIFF 户必须保证**主 + 全部扣减闸口都有数据**。
2. 保证存在该户的执行闸口 = 上述闸口、状态「执行中/已完成」、未计费的调度方案（时段起决定账期归属）。
3. 走 ②③④ 出账；出账前可先看 ③ 的 `amount` 是否有值（`null` + `meterIssue` 就是计量不可得，别硬提交）。

## 四、明细从哪里来（三处「明细」对应三个接口）

| 页面位置 | 接口 | 数据行字段 | 数值来源 |
|----------|------|------------|----------|
| 台账第二层「调度方案明细 / 待出账数据」 | `GET /water-bill/user-plans?userId=` | `records[]`（`BillPlanRowVO`） | **未计费行 = 实时计量**（每次请求重算）；已计费行 = 账单快照 |
| 账单列表「明细」弹窗 | `GET /water-bill/detail?id=` | `plans[]`（同 `BillPlanRowVO`） | 出账时固化的快照（`billed_qty`），不随流量变化 |
| 账单列表行本身 | `GET /water-bill/page` | `records[]`，`planCount` 有值、`plans` **恒为空数组** | 列表不给方案明细，必须再调 `/detail?id=` |

`BillPlanRowVO` 关键字段（原型页需按此改名）：

| 字段 | 含义 |
|------|------|
| `dispatchId` | **出账要传的就是它**（调度方案 id） |
| `dispatchNo` | 方案编号 `DD0001`（展示用，不是入参） |
| `gateId` / `gateName` | 计量闸口（**`gateCode` 已从接口移除**，别再读它） |
| `sign` | `1` 累加 / `-1` 扣减（DIFF 策略扣减闸口） |
| `startTime` / `endTime` | 执行时段 `YYYY-MM-DD HH:mm` |
| `planAmount` | 计划放水量（万m³） |
| `amount` | 计入水量（万m³，带符号）；未计费且计量不可得 → **`null`** |
| `meterIssue` | **本次新增**：`amount=null` 时的原因文案（`执行时段内该闸口无流量记录` / `执行时段内该闸口无有效累计流量` / `执行时段不正确，无法计量`），建议直接显示在水量列 |
| `billed` / `billNo` | 是否已计费 / 所属账单编号 |
| `status` / `statusName` | 方案执行状态（英文码 / 中文） |
| `cycleKey` / `cycleLabel` | 账期分期（`2026-10` / `2026年10月`） |

台账视图一「数据校验」列 = `GET /water-bill/ledger` 行的 `dataOk`（布尔）+ `dataNote`（逐方案原因，超 3 条折叠为「…等 N 项」）；`dataOk=false` 就代表该户当前出不了账，`dataNote` 已写清是哪个方案哪个闸口。

## 五、原型页要改成什么样（`water-bill.html`）

当前页面数据全在 JS 常量里，与后端字段对不上，逐项映射：

| 原型页写法 | 应改为 |
|------------|--------|
| `farmerCode: 'YH001'` / `led.code` | `waterUserId`（档案 id）+ `waterUserNo`；接口入参用 `userId` |
| `p.id = 'DD0014'` 当作方案标识 | `dispatchId`（真实 id），`dispatchNo` 只用于展示 |
| `gateCode: 'GK002'` + `GATE_NAMES[code]` | 直接用后端 `gateName`；**`gateCode` 已删除** |
| `p.amount` 写死数字 | ③ 接口 `records[].amount`（实时计量 / 快照），为空时展示 `meterIssue` |
| 页内 `createBills(farmerCode, planIds)` 本地拼 `billNo` | `POST /water-bill/bills/create`，账单号由后端发号（`SF{期间码}-{户号}####`） |
| 「数据校验」列本地判断 | ② 接口 `dataOk` / `dataNote` |
| 账单列表顶部统计条本地累加 | `GET /water-bill/stats` |
| 「调整方案计划放水量」 | `PUT /water-dispatch/adjust`（仅未计费方案可改，账期按新开始时间重推） |
| 「确认收款」 | `POST /water-bill/bills/pay?id=` |
| 「删除账单」 | `DELETE /water-bill/bills/delete?id=`（删除后方案恢复未计费，可重新出账） |

参照已对接的 `water-user-list.html`（同一个 `api()` + `qs()` 封装、同一套 400 文案直接 toast 的做法）接线即可。

## 六、待业务确认的 3 个口径（确认后我们再动代码）

1. **无流量数据的闸站要不要在配置阶段就挡掉**：水费配置的闸口下拉 / 调度方案编制时只放「有流量数据」的 21 个站，或保存时提示「该闸站暂无流量数据接入，无法计量计费」，而不是等出账时才 400。
2. **17 个无数据闸站**是补流量接入，还是联调期改用有数据的站演示。
3. **执行时段未结束是否允许出账**：`DD0001` 时段止为 10-15 18:00，而数据只到上午 10:55；目前后端允许「时段未结束」出账并按已入库部分计量（快照后不再变化）。若要求时段结束才能出账，需加校验。
