# 应急通知导航提示接口

导航页需要展示「应急响应 / 响应解除」提示，点击跳转「应急管理-应急通知」。
本期只提供后端只读接口，**前端负责展示与跳转**；通知的增删改仍由低代码平台表单完成。

- 数据源：应急通知 `t_auto_hltgq_bcmxdv_lmqaew`（只读）
- 接口：`GET /emergency-notice/nav-tip`（无参数；**生产环境统一加 `/hltgq-site` 前缀**，需登录会话）
- 权限：与应急保障同口径，所有登录用户可用

---

## 1. 字典（存储值即返回编码）

| 响应类别 `vqpwue` | 编码 | 通知事项 `pxkzdz` | 编码 | 市级响应等级 `sycosi` | 编码 |
|---|---|---|---|---|---|
| 防汛 | `#1#` | 启动响应 | `#1#` | Ⅰ级 | `#1#` |
| 抗旱 | `#vtsx#` | 升级响应 | `#ifde#` | Ⅱ级 | `#ggdd#` |
| 其他 | `#aivs#` | 降级响应 | `#sjib#` | Ⅲ级 | `#mytc#` |
|  |  | 终止响应 | `#doga#` | Ⅳ级 | `#bylw#` |
|  |  | 补充工作要求 | `#tckv#` |  |  |

通知状态 `cgkpil`：草稿 `#1#` / **已发布 `#ucpd#`** / **已终止 `#mevt#`**。

> 导航提示返回**已发布**和**已终止**的通知，只有**草稿**不返回；`items[].status` 直接对应这个状态
> （`published` / `terminated`），前端据此区分「发布的通知」和「终止的通知」。
> 通知事项里的「终止响应」（`pxkzdz=#doga#`）同样算终止类提示。

## 2. 判定口径（后端已实现，前端不需重算）

1. 返回「已发布」和「已终止」通知；草稿不返回。
2. **不按响应类别合并**：每条通知独立返回一条 `items` 元素，有几条就返回几条。
3. `status` 直接反映通知状态：
   - 已发布（`#ucpd#`）→ `status=published`；
   - 已终止（`#mevt#`）→ `status=terminated`；
   - 事项为「终止响应」（`#doga#`）的也按 `terminated` 处理。
4. 时间范围：
   - **终止类只保留近 3 天**（发布时间或录入时间任一在 3 天内即返回）；
   - **已发布**的不限时间，全部返回。
5. 等级取该条自身等级；未填写且非终止时，向更早的同类别通知回溯
   （「补充工作要求」通常不填等级，需要带出当前等级）。
6. `items` 排序：上级发布时间倒序（`innfii` 为空回退录入时间），同时间再按录入时间倒序；
   已发布与已终止**混排**，不按状态分段。
7. 类别、标题、文号、上级通知内容都是非必填，为空不影响返回。

## 3. 返回结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `hasTip` | boolean | 是否有提示（`items` 非空） |
| `tipType` | string | 汇总类型：`published` 存在已发布 / `terminated` 全部已终止 / `none` 无提示 |
| `appCode` | string | 应用编码 `bcmxdv`（跳转用） |
| `pageCode` | string | 表单编码 `lmqaew`（跳转「应急管理-应急通知」用） |
| `items` | array | 每条通知一条，无提示时为空数组 |

`items[]` 字段：

| 字段 | 说明 |
|---|---|
| `noticeId` | 通知主键（跳转定位用） |
| `title` | 通知标题（可能为 null） |
| `categoryCode` / `categoryName` | 响应类别编码 / 中文（仅展示用，不参与合并） |
| `status` / `statusName` | **该条通知状态**：`published` 已发布 / `terminated` 已终止 |
| `itemCode` / `itemName` | 该条事项编码 / 中文（启动/升级/降级/补充工作要求/终止响应） |
| `levelCode` / `levelName` | 该条响应等级编码 / 中文（Ⅰ级~Ⅳ级，可能为空串） |
| `publishUnit` | 上级发布单位（可能为 null） |
| `publishTime` | 上级发布时间 `yyyy-MM-dd HH:mm`（空值回退录入时间） |
| `requirementText` | 灌区落实要求（该条通知表单录入的原文，未填写为 null） |
| `tipText` | 提示文案：**直接等于「灌区落实要求」原文**，未填写时回退通知标题；不做字段拼接 |

> 接口只返回导航提示所需字段。上级文件文号、通知内容（富文本）等详情，
> 点击跳转到表单页查看。

### `tipText` 取值说明

`tipText` 就是「应急通知」表单里录入的**灌区落实要求**字段原文（去首尾空白、保留原文换行），
后端不拼类别/等级/事项，前端可直接展示：

| 场景 | `tipText` |
|---|---|
| 落实要求已填写 | 录入的原文，如「各灌区要落实24小时值班值守，加密巡查……」 |
| 落实要求未填写 | 回退该条通知标题 |
| 两者都为空 | 空串（前端可改用 `categoryName`/`itemName` 等字段自行展示） |

需要「防汛Ⅱ级应急响应启动」这类摘要时，前端可用
`categoryName` + `levelName` + `itemName` 自行拼接，后端不再提供拼装文案。

## 5. 前端对接要点

- 导航页加载时请求一次即可；如需定时刷新，建议轮询间隔 ≥ 5 分钟（无实时推送）。
- 用 `items[].status` 区分每条：`published` 已发布用警示色，`terminated` 已终止用中性/恢复色。
  后端已保证终止类只返回近 3 天的，前端可不再做过期判断。
- `items` 逐条展示即可（顺序即发布时间倒序）；每条直接用 `tipText`，或用字段自行拼装。
- `tipText` 为灌区落实要求原文，可能较长：导航条按单行省略（CSS `text-overflow: ellipsis`）
  展示，完整内容可放 `title` 提示或点击跳转查看。
- 点击任一提示：按平台既有表单路由，用 `appCode=bcmxdv` + `pageCode=lmqaew` 跳转到
  「应急管理-应急通知」（可再带 `noticeId` 定位到该条）。
- 是否可关闭、多条如何滚动/折叠由前端决定，后端每次返回当前事实。

## 6. 联调提示

- 返回范围 = 通知状态「已发布」+「已终止」，草稿不返回；类别、标题、文号、**上级通知内容**
  都是非必填，为空**不影响**返回。
- 验证顺序建议：发布「启动响应」→ 出现一条 `published`；再发布一条 → 再多一条；
  把某条通知状态改为「已终止」→ 该条仍在，只是 `status` 变成 `terminated`；
  把通知存为「草稿」→ 该条不出现。
