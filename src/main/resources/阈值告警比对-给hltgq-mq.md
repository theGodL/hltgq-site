# 阈值告警比对需求（给 hltgq-mq）

> 提出日期：2026-09-24；数据依据：当日全库只读实测（探针 SQL 见第 6 章）
> 涉及改动：**仅 hltgq-mq**（监测数据入库时的阈值比对与告警触发）
> hltgq-site 侧：阈值配置页 `/threshold-setting.html` + `/threshold/*` 接口（已完成，mq 只需**只读**阈值表，本侧不要求 mq 提供接口）

---

## 1. 背景与目标

平台已提供「阈值设置」页面，按「站点 + 阈值类型」配置单级警戒值（表 `t_auto_hltgq_water_threshold`）。
本文给出 mq 侧数据入库时的**阈值比对口径**，保证「配置了即生效」：

1. 监测数据入库时按 `site + 类型` 查阈值，无配置**静默跳过**（不报错、无噪音日志）；
2. 按 `alarmdir` 决定触发方向（**含等号**），`alarmdir` 为空按类型默认方向；
3. 同站点同类型持续超限，默认 **30 分钟内不重复推送**（做成参数，不写死）；
4. 阈值编辑保存后**下一次比对即用新值**（无需重启服务或清缓存）。

## 2. 阈值表字段口径（2026-09-24 实测）

表：`"qixiao-apaas".t_auto_hltgq_water_threshold`

| 列 | 含义 | mq 侧使用方式 |
|---|---|---|
| `site` | 站点档案主键（`t_auto_hltgq_5nw74_vnqqef.id`，19 位） | **匹配键** |
| `zvieyb` | 阈值类型编码（**权威列**，可多值如 `#1#\|#3#`） | 优先读取 |
| `type` | 历史类型列（存量 3 行落首个编码） | 仅兜底，**不得单独使用** |
| `alarmdir` | 告警方向 `#1#` 高于 / `#2#` 低于 | 空值按类型默认方向 |
| `threshold` | 警戒值（numeric） | 比对基准值 |
| `remark` | 描述（≤500 字，展示用） | 不用 |
| `guarantee` / `num` / `device` | 保证值 / 设计值 / 设备级阈值，**本期预留不启用** | 不用 |

**类型读取统一口径（必须照写）**：

```sql
COALESCE(NULLIF("zvieyb", ''), "type", '')
```

只读 `type` 会漏两类数据：新配置的行 `type` 为空；存量多值行（周家河、花凉亭坝上为 `#1#|#2#`）只落了首个编码。

## 3. 匹配键（实测结论：直接用 site，无需编码映射）

| 表 | `site` 列含义 | 实测覆盖（2026-09-24） |
|---|---|---|
| 阈值表 `water_threshold` | 站点档案主键 | 3 行，均 19 位，100% 命中档案 |
| 水位 `water_river_info` | **站点档案主键** | 34622 行，无空值，100% 命中档案 |
| 雨量 `water_rain_info` | **站点档案主键** | 29610 行，无空值，100% 命中档案 |
| 水质 `water_nmisp_info` | **站点档案主键** | 1138 行，无空值，100% 命中档案 |

- 结论 1：**入库比对直接用数据行的 `site` 关联阈值表 `site`**，不需要额外的编码映射；
- 结论 2：数据表另有 `stcd`（测站编码，如 `3206400001`），与档案 `iofhpi` 同源；若只拿到编码，
  按 `SELECT id FROM "qixiao-apaas"."t_auto_hltgq_5nw74_vnqqef" WHERE iofhpi = ?` 反查（实测编号无重复，174 个非空）；
- 结论 3：**支持阈值类型的站点 100% 有测站编码**（水位 18 / 雨量 18 / 流量 135 / 开度 25 / 墒情 4 站，缺编号数均为 0），编码映射不会漏站。

## 4. 比对规则

### 4.1 类型、数据来源与默认方向

| 类型 | 编码 | 数据来源（实测列） | 默认方向 | 单位 |
|---|---|---|---|---|
| 水位 | `#1#` | `water_river_info.z` | 高于 | m |
| 雨量 | `#2#` | `water_rain_info`（列见第 5 章待确认项 1） | 高于 | mm |
| 流量 | `#3#` | `water_river_info.q` | 低于 | m³/s |
| 开度 | `#4#` | `water_gate.open_degree` | 低于 | % |
| 墒情 | `#7#` | `water_soil_data.mten…mhundred`（分层，见待确认项 2） | 低于 | % |

### 4.2 触发判定（含等号，以此为准）

```
alarmdir = '#1#'（高于警戒值触发）：监测值 ≥ threshold → 触发
alarmdir = '#2#'（低于警戒值触发）：监测值 ≤ threshold → 触发
alarmdir 为空：按 4.1 的类型默认方向处理
```

### 4.3 无配置与无效值

- 该站该类型**无阈值行 → 静默跳过**：不产生告警、不打 ERROR/WARN 噪音日志（建议 debug 级或按分钟聚合计数）；
- 无效值（`-999` 设备不存在、`-9991` 设备异常）**不参与比对**（与页面展示口径一致）。

### 4.4 重复告警抑制

- 同站点同类型持续超限，默认 **30 分钟内不重复推送**；数值恢复正常后**重新计数**（再超限立即推送）；
- 抑制时长**做成参数**（建议键 `alarm.suppress-minutes`，默认 30），不写死在代码里。

### 4.5 生效时机

- 每次比对**实时读阈值表**（若加缓存，TTL ≤ 60 秒）；页面编辑保存后下一次比对即用新值，**不需要重启服务或清缓存**。

## 5. 待确认项（需业务确认后固化）

1. **雨量比对字段**：`water_rain_info` 现有 `drp`（时段雨量）、`rainfall1h/3h/6h`、`rainfall_daily`、`pdr`、`dyp`、`pn01`、`pn05` 多列，而阈值表未区分时段——一期建议按 **1 小时雨量** 比对，或按客户口径指定；
2. **墒情比对层深**：`water_soil_data` 为分层数据（`mten`…`mhundred`，10~100cm），需确认比对哪一层（建议 20cm 或按客户口径）；
3. **水质是否纳入阈值**：类型字典当前 5 类（水位/雨量/流量/开度/墒情），未含 `#8#` 水质；如需纳入，本侧加一行字典配置即可；
4. **多值行口径**：周家河、坝上两行 `zvieyb = #1#|#2#` 但只有一个 `threshold`，需确认是否按「该行同时作为水位与雨量阈值」处理（建议先按此口径，后续由平台清理为一行一类型）；
5. **恢复通知**：数值恢复正常时是否需要推送「已恢复」消息（本期未定义）；
6. **告警推送通道与去重键**：推送给谁（平台接口/消息主题）、去重键建议 `site + 类型 + 首次触发时间`。

## 6. 参考 SQL（2026-09-24 实测，只读）

```sql
-- ① 读取某站某类型的阈值（方向与值）：类型必须走 COALESCE 口径
SELECT id, "site", "zvieyb", alarmdir, threshold, remark
FROM "qixiao-apaas".t_auto_hltgq_water_threshold
WHERE "site" = ?
  AND COALESCE(NULLIF("zvieyb", ''), "type", '') LIKE CONCAT('%', '#1#', '%');

-- ② 实测：周家河按上式可读出 threshold = 98.00（zvieyb=#1#|#2#、alarmdir 空 → 按"高于"处理）

-- ③ 测站编码 → 站点档案主键（仅拿到 stcd 时使用；实测 iofhpi 无重复）
SELECT id FROM "qixiao-apaas"."t_auto_hltgq_5nw74_vnqqef" WHERE iofhpi = ?;

-- ④ 数据表 site 命中档案率（本次核对用：水位 34622/34622，雨量 29610/29610，水质 1138/1138）
SELECT count(*) AS rows, count(*) FILTER (WHERE s.id IS NOT NULL) AS hit
FROM "qixiao-apaas".t_auto_hltgq_water_river_info r
LEFT JOIN "qixiao-apaas"."t_auto_hltgq_5nw74_vnqqef" s ON s.id = r.site;

-- ⑤ 各类型站点数（本次核对用：水位 18、雨量 18、流量 135、开度 25、墒情 4）
SELECT count(*) FROM "qixiao-apaas"."t_auto_hltgq_5nw74_vnqqef"
WHERE epjutj LIKE CONCAT('%', '#1#', '%');
```

> **模糊匹配写法强制要求（KingbaseES 实测坑）**：必须写 `LIKE CONCAT('%', ?, '%')`。
> 实测 `LIKE '%' || ? || '%'` 的**绑定参数会静默失效**（退化为匹配全部行：对照实验 `LIKE '%#1#%'` = 18 行，
> `LIKE '%' || '#1#' || '%'` = 183 行），字符串直接拼接同样会把过滤条件丢掉。
> 全库既有 SQL 亦统一使用 `CONCAT`。
