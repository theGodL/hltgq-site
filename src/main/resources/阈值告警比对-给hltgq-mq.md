## 1. 背景与目标

平台已提供「阈值设置」页面，按「站点 + 阈值类型（+ 监测指标 `zb`）」配置单级警戒值（表 `t_auto_hltgq_water_threshold`）。
本文给出 mq 侧数据入库时的**阈值比对口径**，保证「配置了即生效」：

1. 监测数据入库时按 `site + 类型`（多指标类型再加指标列 `zb`）查阈值，无配置**静默跳过**（不报错、无噪音日志）；
2. 按 `alarmdir` 决定触发方向（**含等号**），`alarmdir` 为空按类型默认方向；
3. 同站点同类型持续超限，默认 **30 分钟内不重复告警**（抑制时长做成参数，不写死；抑制窗内如何处理由 mq 侧按自身落库方式决定）；
4. 阈值编辑保存后**下一次比对即用新值**（无需重启服务或清缓存）。

### 2.3 设置侧写入范围与业务规则（2026-09-26 按实现核对）

阈值设置页（`/threshold-setting.html` + `/threshold/*` 接口）对阈值表的写入是**受限的**，mq 读取时可按此判断各列取值的必然性：

| 列 | 页面是否写入 | 说明 |
|---|---|---|
| `site` / `zvieyb` / `zb` / `alarmdir` / `threshold` / `remark` | ✅ 新增时写 | `zb` 仅多指标类型（墒情 `#7#` / 水质 `#8#`）有值，单指标类型为 `null` |
| `id` / `corp_code` / `created_at` / `created_by` / `updated_at` / `updated_by` | ✅ 平台审计列 | `corp_code` 恒为 `hltgq` |
| `alarmdir` / `threshold` / `remark` / `updated_at` / `updated_by` | ✅ 编辑时改 | 站点、类型、指标**锁定不可改**（换指标 = 删除后重新新增） |
| `type` | ❌ 不写 | 历史列，仅读取兜底；页面新增的行恒为 `null` |
| `guarantee` / `num` / `device` | ❌ 不写 | 预留列，恒为 `null` |

**设置侧业务规则**（mq 读取时的隐含前提）：

1. **唯一性**：同「站点 + 类型 + 指标」最多一行——**双层保障**：应用层判重（`LIKE` 子串语义，多值行也算已配置）
   + 数据库唯一索引 `uniq_hltgq_threshold_site_type_zb`（`site` + 类型归一 + `zb` 归一，2026-09-26 建立、只读实证生效）；
   单指标类型指标恒空，即退化为「站点 + 类型」唯一（索引定义与语义边界详见 4.8 三）；
2. **警戒值**：必填且 > 0，落库时统一**保留 2 位小数**（HALF_UP）；
3. **描述**：≤ 500 字，空串按 `null` 落库；
4. **告警方向**：只允许 `#1#` / `#2#`；界面未选时按**指标默认方向**落库（该指标无默认方向则按类型默认方向），故新配置行 `alarmdir` 通常**有值**、为空的多是历史行；
5. **保存即时生效**：接口直写表、无缓存层，mq 下一次比对即读到新值（无需任何通知或刷新动作）。

## 4. 比对规则

### 4.1 类型、数据来源与默认方向

| 类型 | 编码 | 数据来源（实测列） | 取值列选择 | 默认方向 | 单位 |
|---|---|---|---|---|---|
| 水位 | `#1#` | `water_river_info.z` | 固定列 | 高于 | m |
| 雨量 | `#2#` | `water_rain_info.dyp` **差分**（口径见 4.6） | 按 4.6 计算 | 高于 | mm |
| 流量 | `#3#` | `water_river_info.q` | 固定列 | 高于 | m³/s |
| 开度 | `#4#` | `water_gate.open_degree` | 固定列 | 高于 | m |
| 墒情 | `#7#` | `water_soil_data` | **按 `zb` 取列**（`mten`/`mtwenty`/`mthirty`） | 低于 | % |
| 水质 | `#8#` | `water_nmisp_info`（水温在 `pcp_info`） | **按 `zb` 取列**（`nh3n`…`dox`/`wt`） | 高于；溶解氧 `dox` 为**低于** | mg/L（水温 ℃） |

> 水位/雨量/流量/开度这四个单指标类型**一个类型只配一条阈值**——页面上的其他展示口径（水位/闸门页的闸前·闸后水位与 1h 水位涨幅、
> 雨量页的 1h/3h/6h 与历史「累计雨量」、流量/闸门页的累计水量）均**不开放为可配阈值指标**（2026-09-26 已定）：
> 前者属同一物理量的其他位置读数（存于闸门表，河道站无数据），后者属派生统计量（时段雨量、水位涨幅、累计值均单调递增）；
> 这四个类型比对时一律取上表的**固定列**（水位 `z`、流量 `q`、开度 `open_degree`；雨量按 4.6 以 `dyp` 差分计算），新增可配指标以平台发版说明为准。
>
> 「默认方向」仅作平台侧新增阈值时的**初始选中值**与 `alarmdir` 为空的兜底（业主可在界面上切换）；
> 实际判定一律**以行上的 `alarmdir` 为准**，只有 `alarmdir` 为空时才回落到默认方向。

### 4.2 触发判定（含等号，以此为准）

```
alarmdir = '#1#'（高于警戒值触发）：监测值 ≥ threshold → 触发
alarmdir = '#2#'（低于警戒值触发）：监测值 ≤ threshold → 触发
alarmdir 为空：多指标类型取**该指标的默认方向**（溶解氧 `dox`、墒情各层=低于，其余=高于）；
                单指标类型按 4.1 类型默认方向
```

### 4.3 无配置与无效值

- 该站该类型**无阈值行 → 静默跳过**：不产生告警、不打 ERROR/WARN 噪音日志（建议 debug 级或按分钟聚合计数）；
  多指标类型同理：**只比对已配置指标的那些行**，未配置的指标即使超限也不告警（如某站只配了氨氮，则总磷不告警）；
- 无效值（`-999` 设备不存在、`-9991` 设备异常）**不参与比对**（与页面展示口径一致）；
  墒情三层另有物理量程校验：仅 `0 ~ 100`（%）参与比对，**越区间剔除不入库、不比对**（体积含水量百分比上限，实测全库无越区间值，2026-09-26 mq 回执）；
- 单指标类型另以正数守卫挡哨兵（水位 `z > 0`、流量 `q >= 0`、开度 `open_degree >= 0`）；实测现有数据无影响（真实站水位最小值 27.3m，
  仅测试站 `9000000127` 有 17 行 `0`；全库无负值）；若将来有河道站水位降到 `≤ 0`（基准点以下），`> 0` 守卫会静默跳过而不判定“低于”方向告警——
  建议语义改为「哨兵黑名单 + 区间校验」而非单纯正数（健壮性建议，不阻塞）；

### 4.4 重复告警抑制

- 同站点同类型（多指标类型再区分 `zb`）持续超限，默认 **30 分钟内不重复告警**；数值恢复正常后**重新计数**（再超限立即告警）；
- 抑制时长**做成参数**（建议键 `alarm.suppress-minutes`，默认 30），不写死在代码里。

### 4.5 生效时机

- 每次比对**实时读阈值表**（若加缓存，TTL ≤ 60 秒）；页面编辑保存后下一次比对即用新值，**不需要重启服务或清缓存**。

### 4.6 雨量比对口径（2026-09-26 定稿）

雨量是**单指标类型**（`zb` 为空），但比对值不是某一列的原始读数，而是**本水文日累计雨量**：

```
比对值     = 最新记录 DYP − 水文日起点基线 DYP        （负差归 0）
水文日起点 = 当日 08:00（08:00:00 整算当日；当前时刻早于 08:00 时取前一日 08:00）
基线 DYP   = 该站「不晚于水文日起点的最后一条记录」的 DYP 原始读数（**含 08:00 整点行**）
```

与平台侧为**同源口径**（单一实现 `StPptnRServiceImpl#calcCurrentHydroDayRain`，被 `/station-metrics`（核心指标）、
`/gq-daily-rainfall`、`/reservoir-rainfall`、`/reservoir-period-rainfall` 共用；页面「当前降雨量」即此值），mq 侧照此实现：

1. **基线取「不晚于」而非「之前」**：`tm ≤ 水文日起点` 的最后一条（含 08:00 整点行）——08:00 那一行的增量产生于 08:00 之前、归上一水文日，
   故不计入本水文日；若写成 `tm < 08:00`，每个水文日会多算一次报文增量；
2. **不向前回溯**：基线取到哨兵值时**不跳过**继续往前找，否则会把前一水文日的雨量并进本水文日、破坏相邻水文日首尾相接；
3. **负差归 0**：`DYP` 回退（换表 / 复位）按 0 处理（不是负值）；
4. **哨兵值**：链路任一端为 `-9991`（设备异常）→ 该值无效不比对；为 `-999`（设备不存在）→ 视为缺失不比对；
5. **基线 / 最新值缺失**：最新报文停留在水文日起点之前的站，基线与终点同为该行读数、值为 0（语义「08:00 起无降雨增量」），不告警；
6. **阈值语义**：配「雨量 30（高于）」= 「当日 08:00 起累计雨量 ≥ 30mm 告警」，每早 08:00 归零后重新累计；归零会使数值「恢复」
   （进而触发恢复逻辑，属预期，不是漏报/误报）。**注意**：雨量若被业主配成「低于」方向，8:00 归零后必然立即「超限」
   （0 < 阈值）——建议 mq 对「归零后首个报文」不判定低于方向，或与业主确认雨量不开放低于方向；
7. 平台侧**不对 DYP 正向跳变做额外过滤**（只做负差归 0）——mq 侧若额外过滤异常跳变，须单独说明判定阈值与依据，
   避免吞掉真实暴雨（局地强降雨单次报文增量可达十几毫米），**漏报代价远高于一次虚假告警**。
   回执（2026-09-26）：mq 侧护栏为**单次增量 > 5000mm** 才跳过（远高于真实暴雨量级），属 mq 新增、平台无，已在 mq 侧注释注明。

> 历史结论仍成立：`drp` 列在部分站不可靠（花凉亭站恒 0、灌区站归零不准），故一律用 `dyp` 差分；
> `rainfall1h/3h/6h`、`rainfall_daily` 属时段 / 日统计派生列，不作为比对源。

### 4.7 核心指标缓存列（`ccnhtm1` / `ijzsby1`）语义与读取边界（2026-09-26 实测）

本节固化 mq 写入的**站点核心指标缓存列**语义，避免双方再次错认「谁读哪一列」：

- **写入**：`riverInfo` 入库成功后写 `ccnhtm1`（修正后水位，`z > 0` 才写）；`rainInfo` 入库成功后按 4.6 口径写 `ijzsby1`；
  值统一为**四舍五入 2 位小数文本**（如 `"42.59"`、`"0.00"`）；无效值 / 哨兵值不覆盖，保留上次有效值。
- **置 `'0.00'`（语义为「无新数据」，不是真的 0）**：① 时效巡检（每 5 分钟，超「实测上报周期 + 5 分钟」）置 0；
  ② 离线巡检（24h 无任何报文）置 0 并置站点离线——**客户约定：无报文时不展示陈旧值**；历史版本遗留标记为 `'--'`。
- **覆盖边界（实测）**：时效巡检仅对 `epjutj LIKE '#1#%' OR '#2#%'` 的站生效，而写入无类型过滤 →
  类型不含 `#1#` / `#2#` 前缀的站（实测仅虎形潭渡槽 `#3#|#5#` 一例）停报后会在 2h~24h 窗口内保留陈旧值（24h 后由离线巡检兜底）；
  经核查，真正持有实时数值的只有 18 站（水位）/ 11 站（雨量），其余为 `null`（118/119）或 `'0.00'`（56/62）。
  对齐方向（2026-09-26 双方裁定，本轮不修）：将来如需对齐，首选**「置 0 巡检改为有值即纳管」**（去掉类型前缀条件，凡该列有值即纳入时效判定）；
  不宜在**写入侧**加类型判断——已写入的值将不再被刷新，退化为永不过期的死值，比现状更差。
- **站点侧读取边界**：站点侧展示与对外接口读的是**不带 1 的档案列** `ccnhtm` / `ijzsby`（`double precision`，由档案维护方录入，
  193 站中仅 13/16 站有值），与本节缓存列是**两套数据**；站点侧本轮**不改读** `*1` 列 →
  本列的置 0 行为不影响站点侧「站点数据」接口与对外接口；站点侧「实时值」另由 `/station-metrics`
  （水位取 `river_info` 最新 `z`、雨量走 4.6 同源实现）自算提供。

**三、阈值表唯一约束（2026-09-26 站点侧建立，只读实证）**

站点侧已建立「站点 + 类型归一 + 指标归一」唯一索引，mq 侧 `findThreshold` / `findThresholdRows` 的 `LIMIT 1` 取行确定性由此获得**库级保证**：

```sql
CREATE UNIQUE INDEX IF NOT EXISTS uniq_hltgq_threshold_site_type_zb
  ON "qixiao-apaas".t_auto_hltgq_water_threshold
  (
    "site",
    (COALESCE(NULLIF("zvieyb", ''), "type", '')),   -- 类型归一，与 mq 读取同口径
    (COALESCE("zb", ''))                            -- zb 为 NULL 时归一为空串（普通唯一约束对 NULL 不生效，必须包 COALESCE）
  );
```

| 核查项 | 实证结果（2026-09-26 只读） |
|---|---|
| 生效状态 | `indisunique = t`、`indisvalid = t`；定义 = `(site, COALESCE((NULLIF(zvieyb,''))::varchar, type, ''::varchar), COALESCE(zb, ''::varchar))` |
| 空值缝隙 | 本库实测为空串语义（`'' IS NULL` = false）→ 类型全空时归一值落**空串而非 NULL**，不存在「NULL 不参与唯一性」的漏洞 |
| 存量数据 | 3 行 → 3 个归一 key，无重复；亦无「多值行与单值行共享编码」重叠（`#1#\|#3#` 与 `#1#` 并存实测 0 行） |
| 语义边界 | 应用层判重为 `LIKE '%#N#%'` 子串语义（更严：多值行也算已配置）；索引为**精确值**语义（更松）；两者组合下新写入行恒为单值、精确 key 唯一 → 读取确定 |

## 6. 参考 SQL（2026-09-24 实测，只读）

```sql
-- ① 读取某站某类型的阈值（方向与值）：类型必须走 COALESCE 口径；单指标类型不加 zb 条件
SELECT id, "site", "zvieyb", "zb", alarmdir, threshold, remark
FROM "qixiao-apaas".t_auto_hltgq_water_threshold
WHERE "site" = ?
  AND COALESCE(NULLIF("zvieyb", ''), "type", '') LIKE CONCAT('%', '#1#', '%');

-- ② 实测（2026-09-26）：周家河按上式可读出 threshold = 98.00（zvieyb=#1#、alarmdir 空 → 按"高于"处理、zb 为空）

-- ②' 多指标类型（水质）：按「类型 + zb」定位到具体指标那一行
SELECT id, "zb", alarmdir, threshold, remark
FROM "qixiao-apaas".t_auto_hltgq_water_threshold
WHERE "site" = ?
  AND COALESCE(NULLIF("zvieyb", ''), "type", '') LIKE CONCAT('%', '#8#', '%')
  AND "zb" = 'nh3n';     -- 指标编码 = 监测数据表列名

-- ③ 测站编码 → 站点档案主键（仅拿到 stcd 时使用；实测 iofhpi 无重复）
SELECT id FROM "qixiao-apaas"."t_auto_hltgq_5nw74_vnqqef" WHERE iofhpi = ?;

-- ④ 数据表 site 命中档案率（本次核对用：水位 34622/34622，雨量 29610/29610，水质 1138/1138）
SELECT count(*) AS rows, count(*) FILTER (WHERE s.id IS NOT NULL) AS hit
FROM "qixiao-apaas".t_auto_hltgq_water_river_info r
LEFT JOIN "qixiao-apaas"."t_auto_hltgq_5nw74_vnqqef" s ON s.id = r.site;

-- ⑤ 各类型站点数（本次核对用：水位 18、雨量 18、流量 135、开度 25、墒情 4）
SELECT count(*) FROM "qixiao-apaas"."t_auto_hltgq_5nw74_vnqqef"
WHERE epjutj LIKE CONCAT('%', '#1#', '%');

-- ⑥ 雨量（4.6）：水文日起点基线 DYP —— 不晚于 08:00 的最后一条（含 08:00 整点行，不跳过哨兵值）
--    水文日起点 = 该时刻所属水文日的 08:00（8 点日切的标准表达，项目既有写法见 FloodDroughtMapper）
SELECT r.tm, r.dyp FROM "qixiao-apaas".t_auto_hltgq_water_rain_info r
WHERE r.stcd = ? AND r.tm <= date_trunc('day', now() - INTERVAL '8 hours') + INTERVAL '8 hours'
ORDER BY r.tm DESC LIMIT 1;

-- ⑦ 实测复算（2026-09-26 19:06）：花凉亭坝上 3206400007 —— 基线 08:00 行 DYP=19.4、最新 19:00 行 DYP=21.4
--    → 本水文日累计 = 21.4 − 19.4 = 2.0（mm）；联调时该站「当前降雨量」与雨量比对值应同为 2.0
```

> **模糊匹配写法强制要求（KingbaseES 实测坑）**：必须写 `LIKE CONCAT('%', ?, '%')`。
> 实测 `LIKE '%' || ? || '%'` 的**绑定参数会静默失效**（退化为匹配全部行：对照实验 `LIKE '%#1#%'` = 18 行，
> `LIKE '%' || '#1#' || '%'` = 183 行），字符串直接拼接同样会把过滤条件丢掉。
> 全库既有 SQL 亦统一使用 `CONCAT`。

> **时间表达式强制要求（KingbaseES 实测坑，2026-09-26 新增）**：
> 水文日起点**不得**写 `CURRENT_DATE + TIME '08:00'`——实测该表达式不返回时间戳，而是**无报错地得到 `0`**；
> 用它去比较会**永远取到最新一行当基线 → 雨量增量恒为 0 → 雨量阈值全程静默不告警**（比 CONCAT 坑更隐蔽）。
> 也不得用 `||` 拼时间字符串：KingbaseES 下 `'a' || 'b'` 会按布尔 OR 解释，报 `cannot cast type boolean to timestamp`。
> 统一写法：① **应用层算好水文日起点、以绑定参数传入**（推荐，与平台 Java 实现同思路）；
> ② 必须在 SQL 内计算时，用 `date_trunc('day', t - INTERVAL '8 hours') + INTERVAL '8 hours'`（实测 = 当前水文日起点，项目既有写法）。
