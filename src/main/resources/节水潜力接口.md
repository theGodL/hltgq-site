# 节水潜力测算接口（/water-saving-potential）

> 页面：`static/water-saving-potential.html`（01 基础数据 + 02 分行业测算 + 03 分析结果——结果指标由前端按记录数值实时计算，不入库）
> 数据表：`"qixiao-apaas"."t_auto_hltgq_water_saving_potential`（业主 2026-09-12 平台建表）
> 鉴权：与其他接口一致（请求头 `X-Session-Id` / `Authorization` 或 Cookie `sessionId`）

## 1. 接口一览

| 接口 | 方法 | 说明 |
|------|------|------|
| `/water-saving-potential/record` | GET | 读取指定「年度 + 分析范围」的测算记录（页面回显） |
| `/water-saving-potential/record` | POST | 保存测算记录（upsert：存在即整行覆盖，不存在即新增） |

> 一行记录 = 一个「年度 + 分析范围」的测算；数值单位统一 **万m³**。

---

## 2. GET /water-saving-potential/record — 读取记录

**请求参数**

| 参数 | 必填 | 类型 | 说明 |
|------|------|------|------|
| year | 是 | int | 年度（如 `2026`，允许 2000~2100） |
| scope | 是 | string | 分析范围：`#1#` 全灌区 / `#2#` 太湖县 / `#3#` 望江县 / `#4#` 宿松县 / `#5#` 怀宁县 |

**响应**：`{"record": {…} | null}`——无记录时 `record` 为 null（前端按空表单处理，读取失败/无记录均有稳定 JSON body）。

| 字段 | 类型 | 说明 |
|------|------|------|
| year | int | 年度（如 2026） |
| scope / scopeName | string | 范围编码 / 中文名（如 `#2#` / `太湖县`） |
| totalResources | number\|null | 水资源总量(万m³) |
| supplyCapacity | number\|null | 工程年供水能力(万m³) |
| availableSupply | number\|null | 年可供水量(万m³) |
| basisFile | string\|null | 基础数据依据（平台附件引用原文，原样返回） |
| basisFileUrl | string\|null | 附件预览地址（文件服务解析，失败为 null——见「5」） |
| agriBaseline / agriTarget | number\|null | 农业基准需水量 / 节水后需水量(万m³) |
| indBaseline / indTarget | number\|null | 工业基准需水量 / 节水后需水量(万m³) |
| lifeBaseline / lifeTarget | number\|null | 生活基准需水量 / 节水后需水量(万m³) |
| calcBasis | string\|null | 节水测算依据（多行文本） |
| measures | string\|null | 拟采取措施（多行文本） |
| status / statusName | string | 状态编码 / 中文名（`#1#` 草稿 / `#2#` 已测算） |

> 结果指标（节水总量/节水率/供需缺口/农业节水占比）**不在响应内**，由前端按上述数值实时计算。

**示例**

```json

    "year": 2026,
    "scope": "#2#",
    "scopeName": "太湖县",

    "supplyCapacity": 222,
    "availableSupply": 333,
    "basisFile": null,
    "basisFileUrl": null,
    "agriBaseline": 444,
    "agriTarget": 555,
    "indBaseline": 666,
    "indTarget": 777,
    "lifeBaseline": 888,
    "lifeTarget": 999,
    "calcBasis": null,
    "measures": null,
    "status": "#2#",
    "statusName": "已测算"
  }
}
```

## 3. POST /water-saving-potential/record — 保存记录

**请求体**（`application/json`）

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| year | 是 | int | 年度（2000~2100） |
| scope | 是 | string | 分析范围 `#1#`~`#5#`（白名单校验，非法返回 400） |
| totalResources | 否 | number | 水资源总量(万m³) |
| supplyCapacity | 否 | number | 工程年供水能力(万m³) |
| availableSupply | 否 | number | 年可供水量(万m³) |
| basisFile | 否 | string | 基础数据依据（平台附件引用原文） |
| agriBaseline / agriTarget | 否 | number | 农业基准/节水后需水量(万m³) |
| indBaseline / indTarget | 否 | number | 工业基准/节水后需水量(万m³) |
| lifeBaseline / lifeTarget | 否 | number | 生活基准/节水后需水量(万m³) |
| calcBasis | 否 | string | 节水测算依据（多行文本） |
| measures | 否 | string | 拟采取措施（多行文本） |
| status | 否 | string | 状态：缺省 `#2#` 已测算；可选 `#1#` 草稿 |

**保存规则（upsert）**

- 同一「年度 + 分析范围」已存在 → **整行覆盖**（数值留空/未传 = 存 null，可清空已存值）；
- 不存在 → 新增一行（短 ID 主键、`corp_code=hltgq`、created_by/updated_by 取当前登录人）；
- 年度写入规范化为该年 1 月 1 日 00:00:00（查询按年份区间匹配，兼容平台控件写入的任意日期值）；
- 同键多行（平台人工重复录入）时，读取取 `updated_at` 最新一行。

**响应**：`{"ok": true, "id": "记录id"}`；参数非法返回 400 `{"message": "…"}`。

**示例**

```json
{
  "year": 2026,
  "scope": "#2#",
  "totalResources": 111,
  "supplyCapacity": 222,
  "availableSupply": 333,
  "agriBaseline": 444,
  "agriTarget": 555,
  "indBaseline": 666,
  "indTarget": 777,
  "lifeBaseline": 888,
  "lifeTarget": 999,
  "calcBasis": "",
  "measures": "",
  "status": "#2#"
}
```

## 4. 数据表口径

| 项 | 说明 |
|----|------|
| 表 | `"qixiao-apaas"."t_auto_hltgq_water_saving_potential` |
| 年度列 | 物理列名为 `"year"`（保留字，SQL 全程加引号处理），存时间戳 |
| 范围/状态 | 平台编码 `#N#` 形式，接口响应同时附中文名 |
| 更新方式 | 整行全列覆盖（含 null），非增量更新 |
| 结果指标 | 前端计算，不入库 |

---

## 5. 附件回显（basisFileUrl）

- 平台附件引用为**单个文件 id** 时，后端经企效文件服务（`GET /file/m/{fileId}`）换签名预览地址（24h 有效），需携带当前登录会话；
- 以下情形降级为 `null`（仅日志告警，不阻断读取，前端可仅展示引用原文或文件名）：引用为空 / 复合引用（多附件、JSON 数组）/ 无会话 / 文件服务不可用；
- 引用值本身已是 `http(s)://` 完整地址时原样返回。

## 6. 前端需配合的调整（待联调确认后实施）

1. **读取回显**：页面加载/切换「年度 + 分析范围」后调 `GET /record`，`record` 非空时填充 01 基础数据、02 分行业输入框、测算依据/措施、状态；`record=null` 时按空表单处理。
2. **保存提交**：页面「保存/测算」按钮调 `POST /record`，提交当前表单值（含年度、范围、状态），成功后提示并保留当前页编辑态；`ok=true` 即保存成功。
3. **附件字段**：页面当前无附件控件（03 区块为结果展示），需按产品稿补「基础数据依据」上传/展示控件；上传通道待平台提供（当前后端仅实现回显）。
4. **结果指标**：节水总量 = Σ(基准−节水后)；节水率 = 节水总量 ÷ Σ基准；供需缺口 = 年可供水量 − Σ节水后；农业占比 = 农业节水 ÷ 节水总量——维持前端现有计算逻辑即可。
