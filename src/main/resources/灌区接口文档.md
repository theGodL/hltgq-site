# 灌区监测接口文档

> 面向前端，生产环境路径统一加 `/hltgq-site` 前缀
> 涵盖灌区雨量、灌区水位、水库雨情、站点综合指标、水库水情、闸门监测、流量监测、墒情监测、水质监测、登录鉴权、流量计算参数、站点信息维护等模块

## 一、灌区雨量分页

每站点仅返回最新一条，含 1h / 3h / 6h 三档降雨增量。

### 请求

```
GET /st-pptn-r/gq-rainfall
```

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:--:|--------|------|
| page | long | 否 | 1 | 页码 |
| size | long | 否 | 20 | 每页条数 |
| stcd | String | 否 | — | 站点编号（筛选单个站点） |
| startTime | String | 否 | — | 监测起始时间 `yyyy-MM-dd HH:mm:ss` |
| endTime | String | 否 | — | 监测截止时间 `yyyy-MM-dd HH:mm:ss` |

### 调用示例

```
/hltgq-site/st-pptn-r/gq-rainfall?page=1&size=20
/hltgq-site/st-pptn-r/gq-rainfall?stcd=9000000137&startTime=2026-07-20+08:00:00&endTime=2026-07-30+07:59:59
```

### 响应

```json
{
  "total": 15,
  "current": 1,
  "size": 20,
  "pages": 1,
  "records": [
    {
      "stcd": "9000000137",
      "id": "uuid-xxx",
      "stnm": "某某雨量站",
      "tm": "2026-07-29T10:00:00",
      "drp": 125.5,
      "dyp": 28.3,
      "rain1h": 2.3,
      "rain3h": 5.1,
      "rain6h": 8.7,
      "isOnline": true
    }
  ]
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| total | long | 总记录数 |
| current | long | 当前页码 |
| size | long | 每页条数 |
| pages | long | 总页数 |
| records | Array | 数据列表 |

**records[].字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| stcd | String | 站点编号 |
| id | String | 站点 UUID |
| stnm | String | 站点名称 |
| tm | String | 最新监测时间（ISO 格式 `yyyy-MM-ddTHH:mm:ss`） |
| drp | Number | 时段降雨量 (mm) |
| dyp | Number | 日降雨量 (mm) |
| rain1h | Number | 近 1 小时降雨量 (mm)。`null` 仅当 DRP 为 null；无历史记录时返回当前 DRP 值 |
| rain3h | Number | 近 3 小时降雨量 (mm)。`null` 仅当 DRP 为 null；无历史记录时返回当前 DRP 值 |
| rain6h | Number | 近 6 小时降雨量 (mm)。`null` 仅当 DRP 为 null；无历史记录时返回当前 DRP 值 |
| isOnline | Boolean | 在线状态：`true` 在线 / `false` 断联。非水库站按最新采集时间断联判定（MQTT 站 30 分钟、RabbitMQ 站 70 分钟无更新判离线）；水库站按站点表 zebpsu 状态（`#1#` 在线 / `#2#` 离线）；无监测时间或状态未知默认在线 |

### 计算规则

```
rainNh = max(0, 当前DRP − N小时前最后一条DRP)
```

- 传感器归零（DRP 骤降）时增量自动取 0
- 无 N 小时前历史记录时，取当前 DRP 作为增量（SQL 使用 `COALESCE(..., 0)` 兜底，prev 默认 0）
- 当前 DRP 为 `null` 时，增量返回 `null`

## 二、灌区雨量变化图表

单站点小时级增量 + 累计雨量，**前端双 Y 轴图表直接消费**。

### 请求

```
GET /st-pptn-r/gq-rainfall-chart
```

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:--:|--------|------|
| stcd | String | **是** | — | 站点编号 |
| startTime | String | 否 | 7 天前整点 | 起始时间 `yyyy-MM-dd HH:mm:ss` |
| endTime | String | 否 | 当前整点小时 | 截止时间 `yyyy-MM-dd HH:mm:ss` |

### 调用示例

```
/hltgq-site/st-pptn-r/gq-rainfall-chart?stcd=9000000137
/hltgq-site/st-pptn-r/gq-rainfall-chart?stcd=9000000137&startTime=2026-07-20+08:00:00&endTime=2026-07-25+08:00:00
```

### 响应

```json
{
  "stcd": "9000000137",
  "stnm": "某某雨量站",
  "startTime": "2026-07-22T08:00:00",
  "endTime": "2026-07-29T08:00:00",
  "hours": [
    { "hour": "2026-07-22 08:00", "rainfall": 0.0, "cumulative": 0.0 },
    { "hour": "2026-07-22 09:00", "rainfall": 2.5, "cumulative": 2.5 },
    { "hour": "2026-07-22 10:00", "rainfall": 3.1, "cumulative": 5.6 },
    { "hour": "2026-07-22 11:00", "rainfall": 0.0, "cumulative": 5.6 },
    { "hour": "2026-07-22 12:00", "rainfall": 0.8, "cumulative": 6.4 }
  ]
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| stcd | String | 站点编号 |
| stnm | String | 站点名称 |
| startTime | String | 查询起始时间（ISO 格式 `yyyy-MM-ddTHH:mm:ss`） |
| endTime | String | 查询截止时间（ISO 格式 `yyyy-MM-ddTHH:mm:ss`） |
| hours | Array | 小时级数据点（**严格 1h 步长，无缺失**） |

**hours[].字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| hour | String | 小时标签 `yyyy-MM-dd HH:00` |
| rainfall | Number | 该小时内的增量雨量 (mm)。无数据时 = 0 |
| cumulative | Number | 从 startTime 到该小时的**累计**雨量 (mm) |

### 前端图表用法

```javascript
const resp = await fetch(`/hltgq-site/st-pptn-r/gq-rainfall-chart?stcd=${stcd}`);
const { hours } = await resp.json();

// ECharts 双 Y 轴
chart.setOption({
  xAxis:  { data: hours.map(h => h.hour.slice(5, 16)) },       // 只保留 "MM-DD HH:00"
  yAxis:  [
    { name: '实时雨量 (mm)' },
    { name: '累计雨量 (mm)' }
  ],
  series: [
    { name: '实时雨量', type: 'bar',  yAxisIndex: 0, data: hours.map(h => h.rainfall) },
    { name: '累计雨量', type: 'line', yAxisIndex: 1, data: hours.map(h => h.cumulative) }
  ]
});
```

### 计算规则

```
服务端内部逻辑（前端无需关心）：
1. 向前扩展 2h 查询原始 DRP 记录（确保首小时有基线对比）
2. 按时间排序后遍历：
    第一条记录  →  inc = 0
    后续记录    →  inc = max(0, cur.DRP − prev.DRP)
3. 将增量归属到小时桶（HH:00），同一小时的多次上报累加
4. 生成完整小时序列（从 startTime 到 endTime，步长固定 1h）
5. 累计 = 逐小时 rainfall 累加
```

### 边界场景

| 场景 | 表现 |
|------|------|
| 某小时无设备上报 | `rainfall = 0`，`cumulative` 保持上小时值 |
| 传感器归零（DRP 骤降） | 归零时增量 = 0，归零后继续正常计算 |
| 整段时间无数据 | 返回空 `hours: []` |
| 数据断档后恢复 | 恢复后第一条 inc=0，后续恢复累加 |

| startTime | String | 查询起始时间（ISO 格式 `yyyy-MM-ddTHH:mm:ss`） |
| endTime | String | 查询截止时间（ISO 格式 `yyyy-MM-ddTHH:mm:ss`） |
| hours | Array | 小时级数据点（**严格 1h 步长，无缺失**） |

**hours[].字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| hour | String | 小时标签 `yyyy-MM-dd HH:00` |
| waterLevel | Number | 该小时水位值 (m)。无数据时为 `null` |
| change | Number | 该小时水位变化 (cm)。正值=上涨，负值=下降。首小时为 `null` |

### 前端图表用法

```javascript
const resp = await fetch(`/hltgq-site/irrigation-water-level/chart?stcd=${stcd}`);
const { hours } = await resp.json();

// ECharts 双 Y 轴
chart.setOption({
  xAxis:  { data: hours.map(h => h.hour.slice(5, 16)) },
  yAxis: [
    { name: '水位 (m)' },
    { name: '水位变化 (cm)' }
  ],
  series: [
    { name: '水位', type: 'line', yAxisIndex: 0, data: hours.map(h => h.waterLevel) },
    { name: '水位变化', type: 'bar', yAxisIndex: 1, data: hours.map(h => h.change) }
  ]
});
```

### 计算规则

```
服务端内部逻辑（前端无需关心）：
1. 向前扩展 1h 查询原始水位记录（确保首小时有基线对比）
2. 按时间排序后，按整点小时聚合：同一小时内取最新一条水位值
3. 水位变化 (cm) = (当前小时水位 − 前一小时水位) × 100
4. 生成完整小时序列（从 startTime 到 endTime，步长固定 1h）
5. 当前小时无数据时，水位值为 null，前一小时水位值继续延续（保证后续变化计算连续）
```

### 边界场景

| 场景 | 表现 |
|------|------|
| 某小时无设备上报 | `waterLevel = null`，`change = null`，前值延续 |
| 首小时 | `change = null`（无前值可对比） |
| 整段时间无数据 | `waterLevel` 和 `change` 均为 `null`，小时序列始终完整返回 |
| 水位为 0 | 正常显示 `waterLevel = 0` |

### 水位趋势图表

> 单站点小时级水位曲线（无 1h 涨幅，纯水位值），默认近七天，支持按日期区间查询。用于水位监测-详情趋势图。

**请求方式**：`GET`

**请求路径**：`/irrigation-water-level/trend`

#### 请求参数

| 参数 | 必填 | 格式 | 说明 |
|------|:--:|------|------|
| stcd | **是** | String | 站点编号 |
| startTime | 否 | `yyyy-MM-dd HH:mm:ss` | 起始时间，默认 7 天前整点 |
| endTime | 否 | `yyyy-MM-dd HH:mm:ss` | 截止时间，默认当前整点 |

#### 调用示例

```
/hltgq-site/irrigation-water-level/trend?stcd=9000000137
/hltgq-site/irrigation-water-level/trend?stcd=9000000137&startTime=2026-08-10+00:00:00&endTime=2026-08-17+00:00:00
```

#### 响应格式

```json
{
  "stcd": "9000000137",
  "stnm": "某某水位站",
  "startTime": "2026-08-10T00:00:00",
  "endTime": "2026-08-17T00:00:00",
  "hours": [
    { "hour": "2026-08-16 17:00", "waterLevel": 12.35 },
    { "hour": "2026-08-16 18:00", "waterLevel": null }
  ]
}
```

#### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| stcd | String | 站点编号 |
| stnm | String | 站点名称（无匹配数据时回退为 stcd） |
| startTime | String | 查询起始时间（ISO 格式） |
| endTime | String | 查询截止时间（ISO 格式） |
| hours | Array | 小时级数据点（**严格 1h 步长，无缺失**） |

**hours[].字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| hour | String | 小时标签 `yyyy-MM-dd HH:00` |
| waterLevel | Number | 该小时水位值 (m)，截断 2 位小数。无数据时为 `null`（前端图表断线） |

#### 计算规则

1. 查询原始水位记录，按整点小时聚合：同一小时内取最新一条水位值
2. `-9991`（设备异常）、`-999`（设备不存在）视为缺失，不参与聚合
3. 生成完整小时序列（从 startTime 到 endTime，步长固定 1h），无数据小时为 `null`

#### 与 /chart 的区别

| | `/chart` | `/trend` |
|------|:--:|:--:|
| 附加列 | 含 1h 水位变化 `change`（双 Y 轴） | 纯水位曲线（单 Y 轴） |
| 用途 | 水位变化统计分析 | 水位趋势详情图 |

### 灌区日雨情（双视角）

> 非水库站点的「实时雨情 + 日雨情」双视角接口，结构完全复用[六、水库实时雨情 / 水库日雨情](#六水库实时雨情--水库日雨情)：

## 六、水库实时雨情 / 水库日雨情

**同一接口，两种视角**：
- `stations[]` → **实时雨情视角**：各站点最新观测快照（`latestTm` = 实际观测时间，`latestDrp` = 当前 DRP），用于实时监控卡片
- `days[]` → **日雨情视角**：按水文日（8:00 切分）聚合的逐日雨量透视表，用于日雨情报表

12 个固定水库站点。**后端一次计算，前端直接渲染**。

### 请求

```
GET /st-pptn-r/reservoir-rainfall
```

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:--:|--------|------|
| startDate | String | 否 | 当天 | 起始日期 `yyyy-MM-dd` |
| endDate | String | 否 | 当天 | 截止日期 `yyyy-MM-dd` |

### 调用示例

```
/hltgq-site/st-pptn-r/reservoir-rainfall
/hltgq-site/st-pptn-r/reservoir-rainfall?startDate=2026-07-20&endDate=2026-07-29
```

### 响应

```json
{
  "stations": [
    {
      "stcd": "3206400001",
      "stnm": "周家河",
      "id": "uuid-xxx",
      "latestTm": "2026-07-29T10:25:00",
      "latestDrp": 125.5
    }
  ],
  "days": [
    {
      "day": "2026-07-28 08:00:00",
      "values": {
        "3206400001": 5.2,
        "3206400002": 3.1,
        "3206400005": 0.0
      },
      "avg": 0.69
    },
    {
      "day": "2026-07-29 08:00:00",
      "values": {
        "3206400001": 2.8,
        "3206400002": 0.0,
        "3206400005": 1.5
      },
      "avg": 0.36
    }
  ]
}
```

### 字段说明

**stations[] — 实时雨情视角：12 个固定站点最新状态（用于实时监控卡片）**

| 字段 | 类型 | 说明 |
|------|------|------|
| stcd | String | 站点编号（12 个固定站，顺序固定） |
| stnm | String | 站点名称（无匹配数据时为 `null`） |
| id | String | 站点 UUID |
| latestTm | String | 该站点最新观测时间（**实际记录时间**，ISO 格式 `yyyy-MM-ddTHH:mm:ss`，未经水文日调整）。无数据时返回**当前时间**，表示该时刻已检查但无测量值 |
| latestDrp | Number | 该站点最新 DRP 累计值 (mm)，无数据为 `null` |

**days[] — 日雨情视角：逐日雨量透视表（水文日维度，用于日雨情报表）**

| 字段 | 类型 | 说明 |
|------|------|------|
| day | String | 水文日标签 `yyyy-MM-dd 08:00:00` |
| values | Object | 键为 stcd，值为日降雨量 (mm)。无数据站点 = 0，**12 个 key 完整不缺** |
| avg | Number | 该水文日 12 站平均值 (mm)，保留 2 位小数 |

### 前端透视表用法

> `stations` 渲染实时卡片；`days` 渲染透视表。平均值已由后端计算返回。

```javascript
const resp = await fetch('/hltgq-site/st-pptn-r/reservoir-rainfall?startDate=2026-07-20&endDate=2026-07-25');
const { stations, days } = await resp.json();

// 表头：监测日期 + 12 站名称 + 平均值
const thead = `<tr><th>监测日期</th>${stations.map(s => `<th>${s.stnm}</th>`).join('')}<th>平均值 (mm)</th></tr>`;

// 表体：逐行渲染
const tbody = days.map(d => {
  const cells = stations.map(s => {
    const v = d.values[s.stcd] || 0;
    return `<td>${v > 0 ? v.toFixed(1) : ''}</td>`;
  });
  return `<tr><td>${d.day}</td>${cells.join('')}<td>${d.avg.toFixed(2)}</td></tr>`;
}).join('');
```

### 计算规则

完全对齐 `hydro-monitor.html` 的 `buildPptnPivot` 逻辑：

```
1. 向前后各扩展 1 天查询，确保水文日边界（8:00）完整
2. 按站点分组 → 时间升序 → 遍历计算增量
    第一条记录  →  inc = 0
    后续记录    →  inc = max(0, cur.DYP − prev.DYP)
3. 增量归属到水文日桶（getHydroDayLabel 规则）：
    标签 D 区间为 (D-1日 08:00:00, D日 08:00:00]（左开右闭）；
    8:00:00 整点归当日标签，08:00:01 起才归次日标签
4. 同一水文日内同一站点的所有增量累加 → 日降雨量
```

### 水文日切分示意

```
 (2026-07-28 08:00:00 ────── 2026-07-29 08:00:00]  →  标签 "2026-07-29 08:00:00"
 (2026-07-29 08:00:00 ────── 2026-07-30 08:00:00]  →  标签 "2026-07-30 08:00:00"
 8:00:00 整点属于当日标签（如 07-29 08:00:00 归标签 07-29），08:00:01 起归次日
```

### 区间筛选行序列（startDate/endDate 语义）

```
1. 默认当天（startDate == endDate，即不传或传同一天）：返回该日单标签行（最近完整水文日；实时雨情视角与日雨情共用同一响应，依赖 days[0]）
2. 区间筛选（startDate < endDate）：返回 (startDate 08:00, endDate 08:00] 内的完整水文日标签
   → 标签日期 = startDate+1 … endDate（例 startDate=2026-09-06&endDate=2026-09-09 → 仅 09-07/09-08/09-09 三个标签）
   startDate 当日标签代表 (startDate-1 08:00, startDate 08:00]，属起始日前一日尾巴，不返回
```

## 七、水库时段雨情

12 个固定水库站点，按**可配时间间隔**聚合时段雨量，列含每站降雨量 + 平均值。

### 请求

```
GET /st-pptn-r/reservoir-period-rainfall
```

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:--:|--------|------|
| startDate | String | 否 | 当天 | 起始日期 `yyyy-MM-dd` |
| endDate | String | 否 | 当天 | 截止日期 `yyyy-MM-dd` |
| interval | int | 否 | 60 | 时间间隔（分钟），可选 15/30/45/60/120/180/240/360/480/720/1440 |

### 调用示例

```
/hltgq-site/st-pptn-r/reservoir-period-rainfall?startDate=2026-07-28&endDate=2026-07-29&interval=60
/hltgq-site/st-pptn-r/reservoir-period-rainfall?interval=180
```

### 响应

```json
{
  "stations": [
    { "stcd": "3206400001", "stnm": "周家河", ... }
  ],
  "buckets": [
    {
      "time": "2026-07-28 08:00",
      "values": { "3206400001": 1.2, "3206400002": 0.5, ... },
      "avg": 0.38
    },
    {
      "time": "2026-07-28 09:00",
      "values": { "3206400001": 2.3, "3206400002": 0.0, ... },
      "avg": 0.62
    }
  ]
}
```

### 字段说明

**stations[]** — 12 个站点信息，与 [六、水库实时雨情](#六水库实时雨情) 相同

**buckets[] — 时段桶数据：**

| 字段 | 类型 | 说明 |
|------|------|------|
| time | String | 时段标签 `yyyy-MM-dd HH:mm`（interval=60 时为整点） |
| values | Object | 键为 stcd，值为该时段降雨量 (mm)。12 个 key 完整不缺 |
| avg | Number | 该时段 12 站平均值 (mm)，保留 2 位小数 |

### 与日雨情的区别

| | 日雨情 `reservoir-rainfall` | 时段雨情 `reservoir-period-rainfall` |
|------|:--:|:--:|
| 时间维度 | **日**（水文日 08:00 切分） | **可配间隔**（分钟级） |
| 桶标签 | `yyyy-MM-dd 08:00:00` | `yyyy-MM-dd HH:mm` |
| 行平均值 | ✅ `avg` 字段 | ✅ `avg` 字段 |
| 参数 | startDate/endDate | startDate/endDate/**interval** |

### 间隔取值与桶覆盖范围

```
区间筛选（startDate < endDate）：时段窗口 (startDate 08:00, endDate 08:00]
  interval=60  → 从 startDate 08:00 起每小时一个桶（首桶标签 startDate 09:00），到 endDate 08:00 为止
                如 startDate=07-28, endDate=07-29 → 07-28 09:00 ~ 07-29 08:00 共 24 个桶
                如 startDate=09-06, endDate=09-09 → 09-06 09:00 ~ 09-09 08:00 共 72 个桶
  interval=180 → 同上，但每 3 小时一个桶（同区间共 8 个桶/天）

单日/默认（startDate == endDate，即不传或传同一天）：窗口为最近完整水文日
  (startDate-1 08:00, startDate 08:00]，共 24 个 60min 桶（interval=180 时 8 个桶）
```

### 计算规则

完全对齐 `hydro-monitor.html` 的 `buildPeriodPivot` + `floorToInterval` 逻辑：

```
1. 向前后各扩展 1 天查询
2. 按站点分组 → 时间升序 → 遍历计算增量（与实时雨情相同）
    第一条  →  inc = 0
    后续    →  inc = max(0, cur.DYP − prev.DYP)
3. floorToInterval（水文日对齐）：先回退 1 秒（与 getHydroDayLabel 口径一致，8:00:00 整点归当日标签），
   再以当日 08:00 为桶起点按 interval 向下取整（如 08:35 → interval=60 时归属 08:00 桶）
   效果：8:00:00 整点增量归 07:00 时段桶不再丢失，时段合计与日雨情一致
4. 同一时段桶内同一站点的所有增量累加
```

| 字段 | 类型 | 说明 |

```
4. 逐月按旬汇总每日雨量 → 得到旬累计，跨月区间每个月份输出上/中/下旬 3 行
5. 12 站平均值 = Σ(各站旬累计) / 12
```

| waterLevel | Number | 水位值 (m)。无数据时为 `null` |
| change | Number | 1h 水位涨幅 (cm)。正值=上涨，负值=下降。首小时为 `null` |

### 计算规则

与 `/irrigation-water-level/chart` 完全一致：

```
1. 向前扩展 1h 查询原始水位记录（确保首小时有基线对比）
2. 按整点小时聚合：同一小时内取最新一条水位值
3. 水位变化 (cm) = (当前小时水位 − 前一小时水位) × 100
4. 生成完整小时序列（严格 1h 步长，无缺失），再内存分页
5. 当前小时无数据时，水位值为 null，前值延续
```

### 与 /chart 的区别

| | `/chart` | `/history` |
|------|:--:|:--:|
| 用途 | ECharts 曲线图（双 Y 轴） | 数据表格（分页浏览） |
| 分页 | ❌ 全部返回 | ✅ 按 page/size 分页 |
| 包裹信息 | 含 stcd / stnm / startTime / endTime | 仅分页元信息 + records |
| 排序 | 时间升序 | 时间升序 |

| q | Number | 流量 (m³/s)，取 t8 记录 Q 字段，无记录为 `null` |
| w | Number | 蓄水量（百万 m³）。暂无数据源，恒为 `null`，前端显示 `-` |
| maxz | Number | 当年最高水位 (m)：当年 1 月 1 日以来（截至查询日）最大值 |
| maxTm | String | 当年最高水位出现时间（ISO 格式，同高取最早），当年无数据为 `null` |
| dsflz | Number | 设防水位 (m)，阈值表 guarantee，未配置为 `null` |

### 计算规则

- 8 点/20 点水位取「整点之前的最后一条采集」（业主口径）：即在 (整点-1h, 整点] 左开右闭区间内 z 非空的最新一条记录，整点之后的采集归下一整点。一旦进入下一时段，该整点数值固定不再变动（日时段水情表的槽位取值遵循同一口径）
- 覆盖站点固定为：周家河 `3206400001`、花凉亭坝下 `320640000A`、花凉亭坝上 `3206400007`

| lat | Number | 站点纬度（站点表 bviiio_y） |

**holes[].字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| gateNo | String | 闸孔编号，如 `"1"`、`"2"`、`"3"` |
| openDegree | Number | 闸门开度 (m)。前端展示为"开度1"、"开度2"… |
| status | String | 闸门状态，如 `开启` / `关闭` / `停止` |

### 数据来源

| 数据表 | 说明 |
|------|------|
| `t_auto_hltgq_water_gate` | 闸门实时监测数据 |
| `t_auto_hltgq_5nw74_vnqqef` | 站点信息表（关联取站点名称） |

### 查询逻辑

1. 使用 PostgreSQL `DISTINCT ON (site, gate_no)` 对每个站点的每个闸孔取 `tm` 最新的一条记录
2. 支持可选的 `startTime` / `endTime` 参数限定时间范围（仅在该范围内的数据参与查询）
3. 服务层按 `site` 分组，将同一站点的多个闸孔聚合成一条 `GateMonitoringVO` 记录
4. 闸前/闸后水位取各闸孔中最新有值记录的 `up_z` / `down_z`（同一时刻各孔水位原则上一致）
5. **流量同批次取值**：瞬时流量与累计流量取流量表 `t_auto_hltgq_water_wt_nfo` 中**最新监测时刻 ±20 分钟窗口**内的最新一条（报文按批次入库，同一批次流量时间应与开度/水位接近），窗口外无记录则该批次无流量数据
6. **流量联动隐藏**：最新监测时刻（各孔最新时间）的开度、闸前/闸后水位全部无有效值（`null`/`-999`/`-9991`/`0`）时，瞬时流量 `q` 与累计流量 `cumulativeFlow` 一并返回 `null`，与开度/水位展示保持一致，避免客户误判设备数据采集不准
7. **单位换算**：累计流量自库中 m³ 换算为万m³（÷ 10000，3 位小数截断）后返回；瞬时流量 `q` 保持 m³/s 不换算

| tm | String | 小时桶起始时间（ISO 格式，`date_trunc('hour', tm)`） |
| site | String | 站点 UUID |
| gateNo | String | 闸孔编号（`'0'` 归一化为 `'1'`） |
| openDegree | Number | 该小时平均开度 (m)，`-999`/`-9991` 已过滤 |

#### 聚合规则

1. 闸门表按小时桶（`date_trunc('hour', tm)`）+ 闸孔分组，开度/水位取 `AVG`（`-9991` 异常值、`-999` 不存在值已过滤）
2. 流量表按站点 + 小时桶预聚合后 `LEFT JOIN`，同一小时无流量数据时 q 为 `null`

> 数据来源：`t_auto_hltgq_water_soil_data`（site 站点 / device 设备 / stcd 测站编码 / tm 监测时间 / mten~mhundred 8 个深度含水量。2026-09 起墒情独立建表：原墒情/水质共表 `nmisp_info` 拆分为 soil_data 墒情 + nmisp_info 水质，mq `soilData` 报文写入本表）。
>
> 全模块通用口径：
> - 含水量为 `-9991` 表示设备异常，后端**透传**，前端展示 `--`
> - 含水量为 `-999` 表示设备不存在，后端**透传**，前端不展示
> - 含水量为 `null` 表示无数据，前端展示 `-`
> - 站点标识 = `COALESCE(stcd, site)`：有测站编码用编码，无编码站点回退 site UUID（筛选参数两种都能传）

### 20.1 墒情监测-最新数据（首页）

> 每个站点返回最新一条记录，包含站点名称、站点编号、监测时间及 10/20/30/40/50/60/80/100 厘米含水量。支持按站点（多选）和监测日期筛选。

**请求方式**：`GET`

**请求路径**：`/soil-moisture/monitoring`

#### 请求参数

| 参数 | 必填 | 格式 | 说明 |
|------|:--:|------|------|
| stcds | 否 | String | 站点编号，多个逗号分隔。不传=全部墒情站点 |
| date | 否 | `yyyy-MM-dd` | 监测日期。选中日期过滤 `[date 00:00:00, date+1天 00:00:00)` 左闭右开区间 |

#### 调用示例

```
/hltgq-site/soil-moisture/monitoring
/hltgq-site/soil-moisture/monitoring?stcds=9000000101,9000000102&date=2026-08-16
```

#### 响应格式

```json
[
  {
    "stcd": "9000000101",
    "site": "9000000101",
    "stnm": "某某墒情站",
    "tm": "2026-08-16T17:30:00",
    "vol": 12.5,
    "mten": 23.45,
    "mtwenty": 24.12,
    "mthirty": 25.30,
    "mforty": 26.05,
    "mfifty": 26.80,
    "msixty": 27.42,
    "meighty": 28.10,
    "mhundred": 28.66
  }
]
```

#### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| stcd | String | 测站编码（无编码站点为 `null`，前端留空显示） |
| site | String | 站点标识（stcd 或 site UUID，无编号站点查询/筛选用，不用于展示） |
| stnm | String | 站点名称 |
| tm | String | 监测时间（ISO 格式） |
| vol | Number | 电压 (V)，取关联电压表 `t_auto_hltgq_water_vol_info` 在筛选时间范围内最新值，无数据为 `null`（**仅 monitoring 返回，history 不返回**） |
| mten | Number | 10 厘米土壤含水量 |
| mtwenty | Number | 20 厘米土壤含水量 |
| mthirty | Number | 30 厘米土壤含水量 |
| mforty | Number | 40 厘米土壤含水量 |
| mfifty | Number | 50 厘米土壤含水量 |
| msixty | Number | 60 厘米土壤含水量 |
| meighty | Number | 80 厘米土壤含水量 |
| mhundred | Number | 100 厘米土壤含水量 |

#### 查询逻辑

1. `DISTINCT ON (站点标识)` 每站点取 `tm` 最新的一条记录
2. 含水量截断 2 位小数；`-9991`/`-999` 透传，前端分别展示 `--`/不展示
3. 电压 vol 通过 `LEFT JOIN` 电压表 `t_auto_hltgq_water_vol_info`（`vol.site = 墒情表.site`，均为站点 UUID）取筛选时间范围内最新一条；无电压数据时 vol 为 `null`

## 二十一、登录鉴权

> 供前端页面登录鉴权使用：校验 key/secret 后调用外部登录服务获取 sessionId。

**请求方式**：`POST`

**请求路径**：`/auth/login`

### 请求体（JSON）

| 字段 | 必填 | 类型 | 说明 |
|------|:--:|------|------|
| key | **是** | String | 接口调用密钥，需与服务端配置 `auth.api.key` 一致 |
| secret | **是** | String | 接口调用密钥，需与服务端配置 `auth.api.secret` 一致 |

```json
{
  "key": "xxx",
  "secret": "yyy"
}
```

### 响应格式

```json
{
  "success": true,
  "message": "登录成功",
  "sessionId": "abc123..."
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| success | Boolean | 是否登录成功 |
| message | String | 提示信息（失败原因见此处） |
| sessionId | String | 会话 ID（仅成功时有值，由外部登录服务返回） |

### 登录流程

1. 校验 key / secret 是否与服务端配置一致，不一致直接返回失败
2. 调用外部安全码接口（`qx-apaas-uc/user/securityImg`）获取 key，再调用外部登录接口（`qx-apaas-auth/server/auth/login`）获取 sessionId
3. 任一步骤异常均返回 `success=false` 及对应提示

### 当前登录人（`/auth/current-user`）

**请求方式**：`GET`

**请求路径**：`/auth/current-user`

无参数；按当前会话（`Authorization` 头 / `sessionId` Cookie）返回登录人信息，供页面按权限开放操作入口。

```json
{
  "userId": "uuid-user",
  "corpCode": "hltgq",
  "superAdmin": "false",
  "admin": true,
  "loginName": "zhangsan"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| userId | String | 用户主键（t_apaas_uc_user.id） |
| corpCode | String | 企业编码 |
| superAdmin | String | 平台会话中的超管标记（`"true"` / `"1"` 视为超管） |
| admin | Boolean | **是否管理员**（后端统一判定）：平台超管，或命中管理员角色编码 `hltgq_default_admin` / `administra`；前端据此开放编辑入口，与后端 `@RequireAdmin` 校验口径一致 |
| loginName | String | 登录名（三维 SSO 使用） |

> 判定链路：会话超管标记 → Redis 角色缓存 → 查库兜底（角色指派关系表）；结果本地缓存 5 分钟，角色刚调整后有最长 5 分钟延迟。
> 管理员角色编码清单维护于 `RolePermissionService.ADMIN_ROLE_CODES`（单一维护点）。

## 二十六、站点排序

监测页面（水位监测 / 闸门监测 / 流量监测 / 雨量监测 / 墒情监测）「站点排序」抽屉的顺序读写接口：顺序按**监测类型**维度存储，保存后对该类型的所有接口与页面生效（站点下拉、监测列表、图表站点轴等）。

> 站点标识：排序表 `site` 存**站点管理主键**（站点档案表 `t_auto_hltgq_5nw74_vnqqef.id`），与各类型接口用于展示 / 筛选的 `code`（测站编码或业务表 `site`）不是同一列；清单接口已把两者对应好，前端只需回传 `siteId`。
>
> 排序口径：已配置站点按配置序号升序在前；未配置站点保持各接口原有默认顺序、排在已配置站点之后（新接入站点自动排末尾）；该类型从未保存过顺序时，各接口按原默认顺序返回，展示不受影响。
>
> 默认顺序一致性：26.1 清单（抽屉 / 站点下拉）与各类型页面的监测列表**共用同一默认顺序**，未保存过排序时两处顺序也完全一致——闸门（`gate`）为置前站点 `渠首电站防洪闸 → 渠首进水闸 → 双庙湖节制闸 → 南山寺节制闸` 在前、其余站点按名称排序（置前清单见 `StationSiteService.GATE_PRIORITY_STATIONS`，闸门监测列表与站点清单同源）；流量（`flow`）、墒情（`moisture`）、雨量（`rainfall`）均为站点标识（测站编码或站点 UUID）升序。水位（`waterLevel`）另计：清单按测站编码升序（三水情站即 3206400001 周家河 → 3206400007 花凉亭坝上 → 320640000A 花凉亭坝下，与水情表默认序相同）；水情简报 / 多年同期水情为另一业主口径（周家河 > 花凉亭坝下 > 花凉亭坝上），未配置时与该顺序不同（两个业主口径本身不同），保存一次后统一按保存顺序。
>
> `metric_type` 落库值为平台单选枚举编码：`#1#` 水位（水位监测页「花凉亭水库」Tab 的水情各类表共用：河道水情表、水库水情表、日时段水情表、水情简报、多年同期水情）、`#2#` 雨量（灌区站与花凉亭水库站共用一条序列）、`#3#` 流量、`#4#` 闸门（闸门监测页与水位监测页灌区面板共用）、`#5#` 墒情。

#### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| siteId | String | 站点管理主键（= 排序表 `site`，保存时原样回传）；站点档案中无该站记录时为 `null` |

### 26.2 站点排序保存（整表覆盖）

**请求方式**：`POST`

**请求路径**：`/station-sort`

#### 请求参数（JSON Body）

| 参数 | 必填 | 格式 | 说明 |
|------|:--:|------|------|
| type | **是** | String | 监测类型，同 26.1 |
| siteIds | **是** | Array\<String\> | 站点管理主键数组，**数组顺序即展示顺序**（取 26.1 的 `siteId`；`sortable=false` 的站点不必提交） |

#### 调用示例

```json
POST /hltgq-site/station-sort
{
  "type": "gate",
  "siteIds": ["CAYQ739MiBWMg9gQvyi", "dByBR1Xdze8shnRGAw9"]
}
```

#### 响应格式

```json
{ "success": true, "count": 2 }
```

#### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| success | Boolean | 是否保存成功 |
| count | Integer | 落库站点数（= 该类型可排序站点总数，含后端自动追加的未提交站点） |

#### 保存逻辑

1. 白名单校验：不属于该类型的站点管理主键（含无档案的站点）忽略（前端传错或历史脏数据不落库）
2. 提交顺序去重后按序落库（`sort_no` 从 1 递增）；未提交的站点按默认顺序追加在后，因此**一次保存即固化该类型全量顺序**（新接入站点默认排末尾，下次打开抽屉可见并可调整）
3. 整表覆盖：同一 `metric_type` 旧配置先清除再写入（事务内），配置缓存同步失效，保存后立即生效
4. 校验失败（类型不存在、该类型下无站点）返回 400，错误信息含原因
5. 水位序列（`waterLevel`）供水情类接口消费时，后端按站点档案 `iofhpi` 把排序表的主键反解为数据表测站编码再排序（配置中缺编码的站点自动跳过，其余站点不丢）；顺序解析结果发生变化（含服务重启后首次读取）打一条日志：`水位站展示顺序按站点排序配置生效：解析 N 站（未解析 M），SQL 顺序=…`，便于联调核对站点编码解析是否正确

#### 页面入口

| 页面 | type | 按钮位置 |
|------|------|------|
| 水位监测 `irrigation-water-level.html` | `waterLevel` + `gate`（一个抽屉两组） | Tab 栏同行最右侧；抽屉内分组：水位站组 → `waterLevel`，闸站组 → `gate`（保存时分别落库） |
| 闸门监测 `gate-monitor-page.html` | `gate` | Tab 栏同行最右侧 |
| 流量监测 `flow-monitor.html` | `flow` | Tab 栏同行最右侧 |
| 雨量监测 `rainfall-monitor.html` | `rainfall` | Tab 栏同行最右侧（抽屉含花凉亭水库站，两处共用一条序列） |
| 墒情监测 `soil-moisture-monitor.html` | `moisture` | Tab 栏同行最右侧 |

> 抽屉列「序号 + 站点名称」两列，支持鼠标拖拽与序号输入两种排序方式（可混用）；无档案的站点置灰显示「不参与排序」；保存后自动重载当前页站点下拉与列表。
>
> 水位监测页的抽屉为**一个按钮、两组清单**：组标题「水位站（水情）」= `waterLevel` 序列（河道/水库水情表、日时段水情表、水情简报、多年同期水情共用），「闸站（闸前/闸后水位）」= `gate` 序列（与闸门监测页共用）；两组顺序各自独立（组内序号各自从 1 起、拖拽限在组内），保存时按组分别提交，互不影响；该按钮不再随 Tab 切换排序对象。
>
> 「站点排序」按钮与页面 Tab 同款卡片样式（白底、8px 圆角、同款阴影与字号，hover 变蓝），并固定在同一行的最右侧（不紧贴最后一个 Tab）。

### 取数与字段口径

1. 列表导出**当前筛选条件下的全量数据**（非当前页）：水库水情 / 河道水情等走既有全量导出接口；服务端分页的列表（灌区实时雨情）与各类详情历史按分页接口循环拉取（`size=500`，最多 40 页），避免超长区间卡死浏览器。
2. 详情导出弹窗勾选字段，**导出表头只包含勾选字段**；闸门详情可勾选开度 / 闸前水位 / 闸后水位 / 瞬时流量 / 累计水量，多类型按监测时间并集合并为一张宽表（同一时刻的不同类型数据合并在同一行）。
3. 取值口径与页面展示一致：`-9991`（设备异常）→ `--`，`-999`（设备不存在）→ 空白，`null` / 空串 → 空白；纯数字长码（站点编号等）按文本写入（避免 Excel 科学计数法）；数值列保留数值类型（便于 Excel 求和）。
4. 详情导出的取数区间随页面日期筛选（如闸门 / 流量 / 墒情 / 水质 / 雨量详情与水位监测-花凉亭灌区详情的日期选择）；文件名格式为 `{页面或站点}_{区间}.xlsx`。
5. 水位监测-花凉亭灌区列表「详情」弹窗为**历史水位**（复用 `/gate-monitor/history?type=waterLevel`，仅闸前 / 闸后水位，无开度与流量），弹窗内字段为监测日期 / 闸前水位 (m) / 闸后水位 (m)，默认近 7 天、分页展示。
