# 灌区用水接口（/water-user 等七组）

> 页面：灌区用水管理七页 —— 用水户管理（`static/water-user-list.html`）、用水定额标准（`static/water-quota-list.html`）、用水计划管理（`static/water-plan-list.html`）、需水上报（`static/water-demand-report.html`）、调度方案（`static/water-dispatch-plan.html`）、调度记录（`static/water-dispatch-record.html`）、水费账单（`static/water-bill.html`）
> 鉴权：与其他接口一致（请求头 `X-Session-Id` 或 Cookie `sessionId`，完整前缀见平台登录态）
> 生产环境路径统一加 `/hltgq-site` 前缀，下文调用示例均已带前缀

## 接口总览

| 分组 | 路径前缀 | 接口数 | 说明 |
|------|----------|--------|------|
| 用水户管理 | `/water-user` | 7 | 户档案 + 关联闸口组 + 计算策略 + 统计周期 |
| 用水定额标准 | `/water-quota` | 7 | 作物 × 灌溉方式（字典下拉）定额库（m³/亩） |
| 用水计划管理 | `/water-plan` | 14 | 年度 / 月度 / 旬度计划编制、生效、归档、作废 + 实测进度 / 保证率 |
| 需水上报 | `/water-demand` | 10 | 上报 → 审核（通过 / 驳回）闭环 |
| 调度方案 | `/water-dispatch` | 11 | 闸口 × 时段的放水载体；配额闭环 + 计费锁 |
| 调度记录 | `/water-dispatch-record` | 7 | 闸口操作留痕（不参与水量与费用计算） |
| 水费账单 | `/water-bill` | 15 | 手工台账（列表 / 统计 / 用水户下拉 / 保存 / 删除 / 出账）/ 户方案明细 / 账单（列表 / 统计 / 详情）/ 方案出账 / 收款 |

## 〇、通用约定

### 0.1 分页响应结构

所有 `/page` 接口返回统一结构：

```json
{
  "total": 36,
  "page": 1,
  "size": 20,
  "pages": 2,
  "records": [ ... ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| total | number | 满足筛选条件的总行数 |
| page | number | 当前页码（请求参数收敛 1 ~ 100000） |
| size | number | 每页行数（请求参数收敛 1 ~ 100，默认 20） |
| pages | number | 总页数 = ⌈total / size⌉ |
| records | array | 当前页数据行 |

### 0.2 错误应答格式

| HTTP | 场景 | 应答体 |
|------|------|--------|
| 400 | 参数校验失败（含状态机非法流转） | `{"message":"…具体原因…"}` |
| 401 | 未登录 / 会话过期 | `{"code":401,"message":"未登录"}` |
| 409 | 唯一约束冲突（编号撞号重试耗尽 / 名称并发重复） | `{"message":"编号生成冲突，请重试"}`、`{"message":"用水户名称已存在，请刷新列表后重试"}`、`{"message":"计划名称已存在，请刷新列表后重试"}` |
| 409（兜底） | 其他唯一约束冲突 | `{"message":"数据已存在或不满足约束，请刷新后重试"}` |

**前端建议**：所有写操作失败时优先展示应答体 `message` 字段（后端已给出可直接上屏的中文文案）。

### 0.3 数量口径（重点）

| 页面分组 | 接口对外单位 | 库内单位 |
|----------|--------------|----------|
| 用水户 / 定额 / 用水计划（三页） | **m³** | m³ |
| 需水上报 / 调度方案 / 水费账单（四页面） | **万m³** | m³ |

- **例外（手工台账）**：`/water-bill/ledger/records`、`/water-bill/ledger/save`、`/water-bill/ledger/bill` 三个接口的数量字段为 **m³（2 位小数）**——手工台账按「用水量（m³）× 单价（元/m³）」计费，与界面上填写的单位一致；账单接口仍按万m³ 输出。

- **四页面写入**：请求体数量按 **万m³（≤2 位小数）** 提交，后端 ×10000 转 m³ 落库；**读出**统一 ÷10000 输出，保留 **4 位小数**（前端按自身展示口径取位）。
- **计划明细** `planWater` 按 **m³（2 位小数）** 提交（前端以万m³ 录入时自行 ×10000 换算），响应 `totalWater` 等同样为 m³。
- **用水户年度计划水量** `annualPlanWater`（档案字段）：写入按 **万m³（≤2 位小数）** 提交、后端 ×10000 转 m³ 落库（不传 / 0 视为未设定）；**读出为 m³（2 位）**，前端 ÷10000 按万m³ 展示。
- 金额一律 **元**（2 位小数）；水价 **元/m³**（3 位小数）；灌溉面积 **亩**（2 位小数）。

### 0.4 状态码体系（筛选参数传什么）

| 字典 | 库内码 | 前端码 | 取值 |
|------|--------|--------|------|
| 用水类型 | `#1#`~`#4#` | 同库内码 | #1# 农业 / #2# 工业 / #3# 生活 / #4# 生态 |
| 计算策略 | `#1#`/`#2#` | 同库内码 | #1# 指定闸口累加 / #2# 闸口差额计量 |
| 统计周期 | `#1#`~`#3#` | month/quarter/year | #1# 月度 / #2# 季度 / #3# 年度 |
| 用水户状态 | `#1#`/`#2#` | 同库内码 | #1# 正常 / #2# 停用 |
| 计划类型 | `#1#`~`#3#` | 同库内码 | #1# 年度 / #2# 月度 / #3# 旬度 |
| 计划状态 | `#1#`~`#4#` | 同库内码 | #1# 编制中 / #2# 已生效 / #3# 已归档 / #4# 已作废 |
| 需水审核状态 | `#1#`~`#3#` | **wait/pass/reject** | #1# 待审核 / #2# 已通过 / #3# 已驳回 |
| 调度执行状态 | `#1#`~`#4#` | **pending/running/done/canceled** | #1# 待执行 / #2# 执行中 / #3# 已完成 / #4# 已取消 |
| 记录操作类型 | `#1#`~`#3#` | **up/down/adjust** | #1# 闸门提升 / #2# 闸门下降 / #3# 流量调整 |
| 账单状态 | `#1#`/`#2#` | **generated/paid** | #1# 已生成 / #2# 已缴清 |

**规则**：前三页（用水户 / 定额 / 计划）筛选参数传**库内码原值**（如 `status=#1#`，URL 编码为 `%231%23`）；四页面（需水 / 调度 / 账单）筛选传**前端英文码**。任一接口的**响应**字段均按各自页面的对外码输出（响应中同时提供 `xxxName` 中文名），且 `meta` 接口返回的字典项 `value` 即为应交回筛选参数的形态。

### 0.5 编号规则（全部由后端自动生成，不可填写）

| 实体 | 编号格式 | 示例 |
|------|----------|------|
| 用水户 | `YH` + 3 位序号（自动生成，**不可修改**） | `YH001` |
| 用水计划 | `YJ` + 3 位序号（自动生成，不可改） | `YJ012` |
| 需水上报 | `XS` + 4 位序号 | `XS0015` |
| 调度方案 | `DD` + 4 位序号 | `DD0008` |
| 水费账单 | `SF` + 期间码 + `-` + 户号 + 4 位序号 | `SF202610-YH0010003`（期间码：2026-10 → `202610`；2026-Q3 → `2026Q3`；2026 → `2026`） |
| 手工用水台账 | `TZ` + 期间码 + `-` + 户号 + 4 位序号 | `TZ202610-YH0010001`（期间码同上；编辑不重编号） |

> 编号由后端 MAX+1 生成、唯一索引兜底并发；撞号时后端自动重试（最多 3 次），最终失败返回 409「编号生成冲突，请重试」。
> 用水户编号在新增 / 编辑表单中**只读展示**（新增保存后生成、编辑恒保持原编号），提交体无需传 `userNo`（传了也会被忽略）。

### 0.6 分期 key（水费口径）

调度方案按其**执行时段起**所在日期 + 所属用水户的**统计周期**推导分期 key：

| 统计周期 | 分期 key | 中文标签 |
|----------|----------|----------|
| 月度 | `2026-10` | 2026年10月 |
| 季度 | `2026-Q3` | 2026年第3季度 |
| 年度 | `2026` | 2026年度 |

出账按 **(用水户 × 分期 key)** 分组拆分多张账单（1 账单 : N 方案）；手工台账出账为 **1 台账 : 1 账单**（账期直接取台账填写的分期 key）。

### 0.7 规则文件版本（rulesVersion，三页面同源机制）

用水户 / 定额 / 计划三页面的 `meta` 接口均返回 `rulesVersion`（后端读取 `static/lib/rules.json` 的 `rules_version`）。前端加载 `static/lib/rules.js`（内含同名版本号）后比对：

- **一致** → 正常；**不一致** → 页面顶部常驻黄条提示 + 控制台告警（多为浏览器缓存了旧版 rules.js，强制刷新 Ctrl+F5 即可）；后端未返回时跳过比对。
- 规则值（万m³ 换算基数 10000、存储 2 位 / 展示 1 位、周期公式、编号前缀等）由 rules.js 与 rules.json 成对维护，仅改其一即为不同源。

### 1.4 GET /water-user/gates — 该用水户关联闸口下拉

**请求参数**

| 参数 | 必填 | 类型 | 说明 |
|------|------|------|------|
| userId | 是 | string | 用水户 id（不存在 400「用水户不存在」） |

**响应**：数组（该户关联闸口组，结构同 1.1 `gates`）

```json
[{"id": "8Kx2…", "name": "南干渠进水闸"}]
```

> 按闸口 id 回查站档补全 `name`，**输出顺序为配置顺序**（差额 DIFF：主闸口在前、扣减闸口随后）。户**未配置关联闸口 / 配置解析失败时返回空数组**（前端据此提示先去用水户管理配置关联闸口）。供调度方案编制「调度闸口」下拉收敛（选定用水户后调用），可选范围与保存校验（闸口须属该户关联闸口组）同口径。
>
> **调度闸口下拉的唯一数据源**：不管是调度方案页的新增/编辑，还是需水上报页的「编制方案」弹窗，**都调本接口（带 `userId`）**，不要拿 1.1 `meta.gates`（那是给用水户配闸用的全量候选池）当业务表单下拉——否则现象就是“闸口没按用水户限制”，选到非法闸口后提交才被 400「调度闸口不属于该用水户的关联闸口组」拦下。未选用水户时下拉置空并提示先选户。

### 1.5 POST /water-user/create — 新增

**请求体**（`Content-Type: application/json`）

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| name | 是 | string | 名称，≤100 字，全局唯一 |
| userType | 是 | string | 用水类型（库内码 `#1#`~`#4#`） |
| status | 否 | string | 状态（`#1#` 正常 / `#2#` 停用）；不传默认 `#1#` |
| contactUserId | 是 | string | 联系人用户 id（从 `meta.contacts` 下拉池选择；**后端按 id 回查固化姓名/手机号快照，不信任前端传入**；不存在 400「联系人不存在，请重新选择」） |
| contactName | 否 | string | 联系人姓名（快照回传；仅编辑未换人时生效，新增传参被回查值覆盖） |
| contactPhone | 否 | string | 联系电话（快照回传；仅编辑未换人时生效，新增由后端按联系人回查手机号） |
| irrigationArea | 条件 | number | 灌溉面积（亩，>0，≤2 位小数）；**农业 / 生态必填**，工业 / 生活可空 |
| lng / lat | 否 | number | 位置经度（-180 ~ 180）/ 纬度（-90 ~ 90），≤6 位小数 |
| annualPlanWater | 否 | number | 年度计划水量（**万m³**，≤2 位小数；后端 ×10000 转 m³ 落库；不传 / 0 视为未设定） |
| waterPrice | 是 | number | 水价（元/m³，>0，≤3 位小数） |
| calcMode | 是 | string | 计算策略（`#1#` 累加 / `#2#` 差额） |
| gateConfig | 是 | object | 关联闸口（结构须与 calcMode 一致，见下） |
| settleCycle | 是 | string | 统计周期（`#1#`/`#2#`/`#3#`） |
| remark | 否 | string | 备注，≤200 字 |

**gateConfig 结构**

```json
// 累加（calcMode = #1#）
{"mode": "SUM", "gates": [{"id": "8Kx2…", "name": "南干渠进水闸"}]}

// 差额（calcMode = #2#）
{"mode": "DIFF", "main": {"id": "8Kx2…", "name": "主闸"}, "deduct": [{"id": "9Yt3…", "name": "扣减闸"}]}
```

- 结构必须与 `calcMode` 匹配：SUM 须 `gates` ≥1 个；DIFF 须 `main` 必填、`deduct` ≥1 个，且**主闸口不得同时作为扣减闸口**。
- `name` 前端可传占位（如空串）；**后端按 id 回查站档固化名称快照**，不信任前端名称；id 不存在/非闸站则报 400「关联闸口不存在，请重新选择」。
- **差额读数校验（DIFF 专属）**：保存时以闸口最新累计流量读数校验「主闸口读数 − 扣减闸口读数合计 ≤ 0 禁止保存」，400 文案如「差额策略保存失败：主闸口读数（X m³）未大于扣减闸口读数合计（Y m³），请检查闸口选择或待流量数据更新后重试」；主闸口或任一扣减闸口**无读数（哨兵/无数据）时跳过校验**，保存不被流量数据阻塞。

**调用示例**


> 页面：`static/water-plan-list.html`。计划 = 按周期（年度 / 月度 / 旬度）编制的一批「用水户 × 定额」明细行，总水量 = 明细计划水量之和；生效后作为调度方案的关联与配额依据。

| need | number | 应供量（**m³**）：**本年度**已通过申请 `amount` 之和 |
| actual | number | 已有计量（**m³**）：**本年度**逐条申请按户级计量实测供水量之和（不可计量条目不贡献，计入 `missing`） |
| missing | number | 待补计量条数（申请时段缺失或非法 / 用水户无有效闸口配置 / 区间计量不可得） |
| count | number | **本年度**已通过申请总条数 |
| overlap | boolean | **同一户**存在两条及以上本年度已通过申请时段**严格相交**（半开区间 `[起,止)`）时为 true；**相邻共用边界不算重叠**（如 1/2—1/15 与 1/15—1/25） |

**年度归集口径**：申请按**需水开始日期（`startDate`）所属年份**归入该年度。**跨年申请本期不拆分，整条归入开始日期所属年度**——因此跨年申请不能严格代表该自然年度内实际发生的用水量，此为控制改动范围采用的简化规则，后续如需按自然年精确拆分再行扩展。分子（`actual`）、分母（`need`）**共用同一批本年度已通过申请**。

**逐条申请实测口径**：以申请时段 **半开区间 `startDate 00:00 ~ endDate 00:00`**（结束日期为下一条申请的起点，**不计入本日**放量）调用**户级区间计量**（`WaterUsageMeter.userInterval`，按该户闸口规则累加或扣减，与账单出账同源）。

**前端四态展示**（优先级从高到低）：

| 条件 | 展示 |
|------|------|
| `need = 0` | 「暂无审核通过需水」 |
| `overlap = true` | 「申请时段重叠，待核对」（重叠申请不能直接相加，需人工核对） |
| `missing > 0` | 「待补计量数据」（缺读数不能认定为零供水） |
| 其他 | `actual ÷ need × 100%`（保留 2 位小数） |

**脚注文案**：`应供 {need÷10000} 万m³ · 已有计量 {actual÷10000} 万m³ · {missing} 条待补`（万m³ 保留 1 位）。

### 3.9 PUT /water-plan/update — 编辑（两态两规则）

**请求参数**：`id`（必填）

**编制中（全量替换）**：请求体同新增；名称 / 类型 / 周期 / 备注 / 明细全部可改（名称/同户唯一校验同新增）。

**已生效（受限编辑）**：
- `items` 行数必须与现有一致，每行必传 `id` + `planWater` + `overrideReason`；
- 名称 / 类型 / 周期 / 用水户 / 灌溉面积 / 适用定额**锁定**——传了且与现值不同即 400（文案如「已生效计划不可更换用水户」「已生效计划不可修改适用定额」等）；
- **主表备注可单独修改**；
- 改后重算总水量；**双级守恒校验**（前后端一致拦截）：
  - **计划级**：若计划已有调度下达（scheduledQty > 0），改后总水量不得低于已调度水量；
  - **户级**：单行计划水量不得低于该用水户已下达（未取消）调度方案合计，否则 400「第 N 行：计划水量（X 万m³）不能低于该用水户已下达调度方案合计（Y 万m³）」（约束依据见 0.6 调度配额闭环）。

**已归档 / 已作废**：400「已归档 / 已作废计划不可编辑」。

**响应**：更新后的计划详情。

### 3.11 GET /water-plan/conflict-check — 生效校验只读预览

生效前调用（只读），前端据 `blocked` / `warnings` 渲染拦截/确认弹窗；`activate` 事务内以同一校验函数最终裁决。

**三层校验规则**

| 层 | 条件 | 结果 | 文案形态 |
|----|------|------|----------|
| ① 明细完备 | 无明细行，或某行计划水量 ≤ 0 | **block** | `计划至少需要 1 条明细`、`第 N 行（户名）：计划水量必须大于 0` |
| ② 同类型周期重叠 | 与另一**已生效**同类型计划周期重叠 | **block** | `与 YJ###（计划名称）周期重叠` |
| ③ 年度基准弱约束 | 月度/旬度计划某户（月度合计 + 本次）超出该户**档案「年度计划水量」**（用水户 `annualPlanWater`，见 0.3/1.5；为 0 或缺失时不触发） | **warn 不拦截** | `{户名}：月度 / 旬度合计将超出年度计划 X.X 万m³（年度基准 Y.Y 万m³）` |

### 5.0 状态机与操作矩阵

```
待执行 pending ──start──▶ 执行中 running ──done──▶ 已完成 done
      │                        │
      └────────cancel──────────┴──▶ 已取消 canceled（不占配额、不参与出账）
```

| 操作 | 待执行 | 执行中 | 已完成 | 已取消 | 附加条件 |
|------|--------|--------|--------|--------|----------|
| 编辑 update（全字段） | ✔ | ✘ | ✘ | ✘ | 且未计费 |
| 调整 adjust（水量/时段/备注） | ✔ | ✔ | ✔ | ✘ | 且未计费；已完成方案也可调整（水费页「编辑水量」） |
| 开始执行 / 完成 / 取消 | start / cancel | done / cancel | — | — | 取消且未计费 |
| 删除 delete | ✔ | ✔ | ✔ | ✔ | **未计费即可，不限执行态** |
| 出账（水费页） | ✔ | ✔ | ✔ | ✘ | 未计费 |

> **计费锁**：方案一旦被账单挂接（`billId` 非空），编辑 / 取消 / 删除均被拦截，文案「该方案已计费，请先删除关联账单后再…」；先删账单恢复未计费后可再操作。

### 5.0.1 配额闭环（关联计划时）

关联「已生效」用水计划且选择了具体户/闸口后，下达量受**该计划该户计划水量**约束：

```
已下达合计（未取消，排除自身） + 本次 planAmount ≤ 该户在该计划中的计划水量合计
```

超限 400：`超出计划配额：该户关联计划水量 X.X 万m³，已下达 Y.Y 万m³，本次下达 Z.Z 万m³`。校验在事务内 `FOR UPDATE` 锁计划行防并发；创建 / 编辑 / 调整 / 取消 / 删除后自动回写计划的 `scheduledQty`（未取消方案合计）。

## 七、水费账单（/water-bill）

> 页面：`static/water-bill.html`。四个视图共用一组接口：**① 用水台账**（手工台账，一行一笔水量）/ledger/records（+ 统计条 /ledger/stat、用水户下拉 /ledger/users、保存 /ledger/save、删除 /ledger/delete、出账 /ledger/bill）、**② 户方案明细**（单户逐方案）/user-plans（+ 调度方案的 adjust 编辑水量）、**③ 账单列表** /page（+ 顶部统计条 /stats）、**④ 账单详情**（方案快照）/detail；写操作：**方案出账** /bills/create、**确认收款** /bills/pay、**删除账单** /bills/delete。旧的按户归集台账 `/ledger` 仍保留（汇总视图使用，§7.5）。数量对外单位：手工台账接口为 **m³**，其余为 **万m³**；金额元。

### 7.0 计费模型速览

- **出账单元**：① 手工台账（1 台账 : 1 账单，金额 = 用水量 × 单价，2 位小数）；② 一批调度方案（未取消、未计费）→ 按 *(用水户 × 分期 key)* 分组 → 每组一张账单（1 账单 : N 方案）。
- **计入水量**：方案出账时每方案按「该闸口在 [执行时段起, 止] 的实测累计流量」实时计量；差额策略下扣减闸口结果取**负**参与合计（`sign` 字段标明）。
- **净计入拦截**：方案分组内净计入水量 ≤ 0 不可出账。
- **金额**：`quantity(m³) × 水价(元/m³)`，保留 2 位；账单生成时固化水价与水量**快照**（方案 `billed_qty` 打标 / 台账取录入值），之后台账展示取快照、不随流量变化。
- **双向挂接**：手工台账出账后账单 `ledger_id` 反向留痕、台账 `bill_id` 正向挂接；方案出账 `ledger_id` 为空。
- **编辑 / 删除限制**：手工台账已出账禁改禁删（须先删除关联账单）。
- **账单删除**：清空方案挂接（`billId`/快照清空 → 恢复未计费实时计量）与手工台账挂接（恢复未出账可重新出账），均可重新出账。

### 7.7 POST /water-bill/bills/create — 出账

**请求体**：调度方案 id 的 **JSON 数组**（`Content-Type: application/json`）。

```
POST /hltgq-site/water-bill/bills/create
Content-Type: application/json

["d1…", "d2…", "d3…"]
```

> 分批 / 按户 / 按分期出账均走本接口，差异仅是所选方案集合：按 *(用水户 × 分期 key)* 自动分组拆分为多张账单。

**响应**

```json
{
  "success": true,
  "count": 2,
  "bills": [ { "...WaterBillVO（含 plans 详情），见 7.2/7.4..." } ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| success | boolean | 恒 true |
| count | number | 本次生成账单张数 |
| bills | array | 新生成的账单（含方案明细快照），可直接跳转详情/回显 |

**失败文案（400，前端直接展示）**

- `请选择要出账的调度方案`（空数组）
- `部分调度方案不存在，请刷新后重试`
- `方案 DD#### 已取消，不可出账`
- `方案 DD#### 已计费（账单 SF…），不可重复出账`
- `用水户 X 未配置统计周期，无法出账`
- `用水户 X 未配置关联闸口，无法出账`（户档案 gate_config 缺失或结构不合 SUM/DIFF 规范）
- `方案 DD#### 不可出账：{不可得原因}（时段 {起} ~ {止}，闸口 {闸口名}）`——原因取值：
  `执行时段内该闸口无流量记录` / `执行时段内该闸口无有效累计流量` / `执行时段不正确，无法计量`（详见 8.1）
- `方案 DD#### 计入水量为 0 或负值（N m³），请核对流量数据`
- `用水户 X {2026年10月} 净计入水量为 Z.Z 万m³（≤0），不可出账，请核对各闸口流量数据`
- `用水户 X 未配置有效水价，无法出账`
- `方案 DD#### 已被其他出账操作占用，请刷新后重试`（并发抢标）

**失败文案（400）**：`请选择用水户` / `结算周期不正确` / `结算周期与结算年份/月份不匹配` / `用水量必须大于 0` / `单价必须大于 0` / `金额须不少于 0.01 元，请核对用水量与单价` / `用水户 X 已停用，无法新增台账` / `用水台账不存在` / `该台账已出账（账单 SF…），不可修改` / `台账状态已变更，请刷新后重试`（并发）。

### 7.14 DELETE /water-bill/ledger/delete — 删除手工台账

**请求参数**：`id`（是）。**响应**：`{"success": true}`

**说明**：仅未出账可删；已出账 400「该台账已出账（账单 SF…），请先删除关联账单」。

### 7.15 POST /water-bill/ledger/bill — 手工台账出账（1 台账 : 1 账单）

**请求参数**：`id`（是，台账 id）。**响应**：新账单 `WaterBillVO`（含 `ledgerNo`，`plans` 为空）。

**说明**：账单数量 / 单价 / 金额取台账快照，账期按台账 `cycleKey` 推导；账单回填 `ledger_id`、台账回填 `bill_id`。并发重复出账 400「该台账已被其他出账操作占用，请刷新后重试」；账单编号冲突自动重试 3 次（`uk_water_bill_no`）。

## 八、计量与金额口径（水费数值来源）

前端若需在页面上解释/复核账单数值，按以下口径：

### 8.1 单闸口区间累计（实时计量）

```
计入水量(闸口) = ttf(执行时段窗口内末条有效行) − prevTtf(起点前最近一条有效行)
```

- **有效行** = `ttf` 非空且不为哨兵值：窗口内与起点前两端同口径过滤（否则末行缺报会被误判“无数据”，起点前命中哨兵会算出虚高水量）。
- 哨兵值 `-999`（设备不存在）/ `-9991`（设备异常）视为缺失。
- 起点前无基准按 **0**；窗口内无有效行 → **计量不可得**（台账 `dataOk=false` + `dataNote`、明细行 `amount=null` + `meterIssue`、出账 400 拦截）。
- 不可得原因文案（对外展示，同时落后端日志 `[灌区用水] 计量不可得…`）：
  `执行时段内该闸口无流量记录`（方案闸口在流量表中该时段一行都没命中：时段选错 / 数据未接入 / 闸口与流量表站点标识不同源）、
  `执行时段内该闸口无有效累计流量`（有流量行但 ttf 全为空/哨兵）、
  `执行时段不正确，无法计量`（方案 start_time / end_time 缺失或格式非法）。
- 与流量监测 / 闸门监测 / 灌溉用水模块同一取数口径。

### 8.2 户级计入与出账金额

```
计入水量(方案) = 单闸口区间累计（差额策略下扣减闸口取负）
账单 quantity   = Σ 该组方案计入水量（出账时点快照，带符号），HALF_UP 2 位
账单 amount     = quantity(m³) × 水价(元/m³)，HALF_UP 2 位
```

- 出账资格：方案存在、未取消、未计费；组内**净计入水量 > 0**；户已配置统计周期 / 关联闸口 / 有效水价。
- 账单生成后：方案打标 `bill_id` + 快照 `billed_qty`；**已计费行一切展示取快照**（不随时间重算）。
- **手工台账出账**：`账单 quantity = 台账 volume(m³)`、`账单 amount = 台账 amount`（= volume × price）；出账后台账 `bill_id` 非空，禁改禁删。

### 8.3 账期（分期）推导

方案归属分期 = `方案执行时段起日期` + `所属户统计周期`：

| 例 | 执行时段起 | 户周期 | cycleKey | cycleLabel | 账期区间 |
|----|-----------|--------|----------|------------|----------|
| 1 | 2026-10-06 | 月度 | `2026-10` | 2026年10月 | 2026-10-01 ~ 2026-10-31 |
| 2 | 2026-08-15 | 季度 | `2026-Q3` | 2026年第3季度 | 2026-07-01 ~ 2026-09-30 |
| 3 | 2026-03-01 | 年度 | `2026` | 2026年度 | 2026-01-01 ~ 2026-12-31 |

> 调整（adjust）改变执行时段起时，账期归属按**新开始时间**重新推导；已出账的快照不变。
> 手工台账的账期由录入时选择的「结算周期 + 年份 + 月份/季度」直接确定（不反推方案执行时段），如 `cycle=month` + `cycleKey=2026-10` → 账期 2026-10-01 ~ 2026-10-31。

### 8.4 四页面数量单位对照（再次强调）
