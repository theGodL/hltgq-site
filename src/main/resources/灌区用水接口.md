# 灌区用水接口（/water-user 等七组）

> 页面：灌区用水管理七页 —— 用水户管理（`static/water-user-list.html`）、用水定额标准（`static/water-quota-list.html`）、用水计划管理（`static/water-plan-list.html`）、需水上报（`static/water-demand-report.html`）、调度方案（`static/water-dispatch-plan.html`）、调度记录（`static/water-dispatch-record.html`）、水费账单（`static/water-bill.html`）
> 鉴权：与其他接口一致（请求头 `X-Session-Id` 或 Cookie `sessionId`，完整前缀见平台登录态）
> 生产环境路径统一加 `/hltgq-site` 前缀，下文调用示例均已带前缀

## 接口总览

| 分组 | 路径前缀 | 接口数 | 说明 |
|------|----------|--------|------|
| 用水户管理 | `/water-user` | 7 | 户档案 + 关联闸口组 + 计算策略 + 统计周期 |
| 用水定额标准 | `/water-quota` | 6 | 作物 × 灌溉方式定额库（m³/亩）；无 meta 接口 |
| 用水计划管理 | `/water-plan` | 13 | 年度 / 月度 / 旬度计划编制、生效、归档、作废 |
| 需水上报 | `/water-demand` | 10 | 上报 → 审核（通过 / 驳回）闭环 |
| 调度方案 | `/water-dispatch` | 11 | 闸口 × 时段的放水载体；配额闭环 + 计费锁 |
| 调度记录 | `/water-dispatch-record` | 7 | 闸口操作留痕（不参与水量与费用计算） |
| 水费账单 | `/water-bill` | 8 | 台账 / 户方案明细 / 账单 / 出账 / 收款 |

## 〇、通用约定

### 0.1 分页响应结构

所有 `/page` 接口返回统一结构：

```json
{
  "total": 36,
  "page": 1,
  "size": 20,
  "pages": 2,
  "records": [ ... ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| total | number | 满足筛选条件的总行数 |
| page | number | 当前页码（请求参数收敛 1 ~ 100000） |
| size | number | 每页行数（请求参数收敛 1 ~ 100，默认 20） |
| pages | number | 总页数 = ⌈total / size⌉ |
| records | array | 当前页数据行 |

### 0.2 错误应答格式

| HTTP | 场景 | 应答体 |
|------|------|--------|
| 400 | 参数校验失败（含状态机非法流转） | `{"message":"…具体原因…"}` |
| 401 | 未登录 / 会话过期 | `{"code":401,"message":"未登录"}` |
| 409 | 唯一约束冲突（编号撞号重试耗尽 / 名称并发重复） | `{"message":"编号生成冲突，请重试"}`、`{"message":"用水户名称已存在，请刷新列表后重试"}`、`{"message":"计划名称已存在，请刷新列表后重试"}` |
| 409（兜底） | 其他唯一约束冲突 | `{"message":"数据已存在或不满足约束，请刷新后重试"}` |

**前端建议**：所有写操作失败时优先展示应答体 `message` 字段（后端已给出可直接上屏的中文文案）。

### 0.3 数量口径（重点）

| 页面分组 | 接口对外单位 | 库内单位 |
|----------|--------------|----------|
| 用水户 / 定额 / 用水计划（三页） | **m³** | m³ |
| 需水上报 / 调度方案 / 水费账单（四页面） | **万m³** | m³ |

- **四页面写入**：请求体数量按 **万m³（≤2 位小数）** 提交，后端 ×10000 转 m³ 落库；**读出**统一 ÷10000 输出，保留 **4 位小数**（前端按自身展示口径取位）。
- **计划明细** `planWater` 按 **m³（2 位小数）** 提交（前端以万m³ 录入时自行 ×10000 换算），响应 `totalWater` 等同样为 m³。
- 金额一律 **元**（2 位小数）；水价 **元/m³**（3 位小数）；灌溉面积 **亩**（2 位小数）。

### 0.4 状态码体系（筛选参数传什么）

| 字典 | 库内码 | 前端码 | 取值 |
|------|--------|--------|------|
| 用水类型 | `#1#`~`#4#` | 同库内码 | #1# 农业 / #2# 工业 / #3# 生活 / #4# 生态 |
| 计算策略 | `#1#`/`#2#` | 同库内码 | #1# 指定闸口累加 / #2# 闸口差额计量 |
| 统计周期 | `#1#`~`#3#` | month/quarter/year | #1# 月度 / #2# 季度 / #3# 年度 |
| 用水户状态 | `#1#`/`#2#` | 同库内码 | #1# 正常 / #2# 停用 |
| 计划类型 | `#1#`~`#3#` | 同库内码 | #1# 年度 / #2# 月度 / #3# 旬度 |
| 计划状态 | `#1#`~`#4#` | 同库内码 | #1# 编制中 / #2# 已生效 / #3# 已归档 / #4# 已作废 |
| 需水审核状态 | `#1#`~`#3#` | **wait/pass/reject** | #1# 待审核 / #2# 已通过 / #3# 已驳回 |
| 调度执行状态 | `#1#`~`#4#` | **pending/running/done/canceled** | #1# 待执行 / #2# 执行中 / #3# 已完成 / #4# 已取消 |
| 记录操作类型 | `#1#`~`#3#` | **up/down/adjust** | #1# 闸门提升 / #2# 闸门下降 / #3# 流量调整 |
| 账单状态 | `#1#`/`#2#` | **generated/paid** | #1# 已生成 / #2# 已缴清 |

**规则**：前三页（用水户 / 定额 / 计划）筛选参数传**库内码原值**（如 `status=#1#`，URL 编码为 `%231%23`）；四页面（需水 / 调度 / 账单）筛选传**前端英文码**。任一接口的**响应**字段均按各自页面的对外码输出（响应中同时提供 `xxxName` 中文名），且 `meta` 接口返回的字典项 `value` 即为应交回筛选参数的形态。

### 0.5 编号规则（系统自动生成，前端只读）

| 实体 | 编号格式 | 示例 |
|------|----------|------|
| 用水户 | `YH` + 3 位序号 | `YH001` |
| 用水计划 | `YJ` + 3 位序号 | `YJ012` |
| 需水上报 | `XS` + 4 位序号 | `XS0015` |
| 调度方案 | `DD` + 4 位序号 | `DD0008` |
| 水费账单 | `SF` + 期间码 + `-` + 户号 + 4 位序号 | `SF202610-YH0010003`（期间码：2026-10 → `202610`；2026-Q3 → `2026Q3`；2026 → `2026`） |

> 编号由后端 MAX+1 生成、唯一索引兜底并发；撞号时后端自动重试（最多 3 次），最终失败返回 409「编号生成冲突，请重试」。

### 0.6 分期 key（水费口径）

调度方案按其**执行时段起**所在日期 + 所属用水户的**统计周期**推导分期 key：

| 统计周期 | 分期 key | 中文标签 |
|----------|----------|----------|
| 月度 | `2026-10` | 2026年10月 |
| 季度 | `2026-Q3` | 2026年第3季度 |
| 年度 | `2026` | 2026年度 |

出账按 **(用水户 × 分期 key)** 分组拆分多张账单（1 账单 : N 方案）。

### 1.3 GET /water-user/detail — 详情

**请求参数**

| 参数 | 必填 | 类型 | 说明 |
|------|------|------|------|
| id | 是 | string | 用水户 id |

**响应**：单个 WaterUserVO（结构同上表）。用于编辑回显；`gateConfig` 对象可直接回填闸口选择控件。

### 1.4 POST /water-user/create — 新增

**请求体**（`Content-Type: application/json`）

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| name | 是 | string | 名称，≤100 字，全局唯一 |
| userType | 是 | string | 用水类型（库内码 `#1#`~`#4#`） |
| contactName | 是 | string | 联系人，≤50 字 |
| contactPhone | 否 | string | 填写须为 **11 位数字** |
| irrigationArea | 条件 | number | 灌溉面积（亩，>0，≤2 位小数）；**农业 / 生态必填**，工业 / 生活可空 |
| waterPrice | 是 | number | 水价（元/m³，>0，≤3 位小数） |
| calcMode | 是 | string | 计算策略（`#1#` 累加 / `#2#` 差额） |
| gateConfig | 是 | object | 关联闸口（结构须与 calcMode 一致，见下） |
| settleCycle | 是 | string | 统计周期（`#1#`/`#2#`/`#3#`） |

**gateConfig 结构**

```json
// 累加（calcMode = #1#）
{"mode": "SUM", "gates": [{"id": "8Kx2…", "name": "南干渠进水闸"}]}

// 差额（calcMode = #2#）
{"mode": "DIFF", "main": {"id": "8Kx2…", "name": "主闸"}, "deduct": [{"id": "9Yt3…", "name": "扣减闸"}]}
```

- 结构必须与 `calcMode` 匹配：SUM 须 `gates` ≥1 个；DIFF 须 `main` 必填、`deduct` ≥1 个，且**主闸口不得同时作为扣减闸口**。
- `name` 前端可传占位（如空串）；**后端按 id 回查站档固化名称快照**，不信任前端名称；id 不存在/非闸站则报 400「关联闸口不存在，请重新选择」。

**调用示例**

```
POST /hltgq-site/water-user/create
Content-Type: application/json
X-Session-Id: <会话ID>

{
  "name": "宿松县洲头乡示范片",
  "userType": "#1#",
  "contactName": "张明",
  "contactPhone": "13900000000",
  "irrigationArea": 3200,
  "waterPrice": 0.12,
  "calcMode": "#1#",
  "gateConfig": {"mode": "SUM", "gates": [{"id": "8Kx2…", "name": ""}]},
  "settleCycle": "#1#"
}
```

**响应**：返回新建后的 WaterUserVO（同详情结构；编号 `YH###` 已生成）。编号冲突时后端自动重试，重试耗尽返回 409。

### 1.5 PUT /water-user/update — 编辑

**请求参数**

| 参数 | 必填 | 类型 | 说明 |
|------|------|------|------|
| id | 是 | string | 用水户 id（query 参数） |

**请求体**：同新增（`WaterUserSaveVO`）。**编号与状态不变**（编辑不含停用/启用操作）。

**响应**：更新后的 WaterUserVO。

> 已配置的闸口组被编辑后，**不影响历史单据**：需水/调度已保存的闸口引用即时校验仅针对当次提交，水费计量按**当时**的闸口组实时计算。

### 1.6 GET /water-user/delete-check — 删除前置检查

删除保护三级规则：**① 四页业务引用（需水/调度/记录/账单）硬拦；② 被非编制中计划引用禁止；③ 仅被编制中计划引用 → 二次确认后连带清理。**

**请求参数**

| 参数 | 必填 | 类型 | 说明 |
|------|------|------|------|
| id | 是 | string | 用水户 id |

**响应**

```json
{
  "blocked": [
    {"planId": "p1…", "planNo": "YJ002", "planName": "2026年10月月度调度计划", "status": "#2#", "itemCount": 2}
  ],
  "pending": [
    {"planId": "p2…", "planNo": "YJ005", "planName": "2026年11月月度调度计划", "status": "#1#", "itemCount": 1}
  ],
  "refs": {"demands": 0, "dispatches": 0, "records": 0, "bills": 0}
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| blocked | array | 非编制中计划引用（`PlanRefVO`：planId/planNo/planName/status/itemCount）——**非空即禁止删除** |
| pending | array | 编制中计划引用——**非空时提示将连带清理明细并重算总水量，用户确认后带 force=true 再删** |
| refs | object\|null | 四页业务引用计数 `{demands,dispatches,records,bills}`；任一 >0 即禁止删除（后端删除时以此硬拦） |

**前端交互建议**：`refs` 有值 → 提示"该用水户已存在业务数据，不可删除"；`blocked` 非空 → 提示引用计划清单不可删除；仅 `pending` 非空 → 弹二次确认，确认后 `DELETE /water-user/delete?id=…&force=true`。

### 1.7 DELETE /water-user/delete — 删除

**请求参数**

| 参数 | 必填 | 类型 | 说明 |
|------|------|------|------|
| id | 是 | string | 用水户 id |
| force | 否 | boolean | 默认 false；true = 确认连带清理编制中计划的引用明细并重算总水量 |

**响应**

```json
{"success": true}
```

**失败文案（400，前端直接展示）**

- 四页引用：`该用水户已存在业务数据（需水上报 N 条 / 调度方案 N 条 / 调度记录 N 条 / 账单 N 张），删除会使业务与财务记录悬空，不可删除`
- 非编制中计划引用：`该用水户已被 N 个非编制中计划引用（已生效 / 已归档 / 已作废），不可删除`
- 编制中引用且未 force：`该用水户被 N 个编制中计划引用（明细 N 行），删除后将从这些计划中移除对应明细并重算总水量，请确认`

## 二、用水定额标准（/water-quota）

> 页面：`static/water-quota-list.html`。定额库按「作物种类 × 灌溉方式」维护定额标准（m³/亩），是用水计划明细自动测算的数据源。**注意：本组无 meta 接口**（页面无字典依赖，作物种类为自由文本）。

### 2.1 GET /water-quota/page — 列表分页

**请求参数**

| 参数 | 必填 | 类型 | 说明 |
|------|------|------|------|
| page | 否 | int | 页码，默认 1 |
| size | 否 | int | 每页行数，默认 20（max 100） |
| keyword | 否 | string | 模糊匹配 作物种类 / 灌溉方式 / 备注 |

**响应 `records[]` 行**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 主键 |
| cropType | string | 作物种类（如 水稻 / 冬小麦，亦含工业用水、城镇生活等行业类型） |
| irrigationMethod | string\|null | 灌溉方式（可空） |
| quotaValue | number | 定额标准（**m³/亩**，2 位小数） |
| remark | string\|null | 备注 |
| refCount | number | **被引用计划数**（实时 count：明细中引用该定额的 DISTINCT 计划数，**不过滤计划状态**） |

**响应示例**

```json
{
  "total": 8, "page": 1, "size": 20, "pages": 1,
  "records": [
    {"id": "q1…", "cropType": "水稻", "irrigationMethod": "常规灌溉", "quotaValue": 580.00, "remark": null, "refCount": 3},
```

### 3.8 PUT /water-plan/update — 编辑（两态两规则）

**请求参数**：`id`（必填）

**编制中（全量替换）**：请求体同新增；名称 / 类型 / 周期 / 明细全部可改。

**已生效（受限编辑）**：
- `items` 行数必须与现有一致，每行必传 `id` + `planWater` + `overrideReason`；
- 名称 / 类型 / 周期 / 用水户 / 灌溉面积 / 适用定额**锁定**——传了且与现值不同即 400（文案如「已生效计划不可更换用水户」「已生效计划不可修改适用定额」等）；
- 改后重算总水量；若计划已有调度下达（scheduledQty > 0），校验总水量不得低于已调度水量。

**已归档 / 已作废**：400「已归档 / 已作废计划不可编辑」。

**响应**：更新后的计划详情。

### 3.9 DELETE /water-plan/delete — 删除

**请求参数**：`id`（必填）

**响应**：`{"success": true}`；仅编制中可删（400「仅编制中计划可删除（已生效 / 已归档 / 已作废为终态保护）」），主表 + 明细物理删除。

### 3.10 GET /water-plan/conflict-check — 生效校验只读预览

生效前调用（只读），前端据 `blocked` / `warnings` 渲染拦截/确认弹窗；`activate` 事务内以同一校验函数最终裁决。

**请求参数**：`id`（必填）

**响应**

```json
{
  "blocked": [],
  "warnings": ["宿松县洲头乡示范片：月度 / 旬度合计将超出年度计划 12.5 万m³（年度基准 180.0 万m³）"]
}
```

**三层校验规则**

| 层 | 条件 | 结果 | 文案形态 |
|----|------|------|----------|
| ① 明细完备 | 无明细行，或某行计划水量 ≤ 0 | **block** | `计划至少需要 1 条明细`、`第 N 行（户名）：计划水量必须大于 0` |
| ② 同类型周期重叠 | 与另一**已生效**同类型计划周期重叠 | **block** | `与 YJ###（计划名称）周期重叠` |
| ③ 年度基准弱约束 | 月度/旬度计划某户（月度合计 + 本次）超出该户**当年年度已生效+已归档计划**基准 | **warn 不拦截** | `{户名}：月度 / 旬度合计将超出年度计划 X.X 万m³（年度基准 Y.Y 万m³）` |

### 3.11 POST /water-plan/activate — 生效

**请求参数**：`id`（必填）

**响应**：`{"success": true}`

**说明**：编制中 → 已生效；`blocked` 非空时 400，文案为 `无法生效：{原因1}；{原因2}`（与 conflict-check 同源）；`warnings` 仅提示，不拦截（前端负责二次确认交互）。

### 3.12 POST /water-plan/archive — 归档

**请求参数**：`id`（必填）

**响应**：`{"success": true}`；仅已生效可归档，否则 400「仅已生效计划可归档」。归档后为终态。

### 3.13 POST /water-plan/void — 作废

**请求参数**

| 参数 | 必填 | 类型 | 说明 |
|------|------|------|------|
| id | 是 | string | 计划 id |
| reason | 是 | string | 作废原因（≤200 字），为空 400「请填写作废原因」 |

**响应**：`{"success": true}`；仅已生效可作废（400「仅已生效计划可作废」），作废人 / 时间 / 原因随记录保存并在列表行返回。

## 四、需水上报（/water-demand）

> 页面：`static/water-demand-report.html`。上报 → 审核闭环；**只有「已通过」的上报单才能被调度方案关联**。数量对外单位：**万m³**。

### 4.0 状态机（前端按钮显隐依据）

| pass 已通过 | **不可**（400「已通过的上报单不可编辑」） | 不可 | 可（未被调度引用时） |
| reject 已驳回 | 可（保存后回 wait） | 不可 | 可（未被调度引用时） |

## 五、调度方案（/water-dispatch）

> 页面：`static/water-dispatch-plan.html`。调度方案 = **闸口 × 时段** 的放水载体：计划放水量（万m³）+ 执行时段，执行完成后即成为计费对象（水费账单按其计量）。数量对外单位：**万m³**。

### 5.0 状态机与操作矩阵

```
待执行 pending ──start──▶ 执行中 running ──done──▶ 已完成 done
      │                        │
      └────────cancel──────────┴──▶ 已取消 canceled（不占配额、不参与出账）
```

| 操作 | 待执行 | 执行中 | 已完成 | 已取消 | 附加条件 |
|------|--------|--------|--------|--------|----------|
| 编辑 update（全字段） | ✔ | ✘ | ✘ | ✘ | 且未计费 |
| 调整 adjust（水量/时段/备注） | ✔ | ✔ | ✔ | ✘ | 且未计费；已完成方案也可调整（水费页「编辑水量」） |
| 开始执行 / 完成 / 取消 | start / cancel | done / cancel | — | — | 取消且未计费 |
| 删除 delete | ✔ | ✔ | ✔ | ✔ | **未计费即可，不限执行态** |
| 出账（水费页） | ✔ | ✔ | ✔ | ✘ | 未计费 |

> **计费锁**：方案一旦被账单挂接（`billId` 非空），编辑 / 取消 / 删除均被拦截，文案「该方案已计费，请先删除关联账单后再…」；先删账单恢复未计费后可再操作。

### 5.0.1 配额闭环（关联计划时）

关联「已生效」用水计划且选择了具体户/闸口后，下达量受**该计划该户计划水量**约束：

```
已下达合计（未取消，排除自身） + 本次 planAmount ≤ 该户在该计划中的计划水量合计
```

超限 400：`超出计划配额：该户关联计划水量 X.X 万m³，已下达 Y.Y 万m³，本次下达 Z.Z 万m³`。校验在事务内 `FOR UPDATE` 锁计划行防并发；创建 / 编辑 / 调整 / 取消 / 删除后自动回写计划的 `scheduledQty`（未取消方案合计）。

## 七、水费账单（/water-bill）

> 页面：`static/water-bill.html`。四个视图共用一组接口：**① 台账**（按户归集）/ledger、**② 户方案明细**（单户逐方案）/user-plans（+ 调度方案的 adjust 编辑水量）、**③ 账单列表** /page、**④ 账单详情**（方案快照）/detail；写操作：**出账** /bills/create、**确认收款** /bills/pay、**删除账单** /bills/delete。数量对外单位：**万m³**；金额元。

### 7.0 计费模型速览

- **出账单元**：一批调度方案（未取消、未计费）→ 按 *(用水户 × 分期 key)* 分组 → 每组一张账单（1 账单 : N 方案）。
- **计入水量**：每方案按「该闸口在 [执行时段起, 止] 的实测累计流量」实时计量；差额策略下扣减闸口结果取**负**参与合计（`sign` 字段标明）。
- **净计入拦截**：组内净计入水量 ≤ 0 不可出账。
- **金额**：`quantity(m³) × 水价(元/m³)`，保留 2 位；账单生成时固化水价与水量**快照**（方案 `billed_qty` 打标），之后台账展示取快照、不随流量变化。
- **账单删除**：清空方案挂接（`billId`/快照清空 → 恢复未计费实时计量），可重新出账；方案随即恢复可编辑/可取消/可删除。

## 八、计量与金额口径（水费数值来源）

前端若需在页面上解释/复核账单数值，按以下口径：

### 8.1 单闸口区间累计（实时计量）

```
计入水量(闸口) = ttf(执行时段窗口内末行) − prevTtf(起点前最近一条 ttf 非空行)
```

- 起点前无基准按 **0**；窗口内无有效行 / 末行 ttf 缺失 → **计量不可得**（台账标 `dataOk=false`，出账拦截）。
- 哨兵值 `-999`（设备不存在）/ `-9991`（设备异常）视为缺失。
- 与流量监测 / 闸门监测 / 灌溉用水模块同一取数口径。

### 8.2 户级计入与出账金额

```
计入水量(方案) = 单闸口区间累计（差额策略下扣减闸口取负）
账单 quantity   = Σ 该组方案计入水量（出账时点快照，带符号），HALF_UP 2 位
账单 amount     = quantity(m³) × 水价(元/m³)，HALF_UP 2 位
```

- 出账资格：方案存在、未取消、未计费；组内**净计入水量 > 0**；户已配置统计周期 / 关联闸口 / 有效水价。
- 账单生成后：方案打标 `bill_id` + 快照 `billed_qty`；**已计费行一切展示取快照**（不随时间重算）。

### 8.3 账期（分期）推导

方案归属分期 = `方案执行时段起日期` + `所属户统计周期`：

| 例 | 执行时段起 | 户周期 | cycleKey | cycleLabel | 账期区间 |
|----|-----------|--------|----------|------------|----------|
| 1 | 2026-10-06 | 月度 | `2026-10` | 2026年10月 | 2026-10-01 ~ 2026-10-31 |
| 2 | 2026-08-15 | 季度 | `2026-Q3` | 2026年第3季度 | 2026-07-01 ~ 2026-09-30 |
| 3 | 2026-03-01 | 年度 | `2026` | 2026年度 | 2026-01-01 ~ 2026-12-31 |

> 调整（adjust）改变执行时段起时，账期归属按**新开始时间**重新推导；已出账的快照不变。

### 8.4 四页面数量单位对照（再次强调）

| 接口字段 | 单位 | 精度 |
|----------|------|------|
| 需水 amount | 万m³ | 4 位输出（录入 ≤2 位） |
| 调度 planAmount / amount | 万m³ | 4 位输出（录入 ≤2 位） |
| 账单 quantity / BillPlanRowVO amount | 万m³ | 4 位输出 |
| 台账板块各数量列 | 万m³ | 4 位输出 |
| 计划 totalWater / planWater / calcWater | **m³** | 2 位 |
| 用水户 annualPlanWater / annualScheduledQty | **m³** | 2 位 |
| 金额（amount / paid / pendingAmount 等） | 元 | 2 位 |
