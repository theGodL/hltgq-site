> 适用范围：三维系统（大屏 / 数字孪生）数据对接。`/external/*` 为专用接口；天气、雨量、闸站/雨量/流量/水位监测直接复用现有页面接口（第七章～第十三章）。
>
> **状态标注（2026-09-08 全量线上实测）**：业务接口共 25 个（含 POST `/auth/login`），全部已在现网实测 HTTP 200，**各章「响应示例」均为 2026-09-08 实测真实返回**（节选；分页壳 `total`/`pages` 与示例请求参数一致）。第二章 `/external/intake-gate` 为渠首实时接口的**原路径（对接方在用，路径不变）**：2026-09-08 已上线「可选 stcd 参数按任意闸站查询」增强并实测通过——不传 stcd 返回渠首进水闸（向后兼容，对接方无感知），传 stcd / 站点 ID 返回任意闸站，站点不存在报 400（详见第二章）。第九～十一章 9 个监测接口与第十二、十三章 8 个水位接口均为监测页面在用接口（2026-09-08 收编/补录：前 9 个来自历史交付文档《给中水三维系统的接口文档》，后 8 个按客户技术反馈补录），直接复用无需新开发。第四、五章应急口径 = 告警表 `type=#3#` 智能分析；实测当日告警表暂无 `type=#3#` 数据，`emergencyTotal`/`resolved`/`unresolved` 返回 0 属正常。登录会话获取见「通用约定」，平台站点档案查询说明见附录 5。

> 本文档面向对接方：正文只讲「请求什么、拿到什么」；后端数据来源与口径见各接口「数据口径」说明。

## 通用约定（对接方必读）

| 约定 | 说明 |
|------|------|
| 环境 | 生产访问前缀 `http://220.179.1.110:8081/hltgq-site`；正文各处均省略该前缀 |
| 鉴权 | 所有数据接口需携带登录会话：请求头 `Authorization: <sessionId>`（或 `X-Session-Id`；Cookie `sessionId` 亦可）；`<sessionId>` 经下方「会话获取」取得。是否对三维系统开放免鉴权白名单**待确认**（见附录 3） |
| null 语义 | 无数据返回 `null`，**不返回 0**（0 = 真实值为 0）；对接方按 `null` 处理缺数。例外：逐日趋势数组为保持日期连续，无记录补 0（见第四章）；第九～十三章小时序列为保持步长连续，无记录行保留（值口径见各章） |
| 数字精度 | `/external/*` 输出统一**截断不四舍五入**：瞬时流量 3 位小数、水位 2 位小数、雨量 2 位小数，不足位补零（如 42.70），计数类为整数；复用页面接口（第七～十三章）为页面同源输出（库值直出、保留小数尾零），精度以返回值为准 |
| 时间格式 | 参数：日期 `yyyy-MM-dd`、时间戳 `yyyy-MM-dd HH:mm:ss`；响应时间戳：`/external/*` 为 `yyyy-MM-dd HH:mm:ss`，复用监测接口（第九～十三章）为 ISO `yyyy-MM-dd'T'HH:mm:ss`（例外：`gate-monitor/history` 的 records 内为空格格式 `yyyy-MM-dd HH:mm:ss`；小时标签统一 `yyyy-MM-dd HH:00`） |
| 频率 | `/external/*` 与第九～十三章复用监测接口均为实时查询（无缓存、无轮询任务）；天气接口带 Redis 缓存（TTL 约 10 分钟）。对接方按 60s 间隔刷新即可 |
| 样例说明 | 各章「响应示例」为 2026-09-08 现网实测真实返回（节选，数值形态与实测一致；`…` 表示省略同构行）；请求示例中参数均为实测可用取值，样例数据为当日实时观测，会随时间变化 |

**会话获取（首次接入必做）**

```
POST /auth/login
Content-Type: application/json

{ "key": "<32位key>", "secret": "<32位secret>" }
```

- key / secret（各 32 位字符串）由我方线下提供；历史交付文档示例中的 `a1b2c3...` 仅为格式示例，实际以线下下发为准
- 成功（HTTP 200）：`{"success": true, "message": "登录成功", "sessionId": "dev_hltgq_session:xxxx"}`
- 失败：`success=false` + `message` 说明原因（key/secret 不匹配、上游安全码或登录服务异常等），HTTP 状态仍为 200
- 登录后所有数据接口请求头携带 `Authorization: <sessionId>`（值原样透传，无需 `Bearer ` 前缀；亦可改放 `X-Session-Id` 头）

## 二、闸站实时数据

```
GET /external/intake-gate?stcd=QSJSZ
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| stcd | String | 否 | 站点编码（站点档案表 `iofhpi`，如渠首进水闸 `QSJSZ`、南山寺节制闸 `NSS`）；兼容传站点 ID（档案表 `id`，即闸门/流量表 `site` 值）。**不传时返回渠首进水闸**（原无参行为，向后兼容）；stcd 仅支持编码/站点 ID，不支持站点名称 |

stcd 对应站点不存在时报 400（`{"message": "站点不存在: xxx"}`）。

**无参调用示例（2026-09-08 上线后实测，默认渠首进水闸）**：

```json
{
  "site": "CAYQ739MiBWMg9gQvyi",
  "stcd": "QSJSZ",
  "stnm": "渠首进水闸",
  "upZ": 42.34,
  "downZ": 42.05,
  "q": 36.457,
  "tm": "2026-09-08 20:30:00",
  "managementUnit": "花凉亭灌区"
}
```

**按 stcd 查任意闸站示例（2026-09-08 上线后实测，`stcd=NSS` 南山寺节制闸；传站点 ID `dByBR1Xdze8shnRGAw9` 返回同站）**：

```json
{
  "site": "dByBR1Xdze8shnRGAw9",
  "stcd": "NSS",
  "stnm": "南山寺节制闸",
  "upZ": 40.34,
  "downZ": 40.15,
  "q": 73.850,
  "tm": "2026-09-08 20:30:00",
  "managementUnit": "花凉亭灌区"
}
```

实测抽查其余闸站（2026-09-08 20:30~20:40）：渠首电站防洪闸 `stcd=2RR3HvjVi1ONzFewDim`（编码 `QSDZ`，q 13.422）、北干渠进水闸 `stcd=4Ieu32Stnz8dTD8S8GD`（编码 `9000000001`，q 11.737）均正常返回；全部 10 个闸站见附录站点映射或 `GET /station-metrics/sites?type=gate`。

| 字段 | 类型 | 说明 |
|------|------|------|
| site | String | 站点 ID（站点档案表 `id`；闸门/流量等数据表 `site` 字段即此值） |
| stcd | String | 站点编码（站点档案表 `iofhpi`；与各监测数据表 `stcd` 同口径） |
| stnm | String | 站点名称（站点档案表 `zzkaec`） |
| upZ | Number? | 闸前（上游）水位（m，**2 位小数截断补零**）；取闸门表 `up_z` 最新一条，无数据 null |
| downZ | Number? | 闸后（下游）水位（m，**2 位小数截断补零**）；取闸门表 `down_z` 最新一条，无数据 null |
| q | Number? | 瞬时流量（m³/s，**3 位小数截断**）；取流量表最新 `q`，无数据 null |
| tm | String | 数据时间（取水位/流量中较新者） |
| managementUnit | String | 管理单位（固定「花凉亭灌区」） |

数据口径：按站点键查站点档案表 `t_auto_hltgq_5nw74_vnqqef`（stcd = `iofhpi`、site = `id`、站名 = `zzkaec`）；无参时默认取渠首进水闸（配置 `external.intake-gate-site`，与页面闸门监测口径一致）；
水位源 `t_auto_hltgq_water_gate`（up_z/down_z）、流量源 `t_auto_hltgq_water_wt_nfo`（q），均按档案 `id` = 表 `site` 关联。
精度口径（业主规则）：瞬时流量 3 位小数、水位 2 位小数，均截断不四舍五入；无效值 -999/-9991 返回 null。

> **变更记录（2026-09-08）**：接口路径 `/external/intake-gate` **保持不变**（对接方已在用，严禁改名，否则已接入方功能异常）。代码在**原路径**上新增**可选** `stcd` 参数支持按任意闸站查询：不传 stcd → 渠首进水闸（与原行为一致，向后兼容）；传 stcd（= 档案 `iofhpi`，兼容站点 ID = 档案 `id`）→ 查询该闸站；stcd 对应站点不存在报 400。**部署状态**：新增强已于 2026-09-08 打包上线并实测通过（无参返回渠首；`stcd=NSS` 返回南山寺节制闸、`stcd=2RR3HvjVi1ONzFewDim` 返回渠首电站防洪闸、`stcd=4Ieu32Stnz8dTD8S8GD` 返回北干渠进水闸；`stcd=BADSTCD999` 报 400「站点不存在」）。无参调用行为与改造前一致，对接方无需改动。

## 四、巡检/突发事件逐日趋势

```
GET /external/daily-trend?startDate=2026-08-10&endDate=2026-09-08
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| startDate | String | 否 | 起始日期 `yyyy-MM-dd`（含）；不传默认近 30 天起点 |
| endDate | String | 否 | 截止日期 `yyyy-MM-dd`（含）；不传默认今天 |

响应：

```json
{
  "dates":     ["2026-08-31", "2026-09-01", "2026-09-02"],
  "patrol":    [0, 1, 1],
  "emergency": [0, 0, 0]
}
```

（节选；实测 2026-08-10 ~ 2026-09-08 共 30 天等长数组：`patrol` 仅 09-01/09-02 各 1 次，其余为 0；`emergency` 全 0）

| 字段 | 类型 | 说明 |
|------|------|------|
| dates | String[] | 横轴逐日标签（含首尾，`yyyy-MM-dd`） |
| patrol | Number[] | 逐日巡检次数（已提交记录按巡检时间取日期聚合），无记录补 0 |
| emergency | Number[] | 逐日突发事件数量 = AI 智能分析告警（告警表 `type=#3#`，全状态）按发生时间取日期聚合，无记录补 0 |

要点：三数组等长；区间上限 366 天、日期格式错误、startDate 晚于 endDate 均报 400。无日期参数时默认返回近 30 天窗口。

## 五、问题统计 + 应急响应统计

```
GET /external/issue-stats
```

无参数。响应：

```json
{
  "handled": 5,
  "unrectified": 13,
  "emergencyTotal": 0,
  "resolved": 0,
  "unresolved": 0
}
```

| 字段 | 类型 | 口径 |
|------|------|------|
| handled | Number | 已处理 = 问题表「已关闭」的问题总数 |
| unrectified | Number | 未整改 = 问题表「处理中」+「已转工单」的问题总数 |
| emergencyTotal | Number | 突发事件 = AI 智能分析告警总数（告警表 `type=#3#`，全状态） |
| resolved | Number | 已解除响应 = AI 告警中已关闭数（告警表 `status=#4#`） |
| unresolved | Number | 未解除响应 = AI 告警中未关闭数（`status≠#4#`，= emergencyTotal − resolved） |

要点：两组口径来源不同——问题口径来自问题表，应急口径来自告警表（突发事件判定：告警表 `type=#3#` 智能分析）。
