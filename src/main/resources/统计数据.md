# 统计数据（hltgq-site 地图大屏接口）

> 面向地图大屏（hlt-theme-new，含 static/data-statistics.html 数据统计页）的后端接口文档：
> 数据统计 7 个端点（`/data-statistics/*`，第 1~5 章）+ 右侧面板水资源模块聚合接口（`/h5/water-resource/overview`，第 6 章）。
> 生产环境路径统一加 `/hltgq-site` 前缀，全部接口需登录态。
> 数据统计部分的上游契约（口径/字段定义）见《数据统计.md》（hltgq-mq 侧对接文档）；本文件只描述 hltgq-site 网关层的接口形态与行为。

---

## 1. 定位与架构

数据统计大屏的数据分三路来源，统一由 hltgq-site 的 `DataStatisticsController` 对外提供：

| 来源 | 端点 | 说明 |
|------|------|------|
| hltgq-mq 内部统计接口（`/api/report/*`，仅内网） | arrival-stats / arrival-detail / miss-detail / collect-stats / service-status | site 作为网关转发，**把上游 `{code,msg,data}` 中的 data 段原样透传**（code=0 时）；口径由 mq 统一计算（mq 侧 60s 缓存），site 不另起口径、不做本地 COUNT |
| hltgq-device 视频巡检统计（`/api/dahua/video/patrol-stats`，仅内网） | video-collect | 透传 device `{success,code,desc,data}` 中的 data 段（按 `success==true` 判定）；device 与 site 共用平台会话，出站自动透传 X-Session-Id |
| site 本地（预警发布） | publish-stats | 告警表当日计数，本地毫秒级查询，不依赖上游 |

```
数据统计大屏（前端）
   │  GET /hltgq-site/data-statistics/*
   ▼
hltgq-site 网关（DataStatisticsController）
   │  ┌──────────────────────┬─────────────────────────┐
   ▼  ▼（转发，透传 data 段）  ▼（转发，透传 data 段）      ▼（本地）
hltgq-mq /api/report/*     hltgq-device /api/dahua/*   t_auto_hltgq_water_alert
```

## 2. 通用约定

### 2.1 响应形态

- 成功：直接返回上游 `data` 段（对象或数组），**无外层 code/msg 包装**；前端字段契约与《数据统计.md》第 4 章一致。
- 失败：mq/device 不可达或返回业务错误时，统一 HTTP 502 + 错误包装：
  ```json
  { "code": 502, "message": "数据统计服务调用失败(/api/report/arrival-stats): ..." }
  ```

### 2.2 区间参数（startDate / endDate）

| 场景 | 语义 |
|------|------|
| 都不传 | 今日口径（=显式传今天日期） |
| 只传 startDate | `[startDate, 今日]` |
| 只传 endDate | 单日 `[endDate, endDate]` |
| 都传 | 闭区间 `[startDate, endDate]`（含两端） |

- 格式 `yyyy-MM-dd`；参数非法时不缓存、**原样透传上游**，由上游校验报错。
- publish-stats 无区间参数，恒今日口径。

### 2.3 响应缓存（site 网关层，2026-09-13）

背景：mq 统计接口单次响应 8s+，为保首屏秒开加缓存：

| 项 | 行为 |
|----|------|
| 缓存键 | `stats:api:{path}:{start}:{end}`（区间先归一化，见 2.2） |
| TTL | 区间含今日 → 20 分钟；纯历史区间 → 60 分钟 |
| 预热 | 定时任务每 10 分钟串行刷新 5 个 mq 接口的今日口径缓存（失败保留旧值等下一轮）；video-collect 依赖登录会话不预热；publish-stats 不缓存 |
| 未命中 | 回退上游实时查询并回填；同键单飞合并（同时只放行一次上游查询，等待 20s 复用结果；leader 失败时等待方透传同源 502） |
| 降级 | Redis 不可达/缓存损坏 → 视为未命中走上游实时查询，不影响主链路 |

## 3. 接口清单

### 3.1 统计卡片聚合（KPI）

```
GET /hltgq-site/data-statistics/arrival-stats
GET /hltgq-site/data-statistics/arrival-stats?startDate=2026-09-01&endDate=2026-09-14
```

**响应**（对象，= mq data 段）：

```json
{
  "stationTotal": 130,
  "todayArrivalRate": 74.46,
  "monthAvgArrivalRate": 74.46,
  "todayMissRate": 19.68,
  "statStartDate": "2026-09-09",
  "noReportSites": [
    { "siteId": "...", "siteName": "周家河", "stcd": "3206400001" }
  ],
  "missedSites": [
    { "siteId": "...", "siteName": "...", "stcd": "...",
      "lastValidTm": "2026-09-14 08:00:00", "missedWindows": 3, "missRate": 12.5 }
  ]
}
```

| 字段 | 说明 |
|------|------|
| stationTotal | 参与统计的站点总数（KPI 站点总数直接用它，与 arrival-detail 行数一致） |
| todayArrivalRate | 今日到报率(%) |
| monthAvgArrivalRate | 本月平均到报率(%)，从流水上线日起逐日平均 |
| todayMissRate | 今日缺测率(%)（与到报率分母不同，两者不互为补数） |
| statStartDate | 本月实际统计起始日 |
| noReportSites | 今日未到报站点 |
| missedSites | 今日缺测站点（含最近有效时间/缺测窗数/缺测率） |

### 3.2 站点到报明细

```
GET /hltgq-site/data-statistics/arrival-detail
GET /hltgq-site/data-statistics/arrival-detail?startDate=2026-09-01&endDate=2026-09-14
```

**响应**（数组，每站一行）：

```json
[
  { "siteId": "...", "siteName": "周家河", "stcd": "3206400001",
    "msgType": "整点报",
    "expected": 15, "arrived": 14, "missed": 1, "arrivalRate": 93.33 }
]
```

| 字段 | 说明 |
|------|------|
| msgType | 分钟报 = MQTT 四闸站；整点报 = RabbitMQ 站 |
| expected / arrived / missed | 应到 / 实到 / 缺报次数（今日已结束完整窗口径） |
| arrivalRate | 到报率(%)；「状态」档位（正常/偏低/异常/未到报）属展示口径，由前端按产品阈值渲染 |

### 3.3 缺测明细

```
GET /hltgq-site/data-statistics/miss-detail
GET /hltgq-site/data-statistics/miss-detail?startDate=2026-09-01&endDate=2026-09-14
```

**响应**（数组，连续缺测窗合并为段）：

```json
[
  { "siteId": "...", "siteName": "...", "stcd": "...",
    "startTm": "2026-09-14 09:00:00", "endTm": "2026-09-14 12:00:00",
    "missMinutes": 180,
    "dataTypes": ["水位"],
    "status": "缺测中" }
]
```

| 字段 | 说明 |
|------|------|
| endTm | 缺测结束时间（开区间） |
| dataTypes | 缺测的数据类型（水位/雨量/流量/闸门开度/墒情） |
| status | 缺测中 = 覆盖最近完整窗；已恢复 = 已有有效数据 |

### 3.4 数据采集状态统计

```
GET /hltgq-site/data-statistics/collect-stats
GET /hltgq-site/data-statistics/collect-stats?startDate=2026-09-01&endDate=2026-09-14
```

**响应**（数组，按数据类型聚合，固定五维：水位/流量/雨量/闸门开度/墒情，**不含视频**）：

```json
[
  { "dataType": "水位数据",
    "expected": 200, "collected": 185, "success": 180, "failed": 5,
    "successRate": 90.0, "failRate": 2.5 }
]
```

自洽约束：`collected = success + failed` 恒成立，`success ≤ collected`。视频行由 3.5 单独提供，前端与五行合并渲染。

### 3.5 视频数据采集统计

```
GET /hltgq-site/data-statistics/video-collect
GET /hltgq-site/data-statistics/video-collect?startDate=2026-09-01&endDate=2026-09-14
```

**响应**（device data 段，与 3.4 行同构，dataType 为「视频数据」）：

```json
{ "dataType": "视频数据",
  "expected": 48, "collected": 47, "success": 46, "failed": 1,
  "successRate": 95.8, "failRate": 2.1 }
```

说明：本接口需登录态（出站自动透传 X-Session-Id 过 device 登录校验）；不参与预热缓存，仅请求路径命中/回填。

### 3.6 采集服务状态

```
GET /hltgq-site/data-statistics/service-status
GET /hltgq-site/data-statistics/service-status?startDate=2026-09-01&endDate=2026-09-14
```

**响应**（对象，mq 进程指标 + 三逻辑服务）：

```json
{
  "process": { "startTime": "2026-09-09 08:00:00", "uptimeMinutes": 340,
               "cpu": 12.5, "memoryUsedMB": 320, "memoryMaxMB": 1024 },
  "services": [
    { "name": "数据接收服务", "status": "运行中", "todayRequests": 350, "successRate": 100.0 },
    { "name": "数据解析服务", "status": "运行中", "todayRequests": 350, "successRate": 100.0 },
    { "name": "数据存储服务", "status": "运行中", "todayRequests": 220, "successRate": 98.5 }
  ]
}
```

说明：三逻辑服务同进程，进程指标共享；「信息发布/告警推送」不在本接口（发布统计由 3.7 本地提供）。

### 3.7 信息发布情况（本地，恒今日口径）

```
GET /hltgq-site/data-statistics/publish-stats
```

**响应**（数组，仅一行「预警信息」）：

```json
[
  { "type": "预警信息", "count": 3, "ok": 3, "fail": 0, "okRate": 100.0,
    "latest": "2026-09-14 07:30:00", "status": "正常" }
]
```

口径：本项目无发布操作，业务定稿「每次生成告警即发布」——count = 告警表 `t_auto_hltgq_water_alert` 当日生成的告警数；生成即发布成功，fail 恒 0；水情通报/调度指令/日报周报均不统计。

## 4. 边界场景

| 场景 | 表现 |
|------|------|
| mq 不可达 / 返回业务错误 | HTTP 502 + `{code:502, message:...}`（六个转发端点；publish-stats 本地不涉及） |
| device 不可达 / success=false | HTTP 502 同上；前端对视频行失败静默省略（不计入硬错误） |
| 参数非法（非 yyyy-MM-dd） | 不缓存、原样透传上游，由上游校验返回错误 |
| 首访历史区间（缓存未命中） | 回退上游实时查询（慢，8s+ 属上游瓶颈）并回填缓存，第二次起命中 |
| Redis 不可达 | 降级为未命中直连上游，功能不受影响（仅性能回退） |
| 今日口径首屏 | 命中预热缓存秒开（预热每 10 分钟滚动刷新） |

- 上游接口契约（mq 侧 `{code,msg,data}` 完整字段）见《数据统计.md》第 4 章；本文件 3.1~3.6 的响应即其 `data` 段。

## 6. 右侧面板水资源概览（/h5/water-resource/overview）

> 地图大屏（hlt-theme-new）右侧面板「水资源/灌溉配水」两个 Tab 共 4 个数据区块的聚合接口，
> 一次返回四块组件，替代前端原先对接的 3 个 apaas 关联查询（取水数据/配送计划/灌溉统计，字段靠猜）。
> 本章为完整契约（请求/响应/字段口径/联调约定/边界场景），前端仅凭本章即可对接，无需其他文档。

### 6.1 请求

```
GET /hltgq-site/h5/water-resource/overview?startDate=2026-01-01 00:00:00&endDate=2027-01-01 00:00:00
```

| 参数 | 必填 | 类型 | 说明 |
|------|------|------|------|
| startDate | 否 | string | 年度区间起点（yyyy-MM-dd HH:mm:ss，前端 date.min 直传）；缺省=本年度 01-01 00:00:00 |
| endDate | 否 | string | 年度区间终点（不含，date.max 直传）；缺省=startDate 次年 01-01 00:00:00；不晚于 startDate 时回退为 startDate+1 年 |

> 年份取 startDate 的年份，作用于用水计划/需水方案/配水方案选取。

### 6.3 区块 ↔ 数据源映射

| 区块（前端位置） | 响应字段 | 数据源 | 口径 |
|-----------------|----------|--------|------|
| 1 水资源量分布（水资源 Tab 环形饼图） | `distribution[]`（code/name/value） | 年度区间内最新已完成**配水方案**旬明细三列求和 | 固定三项：塘坝供水/水厂供水/花凉亭水库灌溉供水（万m³，2 位截断）；**文案与颜色按 code（pond/waterworks/reservoir）精确匹配，不依赖数组顺序**；主题内置文案「地下水/河道提水/水库供水」与颜色由前端自行映射到 code |
| 2 水资源分配方案及执行（水资源 Tab 底部列表） | `allocationList[]`（code/district/allocatedVolume/progress） | 年度已确认**用水计划**（t_auto_hltgq_yn8cm_hjwwcb，plsuub='#1#'、byihlu='#ikok#'，当年最新一条）四县列；进度=实际供水量÷分配水量×100 | 分配水量万m³ 2 位截断；进度 % 1 位截断；供水量缺失为 null；**进度由后端直接算好，前端不再关联两个 apaas 接口**；后端已按固定四县顺序返回，code（susong/huaining/wangjiang/taihu）可作唯一键 |
| 3 灌溉统计（灌溉配水 Tab 两卡片） | `irrigationStats`（totalArea/finishedVolume） | 总面积=固定值；已完成灌溉=四县实际供水量合计 | totalArea 恒 105.83 万亩（产品定稿）；finishedVolume 为**万m³**（3 位截断，累计流量口径）——业务定稿水量口径，**前端文案改「已完成供水 XX 万m³」**，不做面积换算 |
| 4 各区域灌溉详情（灌溉配水 Tab 卡片列表+柱状图） | `countyDetails[]`（code/district/irrigationArea/finishedVolume） | 灌溉面积=需水方案支渠明细按支渠去重、片区归县求和÷10000；已完成灌溉=该县实际供水量 | 面积万亩 2 位截断；finishedVolume 为**万m³**（3 位截断，累计流量口径）——前端文案「已灌 XX 万m³」；固定四县顺序；柱状图「灌溉面积(万亩) vs 已灌(万m³)」两端单位不同，前端分别标注单位 |

实际供水量口径与 `/irrigation-water/summary` 完全一致（宿松=章大计量闸、怀宁=太怀干渠长喉槽、望江=南/北干渠进水闸、太湖=渠首进水闸总量扣减），站点无数据时为 null 不做估算。

### 6.4 契约约定（前端联调 2026-09-15 定稿）

1. **空值语义**：progress / finishedVolume / irrigationArea 为 null 即「缺失/未接入」，**后端绝不替换为 0**；
   前端 null 展示「--」，柱状图断点（勿用 Number(x)||0）。唯一例外：distribution 固定三项、
   配水方案存在但无旬明细行时三项 value 为 0.00（无方案时整体空数组）。
2. **映射规则**：distribution 文案与颜色按 code 精确匹配（pond/waterworks/reservoir），不按数组下标；
   主题内置文案与颜色由前端自行映射到 code，后端不返回颜色。
3. **四块恒返回**：缺数据时 distribution/allocationList 为空数组、卡片为 null 或固定值，整个接口不会 502
   （登录失败除外）；前端可进页面拉一次、两个 Tab 共用。
4. **行政区**：district 后端已排好固定四县顺序，且 code 稳定（susong/huaining/wangjiang/taihu），两者均可作唯一键。

### 6.5 边界场景

| 场景 | 表现 |
|------|------|
| 年度区间内无已完成配水方案 | distribution 返回空数组 `[]` |
| 年度无已确认用水计划 | allocationList 空数组（即使有需水方案） |
| 无已完成需水方案 | allocationList 各行 progress 为 null；countyDetails 仍返回固定四县行（irrigationArea/finishedVolume 均为 null）；totalArea 仍为 105.83、finishedVolume 为 null |
| 某县设备未接入/窗口内无流量数据 | 该县 progress 与 finishedVolume 为 null（不估算），其余县正常；前端展示「--」 |
| 需水方案无支渠明细 | countyDetails 各行 irrigationArea 为 null |
| startDate/endDate 非法或未传 | 缺省本年度区间（非法格式记 warn 日志） |

> 联调排查：后端按 `[水资源概览]` 前缀输出全链路日志（区间解析、方案选取、用水计划行值、每县面积与供水量），部署后从服务器日志核对即可。
