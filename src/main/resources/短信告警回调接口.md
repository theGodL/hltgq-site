# 短信模块说明（阿里云 Dysmsapi 2017-05-25）

本模块负责三类短信：日汇总（每天 08:01）、雨量告警、水位涨幅告警。
告警短信由 mq 落库后回调本系统接口发送，本系统负责组装变量、幂等去重、失败重试、发送记录落库；
另有每 5 分钟补偿扫描兜底回调丢失。密钥/签名/模板/接收人全部走环境变量，代码与镜像不落真实密钥。

## 1. 代码结构

```
sms/
├── SmsProperties.java              全部配置项（sms.*）
├── client/AliyunSmsClient.java     零依赖 RPC 签名客户端（HMAC-SHA1 + POST form）
├── mapper/SmsRecordMapper.java     发送记录 CRUD + 取数源（雨量/水位/告警/阈值）
├── service/
│   ├── SmsSendService.java         逐号码发送 + 网络异常重试 2 次 + 逐个落记录
│   ├── SmsDailySummaryService.java 12 站雨量（DYP 差值平均）+ 等 08:00 报文齐 + 三站 08:00 水位
│   └── SmsAlarmService.java        回调处理（幂等/静默）+ 补偿扫描（指标判定/告警时刻取数）
├── task/
│   ├── SmsDailySummaryTask.java    每天 08:01（sms.daily.cron）
│   └── SmsAlarmCompensationTask.java 每 5 分钟（sms.alarm.compensation-cron）
├── controller/SmsController.java   POST /sms/alarm-event、POST /sms/test、GET /sms/record/page
└── vo/                             请求/响应/分页/补偿候选 VO
```

发送记录表 DDL：仓库根目录 `sms-record-ddl.sql`（`t_auto_hltgq_water_sms_record`，含 3 个索引）。

| `SMS_ALIYUN_AK_ID` | 是 | 空 | 阿里云 AccessKeyId（花凉亭账号） |
| `SMS_ALIYUN_AK_SECRET` | 是 | 空 | 阿里云 AccessKeySecret |
| `SMS_SIGN_NAME` | 否 | 安庆花凉亭水库灌区管理处 | 短信签名（模板审核时绑定的签名） |
| `SMS_TEMPLATE_DAILY` | 否 | SMS_489685013 | 日汇总模板 |
| `SMS_TEMPLATE_RAIN` | 否 | SMS_489715008 | 雨量报警模板 |
| `SMS_TEMPLATE_LEVEL` | 否 | SMS_489545110 | 水位涨幅模板 |
| `SMS_RECEIVERS_DAILY` | 否 | 32 个号码（30 运维 + 项目经理 + 研发负责人，见 properties） | 日汇总接收人，逗号分隔 |
| `SMS_RECEIVERS_ALARM` | 否 | 4 个号码（2 运维 + 项目经理 + 研发负责人，见 properties） | 告警接收人，逗号分隔（deploy.sh 联调期默认覆盖为测试号，上线前必须核对） |

`sms.read-timeout-ms`、`sms.daily.cron`（默认 `0 1 8 * * ?`）、`sms.alarm.silence-minutes`（默认 30）、
`sms.alarm.compensation-cron`（默认 `0 */5 * * * ?`）、`sms.alarm.compensation-lookback-minutes`（默认 30）、
`sms.station.bashang/baxia/zhoujiahe`（默认 3206400007/320640000A/3206400001）。

## 3. mq 回调契约：POST /sms/alarm-event

告警落库后由 mq 调用；本接口已加入 `auth.white-list`（不走登录会话），鉴权走 `X-Sms-Token` 请求头。

**请求**

```
POST /sms/alarm-event
Content-Type: application/json
X-Sms-Token: <SMS_CALLBACK_TOKEN 的值>

{
  "alertId":   "告警表记录 id（必填，幂等键）",
  "metric":    "rain | water_level（必填）",
  "stcd":      "站点 id（必填，iofhpi）",
  "threshold": 30,        // rain 必填：阈值表本次实际警戒值 mm
  "hour":      2,         // rain 必填：距水文日 08:00 起点整小时数（1~24，mq 判定口径）
  "value":     12.5       // 可选：本次判定实际比较的累积雨量，拼进模板 ${stcd} 变量（如：周家河12.5）
}
```

**响应**（HTTP 200 且 `code=0` 即视为调用成功）

```json
{"code": 0, "data": {"sent": true, "reason": "ok"}}
```

`sent=false` 的 `reason` 为中文说明（均为正常业务跳过，mq 无需重试），常见值：
"短信功能未启用"（总开关关闭）、"该告警短信已处理（幂等跳过）"（重复回调）、
"同站点同指标 30 分钟内已发送（静默）"、"该告警正在处理中（并发锁）"、
"短信发送失败（详见发送记录）"、"雨量告警 threshold/hour 不能为空"（参数缺失）、
"水位取数不完整，未发送（补偿窗口内将重试）"（数据源暂缺，补偿自动补发）。

Token 缺失/不匹配返回 HTTP 403 `{"code":403,"message":"鉴权失败"}`。

**curl 示例**

```bash
curl -X POST http://<host>:<port>/sms/alarm-event \
  -H "Content-Type: application/json" \
  -H "X-Sms-Token: $SMS_CALLBACK_TOKEN" \
  -d '{"alertId":"alert-001","metric":"rain","stcd":"00000001","threshold":30,"hour":1,"value":12.5}'
```

**mq 侧失败处理**：mq 对超时 / 非 200 / `code!=0` 只记一条带 alertId 的错误日志，
不回滚告警、不重试（mq 回调超时 3 秒）；漏发由本系统每 5 分钟补偿扫描自动补发，mq 无需任何补偿动作。

## 4. 处理机制

| 机制 | 说明 |
| --- | --- |
| 幂等 | 以 `alertId` 为键，已有"已处理"记录（`success`=已发 / `skipped`=静默）则跳过；并发场景用 Redis 抢占锁（`qx.hltgq.sms.alert.{alertId}`，TTL 10 分钟）防回调与补偿同时双发，Redis 异常降级无锁 |
| 静默 | 同站点同指标默认 30 分钟窗口（`sms.alarm.silence-minutes`），窗口内新告警落 `skipped` 记录不发短信，防轰炸；skipped 计入"已处理"，静默过期后补偿不会延迟补发 |
| 重试 | 仅网络异常（超时/IO）重试 2 次（间隔 1s/2s）；阿里云返回业务错误码（如限流 `isv.BUSINESS_LIMIT_CONTROL`）不重试，直接记失败 |
| 补偿 | 每 5 分钟扫描最近 30 分钟 `type='#1#'` 且状态为 `#1#`（活动中）的告警，未处理且能判定指标的自动补发（设备名含"雨量"/"水位"优先；否则仅当阈值表只配置单指标时推定——`#2#` 雨量 / `#1#` 水位，双指标/无配置跳过）；`#4#`（已解除）与 `#2#`（语义未确认，疑似已处理）不补发 |
| 落库 | 每个号码每次发送均写一条记录（成功/失败/静默跳过都写），含模板参数、阿里云 RequestId/BizId、响应码/信息，供排查 |

**告警模板变量组装**

- 雨量（SMS_489715008）：`hour`=mq 传入的水文日小时数（距当日 08:00 起点的整小时，1~24，向下取整最少 1）、
  `threshold`=去尾零阈值、`stcd`=站名+实测值（如 `周家河12.5`，value 缺省或 <=0 时仅站名）；
  补偿扫描时 hour 按告警时间同口径推定，**实测雨量值不拼**（DRP 字段实测恒 0，拼进模板就是假 0 错值）
- 水位（SMS_489545110）：`station_code`=站名、`waterLevel`=水位（2 位截断小数）、`increaseRate`=1 小时涨幅
  （当前值 − 1 小时前值，2 位截断）。取数字段与该站阈值行的 `zb` 严格一致（告警引擎按哪个字段判定就取哪个）：
  `up_z`→闸站闸前水位、`down_z`→闸站闸后水位、空→河道 `COALESCE(Z,Z1)`；闸站按 site 关联（gate 表约 39% 行 STCD 为 NULL）。
  取数基准：回调用当前时刻、补偿用告警时刻。**取数不完整不发送**（不落处理记录，补偿窗口内自动重试），绝不填"暂无"

**日汇总（SMS_489685013）**

- 每天 08:01 执行并**先等 08:00 整点报文到齐（最迟 08:15）再结算**；数据上界严格 `TM <= 今日 08:00:00`
  （08:00 后属于下一水文日，绝不取用）
- `rain` = 320640 系列全部 12 个雨量站上一水文日雨量的算术平均：单站 = DYP 正向增量累加
  Σmax(0, DYP_i − DYP_{i−1})（该表 DRP 实测恒 0 不可用），**平均 = 全站之和 ÷ 12，四舍五入两位**
  （与业主老系统逐行对账定稿；缺报文站按 0 参与、分母固定 12）
- `bashang/baxia/zhoujiahe` = 三站 `< 今日 08:00` 最新水位（2 位截断）
- `time` = 昨日日期（水文日标签）、`hour` = 8
- **拒发条件（宁可少发不误发）**：12 站整点报文全缺、到报不足半数（缺站按 0 平均严重失真）、
  任一站水位缺数 → 不发送，落 `skipped` 记录（`response_code=NO_DATA`）并在日志说明原因
- 取数明细（逐站雨量/报文数、三站水位 TM/Z）逐条打日志，部署后按日志核对口径

**已知边界（已评估接受）**

- 回调同步发送：告警仅 2 个号码，正常 <2 秒；网络故障重试时可能超过 mq 的 3 秒超时——
  mq 记失败不重试，我方若实际已发出则幂等记录在案、补偿不会重复；若确实失败，补偿 5 分钟后补发。
- 幂等粒度为"告警"而非"告警+号码"：部分号码发送失败（另一号码成功）时，补偿不会补发失败号码，
  可从发送记录（`send_status='failed'`）看出并人工补发。
- 日汇总无"当日已发"幂等：单容器部署 + cron 不会补跑，重启不会重复；未来多副本部署前需加幂等保护。
- 日汇总"到报不足半数拒发"比老系统严格：老系统 08:02 缺个别站也按 0 平均照发；我们等到 08:15，
  正常日 12/12 齐，个别站缺（≥半数）仍按老系统口径发，链路半断（<半数）则拒发并留痕，由运维人工判断。
- 网络异常重试可能重复送达：阿里云已受理但响应超时时会重试一次，用户可能收到两条相同短信（行业通行取舍，
  重复可忍受，漏发不可接受）。
- 补偿雨量告警不显示实测雨量值：DRP 字段在本库实测恒 0（假值），模板只拼站名；mq 实时回调的 value 由告警引擎传入，正常显示。

## 5. 部署步骤

1. 执行 DDL（KingbaseES）：

   ```bash
   ksql -h <host> -p 54321 -U SYSTEM -d qixiao-apaas -f sms-record-ddl.sql
   ```

2. 凭证与部署：deploy.sh 顶部（约第 18~21 行）直接填写 AK/SK/token 明文（值含 # @ 等字符时必须用单引号包裹），然后：

   ```bash
   ./deploy.sh
   ```

   ⚠ 提交 git 前必须把这 3 行清空为空串。AK/SK 为空时 `SMS_ENABLED` 自动 false 并打印警告。
   接收人默认取镜像内生产清单（日汇总 32 人 / 告警 4 人，见 application.properties）；
   临时只发测试号用环境变量覆盖：`SMS_RECEIVERS_DAILY=... SMS_RECEIVERS_ALARM=... ./deploy.sh`。

3. 联调验证（管理员登录后调用）：

   ```bash
   # 发一条日汇总样例给指定号码
   curl -X POST "http://<host>:<port>/sms/test?phone=<手机号>&type=daily"

   # 回调链路自测（token 用实际值）
   curl -X POST http://<host>:<port>/sms/alarm-event \
     -H "Content-Type: application/json" -H "X-Sms-Token: $SMS_CALLBACK_TOKEN" \
     -d '{"alertId":"test-001","metric":"rain","stcd":"00000001","threshold":30,"hour":1,"value":12.5}'
   ```

4. 日志核对点：
   - 日汇总：`日汇总 08:00 整点报文已齐（N/12 站）` → `日汇总短信取数 endTm=... 雨量(...) 水位[...]`
     （逐站明细见 `日汇总雨量：站号=... 雨量=...`；拒发时 `日汇总短信不发送：...`）
   - 告警：`短信发送完成`、`告警短信已处理过`、`同站点同指标 ... 静默`、`告警短信补偿扫描完成` 关键字

## 6. 运维排查

```sql
-- 某类短信最近发送记录
SELECT phone, send_status, response_code, response_message, sent_at
FROM "qixiao-apaas".t_auto_hltgq_water_sms_record
WHERE biz_type = 'daily' ORDER BY created_at DESC LIMIT 50;

-- 某个号码的发送历史
SELECT biz_type, template_code, send_status, sent_at
FROM "qixiao-apaas".t_auto_hltgq_water_sms_record
WHERE phone = '18956904399' ORDER BY created_at DESC LIMIT 50;

-- 某条告警是否已发
SELECT phone, send_status, sent_at FROM "qixiao-apaas".t_auto_hltgq_water_sms_record
WHERE alert_id = 'alert-001';
```

接口 `GET /sms/record/page?bizType=&phone=&startTime=&endTime=&page=1&size=10` 提供同样查询（需系统管理员登录，页大小上限 200）。
