## 一、通用约定

| 约定 | 说明 |
|------|------|
| 环境前缀 | `http://220.179.1.110:8081/hltgq-site`（下文路径均省略此前缀） |
| 鉴权 | 请求头 `Authorization: <sessionId>`（或 `X-Session-Id` 头、Cookie `sessionId`）；未登录 / 会话过期 → **401** `{"code":401,"message":"未登录"}`；会话服务不可用 → **503** |
| 会话获取 | `POST /auth/login`，`Content-Type: application/json`，body `{"key":"<32位key>","secret":"<32位secret>"}` → `{"success":true,"message":"登录成功","sessionId":"…"}`；key/secret 由我方线下提供 |
| 鉴权开关 | 由 `auth.enabled` 控制（默认 `false`，关闭时全部接口不校验）。灰度开启后所有接口统一要求 sessionId |
| null 语义 | 无数据返回 `null`，**不返回 0**（`0` = 真实值为 0）。前端按 `null` 显示「--」 |
| 时间格式 | 档案类字段 = 空格格式 `yyyy-MM-dd HH:mm:ss`；实时值 `tm` = ISO `yyyy-MM-dd'T'HH:mm:ss` |
| 刷新频率 | 全部为实时查询（无缓存），建议 60s 轮询 |

## 三、地图站点 + 实时值（`/external/station-monitor`）

### 3.1 请求

```
GET /external/station-monitor
GET /external/station-monitor?type=2
GET /external/station-monitor?type=2&name=渠首
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| type | String | 否 | `1` 水位（**不含闸站**，闸站见 `4`）/ `2` 雨量 / `3` 流量 / `4` 闸门 / `5` 视频 / `7` 墒情 / `8` 水质。亦兼容 `#2#` 编码与 `waterLevel` / `rainfall` / `flow` / `gate` / `video` / `moisture` / `waterQuality` 语义串。**不传或空白 = 全部点位（含实时值）**，见 3.8 |
| name | String | 否 | 站名模糊筛选，**包含即命中**（`渠首` 命中「渠首管理所」「渠首进水闸」）；不传或空白 = 不筛选 |

- `type` 非法 → **400** `{"message":"监测类型无效: xxx"}`（不传不报错）。
- `name` 只匹配站名（档案 `zzkaec`），不匹配站码；大小写敏感；纯空白等同不筛选。
- `name` 无命中 → `data: []`（HTTP 200、`success` 仍为 `true`），不再查实时值。
- **无分页**，一次返回全部站点（当前百站量级），不需要循环拉取。

### 3.2 响应结构

顶层信封为 `success` / `status` / `data` / `msg` 等，站点行数组在 `data`：

```json
      "hasData": true
    }

  "msg": null, "errCode": null, "time": null, "errorCode": null, "errorMsg": null

```

站点行 = **档案字段** + **实时值字段（平铺）** + `data` 子对象 + `hasData`。

顶层 **`totalCount` / `onlineCount`**：本次返回结果集的统计，按 `type` + `name` 过滤**之后**的站点算——
`totalCount` = `data` 行数，`onlineCount` = 其中 `isOnline=true` 的行数（不传 `type` 的全部模式同样有值）；
没有命中站点时为 `0` / `0`。前端「在线站点数 / 总站点数」直接取这两个字段，不要自己遍历 `data` 统计。

顶层 **`typeCounts`**：**仅全部模式（不传 `type`）有值**，按类型分组给出同样的两个数（键 `1`..`8`，与 `station-count.byType` 对齐）：
左侧图例的「总站点数 / 在线站点数」**一次请求即可拿全**，不需要为每个类型各发一次 `station-monitor`。
`1`/`2`/`3`/`4`/`5`/`7`/`8` 每项与该类型单独请求时信封上的 `totalCount` / `onlineCount` 完全一致（`type=1` 不含闸站、`type=5` 视频无实时值按档案状态判定）；
`6`（模型）不是合法 `type`（`?type=6` 返回 400 `监测类型无效: 6`），该项只能在此取。单类型请求该字段为 `null`。

- 平铺实时值与 `data` 是**同一份数据**的两种取法，二选一即可（新代码建议用平铺 + `hasData`）。
- `hasData=false` 时**实时值字段整体不出现**（不是值为 `null`，JS 取到 `undefined`）→ 判空用 `??` 或 `== null`，**不要用 `=== null`**。
- `hasData=true` 时个别指标仍可能为空（该时刻无采集），字段级也要兜底。
- 设备哨兵值 `-999`（设备不存在）后端已转 `null`；`-9991`（设备异常）部分类型原样返回，前端统一按「--」处理。

### 3.5 `isOnline` 口径

- **有实时值**：按各类型断联判定（水位站按档案状态；雨量按断联时长，水库站按站点状态；闸门按断联判定）。
- **全部点位模式（不传 `type`）**：该站任一类型实时值在线即 `true`（同站多类型共用采集设备时以任一类上报为准）；全无实时值时同样按档案状态回退。
- **无实时值（`hasData=false`）**：按档案状态回退——`zebpsu=2` → `false`（显示离线 / 标红）、`zebpsu=1` → `true`；档案未设状态按在线输出。
- 前端标红统一用 `isOnline`，不要直接读 `zebpsu`。

### 3.6 站点顺序

1. 已配置「站点排序」的站点：按配置序号在前，**不按在线状态调整**。
2. 未配置的站点：`type=1` 先按**有无实时水位**分组（`z` 有值在前、`z` 为空的站在后，含 `hasData=false`），组内再按在线优先（`isOnline=false` 落在所在组末尾），同组内保持档案 `iofhpi` 升序；其他类型只按「在线优先 + 档案 `iofhpi` 升序」。
3. 水质（`type=8`）无排序配置，保持默认顺序。
4. 排序配置与监测列表页同一份数据；但大屏对未配置站点额外做了「有值优先 / 在线优先」，页面没有这两级调整，两边顺序可能不同；前端**不要**再自行排序（会覆盖上述规则）。

### 3.7 取值兜底

```js
// 无数据统一判定：null / undefined / 设备哨兵值
const isEmpty = v => v == null || v === -999 || v === -9991;
const shown = v => (isEmpty(v) ? '--' : v);
const num = (v, digits = 2) => (isEmpty(v) ? '--' : Number(v).toFixed(digits));
const timeText = v => (v == null ? '--' : String(v).replace('T', ' ').slice(0, 16));

// 站点行
// s.hasData          该站此刻有无实时数据
// s.zzkaec           站名（档案）
// s.bviiio && s.bviiio.x   经度（档案）

```

- **分组计数 `typeCounts`**：`totalCount` = 档案 `epjutj` 含该类型的站点数（`type=1` 排除闸站，与 `type=1` 列表完全一致）；`onlineCount` = 其中该类型在线的站点数（该类型有实时值时取实时值 `isOnline`，无实时值时按档案 `zebpsu` 兜底——与单独请求同一判定）。多类型站各键重复计（7 类之和大于全部模式 `totalCount` 属预期）；`type=6` 模型类型一并给出供核对（`?type=6` 非法，不能单类型请求，只能在此取）。
- **`dataByType["1"]` 含闸站**：它是该站水位类型的实时值，闸站（`epjutj` 含 `4`）的水位实时值照常输出；而 `type=1` 列表在档案层排除闸站（闸站在 `type=4`）。**要统计「水位站数」请用 `typeCounts["1"]`，不要拿 `dataByType` 自己数**。
- **`coreIndicator`**：按站点自身登记的类型取——登记了水位（`1`）取水位核心指标，否则登记了雨量（`2`）取雨量；闸站恒为 `null`（同 3.3）。

- `dataByType` 只在全部模式出现；单类型请求仍只有 `data`，旧前端解析逻辑不受影响。

| 项 | 口径 |
|------|------|
| 县归属 | 用水户名称**包含县名**即归属该县（兼容「太湖县XX用水户」命名），命中多个全部计入 |

| 空值 | 全部为 `null` 即「缺失/未接入」，**绝不补 0**；前端 `null` 显示「--」 |

| `total.collectionRate` | Number? | 收费率(%) = 已收 ÷ 应缴 × 100，1 位截断；应缴缺失或 ≤ 0 为 `null` |
| `total.arrears` | Number? | 欠收(万元) = 应缴 − 已收，2 位截断；任一侧缺失为 `null` |
| `regions` | Array | 各区域征收情况；**按应缴降序**，`null` 排末位（同值按区域名升序） |
| `regions[].region` | String | 区域名称 = 账单关联的**用水户名称**（如「望江县」；含县 / 乡镇实际录入值，非固定四县） |
| `regions[].receivable` / `received` / `collectionRate` | Number? | 口径同 `total` |
| `months` | Array | 月度趋势，**固定 12 项**（`2026-01` ~ `2026-12`） |
| `months[].month` | String | `yyyy-MM` |
| `months[].receivable` / `received` / `collectionRate` | Number? | 口径同 `regions`；按账期终点 `period_end` 落月，该月无账单为 `null` |
| `years` | Array | **年度趋势（2026-10-28 新增）**，固定 3 项 = 近三年（`year-2` ~ `year`，升序） |
| `years[].year` | Number | 年份（如 `2026`） |
| `years[].receivable` / `received` / `collectionRate` / `arrears` | Number? | 口径同 `total`；按账期终点 `period_end` 落年，该年无账单为 `null` |

### 7.4 图表接入

| 页面元素 | 取数 |
|------|------|
| 四张卡片 | `total`：应缴 / 已收 / 收费率 / 欠收，直接展示，无需再聚合 |
| 各区域征收柱状折线图 | x 轴 `regions[].region`，柱 `receivable` / `received`，折线 `collectionRate` |
| 月度收缴趋势柱状折线图 | x 轴 `months[].month`，柱同上，折线同上（2026-10-28 起大屏已不用，保留回退） |
| **年度收缴趋势柱状折线图（替代月度）** | x 轴 `years[].year`（近三年、升序），柱 `receivable` / `received`，折线 `collectionRate` |

- 建议图例：柱「应缴水费 / 已收水费」，折线「收费率」。
- `receivable` / `received` 为 `null` 时该点**不画柱**；`collectionRate` 为 `null` 时折线**断开**。
- `years` 末项与 `total` 同源（同一年、同一批账单），可用 `total` 校验最后一年。

### 7.5 口径要点

| 项 | 口径 |
|------|------|
| 金额单位 | 账单库内为**元**，出参统一换算为**万元**（÷10000，2 位截断） |
| 归桶 | 按账单**账期终点 `period_end`** 落月 / 落年（跨月账单归终点所在月） |
| 区域归属 | 账单 `water_user_id` → 用水户名称；无区域（未挂接 / 已删 / 名称为空）的账单**不计入区域图、仍计入月度/年度与合计** |
| 年度趋势 | 近 3 年含统计年、升序；每年按账期终点 `period_end` 落年 |
| 四段一致性 | `total` / `regions` / `months` / `years` 由同一次取数聚合，`total` = 统计年各月之和 = `years` 末项 |

### 8.3 弹窗接入

```js
const sid = s.id;    // 或 s.iofhpi，两个接口均支持

// ① 该站全部设备
const dev = await get(`station-detail/device/page?stationId=${sid}&page=1&size=100`,
                      { headers: { Authorization: sessionId } });
dev.records.forEach(d => {
  d.status;              // 在线 / 离线（已翻译）
  d.location ?? '--';    // 安装位置（仅视频设备有值）
  d.code ?? '--';        // 设备编号（仅视频设备有值）
});

// ② 该站未关闭告警

```

流量站（档案 `epjutj` 含 `3`）不需要新接口——流量监测页面用的三个接口已直接支持大屏：
`stcd` 参数**同时接受站点编号 `iofhpi` 与档案主键 `id`**（服务端按 `stcd` / `site` 双键匹配），

> 仅 1 个站（`流量站点-1`，站码 `9999900001`）的 116 行历史数据 `site` 指向已删除的旧档案 id（2026-08 旧数据），
> 这类旧数据只能传站码命中；实际调用链传的是 `stcds` 返回的 `site`（= 站码），不受影响。
> 若按 `s.id` 传参遇到空结果，改传 `s.iofhpi` 即可（兜底规则保留）。

#### ① 实时信息（弹窗头部 + 瞬时 / 累计流量卡片）

```

```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| stcds | String | 否 | 站点标识（`iofhpi` 或档案 `id`），**逗号分隔可多选**；不传 = 全部流量站 |
| canalId | String | 否 | 渠系 id（按渠系及其子孙过滤），大屏不用 |
| startTime / endTime | String | 否 | `yyyy-MM-dd HH:mm:ss`，按时间区间筛选记录 |

返回**数组**（无信封），常用字段：`stcd` 站码、`site` 站点标识、`siteId` 档案主键、`stnm` 站名、`tm` 监测时间、
`q` 瞬时流量(m³/s)、`tf` / `cumulativeFlow` 累计流量(万m³)、`flowTm` 断联时累计的统计截止时刻、`vol` 电压、

#### ② 趋势图


| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| stcd | String | **是** | 站点标识（`iofhpi` 或档案 `id`） |
| startTime / endTime | String | 否 | `yyyy-MM-dd HH:mm:ss`；缺省 = 近 7 天 |

`granularity=hour` 时 `hour` 形如 `2026-11-06 15:00`（严格 1h 步长、无缺失，`flow` 为 `null` 即该小时无数据）；
`granularity=minute` 时 `hour` 为完整时刻 `2026-11-06 15:40:12`（不补齐、不聚合，曲线按实际采集点连）。
`flow` 为 `null` 表示该点无数据（`-999` / `-9991` 已过滤），前端断点不连线。

#### ③ 历史数据（表格 / 明细列表）

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| stcd | String | **是** | 站点标识（`iofhpi` 或档案 `id`） |
| startTime / endTime | String | 否 | `yyyy-MM-dd HH:mm:ss` |
| page / size | Number | 否 | 默认 1 / 10 |

返回 MyBatis-Plus 分页壳（`records` / `total` / `size` / `current` / `pages`），`records` 行字段同 ①，
按监测时间**倒序**（最新在前）；`tf` 已换算为万 m³。

> 本接口的 `q` 仅把 `-999`（设备不存在）转为 `null`，`-9991`（设备异常）原样透传；
> 趋势接口的 `flow` 则把 `-999` / `-9991` 均按无数据处理（断点）。前端按 `--` 兼底。

## 十、排错

| 现象 | 排查 |
|------|------|
| 401 `未登录` | 未带 `Authorization` 头 / 会话过期，重新 `POST /auth/login` |
| `station-monitor` 400 `监测类型无效: xxx` | `type` 不在 `1/2/3/4/5/7/8`（或兼容写法）内（未传 `type` 不报错：返回全部点位 + 各类型实时值） |
| `station-monitor` 全部模式某类实时值为空 | 该类实时值装载失败、超出 5s 总预算或被线程池拒绝（后端 WARN `全部点位模式装载 #N# 实时值失败` / `超出总预算` / `任务被拒绝`），只降级该类型；先确认对应业务接口是否异常、服务端并发是否过高 |
| 站点在列表里但实时值为空 | 该站当前无监测数据，`hasData=false` 属正常。实时值字段是「不出现」（`undefined`）而非 `null`，判空用 `??` / `== null`，不要用 `=== null` |
| 无数据站显示「离线」（标红） | 正常：`hasData=false` 时 `isOnline` 按档案状态回退。要变更请改站点档案在线状态 |
| 站点顺序与预期不同 | 先确认两条规则：未配置排序的按 `iofhpi` 升序排后、其中离线站落最后；已配置排序的以配置顺序为准。其余在「站点排序」页面配置 |
| `station-monitor` 传 `name` 返回 `data: []` | `name` 只匹配站名（不含站码）、包含匹配、大小写敏感；先不带 `name` 看全部站名再取片段重试 |
| 时间显示 `Invalid Date` | 档案 `createdAt` / `updatedAt` 是空格格式，Safari / iOS 需先 `.replace(' ', 'T')`；实时值 `tm` 自带 `T` |
| `overview` 的 `progress` / `allocatedVolume` 全为 `null` | 该年还没有有效年度计划（已生效/已归档）；需先在「用水计划」录入并生效 |
| `overview` 的 `demandVolume` 全为 `null` | 该年还没有待审核/已通过的用水申请 |
| `overview` 的 `irrigationArea` 为 `null` | 该县用水户档案未填「灌溉面积」（单位亩） |
| `overview` 的 `finishedVolume` 为 `null` | 该县用水户未配置闸口，或关联闸口当年无累计流量读数 |
| `fee-collection` 400 `year 取值范围 2000 ~ 2100` | `year` 越界或非数字 |
| `fee-collection` 的 `regions` 为空、`months` 全 `null` | 该年还没有已出账的水费账单；出账后自动出数 |
| `fee-collection` 的 `received` / `collectionRate` 恒为 `null` | 账单已出账但尚未收款（`paid` 为空） |
| `fee-collection` 的 `regions` 合计与 `total` 对不上 | 该年存在**无区域**账单（用水户未挂接 / 已删 / 名称为空），这类账单不入区域图、仍计入月度/年度与合计 |
| `fee-collection` 的 `years` 前两年全 `null` | 新账单表 2026 年才开始沉淀，往年均无已出账账单；随年份推移自动有数，非接口异常 |
| `station-detail` 400 `站点不存在` | `stationId` 传了档案里没有的键；先确认该站是否已删除 |
| 弹窗设备 `code` / `location` 全为 `--` | 台账现状：仅视频设备录了编号与位置，非接口异常 |
