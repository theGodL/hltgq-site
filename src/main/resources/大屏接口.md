# 大屏接口

> 面向大屏前端。按**页面位置**组织：地图站点 → 右侧面板 → 站点弹窗。
> 文中路径、参数、字段均与 `hltgq-site` 当前代码一致；如有出入以代码为准并回头修改本文档。

## 一、通用约定

| 约定 | 说明 |
|------|------|
| 环境前缀 | `http://220.179.1.110:8081/hltgq-site`（下文路径均省略此前缀） |
| 鉴权 | 请求头 `Authorization: <sessionId>`（或 `X-Session-Id` 头、Cookie `sessionId`）；未登录 / 会话过期 → **401** `{"code":401,"message":"未登录"}`；会话服务不可用 → **503** |
| 会话获取 | `POST /auth/login`，`Content-Type: application/json`，body `{"key":"<32位key>","secret":"<32位secret>"}` → `{"success":true,"message":"登录成功","sessionId":"…"}`；key/secret 由我方线下提供 |
| 鉴权开关 | 由 `auth.enabled` 控制（默认 `false`，关闭时全部接口不校验）。灰度开启后所有接口统一要求 sessionId |
| null 语义 | 无数据返回 `null`，**不返回 0**（`0` = 真实值为 0）。前端按 `null` 显示「--」 |
| 时间格式 | 档案类字段 = 空格格式 `yyyy-MM-dd HH:mm:ss`；实时值 `tm` = ISO `yyyy-MM-dd'T'HH:mm:ss` |
| 刷新频率 | 全部为实时查询（无缓存），建议 60s 轮询 |

## 三、地图站点 + 实时值（`/external/station-monitor`）

### 3.1 请求

```
GET /external/station-monitor?type=2
GET /external/station-monitor?type=2&name=渠首
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| type | String | **是** | `1` 水位 / `2` 雨量 / `3` 流量 / `4` 闸门 / `7` 墒情 / `8` 水质。亦兼容 `#2#` 编码与 `waterLevel` / `rainfall` / `flow` / `gate` / `moisture` / `waterQuality` 语义串 |
| name | String | 否 | 站名模糊筛选，**包含即命中**（`渠首` 命中「渠首管理所」「渠首进水闸」）；不传或空白 = 不筛选 |

- `type` 非法或缺参 → **400** `{"message":"监测类型无效: xxx"}`。
- `name` 只匹配站名（档案 `zzkaec`），不匹配站码；大小写敏感；纯空白等同不筛选。
- `name` 无命中 → `data: []`（HTTP 200、`success` 仍为 `true`），不再查实时值。
- **无分页**，一次返回全部站点（当前百站量级），不需要循环拉取。

### 3.2 响应结构

顶层信封为 `success` / `status` / `data` / `msg` 等，站点行数组在 `data`：


站点行 = **档案字段** + **实时值字段（平铺）** + `data` 子对象 + `hasData`。

- 平铺实时值与 `data` 是**同一份数据**的两种取法，二选一即可（新代码建议用平铺 + `hasData`）。
- `hasData=false` 时**实时值字段整体不出现**（不是值为 `null`，JS 取到 `undefined`）→ 判空用 `??` 或 `== null`，**不要用 `=== null`**。
- `hasData=true` 时个别指标仍可能为空（该时刻无采集），字段级也要兜底。
- 设备哨兵值 `-999`（设备不存在）后端已转 `null`；`-9991`（设备异常）部分类型原样返回，前端统一按「--」处理。

### 3.5 `isOnline` 口径

- **有实时值**：按各类型断联判定（水位站按档案状态；雨量按断联时长，水库站按站点状态；闸门按断联判定）。
- **无实时值（`hasData=false`）**：按档案状态回退——`zebpsu=2` → `false`（显示离线 / 标红）、`zebpsu=1` → `true`；档案未设状态按在线输出。
- 前端标红统一用 `isOnline`，不要直接读 `zebpsu`。

### 3.6 站点顺序

1. 已配置「站点排序」的站点：按配置序号在前，**不按在线状态调整**。
2. 未配置的站点：按档案 `iofhpi` 升序排在已配置站点之后，其中 `isOnline=false` 的离线站落在这批的最后。
3. 水质（`type=8`）无排序配置，保持默认顺序。
4. 排序配置与监测列表页同一份数据，因此大屏顺序与页面顺序天然一致；前端**不要**再自行排序（会覆盖上述规则）。

### 3.7 取值兜底

```js
// 无数据统一判定：null / undefined / 设备哨兵值
const isEmpty = v => v == null || v === -999 || v === -9991;
const shown = v => (isEmpty(v) ? '--' : v);
const num = (v, digits = 2) => (isEmpty(v) ? '--' : Number(v).toFixed(digits));
const timeText = v => (v == null ? '--' : String(v).replace('T', ' ').slice(0, 16));

// 站点行
// s.hasData          该站此刻有无实时数据
// s.zzkaec           站名（档案）
// s.bviiio && s.bviiio.x   经度（档案）
// s.drp              当前雨量（实时值平铺；hasData=false 时取不到）
```

> 档案字段（`zzkaec` / `iofhpi` / `bviiio` / `ahieto` / `ccnhtm` / `ijzsby` / `createdAt` 等）与实时值无关，`hasData=false` 时仍有值，不参与「--」。

## 四、右侧面板 · 水资源 + 灌溉配水（`/h5/water-resource/overview`）

> **两个 Tab 共用一个接口、一次请求**：水资源 Tab 取 `allocationList`；灌溉配水 Tab 取 `irrigationStats` + `countyDetails`。
> 原「水资源量分布」饼图已下线，响应中**不再有 `distribution` 字段**。

### 4.1 请求

```
GET /h5/water-resource/overview
GET /h5/water-resource/overview?startDate=2026-01-01 00:00:00&endDate=2027-01-01 00:00:00
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| startDate | String | 否 | 统计起点，`yyyy-MM-dd HH:mm:ss`（前端 `date.min` 直传）；缺省 = 本年度 1 月 1 日 0 点 |
| endDate | String | 否 | 统计终点（**不含**），格式同上（前端 `date.max` 直传）；缺省 = 次年 1 月 1 日 0 点 |

- **年份取 `startDate` 所在年**，作用于「该年年度计划」与「该年用水申请」的选取。
- 参数非法/未传 → 记 warn 日志并回退本年度区间，**不报错**。
- 响应**无信封**，直接返回数据对象（与第三章 `station-monitor` 不同）。

| `userNo` | String | 用水户编号（如 `YH006`） |
| `district` | String | **行政区 = 用水户名称**（如「宿松县」），不是固定四县 |
| `allocatedVolume` | Number? | **分配水量**(万m³) = 该用水户当年有效年度计划的计划水量合计，2 位截断；无有效计划为 `null` |
| `progress` | Number? | **执行进度**(%) = 该户闸口当年放水量 ÷ 分配水量 × 100，1 位截断；缺口径为 `null` |

- 行数 = 当年度正常状态用水户数（业务上配置为一县一户，**不硬编码 4 行**）。
- 年度计划口径：`plan_type='#1#'`（年度计划）且状态为已生效/已归档，`period_start` 年份 = 统计年，同户多份取最新一份。
- 放水量口径：该户关联闸口逐个按计量符号合计（差额站扣减取负）；**任一闸口无读数或读数回退 → 该户不计入**（不估算）。

#### `irrigationStats` — 灌溉配水两卡片

| 字段 | 类型 | 说明 |
|------|------|------|
| `totalArea` | Number | **灌溉总面积**(万亩)，固定 `105.83` |
| `finishedVolume` | Number? | **已完成供水**(万m³) = 四县供水之和，3 位截断；四县全缺失为 `null` |

#### `countyDetails` — 各区域灌溉详情（固定 4 行）

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | String | 稳定编码：`susong` / `huaining` / `wangjiang` / `taihu`（前端按 code 映射，不依赖数组顺序） |
| `district` | String | 行政区名（固定顺序：宿松 → 怀宁 → 望江 → 太湖） |
| `irrigationArea` | Number? | **该县面积**(万亩) = 该县用水户档案「灌溉面积」(亩) ÷ 10000，2 位截断；未维护为 `null` |
| `finishedVolume` | Number? | **供水**(万m³) = 该县用水户关联闸口当年放水量合计，3 位截断；无数据为 `null` |
| `demandVolume` | Number? | **总需水**(万m³) = 该县用水户当年用水申请合计，2 位截断；无申请为 `null` |

### 4.4 口径要点

| 项 | 口径 |
|------|------|
| 县归属 | 用水户名称**包含县名**即归属该县（兼容「太湖县XX用水户」命名），命中多个全部计入 |
| 面积维护 | 在「用水户」页面手填 `灌溉面积`（单位**亩**），一县一户即县面积；改档案即生效，无需改代码或重启 |
| 用水申请 | 状态 `#1#`（待审核）+ `#2#`（已通过）；已驳回不计；年份取 `period_year`，为空回退 `start_date` 的年份 |
| 数值精度 | 供水 3 位截断（累计流量口径）；分配水量 / 总需水 / 面积 2 位截断；进度 1 位截断；**一律截断不四舍五入** |
| 空值 | 全部为 `null` 即「缺失/未接入」，**绝不补 0**；前端 `null` 显示「--」 |
| 合计一致性 | `irrigationStats.finishedVolume` = `countyDetails` 各行 `finishedVolume` 之和（先分县截断再相加，避免 0.001 级偏差） |

### 4.5 前端接入

| 页面元素 | 取数 |
|------|------|
| 水资源 Tab · 分配方案列表 | `allocationList`：行政区=`district`、分配水量=`allocatedVolume`、执行进度=`progress` |
| 水资源 Tab · 月度取水量趋势 | 不取本接口，见「六」月度累计趋势 |
| 灌溉配水 Tab · 两卡片 | `irrigationStats.totalArea` / `finishedVolume` |
| 灌溉配水 Tab · 四县卡片 | `countyDetails`：县名 `district`、面积 `irrigationArea`、供水 `finishedVolume`、总需水 `demandVolume` |
| 灌溉配水 Tab · 供/需对比柱状图 | x 轴 `countyDetails[].district`，两组柱子 `finishedVolume` / `demandVolume` |
| 灌溉配水 Tab · 已灌亩数 | **已下线**，前端不再展示「已灌 xx 万亩 / xx 万平方米」 |

- `finishedVolume` / `demandVolume` 为 `null` 时该柱**不画**（不要按 0 处理）；
- `irrigationArea` 为 `null` 时面积标签显示「--」。

### 4.6 边界场景

| 场景 | 表现 |
|------|------|
| 年度无有效年度计划 | `allocationList` 各行 `allocatedVolume` / `progress` 为 `null`（仍返回全部正常用水户行） |
| 用水户未配置闸口 / 闸口无读数 | 该户 `progress` 为 `null`，`countyDetails` 对应县 `finishedVolume` 为 `null` |
| 年度无待审核/已通过的用水申请 | `countyDetails` 各行 `demandVolume` 为 `null` |
| 用水户名称不含县名 | 该户仍出现在 `allocationList`，但不计入任何县卡片 |
| 用水户档案未填灌溉面积 | 该县 `irrigationArea` 为 `null` |
| 无已完成需水方案 | 不影响本接口（面积不依赖需水方案），四县行照常返回 |

## 七、右侧面板 · 用水缴费（`/water-use-summary/fee-collection`）

> 用途：四张卡片（应缴 / 已收 / 收费率 / 欠收）+ 各区域征收柱状折线图 + 月度收缴趋势柱状折线图，**一个接口一次返回三段数据**。
> 数据源：新版水费账单 `t_auto_hltgq_water_bill`（调度方案出账 + 手工台账出账统一沉淀），不读旧水费计算表单。

### 7.1 请求

```
GET /water-use-summary/fee-collection?year=2026
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| year | int | 否 | 统计年份；**不传 = 当年**（大屏常显当年，可不传）；超出 `2000 ~ 2100` → **400** |

响应**无信封**，直接返回数据对象。

### 7.2 响应

```json
{
  "year": 2026,
  "total": { "receivable": 531.89, "received": 531.89, "collectionRate": 100.0, "arrears": 0.00 },
  "regions": [
    { "region": "望江县", "receivable": 1234.56, "received": 900.00, "collectionRate": 72.9 },
    { "region": "太湖县", "receivable": 800.10, "received": null, "collectionRate": null }
  ],
  "months": [
    { "month": "2026-01", "receivable": null, "received": null, "collectionRate": null },
    { "month": "2026-09", "receivable": 2034.66, "received": 900.00, "collectionRate": 44.2 },
    { "month": "2026-12", "receivable": null, "received": null, "collectionRate": null }
  ]
}
```

> 数值为结构示意，以线上实际为准；`months` 实际固定 12 项，示例仅列 3 项。

### 7.3 字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `year` | Number | 实际统计年份 |
| `total` | Object | **年度合计（四张卡片）**；当年无账单时四个字段均为 `null` |
| `total.receivable` | Number? | 应缴水费(万元) = 账单 `amount` 合计 ÷ 10000，2 位截断 |
| `total.received` | Number? | 已收水费(万元) = 账单 `paid` 合计 ÷ 10000，2 位截断 |
| `total.collectionRate` | Number? | 收费率(%) = 已收 ÷ 应缴 × 100，1 位截断；应缴缺失或 ≤ 0 为 `null` |
| `total.arrears` | Number? | 欠收(万元) = 应缴 − 已收，2 位截断；任一侧缺失为 `null` |
| `regions` | Array | 各区域征收情况；**按应缴降序**，`null` 排末位（同值按区域名升序） |
| `regions[].region` | String | 区域名称 = 账单关联的**用水户名称**（如「望江县」；含县 / 乡镇实际录入值，非固定四县） |
| `regions[].receivable` / `received` / `collectionRate` | Number? | 口径同 `total` |
| `months` | Array | 月度趋势，**固定 12 项**（`2026-01` ~ `2026-12`） |
| `months[].month` | String | `yyyy-MM` |
| `months[].receivable` / `received` / `collectionRate` | Number? | 口径同 `regions`；按账期终点 `period_end` 落月，该月无账单为 `null` |

### 7.4 图表接入

| 页面元素 | 取数 |
|------|------|
| 四张卡片 | `total`：应缴 / 已收 / 收费率 / 欠收，直接展示，无需再聚合 |
| 各区域征收柱状折线图 | x 轴 `regions[].region`，柱 `receivable` / `received`，折线 `collectionRate` |
| 月度收缴趋势柱状折线图 | x 轴 `months[].month`，柱同上，折线同上 |

- 建议图例：柱「应缴水费 / 已收水费」，折线「收费率」。
- `receivable` / `received` 为 `null` 时该点**不画柱**；`collectionRate` 为 `null` 时折线**断开**。

### 7.5 口径要点

| 项 | 口径 |
|------|------|
| 金额单位 | 账单库内为**元**，出参统一换算为**万元**（÷10000，2 位截断） |
| 归桶 | 按账单**账期终点 `period_end`** 落月 / 落年（跨月账单归终点所在月） |
| 区域归属 | 账单 `water_user_id` → 用水户名称；无区域（未挂接 / 已删 / 名称为空）的账单**不计入区域图、仍计入月度与合计** |
| 三图一致性 | `total` / `regions` / `months` 由同一次取数聚合，`total` = 各月之和 |

## 八、站点弹窗（设备 + 告警）

> 点击站点后弹出的信息框：该站下**全部设备** + 该站**未关闭告警**。
> 站点参数支持**双键**：档案 `id`（如 `dByBR1Xdze8shnRGAw9`）或站点编号 `iofhpi`（如 `QSJSZ`、`9000000136`），二选一直接传。

### 8.1 该站全部设备

```
GET /station-detail/device/page?stationId=9000000136&page=1&size=100
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|

### 8.2 该站未关闭告警

```
GET /alert/page?siteId=9000000136&page=1&size=10
```

| 参数 | 类型 | 必填 | 说明 |

| siteName | String | 否 | 站点名称模糊筛选（可与 `siteId` 叠加；弹窗建议用 `siteId`） |

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | String | 告警主键 |

| `siteName` | String? | 站点名称 |
| `deviceId` | String? | 设备主键（与设备列表 `id` 对应） |
| `deviceName` | String? | 设备名称 |

### 8.3 弹窗接入

```js
const sid = s.id;    // 或 s.iofhpi，两个接口均支持

// ① 该站全部设备
const dev = await get(`station-detail/device/page?stationId=${sid}&page=1&size=100`,
                      { headers: { Authorization: sessionId } });
dev.records.forEach(d => {
  d.status;              // 在线 / 离线（已翻译）
  d.location ?? '--';    // 安装位置（仅视频设备有值）
  d.code ?? '--';        // 设备编号（仅视频设备有值）
});

// ② 该站未关闭告警
const alert = await get(`alert/page?siteId=${sid}&page=1&size=10`,
                        { headers: { Authorization: sessionId } });
alert.total;             // 未关闭告警总数（可作弹窗角标）
```

> 设备行 `code` / `location` 为空属台账数据现状（仅视频设备已录），按 `--` 兜底，不要判为接口异常。

- 这是**启效平台（qx-apaas）的低代码数据接口**，运行在平台侧，**代码不在本仓库**；返回年度水费明细（字段名为平台随机编码，如 `qnbmzx` 区域、`hdozce` 应缴金额），由前端拉取后自行求和出四张卡片。
- 本仓库的 `fee-collection` 已能直接给出四卡片（`total`），**前端切换到 `total` 之后该接口即可下线**。
- 时间线：前端**尚未切换**，当前四张卡片仍走 helussya。

## 十、排错

| 现象 | 排查 |
|------|------|
| 401 `未登录` | 未带 `Authorization` 头 / 会话过期，重新 `POST /auth/login` |
| `station-monitor` 400 `监测类型无效: xxx` | `type` 不在 `1/2/3/4/7/8`（或兼容写法）内，或未传 |
| 站点在列表里但实时值为空 | 该站当前无监测数据，`hasData=false` 属正常。实时值字段是「不出现」（`undefined`）而非 `null`，判空用 `??` / `== null`，不要用 `=== null` |
| 无数据站显示「离线」（标红） | 正常：`hasData=false` 时 `isOnline` 按档案状态回退。要变更请改站点档案在线状态 |
| 站点顺序与预期不同 | 先确认两条规则：未配置排序的按 `iofhpi` 升序排后、其中离线站落最后；已配置排序的以配置顺序为准。其余在「站点排序」页面配置 |
| `station-monitor` 传 `name` 返回 `data: []` | `name` 只匹配站名（不含站码）、包含匹配、大小写敏感；先不带 `name` 看全部站名再取片段重试 |
| 时间显示 `Invalid Date` | 档案 `createdAt` / `updatedAt` 是空格格式，Safari / iOS 需先 `.replace(' ', 'T')`；实时值 `tm` 自带 `T` |
| `overview` 的 `progress` / `allocatedVolume` 全为 `null` | 该年还没有有效年度计划（已生效/已归档）；需先在「用水计划」录入并生效 |
| `overview` 的 `demandVolume` 全为 `null` | 该年还没有待审核/已通过的用水申请 |
| `overview` 的 `irrigationArea` 为 `null` | 该县用水户档案未填「灌溉面积」（单位亩） |
| `overview` 的 `finishedVolume` 为 `null` | 该县用水户未配置闸口，或关联闸口当年无累计流量读数 |
| `fee-collection` 400 `year 取值范围 2000 ~ 2100` | `year` 越界或非数字 |
| `fee-collection` 的 `regions` 为空、`months` 全 `null` | 该年还没有已出账的水费账单；出账后自动出数 |
| `fee-collection` 的 `received` / `collectionRate` 恒为 `null` | 账单已出账但尚未收款（`paid` 为空） |
| `fee-collection` 的 `regions` 合计与 `total` 对不上 | 该年存在**无区域**账单（用水户未挂接 / 已删 / 名称为空），这类账单不入区域图、仍计入月度与合计 |
| `station-detail` 400 `站点不存在` | `stationId` 传了档案里没有的键；先确认该站是否已删除 |
| 弹窗设备 `code` / `location` 全为 `--` | 台账现状：仅视频设备录了编号与位置，非接口异常 |
