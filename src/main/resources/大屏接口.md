## 零、快速上手（前端先看这里）

> 本章 ~ 第十章均为**站点列表接口**（`/external/station-monitor`）的内容；征收/收缴统计接口见「十一」章。

> 站点列表场景（雨量、水位、流量、闸门、墒情、水质六类）：一次请求拿到「站点清单 + 各站实时值」。
>
> 背景：原做法是「先调上游平台 `qx-api` 取站点列表，再按站逐个调监测接口取值」，雨量站点需 1 + N 次请求（18 站 = 20 次），且站点顺序无法跟随页面配置。本接口将两者合并为**一次请求**：站点集合与上游平台列表**同口径**（含当前无数据的站点），实时值**按类型批量查询**（无逐站请求），站点顺序按我方「站点排序」配置输出。该接口在《三维系统对接接口.md》第十四章有简版描述，细节以本文档为准。

> 阅读顺序建议：本章（怎么接通、字段从哪取）→ 第二、三、四、五章（结构与字段表）→ 第八章（迁移对照）；第六章是后端口径与性能背景，可按需查阅。

### 0.1 一句话理解本接口

一个 `GET` 请求，返回**站点清单 + 每个站的实时值**：站点来自站点档案（与上游平台列表**同名同结构**），实时值来自各监测接口（与该接口**同名同格式**），且**顺序与页面一致**。原来「先取列表、再逐站查数据」的 1 + N 次请求，现在一次完成。

### 0.2 四个术语

| 术语 | 含义 | 取值写法 |
|------|------|------|
| **档案字段** | 站点档案的字段（站名 `zzkaec`、站码 `iofhpi`、经纬度 `bviiio`、管理单位 `ahieto`…），与上游平台列表同名同结构 | `s.zzkaec` |
| **实时值字段** | 各监测接口的字段（`tm` / `drp` / `z` / `q`…），同名同格式，直接**平铺**在站点行上 | `s.drp` |
| **`data` 子对象** | 同一份实时值再包一层，给习惯 `data.xxx` 的代码用 | `s.data.drp` |
| **`hasData`** | 该站此刻有没有实时数据；`false` = 站点在档案里、监测数据还没来 | `s.hasData` |

> 平铺与 `data` 是**同一份数据**的两种取法，二选一即可（新代码建议用平铺 + `hasData`，判空更直观）。

### 0.3 三步接通

**第 1 步：取会话**（key / secret 由我方线下提供）

```js
// 示例为 async 函数（或模块顶层）内的写法
const BASE = 'http://220.179.1.110:8081/hltgq-site';
const login = await fetch(`${BASE}/auth/login`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ key: '<key>', secret: '<secret>' }),
}).then(r => r.json());
const sessionId = login.sessionId;          // 后续请求都带上它
```

**第 2 步：一次请求拿到站点 + 实时值**（`type=2` 雨量）

```js
const res = await fetch(`${BASE}/external/station-monitor?type=2`, {
  headers: { Authorization: sessionId },
}).then(r => r.json());

res.success;      // true
res.data;         // 站点行数组（档案字段 + 实时值字段 + data + hasData）
```

**第 3 步：取值渲染**

```js
res.data.forEach(s => {
  s.zzkaec;                // 站名（档案字段）
  s.bviiio && s.bviiio.x;  // 经度（档案字段；无坐标时 bviiio 为 null）
  s.hasData;               // 该站此刻是否有实时数据
  s.drp;                   // 当前雨量（实时值；hasData=false 时取不到）
  s.data && s.data.tm;     // 或走 data 子对象（与平铺同一份实时值）
});
```

### 0.4 必读 6 条（不踩坑）

| # | 要点 |
|:--:|------|
| 1 | **`hasData=false` 时实时值字段整个不存在**（不是值为 `null`）→ JS 取到 `undefined`。判空用 `??` 或 `== null`，**不要用 `=== null`**（会漏判） |
| 2 | **`hasData=true` 也可能个别字段为空**（该时刻无采集，如 `vol`、水质 `bod5`）→ 字段级也要兜底 |
| 3 | **哨兵值**：`-999`（设备不存在）后端已转 `null`；`-9991`（设备异常）部分类型原样返回 → 两者都按「无数据」处理（见第五章兜底函数） |
| 4 | **两种时间格式**：实时值 `tm` = ISO `2026-09-16T20:43:00`（带 `T`，可直接 `new Date()`）；档案 `createdAt` / `updatedAt` = 空格格式 `2026-05-28 19:54:58`（Safari / iOS 直接 `new Date()` 会得到 `Invalid Date`，展示前先 `replace(' ', 'T')`） |
| 5 | **在线判断用 `isOnline`**（不是档案 `zebpsu`）：`isOnline=false` 才标红；`hasData=false` 时 `isOnline` 不存在（= 无数据），**不要标红** |
| 6 | **无分页**：一次返回全部站点，不需要写分页 / 循环拉取 |

### 0.5 页面元素 → 字段速查

| 页面元素 | 取字段 | 备注 |
|------|------|------|
| 站点名称 | `zzkaec` | 档案权威站名（实时值 `stnm` 同源，建议统一用 `zzkaec`） |
| 站码 / 站点编号 | `iofhpi` | 闸门实时值不含 `stcd`，展示站码用这个 |
| 经纬度 | `bviiio.x` / `bviiio.y` | 无坐标时 `bviiio` 为 `null` |
| 管理单位 | `ahieto.dataTitle` | `ahietoId` 为单位记录 id |
| 所属渠系 | `ywvyds.dataTitle` | 可能为 `null` |
| 监测类型（图标） | `epjutj` | 数组（已去 `#`），如 `["1","2"]` = 水位 + 雨量 |
| 站点主键（关联用） | `id` | 档案主键，也是闸门 / 墒情 / 水质实时值的匹配键 |
| 采集时间 | `tm` | ISO 格式（实时值字段） |
| 在线 / 离线 | `isOnline` | 实时值字段；缺失 = 无数据（见必读第 5 条） |
| 各类型指标 | 见第四章 | 雨量 `drp` / `rain1h`…、水位 `z`、流量 `q` / `tf`（`tf` 为累计流量万m³）、闸门 `upZ` / `downZ`、墒情 `mten`…、水质 `nh3n`… |
| 该站有无实时数据 | `hasData` | `false` 时上表所有实时值字段都不存在 |

## 一、接口定义

```
GET /external/station-monitor?type=2
GET /external/station-monitor?type=2&name=渠首      # name 可选：按站名模糊筛选
```

生产完整地址：`http://220.179.1.110:8081/hltgq-site/external/station-monitor?type=2&name=渠首`

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| type | String | **是** | 监测类型：`1` 水位 / `2` 雨量 / `3` 流量 / `4` 闸门 / `7` 墒情 / `8` 水质（**与上游平台 `type` 数字同口径，原值直接传**） |
| name | String | 否 | 站点名称模糊词，**包含即命中**（如 `name=渠首` 命中「渠首管理所」「渠首进水闸」）；不传或传空白表示不筛选 |

`type` 另兼容两种写法（便于联调，不改也行）：编码 `#2#`、语义串 `waterLevel` / `rainfall` / `flow` / `gate` / `moisture` / `waterQuality`。**非法值或缺参报 400**：`{"message": "监测类型无效: xxx"}`。

`name` 细节（与上游平台 `kjximffu?code=&name=` 的 `name` 同口径，原值直接传）：

- **兼容性**：`name` 为新增可选参数，**不传时接口行为与旧版完全一致**（已接入的调用方无需任何改动）。
- 只匹配**站名**（档案 `zzkaec`），不匹配站码 `iofhpi`；大小写敏感；`%` / `_` 不作转义（与上游平台行为一致）。
- 无命中时返回 `data: []`（HTTP 200、`success` 仍为 `true`）——站名无命中时**不再查询实时值**，响应更快。
- **筛选只影响站点集合**：字段结构、`hasData` 语义、顺序规则均不变（命中站点仍按「站点排序」配置输出，未配置的按 `iofhpi` 升序排在其后）。

| type | 监测类型 | 站点顺序跟随「站点排序」配置 | 实时值来源（同名同格式） |
|:--:|------|:--:|------|
| 1 | 水位 | 水位 | `GET /irrigation-water-level/page` |
| 2 | 雨量 | 雨量 | `GET /st-pptn-r/gq-rainfall`（含水库雨量站） |
| 3 | 流量 | 流量 | `GET /flow-monitor/monitoring` |
| 4 | 闸门 | 闸门 | `GET /gate-monitor/monitoring` |
| 7 | 墒情 | 墒情 | `GET /soil-moisture/monitoring` |
| 8 | 水质 | 无排序配置，保持默认顺序 | `GET /water-quality/monitoring` |

## 三、档案字段（每行都有，与上游平台列表同名同结构）

| `corpCode` | String | 固定 `hltgq` |
| `createdBy` | Object? | 创建人：`dataTitle` 姓名、`id` 用户 id（已解析为姓名） |

## 四、实时值字段（按 type 不同，名为平铺 + `data` 子对象两份）

以下字段名、精度、时间格式与对应监测接口**完全一致**（就是同一份数据；时间均为 ISO `yyyy-MM-dd'T'HH:mm:ss`，数值按各接口精度输出）。**三个通用规则先看这里**：

1. **时间**：`tm` 统一为 ISO `yyyy-MM-dd'T'HH:mm:ss`（**带 `T`**）；档案字段 `createdAt` / `updatedAt` 是空格格式，见第七章。
2. **无采集**：该指标此刻没有数据 → 值为 `null`；合并到站点行后，**平铺字段直接不出现**（`data` 子对象里是 `null`）。
3. **设备哨兵值**：`-999`（设备不存在）后端转 `null`；`-9991`（设备异常）**部分类型原样返回**——两者都表示「不可用」，前端统一按无数据处理（见第五章兜底函数）。

### type=1 水位

| 字段 | 类型 | 说明 |
|------|------|------|
| `stcd` / `stnm` | String | 站点编号 / 站点名称 |
| `tm` | String | 监测时间（ISO） |
| `z` | Number? | 水位（m） |
| `rise1h` | Number? | 1h 水位涨幅（cm） |
| `vol` | Number? | 电压（V） |
| `isOnline` | Boolean | 在线状态（站点档案 `zebpsu` 口径：水位站均为库上站点，不按采集时间断联） |

```json
{ "stcd": "3206400001", "stnm": "周家河", "id": "0puvPIlgT6E7Jg9OGpM",
  "tm": "2026-09-16T20:43:00", "z": 93.96, "rise1h": -3.00, "vol": 0.1, "isOnline": true }
```

### type=2 雨量

| 字段 | 类型 | 说明 |
|------|------|------|
| `stcd` / `stnm` | String | 站点编号 / 站点名称 |
| `lon` / `lat` | Number? | 经纬度（与档案 `bviiio` 同源） |
| `tm` | String | 最新报文时间（ISO） |
| `drp` | Number? | 当前雨量（mm）= 当前水文日（8 点起）累计 |
| `dyp` | Number? | 累计雨量（mm，RTU 安装至今总累计，永不归零） |
| `rain1h` / `rain3h` / `rain6h` | Number? | 1h / 3h / 6h 时段雨量（mm，按水文日边界截断） |

## 五、`data` 子对象与 `hasData`

| 字段 | 类型 | 说明 |
|------|------|------|
| `data` | Object? | 该行实时值的子对象（**内容与平铺实时值完全一致**，供习惯 `data.xxx` 取值的代码使用）；该站无实时数据为 `null` |
| `hasData` | Boolean | 该站当前是否有实时数据：`false` = 档案中存在该类型站点但无监测数据（此时**实时值字段全部不出现**——平铺字段无该 key、`data` 为 `null`；档案字段不受影响） |

> 平铺与 `data` 两者都返回，前端按现有取值习惯二选一即可，无需两份都用。

> 前端取值建议（**判定规则**；显示文案由前端 / 产品定）：
>
> 1. 整站无数据用 `hasData` 判断，**不要写 `s.drp === null`**：`hasData=false` 时实时值字段是「不存在」而非「值为 `null`」，JS 中取到 `undefined`，`=== null` 会漏判；单字段兜底用 `s.drp ?? '--'` 或 `s.drp == null`（双等号）。
> 2. `hasData=true` 也可能**个别字段为空**（该时刻无采集）：平铺里该字段不出现、`data` 取值时为 `null`（如水质 `bod5` 设备不上报恒为空、电压 `vol` 无采集）；字段级仍需兜底。
> 3. 哨兵值：`-999`（设备不存在）后端已转 `null`；`-9991`（设备异常）**部分类型原样返回**（见第四章开头通用规则第 3 条）——有值但不可用，统一按「--」处理。
> 4. `isOnline` 属于实时值字段：`hasData=false` 时不存在，此时按「无数据」处理，**不要当成离线标红**。
> 5. 档案字段（`zzkaec` / `iofhpi` / `bviiio` / `ahieto` / `zebpsu` / `ccnhtm` / `ijzsby` / `createdAt` 等）与实时值无关，`hasData=false` 时仍有值，不参与「--」。

可复制的兜底写法（建议收敛成一个工具，别在页面里散着判）：

```js
// 无数据统一判定：null / undefined / 设备哨兵值（-999 设备不存在、-9991 设备异常）
const isEmpty = v => v == null || v === -999 || v === -9991;

// 文本：空值 → 占位符（占位符文案由前端 / 产品定）
const shown = v => (isEmpty(v) ? '--' : v);

// 数值：按页面口径保留小数（雨量 / 水位 2 位、流量 3 位…）
const num = (v, digits = 2) => (isEmpty(v) ? '--' : Number(v).toFixed(digits));

// 时间：实时值 tm 带 T，直接展示前换空格；档案时间也是空格格式
const timeText = v => (v == null ? '--' : String(v).replace('T', ' ').slice(0, 16));
```

## 六、数据口径与性能

- **站点集合**：站点档案中监测类型含对应 `#N#` 的站点（与上游平台列表**同源同口径，含当前无数据的站点**），SQL 层按站点编号 `iofhpi` 升序。
- **站点顺序**：按我方「站点排序」页面配置输出——水位 / 雨量 / 流量 / 闸门 / 墒情五类各自独立配置的序号，**已配置站点在前按配置顺序、未配置站点保持默认顺序在后**；水质无排序配置，保持默认顺序。排序配置与页面（监测列表页）**同一份数据**，因此大屏顺序与页面顺序天然一致。
  - 水位序列（`type=1`）与水位监测页「花凉亭水库」Tab 的各水情表（河道水情表 / 水库水情表 / 日时段水情表 / 水情简报 / 多年同期水情）**共用同一份配置**，任一入口调整都会同时影响两边顺序；未配置时两边均按各自原有默认顺序返回（与改造前一致）。
- **实时值**：各类型复用现有监测接口的数据源与口径，**一次批量查询取全站最新值**（不再逐站请求）；无缓存、无轮询任务，实时查询（服务端对单次实时值查询设有 1000 行保护上限，当前站点规模远未触及）。
- **请求次数对比**：

| 类型 | 原做法 | 本接口 |
|------|------|------|
| 雨量 | 1（上游列表）+ 1（全量）+ **N（逐站，18 站 = 18 次）** | **1** |
| 水位 / 流量 / 闸门 / 墒情 / 水质 | 1（上游列表）+ 1（监测接口） | **1** |

## 七、鉴权与通用约定

| 约定 | 说明 |
|------|------|
| 环境前缀 | `http://220.179.1.110:8081/hltgq-site`（下文省略） |

## 八、前端迁移对照（两步 → 一次）

| 项 | 改造前 | 改造后 |
|------|------|------|
| 请求地址 | `qx-api/qx-apaas-run/ar/4idWo4GcvCd8fWPQSif/kjximffu?type=2` | `/external/station-monitor?type=2` |
| `type` 取值 | 1 / 2 / 3 / 4 / 7 / 8 | **不变**（原值直接传） |
| 站名筛选 `name` | `…kjximffu?type=2&name=渠首`（上游平台支持） | **同口径**（原 `name` 值直接传：`/external/station-monitor?type=2&name=渠首`） |

| 站点顺序 | 前端自行处理 | 可保留（会覆盖后端顺序）或直接删除 |

## 九、已知差异（对接方注意）

1. `nwbzla.dataTitle`（闸门图片文件名）**恒为 `null`**：文件名需经文件服务换取，本期未接；`nwbzlaId` 原样返回，需要文件名时由前端另行调用文件接口。
2. **默认顺序为 `iofhpi` 升序**（上游平台返回的是库内物理顺序，个别站点位次可能不同）；需要固定顺序时由我方配置「站点排序」。
3. 实时值中的 `id` / `stcd` 与档案**同名**：合并后只出现一次（位置在档案区），值以实时值非空优先（`id` 两个来源本就同值，实测无差异）。
4. `isOnline` 口径按各类型监测接口：水位站按档案状态、雨量按断联时长（水库站按站点状态）、闸门按断联判定；与档案 `zebpsu` 编码值（`1`/`2`）不是同一字段，前端标红请用 `isOnline`。
5. 闸门类型实时值**不含 `stcd`**（上游数据表以站点 id 关联），大屏如需显示站码请用同行档案字段 `iofhpi`。
6. 水质 `thresholds` 仅本接口与 `GET /water-quality/monitoring` 返回，阈值行按站点档案 id 关联；`viwmmc` / `badfhe` 为解包后的富文本对象。
7. `nxtggq`（监测方法）在档案中为**多选**：本接口按上游平台列表同口径返回「去 `#` 包装的编码」（多值时形如 `1|4`）；如大屏需要数组形态（同 `epjutj`），请告知后端调整。

## 十、自测与排错

PowerShell 自测（先取会话，再请求本接口）：

```powershell
$base = "http://220.179.1.110:8081/hltgq-site"
$sid  = (Invoke-RestMethod -Method Post -Uri "$base/auth/login" -ContentType "application/json" `

# 站名模糊筛选（渠首）：中文需 URL 编码，否则可能被按非 UTF-8 传输而查不到
$n = [uri]::EscapeDataString('渠首')
Invoke-RestMethod -Uri "$base/external/station-monitor?type=2&name=$n" -Headers $h |
  Select-Object -ExpandProperty data |
  Format-Table iofhpi, zzkaec, tm, drp, isOnline, hasData
```

| 现象 | 排查 |
|------|------|
| 400 `监测类型无效: xxx` | `type` 传值不在 1/2/3/4/7/8（或兼容写法）内，或未传 `type` |
| 401 `未登录` | 未带 `Authorization` 头 / 会话过期，重新 `POST /auth/login` |
| 站点在列表里但实时值为 `null` | 该站当前无监测数据，`hasData=false`（属正常；与上游平台列表含无数据站的口径一致）。注意此时实时值字段是「不出现」（JS `undefined`）而非值为 `null`，判空请用 `??` / `== null`，不要用 `=== null` |
| 顺序与预期不同 | 该类别的「站点排序」未配置的站点按 `iofhpi` 升序排在其后；在站点排序页面配置序号即可 |
| 与页面监测列表条数不一致 | 页面可能按业务规则过滤了部分站点（如水库站、测试站），本接口按**档案口径**返回全部；如大屏需要页面口径，用对应监测接口 |
| 传 `name` 后返回 `data: []` | `name` 只匹配**站名**（不含站码）、包含匹配且大小写敏感；先发一次不带 `name` 的请求看该类全部站名，再取站名中的连续片段（如「渠首」）重试；`name` 为纯空白等同不筛选（返回全量，而非空数组） |
| 时间显示 `Invalid Date` | 档案 `createdAt` / `updatedAt` 是空格格式，Safari / iOS 不能直接 `new Date()`，先 `.replace(' ', 'T')`；实时值 `tm` 本身带 `T`，可直接解析 |
| 实时值字段取不到值 | 先看该行 `hasData`：`false` = 该站无实时数据（字段整体不存在）；`true` 则该指标此刻无采集（该字段也不存在）。判空用 `??` / `== null`，不要用 `=== null` |

## 十一、征收/收缴统计（`/water-use-summary/fee-collection`）

> 用途：**各区域征收情况柱状折线组合图**（x 轴 = 区域）与**月度收缴趋势柱状折线组合图**（x 轴 = 统计年 12 个月）——**一个接口一次返回两段数据**，两段指标与单位完全一致：柱 y 轴为万元、折线 y 轴为收缴率（%）。
>
> 数据源：水费计算表单（业主**手工录入**，非设备采集）——**不需要按 60s 刷新**，进页面拉取 / 按天刷新即可。
>
> 口径完整版（归桶设计、字段来源、联调日志）见《用水总结接口.md》第三节；本章为大屏对接视角的简版。

### 11.1 接口

```

```

生产完整地址：`http://220.179.1.110:8081/hltgq-site/water-use-summary/fee-collection?year=2026`

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| year | int | 否 | 统计年份；**不传 = 当年**（大屏常显当年，直接不传即可）；超出 `2000 ~ 2100` → **400** `{"message": "year 取值范围 2000 ~ 2100（缺省=当年）"}` |

鉴权：同「七」章（请求头 `Authorization: <sessionId>`，或 `X-Session-Id` 头 / Cookie `sessionId`）；未登录 → **401**。

### 11.2 响应结构

> 响应信封：**本接口直接返回数据对象**（无 `success` / `data` / `msg` 包装），与「二、响应结构」的站点列表接口不同（那个沿用上游平台信封，便于复用原解析逻辑）。

```json
{
  "year": 2026,
  "regions": [
    { "region": "望江县", "receivable": 1234.56, "received": 900.00, "collectionRate": 72.9 },
    { "region": "太湖县", "receivable": 800.10, "received": null, "collectionRate": null }
  ],
  "months": [
    { "month": "2026-01", "receivable": null, "received": null, "collectionRate": null },
    { "month": "2026-09", "receivable": 2034.66, "received": 900.00, "collectionRate": 44.2 },
    { "month": "2026-12", "receivable": null, "received": null, "collectionRate": null }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `year` | Number | 实际统计年份（未传 `year` 时 = 当年） |
| `regions` | Array | 各区域征收情况（x 轴 = 区域）；**按应收水费降序**，应收为 `null` 的区域排末位（同值按区域名升序，顺序稳定） |
| `regions[].region` | String | 区域名称（= 用水户名称，如 `望江县`；**含县 / 乡镇等实际录入值，不是固定四县**） |
| `regions[].receivable` | Number? | 应收水费（**万元**，2 位小数截断） |
| `regions[].received` | Number? | 已收水费（**万元**，2 位小数截断） |
| `regions[].collectionRate` | Number? | 水费收缴率（**%**，1 位小数截断） |
| `months` | Array | 月度收缴趋势，**固定 12 项**（`2026-01` ~ `2026-12`，按月份升序） |
| `months[].month` | String | 月份（`yyyy-MM`） |
| `months[].receivable` / `received` / `collectionRate` | Number? | 口径同 `regions`；该月无数据时为 `null` |

> 示例为**字段结构示意**（数值为口径示意，以线上实际为准；`months` 示例仅列出 3 项，实际固定 12 项）。

### 11.3 图表接入（两张图共用一次请求）

| 图表 | 请求段 | x 轴 | 柱（左轴 万元） | 折线（右轴 %） |
|------|--------|------|----------------|----------------|
| 各区域征收情况柱状折线组合图 | `regions` | `region` | `receivable` / `received` | `collectionRate` |
| 月度收缴趋势柱状折线组合图 | `months` | `month` | `receivable` / `received` | `collectionRate` |

- 建议图例：柱「应收水费 / 已收水费」，折线「水费收缴率」。
- `receivable` / `received` 为 `null` 时该点**不画柱**（不要按 0 处理）；`collectionRate` 为 `null` 时折线**断开**。
- `months` 已是完整 12 个月（含无数据月份），x 轴直接铺开即可，**不需前端补齐**。

### 11.4 口径要点

| 项 | 口径 |
|------|------|
| 金额单位 | 表单录入单位即 **万元**（业主 2026-09-17 确认），接口**直取不换算**，仅 2 位小数**截断**（不四舍五入；表单字段标签「应收水费（元）」为文案，非实际录入口径） |
| 收缴率 | 已收合计 ÷ 应收合计 × 100，1 位小数截断；应收缺失或 ≤ 0 → `null` |
| 归桶 | 按水费记录的**统计周期区间终点**判定年 / 月（跨月记录归终点所在月 / 年） |
| 区域 | 水费记录的用水户外键 → 用水户档案的「用水户名称」；无区域（未填 / 已删 / 名称为空）的记录**不计入区域图、仍计入月度趋势** |
| 缺失 | `null` = 无数据（**不补 0**，与「七」章 null 语义一致）；**「未填」与「填 0」区分**：确实填了 0 返回 `0.00` |
| 两图一致性 | `regions` 与 `months` 由**同一次取数**聚合而来，两图数字可直接对齐 |

### 11.5 自测

```powershell
$base = "http://220.179.1.110:8081/hltgq-site"
$sid  = (Invoke-RestMethod -Method Post -Uri "$base/auth/login" -ContentType "application/json" `
        -Body '{"key":"<key>","secret":"<secret>"}').sessionId
$h    = @{ Authorization = $sid }

# 当年（不传 year）
Invoke-RestMethod -Uri "$base/water-use-summary/fee-collection" -Headers $h |
  ConvertTo-Json -Depth 5

# 指定年份：只看 12 个月的应收 / 已收 / 收缴率
Invoke-RestMethod -Uri "$base/water-use-summary/fee-collection?year=2026" -Headers $h |
  Select-Object -ExpandProperty months |
  Format-Table month, receivable, received, collectionRate
```

| 现象 | 排查 |
|------|------|
| 400 `year 取值范围 2000 ~ 2100（缺省=当年）` | `year` 传了越界值（如 `999` / `20260`）或非数字 |
| 401 `未登录` | 未带 `Authorization` 头 / 会话过期，重新 `POST /auth/login` |
| `regions` 为空数组、`months` 全为 `null` | 该年水费表单还没有记录（业主手工录入）；录入后自动出数，无需改接口 |
| 有数据但 `received` / `collectionRate` 恒为 `null` | 该年水费记录尚未填写「已收水费」（手工录入项） |
| 表单里填了金额，图上却是 `0.00` | 该值不足 0.01 万元（2 位截断）——接口不做换算、返回的就是表单录入值（万元），先在表单侧核对数值量级 |
| `regions` 合计与 `months` 合计对不上 | 该年存在**无区域**的记录（用水户未填 / 已删 / 名称为空），这类记录不入区域图；服务端日志 `[用水总结] 征收统计 … 无区域记录=N 条` 可核对 |
