# 出入库管理接口

物资出入库按「单据」办理：**入库单（RK）与出库单（CK）两张独立主表 + 明细**，保存即生效（不支持编辑与删除，纠错线下处理）。
一次保存联动三件事：单据主/明细留痕 → 台账（`tzkioe` 库存数）建账/增减 → 库存变动流水留痕。
台账页（P4）与出入库记录（P5）完全由单据写入驱动，本身只读。

- 页面：`/inventory-order-list.html`（P1 单据列表 + P2 新增入库 / P3 新增出库抽屉 + 详情 + 选择弹窗）、
  `/inventory-ledger.html`（P4 物资台账 + P5 出入库记录弹窗）；均为单文件页面
- 本期新建 6 张表（`"qixiao-apaas"`）：
  `t_auto_hltgq_water_inbound_order` / `t_auto_hltgq_water_inbound_order_detail`（入库单 + 明细）、
  `t_auto_hltgq_water_outbound_order` / `t_auto_hltgq_water_outbound_order_detail`（出库单 + 明细）、
  `t_auto_hltgq_water_stock_change_log`（库存变动流水，P5 数据源）、
  `t_auto_hltgq_water_order_no_seq`（单据编号序列）
- 复用的既有表：物资台账 `t_auto_hltgq_knc3g_tzkioe`、物资目录 `t_auto_hltgq_knc3g_slaifi`、
  仓库 `t_auto_hltgq_knc3g_twufyx`、平台部门/用户表（归口科室与经办人候选）
- 单据编号：**RK/CK + yyyyMMdd + 4 位序号**（如 `RK202610120001`）；取号走独立事务（REQUIRES_NEW），
  并发/失败场景**跳号属预期**（不重号即可）
- 权限：**本期所有登录用户可用**（与阈值设置同口径）；后续收紧为指定角色时在 `/inbound`、`/outbound`
  加角色断言即可（已留扩展点）

## 1. 字段口径

### 1.1 单据行（P1 列表 / 详情主表）

| 字段 | 含义 |
|---|---|
| `source` | 来源：`RK` 入库单 / `CK` 出库单 |
| `id` | 单据 ID（详情入参） |
| `orderNo` | 单据编号（RK/CK 前缀，全局唯一） |
| `bizType` | 业务类型编码（按 source 解释，见 §2.1） |
| `bizTypeName` | 业务类型中文（后端按 source + bizType 翻译，前端不写死） |
| `orderDate` | 单据日期 `yyyy-MM-dd` |
| `warehouseId` / `warehouseName` | 仓库 |
| `departmentId` / `departmentName` | 归口科室 |
| `counterparty` | 供应商/来源单位（RK）或 领用单位/工程名称（CK）合并列 |
| `operatorId` / `operatorName` | 经办人 |
| `remark` | 备注（可空） |

### 1.2 单据详情明细行（`detail.items[]`）

| 字段 | 含义 |
|---|---|
| `materialId` | 物资 ID（目录 `slaifi.id`） |
| `materialCode` / `materialName` / `materialBrand` / `materialSpec` / `materialUnit` | 物资快照（**固化于单据**，目录后续改动不影响历史） |
| `quantity` | 数量（正整数） |
| `stockBefore` | 变动前库存快照：**仅出库行有值**（台账扣减成功后回算回填）；入库行为 null |

### 1.3 明细级导出行（`/inventory-order/export`）

一行 = 单据 × 物资明细，共 17 列：
`orderNo, source, sourceName（入库单/出库单）, bizType, bizTypeName, orderDate, warehouseName, departmentName,
counterparty, operatorName, remark, materialCode, materialName, materialBrand, materialSpec, materialUnit, quantity`

### 1.4 台账行（P4，`LedgerPageItemVO`）

| 字段 | 含义 |
|---|---|
| `id` | 台账行 ID（`tzkioe.id`） |
| `materialId` | 物资 ID |
| `materialCode` | 物资编号（目录 `higsdd`） |
| `brand` / `name` / `spec` / `unit` | 台账快照列（品牌/名称/规格/单位） |
| `warehouseId` / `warehouseName` | 所属仓库 |
| `quantity` | 库存数量 |
| `safetyStock` | 安全库存（可空；**实时取物资目录** `slaifi.unqvqe`，目录调整即时生效） |
| `statusCode` / `statusName` | 库存状态：`#1#` 正常 / `#2#` 偏低（实时计算，见 §2.2） |
| `departmentId` | 所属部门 |

排序：建账时间倒序（新建账在前）。

### 1.5 流水行（P5，`StockChangeVO`）

| 字段 | 含义 |
|---|---|
| `id` | 流水行 ID |
| `changeType` / `changeTypeName` | 变动类型：`#1#` 入库 / `#2#` 出库 / `#3#` 盘盈 / `#4#` 盘亏（盘盈亏由设备盘点单产生，见《设备盘点接口.md》） |
| `orderKind` | 单据类别：`#1#` 入库单 / `#2#` 出库单 / `#3#` 盘点单 |
| `orderId` / `orderNo` | 单据 ID / 单据编号快照 |
| `bizType` / `bizTypeName` | 业务类型（按 orderKind 解释） |
| `changeQty` | 变动数量（正整数，方向由 changeType 表达） |
| `qtyBefore` / `qtyAfter` | 变动前 / 变动后库存 |
| `counterparty` | 往来单位快照（RK = 供应商/来源，CK = 领用单位） |
| `operatorName` | 经手人快照 |
| `orderDate` | 单据日期 `yyyy-MM-dd` |
| `createdAt` | 流水生成时间 `yyyy-MM-dd HH:mm:ss`（倒序依据） |
| `warehouseId` / `warehouseName` | 仓库 |

排序：`created_at` 倒序（最新一笔在前）。

## 2. 字典

### 2.1 来源与业务类型（联合键）

| 来源 | 业务类型编码 | 中文 |
|---|---|---|
| `RK` 入库单 | `#1#` | 采购入库 |
| `RK` 入库单 | `#2#` | 调拨入库 |
| `RK` 入库单 | `#3#` | 退料入库 |
| `RK` 入库单 | `#4#` | 其他入库 |
| `CK` 出库单 | `#1#` | 工程领用 |
| `CK` 出库单 | `#2#` | 调拨出库 |
| `CK` 出库单 | `#3#` | 退料出库 |
| `CK` 出库单 | `#4#` | 报废出库 |
| `CK` 出库单 | `#5#` | 其他出库 |

**两表编码相互独立**（`#1#` 在入库表 = 采购入库、在出库表 = 工程领用），展示与筛选一律按
「来源（RK/CK）+ 编码」**联合键**解释，禁止单凭编码判断。约定：

- `meta.types[]` 的 `value` 为联合键：`{value:'RK#1#', label:'采购入库', group:'in'}`（前端按 Tab 用 `group` 过滤）；
- 列表/导出筛选参数 `bizType` 同格式（`RK#1#` / `CK#1#`）；前缀非 RK/CK 按「不传」处理（不过滤），编码非法则命中空结果；
- 保存提交体只传**裸编码**（`inboundType='#1#'` / `outboundType='#1#'`，前端从联合键 `substring(2)` 截取）；
- 字典单一维护点：后端 `InventoryTypeDict#typeOptions`，前端经 `/inventory-order/meta` 获取，不写死。

### 2.2 库存状态（实时计算）

| 编码 | 名称 | 说明 |
|---|---|---|
| `#1#` | 正常 | 库存 > 安全库存（安全库存为空按 0 比较） |
| `#2#` | 偏低 | 库存 ≤ 安全库存（**等于即偏低**） |

**安全库存与库存状态一律实时取物资目录** `slaifi.unqvqe`（安全库存下限）计算：目录调整后，
台账列表/导出/状态筛选/出库候选**立即生效**；台账 `tzkioe` 的 `vhvhja` / `mojktw` 列仅建账/增减时
维护存档，不参与页面读取判定。
台账筛选 `status` 参数接受中文（`正常`/`偏低`）或编码（`#1#`/`#2#`），后端统一归一。
（既有「设备库存查询」页对同字典值显示为「安全库存/库存预警」，**文案不同、判断一致**。）

### 2.3 流水字典

- `change_type`：`#1#` 入库 / `#2#` 出库 / `#3#` 盘盈 / `#4#` 盘亏（盘盈亏由设备盘点单产生）
- `order_kind`：`#1#` 入库单 / `#2#` 出库单 / `#3#` 盘点单

## 3. 接口契约

统一前缀 `/inventory-order` 与 `/inventory-ledger`；**生产环境统一加 `/hltgq-site` 前缀**，需登录会话。
业务校验失败返回 **HTTP 400 + `{message}`**（`GlobalExceptionHandler` 统一处理），前端 toast `message` 即可；
数据冲突返回 409、编号/建账等状态冲突返回 502 + `{message}`（罕见，重试即可）。

### 3.1 单据（`/inventory-order`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/inventory-order/meta` | 表单元数据：`types[]`（联合键 value/label/group）+ `warehouses[]`（**仅启用**，含默认科室/经办人）+ `today` |
| GET | `/inventory-order/page` | 列表分页（参数见下）；排序：单据日期倒序、同日内新建在前 |
| GET | `/inventory-order/detail?source=&id=` | 详情（`source=RK\|CK` 与 `id` 必填） |
| POST | `/inventory-order/inbound` | 新增入库单 → 返回保存后详情 |
| POST | `/inventory-order/outbound` | 新增出库单 → 返回保存后详情 |
| GET | `/inventory-order/materials?keyword=` | 物资目录候选（全量、不按仓库过滤；keyword 匹配编号/名称） |
| GET | `/inventory-order/stock-ledgers?warehouseId=&keyword=` | 出库台账候选（**当前仓库库存 > 0**；warehouseId 必填） |
| GET | `/inventory-order/departments?keyword=` | 归口科室候选（平台组织表，按名称排序） |
| GET | `/inventory-order/users?keyword=` | 经办人候选（平台用户表，`sub` = 手机号） |
| GET | `/inventory-order/export` | 明细级导出（同列表 11 个条件、全量无分页，返回裸数组，前端生成 Excel） |

**`/page` 参数（13 个）**

| 参数 | 说明 |
|---|---|
| `page` / `size` | 默认 `1` / `20`；size 上限 100，page 上限 100000 |
| `source` | `RK` / `CK`；空 = 全部；非法 400 |
| `orderNo` | 单据编号模糊 |
| `bizType` | 业务类型联合键（`RK#1#` / `CK#1#`），可选 |
| `warehouseId` / `departmentId` | 仓库 / 归口科室精确匹配，可选 |
| `sourceUnit` / `receiveUnit` | 供应商/来源、领用单位模糊（各自单据类型适用），可选 |
| `materialCode` / `materialName` | **明细级**模糊（单据含任一匹配明细即命中），可选 |
| `startDate` / `endDate` | 单据日期闭区间 `yyyy-MM-dd`，可选；格式非法 400 |

返回：`{total, page, size, pages, records:[§1.1 单据行]}`。

**`/meta` 返回**

```json
{
  "types": [
    {"value": "RK#1#", "label": "采购入库", "group": "in"},
    {"value": "CK#1#", "label": "工程领用", "group": "out"}
  ],
  "warehouses": [
    {"id": "...", "name": "第一仓库", "code": "...", "statusCode": "#1#", "disabled": false,
     "departmentId": "...", "departmentName": "...", "operatorId": "...", "operatorName": "..."}
  ],
  "today": "2026-10-12"
}
```

**POST `/inbound` 提交体**

```json
{
  "inboundType": "#1#",
  "orderDate": "2026-10-12",
  "warehouseId": "...",
  "sourceUnit": "供应商或来源单位",
  "departmentId": "...",
  "operatorId": "...",
  "remark": null,
  "items": [{"materialId": "...", "quantity": 10, "spec": "DN100"}]
}
```

- 物资快照（编号/名称/品牌/单位）**不接受前端传入**，后端按 `materialId` 回查目录固化，防篡改；
- 明细 `spec`（规格型号，**选填**，≤255 字）：不为空时**覆盖目录快照**写入明细（可手工填写/修正），
  为空回退目录值 `iwnyuk`；
- 台账处理：该「物资 × 仓库」**无台账行 → 自动建账**（初始量 = 数量，安全库存取目录 `unqvqe` 原文解析写入
  台账 `vhvhja` 快照存档，可空；页面读取一律实时取目录，见 §2.2）；
  已有行 → 数量累加；并发建账冲突自动重查后累加；
- 保存成功返回 `§1.2` 结构（含明细），前端据此刷新列表。

**POST `/outbound` 提交体**

```json
{
  "outboundType": "#1#",
  "orderDate": "2026-10-12",
  "warehouseId": "...",
  "receiveUnit": "领用单位或工程名称",
  "departmentId": "...",
  "operatorId": "...",
  "remark": null,
  "items": [{"ledgerId": "...", "quantity": 2, "spec": "DN100"}]
}
```

- 出库明细按**台账行**提交（`ledgerId`）：只能来自 `/stock-ledgers`（当前仓库库存 > 0）；
- 明细 `spec`（规格型号，**选填**，≤255 字）：不为空时**覆盖台账快照**写入明细，为空回退台账值；
- 扣减链路：逐行**乐观锁 UPDATE**（`quantity ≥ 出库量` 为条件）；前置校验 ≤ 可用库存，最终以影响行数为准；
  并发/竞争导致不足 → **整单回滚** 400「第 N 行：库存不足，请刷新后重试」；
- 明细分派 `stockBefore` 与流水 `qtyBefore` 取扣减成功后回算值。

### 3.2 台账与记录（`/inventory-ledger`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/inventory-ledger/page?page=&size=&warehouseId=&keyword=&status=` | 台账分页（左树仓库过滤；keyword 匹配编号/名称；status 见 §2.2） |

| 情况 | 后端行为 | 前端行为 |

| detail id 为空 | 400「单据 id 不能为空」 | — |
| 单据不存在 | 400「单据不存在」 | toast 提示 |
| 请求体为空 | 400「请求体不能为空」 | — |
| 类型未选 / 非法 | 400「入库类型无效」/「出库类型无效」 | 字段标红「请选择入库类型/出库类型」拦截保存 |

| 出库并发不足（兜底） | 400「第 N 行：库存不足，请刷新后重试」（整单回滚） | toast，抽屉不关、已填内容保留 |
| 数量非正整数 | 400「第 N 行：数量必须为正整数」 | 行内拦截「第 N 行：数量必须为正整数」 |

| 查询日期格式错 | 400「起始日期格式应为 yyyy-MM-dd：xxx」/「结束日期…」 | 日期控件天然合法 |
| 出库选台账前未选仓库 | — | 「请先选择仓库，再选择出库物资」 |
| 编号/建账等状态冲突（罕见） | 502「单据编号生成失败，请重试」等 | toast，重试即可 |

## 4. 页面说明

### 4.1 P1 单据列表（`/inventory-order-list.html`）

- **Tab**：全部 / 入库单 / 出库单，切换即刷新；「供应商/来源」与「领用单位」筛选条件按 Tab 显隐，
  合计列列头随 Tab 同步（入库单 =「供应商/来源」、出库单 =「领用单位/工程名称」、全部 =「供应商/来源·领用单位」）；
- **筛选 9 条件**：常显 4 项（物资编码、单据编号、业务类型、仓库）+「更多条件」展开 5 项
  （物资名称、归口科室、供应商/来源、领用单位、单据日期起止闭区间）；下拉选中不即查，统一「查询」按钮提交；
  「重置」清空条件并回到第 1 页；
- **列表**：一单一行的单据行（非明细行）；业务类型为彩色圆点标签（入库=蓝 / 出库=橙黄）；
  单据编号蓝字可点击打开详情；操作列「查看」；分页支持每页条数与跳页；
- **导出**：明细级 Excel（一行 = 单据 × 物资明细），文件名「出入库单据明细.xlsx」，
  复用通用导出库 `./lib/monitor-export.js`（长数字码按文本写入防科学计数法，列宽自适应）；
- **新增入库 / 出库**：抽屉表单，单据编号只读（「系统按 RK/CK+日期+4位序号 自动生成」）；

## 5. 注意事项（对外约定）

1. **保存即生效**：入库/出库无编辑与删除接口（设计方案 5.3）；如填错由线下处理，后续如需冲正另行设计；
2. **编号跳号属预期**：取号独立事务，并发或保存失败会跳号；只保证不重号、不保证连续；
3. **台账建账时机**：仅入库自动建账（初始安全库存取目录「安全库存下限」文本解析，可为空）；
   未入库过的「物资 × 仓库」不会出现在台账，也无法出库；建账防重依赖 `tzkioe` 唯一索引
   `uk_tzkioe_material_warehouse`（`init.sql` 创建；该表属低代码平台表，平台重建索引会丢失，部署/重建后需复核）；
4. **出库并发安全**：同一台账行并发出库由 UPDATE 乐观锁兜底，库存不足**整单回滚**（不会部分成功）；
   同一单据内同一物资重复添加由前端防重（已添加行置灰）；
5. **停用仓库**：新建单据不可选（meta 只含启用仓库）；列表/台账查询与历史数据不受影响；
6. **状态口径**：台账页按设计方案显示「正常/偏低」，安全库存与状态实时取物资目录计算（目录调整即时
   生效，见 §2.2）；与「设备库存查询」页对同字典值的「安全库存/库存预警」文案不同，判断方向一致；
7. **导出在前端生成**：后端导出接口只返回 JSON 全量数组（无分页），页面复用通用导出库
   `./lib/monitor-export.js`（底层 `xlsx.full.min.js`，与各监测页同库）生成 Excel，长数字码按文本写入防科学计数法；
8. **权限**：本期与阈值设置同口径（登录即可用）；保存接口的角色收紧是后续扩展点，接口契约不变。
