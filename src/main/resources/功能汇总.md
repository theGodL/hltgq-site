# 花凉亭灌区数据服务平台（hltgq-site）功能汇总

> 本文档对本项目自建设以来交付的全部功能进行统一整理，按业务域分组，每项功能说明其功能描述与所解决的问题，便于项目归档、验收对照与后续运维查阅。
>
> 整理范围：`src/main/resources/static` 全部页面 + 后端各模块接口 + 对外集成能力。
> 配套接口文档：`大屏接口.md`、`三维系统对接接口.md`、`模型接入接口.md`、`智能决策接口.md`、`H5接口.md`、`天气接入接口.md`、`用水总结接口.md`、`灌溉用水接口.md`、`节水潜力接口.md`、`数据统计.md`、`统计数据.md`、`站点详情接口.md`、`水质监测.md`、`阈值设置.md`、`导入-导出对接接口.md` 等。

## 一、项目概述

本项目是花凉亭灌区（覆盖太湖、望江、宿松、怀宁四县及花凉亭水库、麻塘湖灌区）的数据服务与业务支撑平台，定位为"灌区一张数据底座"：

- **数据底座**：基于业主低代码平台（qixiao-apaas）数据，统一对外提供水雨情、闸门、墒情、水质、用水、水费等各类业务数据的查询、统计、分析服务。
- **业务前台**：提供 38 个功能页面，覆盖实时监测、智能决策、模型计算、用水管理、数据统计、运维管理等业务场景。
- **对外服务**：向三维数字孪生系统、大屏、H5 移动端、档案系统等第三方提供标准化数据接口。
- **协同边界**：设备采集与报文入库由 hltgq-mq / hltgq-device / 设备侧完成；水利模型计算由模型服务（Flask）承担；本项目负责数据聚合、口径治理、页面呈现与对外分发。

## 二、实时监测类功能

### 2.1 水位监测

**功能描述**（页面 `irrigation-water-level.html`，接口 `/irrigation-water-level/*`、`/st-river-r/*`）

- 三个主 Tab 切换：花凉亭灌区 / 花凉亭水库 / 麻塘湖灌区，各 Tab 站点范围独立（按渠系归属过滤）。
- 站点筛选（支持渠系树、站点下拉）、日期区间查询、分页展示最新水位数据。
- 水位趋势图表：单站水位历史曲线（时间点可选）。
- 水位变化图：水位 + 涨落幅度双曲线。
- 历史数据弹窗：查看某站历史水位记录，支持勾选字段导出。
- 时段水情表：按日期 + 时段间隔（1/2/3/6/12 小时）生成时间槽位并匹配实测水位。
- 水库水情子模块：河道水情多站合并分页（周家河、花凉亭坝下）、水库水情（花凉亭坝上）、水情简报（三个水情站昨日 8 点/20 点、今日 8 点水位、水势、流量、当年最高水位）、多年同期水情（年份区间 + 月份、各站月平均水位），均支持导出。
- 站点自定义排序、Excel 导出。

**解决的问题**

- 灌区各水位站数据分散在低代码平台各业务表中，缺少统一的实时监控视图，值班人员无法快速掌握全灌区水位态势。
- 河道站水位（river_info 表）与闸站水位（gate 表闸前/闸后）此前口径割裂，本模块按站点类型统一取数，保证"水位监测"页面全量覆盖。
- 替业主解决"某站某时段实测水位如何快速回查"的诉求（时段水情表 + 历史弹窗）。

### 2.2 雨量监测

**功能描述**（页面 `rainfall-monitor.html`、`hydro-monitor.html`，接口 `/st-pptn-r/*`）

- 主页面（rainfall-monitor.html）：三个主 Tab（花凉亭灌区 / 花凉亭水库 / 麻塘湖灌区），站点列表展示各站实时雨量、1h/3h/6h 时段降雨增量、日雨情，支持渠系树侧栏、站点/日期筛选、分页、导出、站点排序、管理员"数据维护"入口。
- 水库雨情多视口（rainfall-monitor.html 水库 Tab 内）：实时雨情、时段雨情、日雨情、旬月雨情、极值雨情、雨情简报，逐层满足水库防汛值守的多粒度雨情查阅需求（另有多年同期雨情视口，数据待接入）。
- 雨量数据页（hydro-monitor.html）：实时雨情 / 时段雨情 / 日雨情子视口与导出。
- 统一水文日口径：全部雨情统计以每日 08:00 为界（水文日），与水利行业及老系统口径一致。
- 实时雨情取"本水文日累计"，确保"外面在下雨时平台能真实体现实时降水"；数据断联时页面时间标红、接口返回断联标识。
- 雨量变化图表：单站小时级增量 + 累计雨量曲线（起点对齐当日 8:00）。

**解决的问题**

- 雨量统计口径混乱问题：历史上存在"自然日 vs 水文日""DRP 当前降雨量 vs DYP 累计降雨量"混用，导致新老系统数据对照不上。本模块统一按水文日口径统计，并与老系统逐站核验收敛。
- 实时性诉求："外面在下雨、平台显示无雨"——通过改为取本水文日累计值（而非固定时段值）解决。
- 异常数据可解释性：针对 34.0 异常值等历史数据事故，建立了"设备补偿值 + 删除重算"的维护机制（见 7.2），并形成《雨量数据异常.md》分析报告闭环。

### 2.3 流量监测

**功能描述**（页面 `flow-monitor.html`，接口 `/flow-monitor/*`）

- 最新数据列表：每站一条最新记录（站点名称、监测时间、瞬时流量），支持站点多选、渠系树、日期区间筛选。
- 流量趋势图表：小时级流量曲线（默认近 7 天）。
- 历史数据分页查询。
- 固定八站瞬时流量：渠首进水闸、双庙湖节制闸、南山寺节制闸、太怀干渠进水闸、毕岭节制闸、汪元渡槽、南干渠进水闸、北干渠进水闸——每站取距选中时间点 ±20 分钟内最近值。
- 流量过程线：时间点粒度 20 分钟，供取水过程精细回溯。
- 累计水量展示（原"累计流量"统一更名为"累计水量"，单位万 m³、3 位小数截断）。
- 全量导出（当前筛选条件）。

**解决的问题**

- 原系统无统一流量监控视图，灌区取水流量、渠道过流情况无法集中掌握。
- 流量取值核对问题：通过多轮实测核对（±20 分钟匹配窗口）确保图表与库中入库值一致。
- 单位口径治理："累计流量"更名"累计水量"，万 m³ 3 位小数截断，与业主对账口径统一。

### 2.4 闸门监测

**功能描述**（页面 `gate-monitor-page.html`，接口 `/gate-monitor/*`）

- 最新数据：每个闸站一条记录，含该站所有闸孔的最新开度、闸前/闸后水位、设备状态、流量及站点经纬度；支持站点、渠系、日期区间筛选。
- 历史数据：按类型（开度 / 水位 / 流量）分页查询，每行含监测时间与各闸孔对应数据。
- 闸站图表：固定七站（渠首进水闸、双庙湖节制闸、南山寺节制闸、毕岭节制闸、汪元节制闸、北干渠进水闸、南干渠进水闸）闸前/闸后水位（±30 分钟匹配）。
- 累计水量：月累计、年累计（万 m³、3 位截断），月度累计取水量趋势图（近 12 个月，可调）。
- 闸站召测：对四站（北干渠进水闸、南干渠进水闸、毕岭节制闸、汪元节制闸）异步下发召测指令，前端轮询状态直至数据确认；页面刷新后可恢复召测状态。
- 闸孔开度、水位、流量字段勾选导出。

**解决的问题**

- 闸门运行状况（开度、闸前闸后水位、过流）原依赖现场巡查或老系统，本模块提供在线集中监控。
- 召测操作从"老系统人工下发"迁移为本平台一键召测，并支持失败重试（仅传失败站）。
- 闸孔设备台账口径治理：发现并修复了"同一批闸孔设备两处口径差 7 台"问题（见《闸门设备台账补录清单.md》），统一按闸孔设备维度统计。

### 2.5 墒情监测

**功能描述**（页面 `soil-moisture-monitor.html`，接口 `/soil-moisture/*`）

- 站点列表展示各站最新土壤含水率（多深度层）、监测时间、设备电压等。
- 数据量程校验：超量程异常值按哨兵值处理，页面展示 "--"，不参与展示与统计。
- 墒情趋势图：单站含水率变化曲线（实时刷新）。
- 站点筛选、导出；首页为最新数据视图（不含日期查询器）。

**解决的问题**

- 灌区墒情（土壤水分）监测此前无平台化视图，抗旱研判缺乏实时数据支撑。
- 设备异常数据（-999 等哨兵值）直接展示造成的观感与误判问题，通过统一量程校验与占位展示解决。

### 2.6 水质监测

**功能描述**（页面 `water-quality-monitor.html`、`water-quality-trend.html`，接口 `/water-quality/*`）

- 水质监测页：各站最新六项指标（高锰酸盐指数等）数据、采集时间标红（数据陈旧提示）、站点下拉、阈值配置行对照。
- 三张趋势图共用 2 小时级序列接口（双 Y 轴展示不同量纲指标）。
- 水质演变趋势页：左侧站点列表 + 统计卡（该站最新一条）+ 趋势图，供指标演变分析。
- 历史数据分页、站点筛选、导出。

**解决的问题**

- 灌区水质监测数据（codmn 等指标）无集中监控页面，超标情况无法及时发现。
- 通过阈值行对照 + 采集时间标红，让"哪些站超标、哪些站数据中断"一目了然。

### 2.7 站点监测图表（单站分析）

**功能描述**（页面 `station-chart.html`、`station-pptn-chart.html`、`station-river-chart.html`）

- 按站点编码（stcd）进入单站多维数据图表分析：雨量统计图、水位趋势图等。
- 支持图表时间点文本框选点、数据缩放。

**解决的问题**

- 满足"对某一重点站点做专题数据分析"的需求，避免在列表页反复筛选。

## 三、智能决策类功能

### 3.1 智能防洪决策

**功能描述**（页面 `flood-drought-decision.html`，接口 `/flood-drought/*`）

- 进页概览：实测 + 预测一张拼图（默认区间 今日-2 至 今日+12 天、花凉亭坝上水位），进页面自动加载，毫秒级响应。
- 预置预跑机制：后端每 4 小时检查预测窗口，无覆盖方案时自动预跑一次短期来水预测（方案名前缀"智能防洪预置_"），并定期清理过期预置方案；后端每 6 小时预跑兜底。
- 候选站下拉：水位 / 雨量 / 流量三组候选站，站名可选。
- 历史实测块：按同步区间查询实测序列（缺数据返回 null）。
- 手动计算：复用短期来水预测接口（开始/结束逐小时窗口 + 降雨输入 + 三个开关默认关闭）。

**解决的问题**

- 防洪决策原需在多个系统间切换取数（水情、预报、降雨），本页将实测与预测合并为一张拼图。
- 模型计算耗时问题：通过"进页读缓存 + 后台预跑刷新"（stale-while-revalidate）实现进页即见数据，避免每次打开页面等待模型计算。
- 水位预测口径聚焦：只盯花凉亭坝上站（配置化 `obs-level-stcd`），与模型初始水位匹配。

### 3.2 智能抗旱决策

**功能描述**（页面 `drought-trend-analysis.html`，接口 `/drought-decision/*`、`/soil-moisture/*`、`/water-forecast/moisture`）

- 站点下拉 + 实测墒情与模型预测一次查询。
- 预测明细含国标干旱等级（droughtLevel：#1# 无旱 ~ #5# 特旱），四站初值自动取。
- 旱情趋势曲线：墒情实测曲线图。

**解决的问题**

- 抗旱研判此前只有实时墒情、无未来趋势，无法提前研判旱情发展。
- 通过模型墒情预测 + 国标干旱等级映射，为抗旱调度提供定量依据。

### 3.3 配水决策

**功能描述**（页面 `water-allocation-decision.html`）

- 方案列表与 3 张汇总卡（复用配水调度方案数据）。
- 按旬支渠拓扑数据查询：以渠系拓扑图形式展示各旬支渠配水关系。

**解决的问题**

- 配水方案与渠系拓扑割裂：方案数字无法直观对应到渠系空间分布，通过拓扑可视化解决。

### 3.4 运行管理决策

**功能描述**（页面 `operation-management-decision.html`，接口 `/operation/*`）

- 总览计数：巡查总次数（仅已提交巡检记录、排除草稿）、巡查符合度、问题上报数、问题符合度、工单数。
- 问题状态分布（待处理/处理中/已转工单/已关闭/已作废）与工单状态分布（待处理/处理中/已关闭/已取消）。
- 按巡查计划、问题记录、工单数据聚合计算。

**解决的问题**

- 运行管理（巡查执行、问题处置）缺少量化考核视图，通过符合度指标量化运行管理质量。

### 3.5 工程管理决策

**功能描述**（页面 `engineering-management-decision.html`，接口 `/engineering/decision-summary`）

- 站点风险等级分布（堆叠柱状图）。
- 工单类型分布（饼图）、问题状态分布（饼图）。

**解决的问题**

- 工程管理数据（站点风险、工单、问题）分散在多个业务表，通过单接口聚合为管理决策视图。

### 3.6 网络资源设备监控

**功能描述**（页面 `network-device-monitor.html`，接口 `/network-device/summary`）

- 按设备类型分类统计在线 / 离线数量，与设备台账同源。
- 与 `/dashboard/overview`、数据统计页设备口径保持一致。

**解决的问题**

- 设备在线状态原无集中视图，运维无法快速定位离线设备规模；同时解决多端（大屏、统计页、决策页）设备数口径不一致问题。

## 四、水利模型接入功能

**总体架构**：模型服务（Flask，独立部署）计算，本项目负责提交、轮询、方案沉淀与页面呈现。七类模型共用同一套接入框架：

- 异步计算流程：提交计算 → 返回 recordId → 前端轮询状态 → 完成后查询方案详情。
- 通用能力：方案列表 / 重命名 / 删除、启动恢复（服务重启后恢复"计算中"记录，超时 15 分钟判失败）、模型服务健康检查（`/model/health`）、Excel 模板下载与上传解析。
- 消息联动：模型计算完成后向提交人推送"模型计算"消息（H5 消息中心第五类）。
- 页面承载：水量预报页（`water-volume-forecast.html`，四个 Tab：短期来水预报 / 中长期来水预报 / 需水预报 / 水量损失预报）、水资源配置页（`water-resource-config.html`）、配水调度预测页（`water-dispatch-forecast.html`）、智能防洪决策页、智能抗旱决策页。

### 4.1 短期来水预测（`/water-forecast/short`）

- 逐小时来水预报，输出日级明细；防洪决策页计算入口复用本接口。
- 解决的问题：短期入库来水无预报手段，防汛调度缺乏前瞻数据。

### 4.2 中长期来水预测（`/water-forecast/long`）

- 月度 / 旬度中长期来水预测方案（主表 + 月度/旬度明细）。
- 解决的问题：水库中长期调度（供水计划、发电计划）缺乏来水展望依据。

### 4.3 水量损失预测（`/water-forecast/loss`）

- 渠系输水损失预测，损失明细落库。
- 解决的问题：渠系输水损耗无法量化，配水计划未考虑损失因素。

### 4.4 需水预测（`/water-forecast/demand`）

- 支持 JSON 直传或 Excel 模板上传两种提交方式；需水片区汇总 + 支渠明细。
- 需水基础数据收集表模板下载 / 上传解析。
- 解决的问题：各片区需水量测算依赖人工 Excel，通过平台化模板收集与模型计算规范化。

### 4.5 墒情预测（`/water-forecast/moisture`）

- 墒情（土壤含水率）逐日预测，含干旱等级；智能抗旱决策页消费本接口。
- 解决的问题：为抗旱决策提供未来墒情演变预测。

### 4.6 水资源配置（`/water-allocation`）

- 支持 auto / manual 两种提交模式（JSON 直传或模板上传）；配置方案详情含支渠分配明细。
- 配水基础数据收集表模板下载。
- 解决的问题：水资源配置计算量大、人工试算困难，通过模型服务自动完成并沉淀方案。

### 4.7 配水调度（`/water-decision`）

- 配水调度方案计算（含缩放系数、支渠明细）；决策页展示历史方案与计算详情。
- 解决的问题：灌溉期配水调度指令制定缺乏模型支撑，方案不可追溯。

补充说明：模型计算结果（决策 Excel）按 recordId 快照存档，下载按 recordId 取用，防止并发覆盖（`model.decision-excel-dir` 配置）。

## 五、用水管理类功能

### 5.1 用水总结

**功能描述**（页面 `water-use-summary.html`，接口 `/water-use-summary/report`）

- 用水总结报表：按统计周期（月 / 灌季 / 年）聚合用水量、应收水费等数据。
- 周期锚点归桶：统计周期为区间字段，按"区间终点锚点"归入对应月/灌季/年桶，跨桶按终点、缺失回退起点，一次满足全部展示条件的归桶需求。
- 灌季定义配置化：夏灌 05-01 至 08-31、秋灌 09-01 至 10-31（业主确认口径，配置于 `wateruse.season.*`）。
- 灌溉水利用系数：按四干渠实测近似值计算（Σ 干渠流量 ÷ 渠首流量，3 位小数；渠首缺失或四干渠全缺返回 null）。
- 用水量、应收水费直取水费计算表单值（2 位截断），后端不做推算。

**解决的问题**

- 用水总结此前靠人工从表单汇总，月/灌季/年多维度口径不一致；归桶设计使"同一份数据满足多种周期展示"成为可能。
- 灌溉水利用系数无实测值，通过渠道实测流量近似，为节水评价提供数据基础。

### 5.2 水费征收/收缴统计

**功能描述**（接口 `/water-use-summary/fee-collection`，大屏页共用）

- 一次请求返回区域段 + 月度段两段数据：各区域征收情况（柱状折线组合图）、月度收缴趋势（柱状组合图）。
- 缺省当年，可指定年份。

**解决的问题**

- 应收 / 已收水费与收缴率此前分散核算；接口将区域维度与月度维度合并，供两张图共用一次请求，同时减少大屏请求数。

### 5.3 灌溉用水

**功能描述**（页面 `irrigation-water.html`，接口 `/irrigation-water/*`）

- 灌溉用水汇总：按县（太湖 / 望江 / 宿松 / 怀宁）展示实际供水量、灌溉进度、保证率等。
- 方案下拉选项查询（需水方案来源）。
- 口径配置化：各县设计保证率（`irrigation.water.design-rate.*`）、太湖行损耗扣减（`loss-volume-m3`）。

**解决的问题**

- 灌溉期各县用水执行情况无法对比（谁供了多少、进度如何、保证率达标否）。
- 县与需水片区映射口径统一：需水量来源（需水方案）与实际供水量（渠道实测累计）分列，消除口径混淆。

### 5.4 节水潜力分析

**功能描述**（页面 `water-saving-potential.html`，接口 `/water-saving-potential/record`）

- 测算记录读取与保存（upsert 整行覆盖）：年度 + 分析范围（全灌区 / 四县）维度的基础数据三件套、分行业基准/目标需水量、测算依据与措施。
- 附件只读回显（basisFileUrl 经文件服务解析，失败降级不阻断）。
- 状态流转：草稿 / 已测算；计算与保存分离。

**解决的问题**

- 节水潜力测算无平台载体（原页面为纯前端演示、数据硬编码），通过表结构与接口落地为可保存、可追溯的管理功能。

## 六、数据统计与站点管理

### 6.1 数据统计（统计大屏）

**功能描述**（页面 `data-statistics.html`，接口 `/data-statistics/*`）

- 统计卡片聚合（KPI）：站点总数、到报数、缺测数、采集状态等核心指标。
- 站点到报明细：按站点列出到报情况。
- 缺测明细：连续缺测窗口合并为段，含起止时间、时长、数据类型、当前状态。
- 数据采集状态统计、视频数据采集统计（对接 hltgq-device 大华视频）、采集服务状态、信息发布情况（本地、恒今日口径）。
- 网关转发：site 转发 hltgq-mq / hltgq-device 内部接口并透传数据段；转发时携带当前登录会话（X-Session-Id）。

**解决的问题**

- 业主对大屏统计口径的核对诉求：把"站点了多少个、到报多少、缺测多少、视频在线多少"在一页说清，且与各监测页、大屏接口口径一致。

**功能描述**（页面 `station-detail.html`、移动端 `station-detail-h5.html`，接口 `/station-detail/*`）

- 设备信息分页：行含设备名称、编号、安装位置（location）及实时数据（按类型取最新值并过滤异常值）。
- 筛选下拉选项：巡检状态、问题类型等下拉数据。
- 绑定候选设备搜索（管理员）：按条件检索可绑定的候选设备。
- 设备换绑（管理员）：更换站点与设备的归属关系，仅视频设备可换绑，候选过滤 + 并发防误转移。

**解决的问题**

- 站点档案、设备、巡检、问题、工单数据分散在不同业务表，通过详情页一站式聚合。
- 设备归属错误修正：此前设备绑定后无法调整（或误操作风险高），提供受控的换绑入口与防误转移保护。

### 6.3 站点排序

**功能描述**（接口 `/station-sort/*`，组件 `lib/station-sort.js`）

- 按页面语义类型（waterLevel / rainfall / gq-rainfall / flow / gate / moisture）配置站点展示顺序，支持保存与查询。
- 各监测页挂载排序组件；大屏与三维对外接口的站点输出顺序同样遵循该配置，且 `/external/station-monitor` 对未配置排序的站点按在线优先分组（离线站统一排在列表最后）。
- 水位监测页按主 Tab 切换站点范围（水库 Tab 只列水位站组、灌区 Tab 只列闸站组，空组不渲染）。

**解决的问题**

- 业主对站点展示顺序有明确诉求（水库站排在上游、渠道按实际顺序等），此前顺序由数据库默认排序决定、不可调整；同时统一了各页面与对外接口的顺序口径。

### 6.4 站点信息导入 / 导出

**功能描述**（页面 `station-manage-import.html`、`station-manage-export.html`，接口 `/station-data/*`）

- 模板下载（`StationImport_Template.xlsx`）、上传解析入库：逐行校验（站点名称/编号必填、编号批内 + 库中双重防重、渠系类别/管理单位按名称匹配），单行失败不影响其他行，同步返回逐行结果。
- 仅新增不覆盖，避免误改已有档案。
- 导出：列表数据源接口 + 前端生成 Excel。

**解决的问题**

- 站点档案批量初始化 / 维护此前靠手工逐条录入，效率低且易错；导入提供模板化、校验化的批量通道。

### 6.5 大屏数据服务

**功能描述**（接口 `/external/station-monitor`、`/dashboard/overview`、`/dashboard/alerts`）

- `/external/station-monitor?type=N`：按监测类型（1 水位 / 2 雨量 / 3 流量 / 4 闸门 / 7 墒情 / 8 水质）返回"站点列表 + 实时值"，每行 = 档案字段（与原上游平台同名字段）+ 实时值平铺 + `data` 子对象 + `hasData` 标记；可按键名模糊筛选；站点顺序按「站点排序」配置输出（未配置排序的站点在线优先）；响应信封与原 qx-api 一致，便于前端无感迁移。
- `/dashboard/overview`：设备总数/在线数/在线率、闸门设备总数/开启数/开启率、未处理告警数（支持按站点过滤）。
- `/dashboard/alerts`：某站点未关闭告警列表。

**解决的问题**

- 大屏前端原需"先取站点列表、再逐站取实时值"两次请求拼接，现一次返回，降低前端复杂度与请求量。
- 设备/闸门统计口径归一（台账口径、闸孔维度），解决大屏与决策页、统计页数值不一致的问题。

### 7.2 雨量数据维护（删除数据 + 设备补偿值）

**功能描述**（页面 `rain-data-manage.html`，接口 `/st-pptn-r/manage/*`、`/rain-adjust/*`）

- 单一入口：雨量监测页仅保留一个"数据维护"按钮（管理员可见），直达数据维护页。
- 历史数据区：雨量历史数据查看 / 删除；删除弹窗必填设备补偿值（多灌为正数、少灌为负数、设备复位填 0），不填不可提交；删除为软删除（`deleted` 标记 + 审计列），数据行占位以防止原始报文重投"复活"。
- 设备补偿值区：已配置补偿值列表，支持修改 / 移除（无新增入口，新增随删除操作自动生成）。
- 三级护栏确认交互：删除不可回滚、不可恢复，界面无"已删除数据"视图。
- 删除生效方式：通过入库前值 / 基线过滤实现（由 mq 侧配合），并对后续累计值做补偿重算。

**解决的问题**

- 设备故障导致的异常雨量入库（典型案例：某站 34.0 异常值事件）无法修正的问题；建立了"删除 + 补偿"的标准处置流程。
- 删除后报文重投导致数据复活的问题（软删占位解决）。
- 删除与补偿的联动一致性：删除时填写的补偿值即进入补偿配置，保证后续重算基线正确、差值守恒。

### 7.3 巡检计划导入

**解决的问题**

- 巡检计划批量录入低效的问题；计划编号人工维护易冲突的问题；通过逐行校验 + 行级错误反馈，导入过程可自解释、可追溯。

### 7.4 管理台账导出

## 八、运维监控类功能

### 8.1 系统资源监控

**功能描述**（页面 `system-monitor.html`，接口 `/system-monitor/*`）

- 多主机聚合展示：本机实时采集 + 远端主机定时上报，远端主机以别名标识（如"中间件服务器""应用服务器 1"），显示在线状态与最后上报时间。
- 监控指标：CPU 使用率与负载、内存总量/已用/可用及百分比、Swap、磁盘分区详情（挂载点、容量、使用率）、数据库模块（库大小、表空间大小及使用率）。
- 阈值告警配置：CPU/内存 90%、Swap/磁盘/表空间 85%（共享页面着色与采样告警）。
- 故障记录：软件/系统两类共用，异常处理器与采样任务写入，同类去重窗口 5 分钟；资源采样每 5 分钟一行、保留 30 天。
- 监控报警子系统对接：故障记录 JSON 经 Webhook 异步推送（可配置开启）。
- 前端轮询实时刷新 + 查询。

**解决的问题**

- 服务器资源状态无监控的问题（磁盘写满、内存耗尽事后才发现）；主机侧视图（宿主机根挂载只读）避免容器内视角失真。
- 跨主机采集的凭据问题：采用"服务器内部脚本采集 → HTTP POST 上报 → 服务端解析入库"架构，脚本仅采集原始文本（/proc/stat、df 等），一切计算在服务端完成；上报接口以 Token + 来源 IP 前缀白名单鉴权，不依赖跨机 SSH 凭据。

### 8.2 服务健康检查

**功能描述**（接口 `/model/health`）

- 模型服务（Flask）可用性探测，供运维与页面判活。

**解决的问题**

- 模型服务不可用时及时暴露（页面提示 / 排查入口），避免"计算提交后才失败"的体验问题。

## 九、天气服务功能

### 9.1 气象预报

**功能描述**（接口 `/weather/*`，前端联调接入）

- 实时天气卡片（`/weather/current`）：灌区参考点实时天气（地图悬浮卡片场景）。
- 逐小时天气（`/weather/hourly`）：过去 7 天历史 + 未来 16 天预报（覆盖模型降雨窗口需求）。
- 40 天日级预报（`/weather/daily`）：两段拼接——第 1~16 天用 Forecast API，第 17~40 天用季节预报 EC46（50 成员服务端聚合），分段缓存与按需拉取。
- 雨情趋势预判（`/weather/rain-trend`）：由 40 天日级缓存实时推导（EC46 成员降水概率）。
- 稳定性设计：分段 TTL + 抖动、stale-while-revalidate 兜底、单飞合并、上游令牌桶限流、命名线程池隔离、预热任务。

**解决的问题**

- 灌区气象信息缺失：从"无气象数据"到提供实时/逐小时/40 天/雨情趋势四层数据。
- 免费源选型治理：实测否决 Ensemble API、改 EC46 为主力；慢速外网源不阻塞公共线程池；上游抖动时旧值兜底，保证页面可用。

### 9.2 台风监测

**功能描述**（接口 `/weather/typhoon/active`、`/recent`、`/detail`）

- 活跃台风列表、最近台风列表（含已停止，供查阅）、台风路径详情。
- 灌区参考中心坐标统一配置（台风距离、天气预热、模型降雨回退共用同一坐标来源）。

**解决的问题**

- 防汛期台风影响研判无数据源；统一坐标来源避免多处配置漂移。

### 9.3 雷达图

**功能描述**（接口 `/weather/radar/frames`、`/weather/radar/tile`）

- 降雨实况雷达帧列表 + 瓦片代理（RainViewer，免费档降级可用 z≤7，颜色固定）。
- 治理：帧列表缓存 + stale 兜底、瓦片进程内 LRU（3000 条）、上游令牌桶 90 次/分钟、客户端 IP 限流、瓦片上游主机固定（SSRF 防护）。
- 瓦片路径加入鉴权白名单（浏览器直载资源无法携带自定义 Header，风险由 z 上限 + 限流约束）。

**解决的问题**

- 降雨实况可视化缺失；免费源全球配额保护（避免超限封禁影响全站）。

## 十一、对外集成功能

### 11.1 三维系统对接

**功能描述**（接口 `/external/*`，契约见《三维系统对接接口.md》《三维点位接入.md》）

- 业务统计类 8 接口：闸门类型数量、渠首进水闸（水位/流量/管理单位）、巡检汇总、巡检/突发事件逐日趋势、问题统计 + 应急响应统计、视频监测按管理所聚合、天气预报（复用）、雨量日聚合（复用）。
- 监测点位接入：水位/闸门、雨量、流量、墒情、水质五类点位 + 经纬度，支持渠系树过滤、站点筛选、时间筛选、异常值与缺失值处理约定。
- 趋势口径修订：突发事件 = AI 智能分析告警（type=#3#）；已解除响应 = AI 告警已关闭数（status=#4#）。
- 站点列表合并接口：按监测类型合并输出（见 6.5）。

**解决的问题**

- 三维数字孪生 / 第三方大屏需要灌区的实时监测与业务统计数据；通过标准契约 + 线上验证（2026-09-05 全部通过）稳定供给。
- 口径裁定过程数字化：如"突发事件"定义、闸门统计维度等争议点，以实测数据核对定稿并留档。

### 11.2 档案系统对接

**功能描述**（接口 `/archive/sync/trigger`，定时任务 `archive.sync-cron`）

- 组织、人员信息推送（先组织后人员），每日定时 + 手动触发两种方式。
- 档案系统 token + userId 获取接口（`/auth/archive-token`），后端兜底处理。

**解决的问题**

- 人员组织信息在两个系统间的一致性问题（新入职、调岗、离职不同步）。

### 11.3 三方单点登录

**功能描述**（接口 `/auth/3d-token`、`/auth/current-user`）

- 三维系统 SSO 代理（ssoLogin）+ token 缓存（30 分钟）；当前登录人信息查询。
- 登录验证拦截说明（供联调参考）：白名单机制 + 登录页重定向。

**解决的问题**

- 三维系统与本平台之间免二次登录，保障用户体验与会话安全传递。

### 11.4 登录鉴权与权限控制

**功能描述**（模块 `auth`）

- 登录验证拦截器（`auth.enabled` 开关、白名单前缀匹配、静态页面放行、`login-page-url` 重定向）。
- 管理员权限注解（RequireAdmin）：数据删除、设备换绑等敏感操作受限；角色缓存走 Redis、缺失回退数据库。
- 会话上下文（UserContext / SessionContextService）：当前登录人贯穿各业务（消息、导入创建人、审计列）。

**解决的问题**

- 平台从"无鉴权访问"升级为"登录态 + 管理员权限"的安全体系；敏感写操作（数据删除、换绑）与普通查询分级。

### 11.5 召测服务对接

**功能描述**（配置 `recall.base-url`）

- 闸站召测指令转发（转发至召测服务，服务端同步挂起等待 RTU 应答入库，窗口 5 分钟 + 余量）。
- 状态聚合查询（任一召测中 → 召测中；全部确认 → 数据确认；否则空闲），页面刷新后恢复按钮状态。

**解决的问题**

- 召测操作平台化、状态可视化；RTU 应答慢导致的前端等待问题通过异步 + 轮询解决。

### 11.6 文件服务对接

**功能描述**（模块 `stationdetail/client/FileClient`）

- 低代码平台附件（文件 id）解析为带签名的访问地址：巡检照片、盘点附件、节水测算附件（回显失败降级 null，不阻断主流程）。

**解决的问题**

- 平台附件数据与页面展示之间的"最后一公里"：文件 id 无法直接展示，统一经文件服务解析。

## 十二、平台基础能力与数据治理

### 12.1 数据口径治理（贯穿全项目）

- **水文日统一**：全部雨情统计以每日 08:00 为界，与水利行业标准及老系统一致。
- **实时雨情取值规范**：取本水文日累计（latestDrp），保证实时性真实反映当前降水。
- **哨兵值与异常值处理**：-999 等异常值页面显示 "--"；墒情量程校验；防洪模型哨兵值不回溯。
- **断联标识**：数据中断时页面时间标红、接口返回 isOnline 标识。
- **数值精度规范**：雨量 2 位小数、水量 3 位截断、百分比 2 位小数。
- **新老系统对照核验**：以老系统为基准逐项复核（如雨量出账滞后归因、时段雨情 08:00 桶差异），形成《雨量数据异常.md》等分析报告。

**解决的问题**：口径混乱导致的新老系统数据对不上、业务质疑与误判；将口径规则沉淀为文档与配置，避免反复返工。

### 12.2 性能与稳定性

- 网关层缓存预热（数据统计当天/历史分档 TTL）、天气分段缓存与 stale 兜底、Redis 分布式缓存。
- 大屏 / 三维接口一次请求聚合多次查询；SQL 层过滤 + 索引兜底；分页两段式（消息中心防范 UNION 全表排序）。
- 并发守卫：设备换绑快照锁 + 并发控制；模型任务全局锁串行执行 + 启动恢复。
- 定时任务线程池隔离（`spring.task.scheduling.pool.size=2`），避免重查询阻塞天气预热/同步任务。
- 区间防御限制：观测区间上限（防洪 90 天）、月份上限（24）、分页上下限等，防止拖库。

**解决的问题**：首屏慢、并发冲突（绑定竞态、重复提交）、慢任务互相拖累、误用大区间查询拖垮数据库。

### 12.3 导出体系

- 监测页导出：列表导出（当前筛选全量）+ 详情导出（弹窗勾选字段，Excel 表头严格对应勾选字段）。
- 管理台账导出：数据源接口返回 JSON，前端生成文件。
- 覆盖页面：水位、雨量、流量、闸门、墒情、水质及六个管理台账导出页。

**解决的问题**：业主"所有监测页面都要有导出、且能自选导出哪些字段"的诉求，一次体系化落地。

### 12.4 消息与通知

- H5 消息中心五类消息（含模型计算完成提醒）。
- 系统监控故障记录 → 监控报警子系统 Webhook。
- 联调确认项日志化：需要确认的事项（字段映射结果等）直接打日志，部署后查日志核对。

**解决的问题**：业务事件（告警、模型完成、值班）与运维事件（资源超限、服务异常）的双通道通知触达。

### 12.5 基础技术设施

- 全局异常处理（参数校验、统一错误响应、业务异常分类）。
- Jackson 配置：BigDecimal 按平文输出（避免精度/科学计数问题）。
- KingbaseES 兼容：LocalDateTimeTypeHandler、日期拼接与保留字规避。
- MyBatis-Plus 多数据源与 Mapper 扫描白名单。

**解决的问题**：数据库兼容性细节（KingbaseES 特有行为）与精度问题的统一兜底。
