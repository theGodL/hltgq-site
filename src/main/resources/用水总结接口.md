# 用水总结接口（/water-use-summary）

> 页面：`static/water-use-summary.html`（月/灌季/年维度 → 「统计时段/用水量/灌溉水利用系数/应收水费」列表 + 用水量柱状/系数折线/应收水费柱状图）
> 鉴权：与其他接口一致（请求头 `X-Session-Id` 或 Cookie `sessionId`）

## 1. 接口一览

| 接口 | 方法 | 说明 |
|------|------|------|
| `/water-use-summary/report` | GET | 用水总结报表（月/灌季/年归桶：用水量、灌溉水利用系数、应收水费） |
| `/water-use-summary/fee-collection` | GET | 征收/收缴统计（一次返回**各区域征收情况** + **月度收缴趋势**两段数据，供两张柱状折线组合图） |

> 页面双维度组 A/B 各调一次 `/report`（参数独立），口径完全一致；该接口的实收水费/水费收缴率不提供（产品已裁剪，详见「4.1」）。
> 实收（已收）水费与收缴率由 `/fee-collection` 提供（另一套图表：各区域征收情况 / 月度收缴趋势，详见「3」）。

## 2. GET /water-use-summary/report — 用水总结报表

**请求参数**

| 参数 | 必填 | 类型 | 说明 |
|------|------|------|------|
| dimension | 是 | string | 归桶粒度：`month`（月）/ `season`（灌季）/ `year`（年）；其他值返回 400 |
| startTime | 是 | string | 查询起点（`yyyy-MM-dd`） |
| endTime | 是 | string | 查询终点（`yyyy-MM-dd`）；早于 startTime 或跨度超 10 年返回 400 |

**归桶规则**（桶覆盖查询区间、按时间升序；桶内无数据时对应列为 null，不补 0）：

| dimension | 一行 = | period / label |
|-----------|--------|----------------|
| `month` | 区间涉及的每个自然月（桶=整月） | `2026-08` |
| `season` | 与区间相交的每个灌季窗口（桶=完整灌季窗口） | `2026-summer` / `2026夏灌`、`2026-autumn` / `2026秋灌` |
| `year` | 区间涉及的每个自然年（桶=整年） | `2026` |

> 「月」桶按**整月**聚合（如查询 08-01 ~ 08-16 同样返回整月合计）；灌季/年桶同理按整窗口聚合。

**响应**：数组，每项字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| period | string | 统计桶键：`2026-08` / `2026-summer` / `2026` |
| label | string | 统计时段展示标签：`2026-08` / `2026夏灌` / `2026`（可直接用于表格「统计时段」列） |
| periodStart / periodEnd | string | 桶起止日期（`yyyy-MM-dd`，含边界），用于提示/核对 |
| usage | number\|null | 用水量(万m³)：计划供水量（mlljya）桶内求和（表单单位即万m³，3 位截断，累计流量口径） |
| irrigationCoef | number\|null | 灌溉水利用系数（近似值，3 位小数）；不可计算时为 null（见「3.3」） |
| receivable | number\|null | 应收水费(万元)：水费表单 hsfvdh 桶内求和（表单按「元」录入，÷10000 换算为万元后 2 位截断） |

**示例**（dimension=season，2026-01-01 ~ 2026-12-31；水费表单尚未录入时 usage/receivable 为 null，系数为流量监测实测近似值）

```json
[
  {
    "period": "2026-summer",
    "label": "2026夏灌",
    "periodStart": "2026-05-01",
    "periodEnd": "2026-08-31",
    "usage": null,
    "irrigationCoef": 0.391,
    "receivable": null
  },
  {
    "period": "2026-autumn",
    "label": "2026秋灌",
    "periodStart": "2026-09-01",
    "periodEnd": "2026-10-31",
    "usage": null,
    "irrigationCoef": 0.731,
    "receivable": null
  }
]
```

> 上例系数为 2026-09-10 前后线上数据形态（窗口内区间累计可取数即出值，随数据上报滚动）；数值以实际为准。水费表单录入后 usage/receivable 自动出数，无需改接口。

## 3. GET /water-use-summary/fee-collection — 征收/收缴统计（区域段 + 月度段）

> 一个接口返回两段数据，分别驱动两张柱状折线组合图：**各区域征收情况**（x 轴 = 区域）与**月度收缴趋势**（x 轴 = 统计年 12 个月）；
> 两段指标与单位完全一致：柱 y 轴为万元，折线 y 轴为收缴率（%）。数据源与「2」同一张水费计算表单，归桶锚点口径一致（见「4.1」）。

**请求参数**

| 参数 | 必填 | 类型 | 说明 |
|------|------|------|------|
| year | 否 | int | 统计年份，缺省 = 当年；超出 2000 ~ 2100 返回 400 |

**响应**

| 字段 | 类型 | 说明 |
|------|------|------|
| year | int | 实际统计年份（未传 year 时为当年） |
| regions | array | 各区域征收情况（x 轴 = 区域），按应收水费降序、应收为 null 的区域排末位 |
| regions[].region | string | 区域（用水户名称，如望江县） |
| regions[].receivable | number\|null | 应收水费(万元)：hsfvdh 求和（表单按「元」录入，÷10000 换算为万元后 2 位截断） |
| regions[].received | number\|null | 已收水费(万元)：vdhlhm 求和（表单按「元」录入，÷10000 换算为万元后 2 位截断） |
| regions[].collectionRate | number\|null | 水费收缴率(%)：已收 ÷ 应收 × 100（1 位截断） |
| months | array | 月度收缴趋势，固定 12 项（`2026-01` ~ `2026-12`，无数据月份字段为 null） |
| months[].month | string | 月份（`yyyy-MM`） |
| months[].receivable / received / collectionRate | number\|null | 同 regions 口径 |

**示例**（`GET /water-use-summary/fee-collection?year=2026`）

```json
{
  "year": 2026,
  "regions": [
    { "region": "望江县", "receivable": 1234.56, "received": 900.00, "collectionRate": 72.9 },
    { "region": "太湖县", "receivable": 800.10, "received": null, "collectionRate": null }
  ],
  "months": [
    { "month": "2026-01", "receivable": null, "received": null, "collectionRate": null },
    { "month": "2026-09", "receivable": 2034.66, "received": 900.00, "collectionRate": 44.2 },
    { "month": "2026-12", "receivable": null, "received": null, "collectionRate": null }
  ]
}
```

> 示例 `months` 仅列首/中/末三项，实际固定返回 12 项；数值为口径示意，以线上数据为准。

**前端接入（两张图共用一次请求）**

| 图表 | 请求段 | x 轴 | 柱 | 折线（副轴） |
|------|--------|------|----|--------------|
| 各区域征收情况柱状折线组合图 | `regions` | `region` | `receivable` / `received`（万元） | `collectionRate`（%） |
| 月度收缴趋势柱状折线组合图 | `months` | `month` | `receivable` / `received`（万元） | `collectionRate`（%） |

- 两个金额都为 null 时该点柱与折线均留空（不画 0 柱）；`collectionRate` 为 null 时折线断开。
- 建议图例：柱「应收水费 / 已收水费」（左轴 万元），折线「水费收缴率」（右轴 %）。
- 落位：`/water-use-summary.html` 用月度收缴趋势图；`/irrigation-water.html` 用各区域征收情况图（区域即用水户名称，含县/乡镇等实际录入值，非固定四县）。

## 4. 计算口径

### 4.1 用水量 / 应收水费（水费计算表单）

| 页面列 | 表单字段 | 换算 | 说明 |
|--------|----------|------|------|
| 用水量 | mlljya 计划供水量 | 表单单位即万m³（不换算，按展示精度 3 位截断） | 桶内多用水单位记录求和 |
| 应收水费 | hsfvdh 应收水费 | 表单按「元」录入 → ÷10000 换算为万元（按展示精度 2 位截断） | 桶内求和 |
| （核对用） | ztmhwx 水费编号、fbnomc 用水单位、lgwutj 执行水价(元/m³) | — | 随日志输出 |

- 表单：`t_auto_hltgq_yn8cm_gfiidm`（业主手动录入；统计周期为区间字段 xxmefs，物理列 xxmefs_min / xxmefs_max）。
- 用水量直取计划供水量 mlljya、应收水费直取 hsfvdh（表单现成值，后端不做推算）。
- **归桶锚点 = 统计周期区间终点 xxmefs_max**（业主 2026-09-11 确认）：跨桶记录按终点归属，终点缺失回退起点；找不到桶的记录忽略并输出计数日志。
- 本接口 **不提供实收水费 / 水费收缴率**（产品裁剪）；实收（已收）水费与收缴率见「3」的 `/fee-collection`。
- **单位口径（表单以 2026-09-17 线上数据复核，已定稿）**：计划供水量 表单单位即**万m³**（直取不换算）；执行水价 元/m³；**应收/已收水费按「元」录入，接口出参统一换算为「万元」（÷10000）**。换算点：`receivableOf` / `receivedOf` / `buildRow`（常量 `FEE_YUAN_TO_WAN_SHIFT`）；收缴率为比值、不受单位影响。依据：金额表单标签即「应收水费（元）」、自动算式 = 用水量 × 执行水价(元/m³)；线上实录 5130000（潜山县）若按万元解读相当于 513 亿元，换算后 513.00 万元与 1500 万m³ × 0.342 元/m³ 自洽（详见「9」第 1 条）。后端每次请求输出前 5 条表单原值（`[用水总结] 水费记录样例`，含统计周期区间/计划供水量/执行水价/应收水费，金额原值为元），可逐条核对。

### 4.2 统计周期区间如何满足全部展示条件（归桶设计）

统计周期为区间字段（xxmefs_min / xxmefs_max），页面全部筛选条件由后端「周期锚点归桶」完成，**不约束业主录入习惯**（按区间终点归属，宽松归属）：

| 页面维度 | 归桶方式 |
|----------|----------|
| 月 | 取统计周期终点的年-月作为月桶（如 `2026-09`） |
| 灌季 | 统计周期终点落入灌季窗口（见「5」）即归属，如 `2026夏灌` |
| 年 | 取统计周期终点的自然年 |

一条记录只归入一个桶（跨桶区间按终点选择），保证「年 = 各月之和、各灌季之和」的汇总口径一致。

### 4.3 灌溉水利用系数（实测近似值）

- 公式：**系数 = Σ(北干/南干/太宿/太怀 四条干渠进水闸区间累计) ÷ 渠首进水闸区间累计**（同桶窗口）。
- 区间累计口径与流量监测/闸门监测/灌溉用水一致：区间累计 = ttf(窗口内末行) − 起点前最近一条 ttf（无基准按 0）。
- 取数站点（stcd / site UUID 双键候选）：北干渠进水闸（`4Ieu32Stnz8dTD8S8GD` / `9000000001`）、南干渠进水闸（`cOGko9nLfFz6rRAvKvY` / `9000000002`）、太宿干渠进水闸（`k6V2otO7e4ZmEba7HMD`）、太怀干渠进水闸（`zxgbgrx0lUXS44Jklo8`）、渠首进水闸（`CAYQ739MiBWMg9gQvyi`）。
- 返回 null 的情形：渠首缺失或 ≤0；或四干渠全部无数据（部分缺失时按现有数据求和并逐站日志）。
- 补充说明：官方灌溉水利用系数需田间量测，本值按闸站监测流量近似，未做校核；窗口内逐站取数明细见日志（`[用水总结] 区间取数`），可直接核对。四干渠/渠首自 2026-08 起有数据，更早窗口系数为 null。

## 5. 灌季定义（第一版，业主 2026-09-11 确认）

| 灌季 | 窗口（含边界） | 农事 |
|------|----------------|------|
| 夏灌 | 05-01 ~ 08-31 | 泡田栽插 → 分蘖拔节、用水高峰 |
| 秋灌 | 09-01 ~ 10-31 | 抽穗灌浆 → 成熟停水 |

- 窗口按 `MM-dd` 配置，逐自然年生成（2026 夏灌 = 2026-05-01 ~ 2026-08-31）。
- 非灌期（11 月 ~ 次年 4 月）的水费记录不归入灌季维度（灌季查询时忽略并输出计数日志），**年/月维度不受影响**。
- 跨年查询按自然年分别生成窗口（如 2025-09-01 ~ 2026-06-30 → 返回 `2025秋灌`、`2026夏灌` 两行）。

## 6. 前端需配合的调整

1. **「天」维度改「月」**：水费数据按统计周期区间归属，最细展示粒度为月。建议维度按钮改为「月 / 灌季 / 年」，日期区间控件改为**月份区间**（起止年月）；请求时转换为 `yyyy-MM-dd`（如月首日/月末日）传入，`dimension=month`。
2. **灌季下拉**：按年生成（如 `2026夏灌`/`2026秋灌`），可直接传该灌季窗口的起止日期（dimension=season），响应 `label` 即选中项文案。
3. **表格列调整**（`/report` 表格）：删除「实收水费」「水费收缴率」两列（该接口不提供；实收/收缴率改用「3」的 `/fee-collection`）。
4. **缺失显示**：`usage` / `receivable` / `irrigationCoef` 为 null 时显示「—」。
5. **A/B 双维度组**：两组各调一次本接口，参数独立；柱/线图直接取 rows 的 `usage` / `irrigationCoef` / `receivable`。

## 9. 联调与待核对项

1. **水费表单字段/单位核对**（**已定稿**）：用水量=计划供水量 mlljya（**万m³**，直取不换算）、应收水费=hsfvdh（表单**元** → 出参**万元**）、已收水费=vdhlhm（表单**元** → 出参**万元**），归桶按统计周期区间终点（见「4.1」）；日志 `[用水总结] 水费记录样例` / `[用水总结] 征收记录样例` 输出前 5 条表单原值（统计周期 / 计划供水量 / 执行水价 / 应收 / 已收），金额原值单位为元、便于与库中 `SUM(hsfvdh)` / `SUM(vdhlhm)` 直接对账。
   - 判定依据（2026-09-17 线上数据复核）：金额表单标签即 `应收水费（元）`、自动算式 = `用水量 × 执行水价(元/m³)`；线上 `?year=2026` 实录潜山县 5130000 / 望江县 188890，按万元解读相当于 513 亿元（与业务量级不符），÷10000 后 513.00 / 18.88 万元与 `1500 万m³ × 0.342 元/m³`、`222.22 万m³ × 0.085 元/m³` 自洽。
   - 与 2026-09-17 早间查库快照（`hsfvdh` = 9 / 51、`vdhlhm` 为空）的差异，说明业主已按新口径补录并改为「元」录入，故服务层改为换算（原「直取不换算」结论作废）。
   - **供水量口径（本次确认）**：计划供水量 mlljya 仍按**万m³**录入，`buildRow` 保持直取不换算（`WaterVolumeUtils.wanScale`）仅做 3 位截断；即同一张表单内**金额按「元」、供水量按「万m³」两种口径并存**，各自按字段标签录入。
   - **交叉校验**：两个字段可相互验证——换算后金额（万元）应 ≈ 计划供水量（万m³）× 执行水价（元/m³）× 1（量纲：万m³ × 元/m³ = 万元），或按原值校验：计划供水量 × 10000 × 执行水价 = 应收水费（元）。例：潜山县 1500 万m³ × 0.342 元/m³ = 513.00 万元 = 5130000 元 ✓。
2. **系数核对**：日志 `[用水总结] 区间取数` 输出逐站区间累计与近似值；与闸门监测/灌溉用水接口交叉验证同窗口数值。
3. **鉴权**：与其他接口一致，登录态下直接可用（`auth.enabled=true` 时受登录拦截器保护）。
4. **征收/收缴核对**（`/fee-collection`）：日志 `[用水总结] 征收记录样例` 输出前 5 条（编号 / 区域 / 归桶锚点 / 应收水费(表单原值·元) / 已收水费(表单原值·元)）；随后逐区域输出 `应收/已收/收缴率`（已换算为万元），并以一行「月度出桶」列出 12 个月的 `应收/已收/收缴率`（无数据显示「无」），可直接与两张图逐点核对。
   - 年度合计行同时输出**表单原值合计**（未截断，单位**元**），可与 `SELECT SUM(hsfvdh), SUM(vdhlhm)` 直接对账（换算与截断只影响出参）。
5. **区域归属核对**：区域取水费表 `xqaoxx` → 用水户表 `t_auto_hltgq_yn8cm_kooivg.id` 的 `iiatzj`（用水户名称）；用水户未填 / 记录被删除 / 名称为空的记录不计入区域图（日志输出「无区域记录」条数），仍计入月度趋势。已核实（2026-09-17 查库）：水费表 17 列、用水户表 8 列（业务列仅 `iiatzj` 与 `kxjhnx`），**两表均无 `del_flag` 列**，故不加删除过滤；用水户记录被物理删除时 LEFT JOIN 取不到名称，按「无区域」处理。
6. **已收水费单位**（**已定稿**）：`vdhlhm` 与应收同口径，表单按**元**录入 → 出参 ÷10000 换算为万元、按展示精度 2 位截断（与应收一致）。早间查库时 2026 年 2 条记录该字段为空（`received` / `collectionRate` 为 null）；现线上已补录（望江县 188890 元 / 潜山县 5130000 元，换算后 18.88 / 513.00 万元，收缴率 100.0%）。
