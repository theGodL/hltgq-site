# 天气接入接口文档

> 本文档供**前端开发**对接使用：生产环境路径统一加 `/hltgq-site` 前缀
> 数据源：Open-Meteo Forecast（实时 / 逐小时 / 1~16 天）+ Open-Meteo Seasonal（EC46 集合预报，17~40 天）+ 中央气象台台风网（NMC，台风）+ RainViewer（雷达瓦片，过去约 2 小时回放）
> 覆盖场景：地图实时天气卡片、逐小时天气弹窗、40 天日级预报、雨情趋势预判、台风路径展示、**观测预判雷达图（叠加图层 + 时间轴回放）**
> 后端统一代理 + Redis 缓存 + 单飞防击穿 + 限流：**上游失败不返回 5xx**，一律以显式降级字段告知前端

## 模块总览

| 接口 | 方法 | 用途 | 前端场景 |
|------|------|------|---------|
| `/weather/current` | GET | 实时天气卡片 | 地图悬浮卡片（建议 10 分钟轮询） |
| `/weather/hourly` | GET | 逐小时天气列表 | 卡片点击弹出的天气列表弹窗 |
| `/weather/daily` | GET | 40 天日级预报（1~16 天常规 + 17~40 天趋势） | 中长期预报列表 / 图表 |
| `/weather/rain-trend` | GET | 雨情趋势预判 | 累计雨量、有雨天数、连续无雨统计 |
| `/weather/typhoon/active` | GET | 活跃台风列表（**非台风季为空**） | 台风概览 / 图层入口 |
| `/weather/typhoon/recent` | GET | 最近台风列表（**含已停编，任何季节都有数据**） | 非活跃期取数 / 历史台风回看 |
| `/weather/typhoon/detail` | GET | 台风路径详情 | 台风路径地图（实况实线 + 预报虚线） |
| `/weather/radar/frames` | GET | 雷达帧列表（时间轴，约 13 帧 / 过去约 2 小时） | 观测预判雷达图的时间轴 |
| `/weather/radar/tile/{z}/{x}/{y}` | GET | 雷达瓦片代理（PNG，**仅 z≤7**） | 地图之上的雷达回波叠加图层 |

## 〇、公共约定

### 0.1 基础信息

- **生产 Base URL**：`http://220.179.1.110:8081/hltgq-site/weather/...`（本地联调去掉 `/hltgq-site` 前缀）
- **坐标系**：WGS-84（与天地图一致，前端地图站点坐标**直传即可，无需坐标转换**）
- **时区**：北京时间（上游 timezone=Asia/Shanghai），响应中日期 `yyyy-MM-dd`、小时 `HH:mm` 均为北京时间
- **数据源与缓存**（均为免费源，无认证无配额）：
  - 实时 / 逐小时：Open-Meteo Forecast，Redis 缓存新鲜期 10~13 分钟随机抖动；卡片温度最多滞后约 13 分钟，**前端无需高频刷新**
  - **上游故障时不会立刻变空**：过期缓存在旧值上限内继续返回（卡片 6 小时、逐小时 24 小时、日级 24 小时、台风 6 小时），同时后端后台异步刷新，上游恢复后自动变新
  - **超出旧值上限即视为缺失**：日级某段超过 24 小时后不再作为数据返回（记入 `degradedSegments`），卡片/逐小时/台风同理（6 / 24 / 6 小时）—— 宁可缺也不展示已过期的预报
  - 40 天日级：1~16 天来自 Forecast，17~40 天来自 Seasonal EC46（集合预报，**趋势参考**），按段缓存 3 小时（+0~30 分钟抖动）
  - 台风：中央气象台台风网（NMC），缓存 30 分钟（+0~10 分钟抖动）；**非台风季 `/typhoon/active` 返回空列表属正常**，需要随时可取的样例数据用 `/typhoon/recent`（含已停编台风）
  - 雷达：RainViewer 帧列表缓存 5 分钟（+0~1 分钟抖动，旧值兜底 1 小时），瓦片由后端进程内缓存 30 分钟（命中不请求上游）；**仅过去约 2 小时回放、最大 z=7**，详见第八节
- **限流**：所有天气接口共用 10 QPS（固定窗口）；正常页面使用不会触发，超限返回 429。**限流只约束对外 HTTP 调用**——后端内部（模型计算的降雨输入）走不限流入口，不挤占该配额，故 429 只可能由对外调用产生。**雷达瓦片是例外**：地图拖动会瞬时产生数十请求，故瓦片不进 10 QPS 全局窗口，改用「上游配额 90/分钟 + 并发 8 + 终端 IP 600/分钟」三层保护（详见 §8.3）

### 0.2 错误与降级约定

| HTTP 状态 | 响应体 | 场景 |
|----------|--------|------|
| 200 | 正常数据 | 正常 |
| 200 | 降级数据 | 上游不可达/超时/数据格式异常（含**响应缺少关键节点，或温度、体感、WMO 码等关键字段缺失/非数值**——字段缺失一律按异常处理，**不折算为 0**）**且缓存中没有可用数据（无缓存，或旧值已超上限）**：卡片返回 `source=default` 占位、逐小时返回空数组 `[]`、日级/雨情返回 `source=default` + 空 `list`、台风返回空列表与空路径——**接口不报错**，前端按降级态展示 |
| 200 | 旧值兜底（最常见） | 上游短暂抖动：返回**最近一次成功的数据**，字段与正常响应完全一致、`source` 仍为 `openmeteo`；数据时间见 `updateTime` / `updatedAt`，后端同时后台刷新，上游恢复后自动更新 |
| 200 | 部分降级（日级/雨情） | 只有其中一段可用：`degradedSegments` 非空（如 `["extended"]`），已有时段照常返回；`days` / `exactDays` 为**实际返回值**，前端按实际长度渲染。**`days ≤ 16` 的请求只含 A 段**：此时若 A 段缺失则返回空 `list` + `degradedSegments=["exact"]`，**不会用 B 段（第 17 天起）数据顶替** |
| 400 | `{"message": "..."}` | 坐标越界（lon 超出 ±180、lat 超出 ±90）；台风详情 `typhoonId` 非纯数字；逐小时 `startDate` / `endDate` 非 `yyyy-MM-dd` 格式（实现期实测补充：此前非法格式会被静默筛空返回 `[]`，已改为 400）；**雷达瓦片**：z 越界（含 z≥8）、x/y 越界、`frame` 缺失或格式不符 |
| 404 | 空响应体 | **仅雷达瓦片**：上游限流/超时/失败，或上游无该瓦片——该瓦片空白，不影响底图与其他瓦片 |
| 429 | 见下 | 超过限流阈值：其他天气接口与雷达帧列表为 10 QPS 全局窗口；**雷达瓦片为终端 IP 600 次/分钟** |
| 401 | `{"code":401,"message":"未登录","redirectUrl":"..."}` | 未带会话 / 会话已失效：除 `/auth/login` 与 `/weather/radar/tile`（白名单，见 §8.3）外**均需登录态**；浏览器地址栏直接访问时因 `Accept` 含 `text/html` 会 302 跳登录页 |

429 实测响应体：

```json
{"timestamp":"2026-08-29T08:39:52.288+00:00","status":429,"error":"Too Many Requests","path":"/weather/current"}
```

### 0.3 取数清单（每个接口都能查出数据）

> 背景：部分接口在某段时间里**天然没有数据**（台风非台风季、逐小时/日级日期越界），前端拿不到响应就无法核对字段。
> 下表给出**可直接复制的请求**与**实测预期**（2026-09-15 在生产环境实测）——照此调用必能取到数据。
> 除雷达瓦片（已白名单）外均**需登录态**：浏览器登录后直接打开下列地址即可，脚本调用带 `X-Session-Id` 请求头（未登录返回 401）。

| 接口 | 可直接复制（生产，浏览器地址栏可用） | 实测预期 |
|------|-----------------------------------|---------|
| 实时卡片 | `/hltgq-site/weather/current?lon=116.359678&lat=30.378607&location=南排` | 200，`temperature` / `weatherDesc` / `source=openmeteo` 均有值 |
| 逐小时 | `/hltgq-site/weather/hourly?lon=116.359678&lat=30.378607`（**不传日期 = 窗口全量**，约 23 天 / 552 条） | 200，数组；筛选用 `startDate/endDate`，**必须落在「今天-7 天 ~ 今天+15 天」窗口内**，越界返回 `[]` |
| 40 天日级 | `/hltgq-site/weather/daily?lon=116.359678&lat=30.378607&days=40` | 200，`list` 40 条、`days=40`；某段上游不可用时会有 `degradedSegments` |
| 雨情趋势 | `/hltgq-site/weather/rain-trend?lon=116.359678&lat=30.378607&days=40` | 200，累计雨量 / 最大单日 / 有雨天数均有值 |
| 活跃台风 | `/hltgq-site/weather/typhoon/active` | **当前返回 `{"count":0,"list":[]}`（非台风季，属正常）** |
| 最近台风（取数用） | `/hltgq-site/weather/typhoon/recent?limit=5` | 200，5 条（含已停编），字段与活跃列表**完全一致** |
| 台风详情（取数用） | `/hltgq-site/weather/typhoon/detail?typhoonId=3326569` | 200，`track` **49 个实况点**、`forecast` 1 点（科罗旺，已停编仍有完整路径） |
| 雷达帧列表 | `/hltgq-site/weather/radar/frames` | 200，`frames` 约 13 条、`maxZoom=7`、`color=4` |
| 雷达瓦片 | `/hltgq-site/weather/radar/tile/7/105/52?frame={frames 最新一帧的 path}` | 200 `image/png`（**免登录**；`frame` 必须实时取自上一行，见 §8.3） |

**三类「查不出数据」的常见原因**（都不是接口故障）：

1. **台风列表为空** —— 当前无活跃台风（非台风季）：上游列表 27 条**全部 `stop`**。取数改用 `/typhoon/recent`（含已停编），或直接查历史台风详情（`typhoonId` 用列表返回的内部数字 ID，如 `3326569`，**不是** `code` 编号）
2. **逐小时 / 日级为空** —— 日期越界：逐小时窗口 = 今天-7 天 ~ 今天+15 天（约 23 天），日级上限 40 天，超出按空处理
3. **雷达瓦片空白** —— `frame` 缺失或写死：`frame` 必须取自 `/radar/frames` 当前返回的 `path`（每 10 分钟滚动一次，写死的旧值会 404）

**关于坐标**：`lon=116.359678&lat=30.378607` 为灌区参考中心（后端 `weather.site-lon/lat` 同值），联调取数可直接复用；正式接入时坐标由前端地图传入。

## 一、实时天气卡片（GET /weather/current）

### 1.1 请求

```
GET /weather/current?lon={经度}&lat={纬度}&location={可选站点名}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| lon | Number | **是** | 经度，范围 -180~180（WGS-84） |
| lat | Number | **是** | 纬度，范围 -90~90 |
| location | String | 否 | 站点名称，缺省取后端默认（当前配置为「南排」，可调整） |

**请求示例**：

```
GET /weather/current?lon=116.359678&lat=30.378607&location=南排
```

### 1.2 响应

**正常响应**（200，生产实测）：

```json
{
  "temperature": "31°C",
  "weatherDesc": "毛毛雨",
  "feelTemperature": "体感温度 36°",
  "weatherIcon": "51",
  "location": "南排",
  "updateTime": "2026-08-29T16:30",
  "source": "openmeteo"
}
```

**降级响应**（200，Open-Meteo 不可达时；`source=default` 为异常态标识）：

```json
{
  "temperature": "--°C",
  "weatherDesc": "数据暂不可用",
  "feelTemperature": "体感温度 --°",
  "weatherIcon": "",
  "location": "南排",
  "updateTime": "2026-08-29T16:40:00.123",
  "source": "default"
}
```

### 1.3 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| temperature | String | 温度（带单位，如 `"31°C"`）；降级时 `"--°C"` |
| weatherDesc | String | 天气描述（**后端已翻译为中文**，如 "毛毛雨"） |
| feelTemperature | String | 体感温度（如 `"体感温度 36°"`） |
| weatherIcon | String | WMO 天气代码（字符串，如 `"51"`），图标映射见 [第六节](#六wmo-天气代码与图标映射) |
| location | String | 站点名称（请求传入或后端默认） |
| updateTime | String | 上游观测时间（北京时间，如 `2026-08-29T16:30`）；**上游该字段缺失时为 `null`**（前端需判空，不要直接渲染） |
| source | String | 数据来源：`openmeteo`=正常；`default`=降级占位，**前端以此判断异常态** |

### 1.4 前端要点

- **异常态判断**：`source === 'default'` 时展示异常样式（如灰色占位卡片 + "数据暂不可用"），正常态展示温度/天气/图标。注意：上游抖动时后端返回的是**旧值**（`source` 仍为 `openmeteo`，最多旧 6 小时），属正常兜底，不要当作错误
- **数据时效**：用 `updateTime`（上游观测时间）展示"数据时间"；若距今超过 1 小时可弱化提示（如"数据可能滞后"）
- **刷新策略**：后端缓存新鲜期 10~13 分钟，前端建议每 10 分钟轮询一次；页面切回前台（visibilitychange）时立即刷新一次；无需更高频率
- 图标：`weatherIcon` 为字符串形式的 WMO 代码，前端自行映射图标（建议映射表见第六节）

## 二、逐小时天气列表（GET /weather/hourly）

### 2.1 请求

```
GET /weather/hourly?lon={经度}&lat={纬度}&startDate={开始日期}&endDate={结束日期}&location={可选}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| lon | Number | **是** | 经度，范围 -180~180 |
| lat | Number | **是** | 纬度，范围 -90~90 |
| startDate | String | 否 | 开始日期 `yyyy-MM-dd`（**格式非法返回 400**，不会静默返回空数组）；不传=不限起点 |
| endDate | String | 否 | 结束日期 `yyyy-MM-dd`（同上）；不传=不限终点 |
| location | String | 否 | 站点名称，缺省取后端默认 |

**数据范围（重要）**：窗口 = **今天 -7 天 ~ 今天 +15 天**（含今天共 **23 天 ≈ 552 条**，2026-09-15 实测）——即上游 `past_days=7`（不含今天）+ `forecast_days=16`（**含今天**）。`startDate/endDate` 仅在该窗口内筛选，**超出窗口返回空数组**（属正常情况，不是错误）；因上游免费层 `forecast_days` 上限即为 16，**窗口上界无法再向后延伸**（模型若需“从当前时刻起 16 天”，末端约 1 天将无逐小时预报）。响应按时间**倒序**（最新在前），`id` 从 1 重新编号，可直接用作表格 rowKey。

**请求示例**：

```
GET /weather/hourly?lon=116.359678&lat=30.378607&startDate=2026-08-28&endDate=2026-08-31
```

### 2.2 响应

**正常响应**（200，生产实测，倒序排列）：

```json
[
  {
    "id": 1,
    "date": "2026-08-31",
    "hour": "23:00",
    "location": "南排",
    "weather": "阴天",
    "temperature": 24,
    "rainfall": 0.0,
    "windDirection": "东北风",
    "windLevel": 5,
    "windSpeed": 30,
    "humidity": 65,
    "weatherIcon": "3"
  }
]
```

**降级响应**（200，Open-Meteo 不可达且无可用缓存时）：空数组 `[]`，前端展示空表格即可。单一小时字段缺失只会**跳过该小时**（不整体降级为空）。

### 2.3 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Number | 序号（列表内重新编号，从 1 连续递增，可作 rowKey） |
| date | String | 日期 `yyyy-MM-dd`（北京时间） |
| hour | String | 小时 `HH:mm` |
| location | String | 站点名称 |
| weather | String | 天气描述（**后端已翻译为中文**） |
| temperature | Number | 温度（°C，整数） |
| rainfall | Number | 降雨量（mm），0 或 null 时前端可显示 "--" |
| windDirection | String | 风向（中文，如 "东北风"） |
| windLevel | Number | 风力等级（蒲福风级 0~12，展示加"级"如 `5级`） |
| windSpeed | Number | 风速（km/h） |
| humidity | Number | 湿度（%RH，展示加 "%"） |
| weatherIcon | String | WMO 天气代码（字符串），图标映射见第六节 |

### 2.4 前端要点

- 弹窗打开时请求一次即可（数据为全量数组，**建议前端分页**，如 50 条/页）
- 日期筛选：传 `startDate/endDate` 重新请求（**格式必须为 `yyyy-MM-dd`，否则 400**）；重置时传默认范围（建议 今天-7 天 ~ 今天+15 天，与后端窗口匹配）
- 排序：后端已按时间倒序返回，表格如需升序可前端自行 `reverse`（注意此时 id 与顺序对应关系改变，建议以 `date+hour` 为 rowKey）
- 后端无分页参数：同一坐标数据已缓存，重复请求开销低
- 上游抖动时返回旧缓存（最多旧 24 小时，`source` 仍为 `openmeteo`）；每行自带 `date`+`hour`，滞后一眼可见，无需额外提示

## 三、40 天日级预报（GET /weather/daily）

> 数据分两段：**1~16 天**来自 Open-Meteo Forecast（`accuracy=exact`，常规预报），**17~40 天**来自 EC46 集合预报聚合（`accuracy=extended`，**延伸期趋势参考**）。两段独立缓存、独立降级，一段失败不影响另一段。

### 3.1 请求

```
GET /weather/daily?lon={经度}&lat={纬度}&days={天数}&location={可选}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| lon | Number | **是** | 经度，范围 -180~180（WGS-84） |
| lat | Number | **是** | 纬度，范围 -90~90 |
| days | Number | 否 | 返回天数，1~40；不传=40，小于 1 按 1、大于 40 按 40 处理 |
| location | String | 否 | 站点名称，缺省取后端默认 |

**请求示例**：

```
GET /weather/daily?lon=116.359678&lat=30.378607&days=40
```

### 3.2 响应

**正常响应**（200，两段齐备；`list` 实际 40 条，此处仅示例首尾各 1 条）：

```json
  "exactDays": 16,
  "degradedSegments": [],
  "list": [
    {
      "date": "2026-08-29",
      "weekday": "周六",
      "weather": "小雨",
      "weatherIcon": "61",
      "tempMax": 33,
      "tempMin": 25,
      "rainfall": 2.35,
      "rainProbability": 55,
      "humidity": 78,
      "windDirection": "东南风",
      "windLevel": 3,
      "windSpeed": 15,
      "accuracy": "exact"
    },
    {
      "date": "2026-09-14",
      "weekday": "周一",
      "weather": "阴天",
      "weatherIcon": "3",
      "tempMax": 31,
      "tempMin": 24,
      "rainfall": 0.0,
      "rainProbability": 30,
      "humidity": 72,
      "windDirection": "东风",
      "windLevel": 2,
      "windSpeed": 9,
      "accuracy": "extended"
    }
  ]
}
```

**部分降级响应**（200，仅 1~16 天可用）：常规段照常返回，`days` 缩短为**实际返回天数**，`degradedSegments` 指明缺失段：

```json
{
  "location": "南排",
  "updatedAt": "2026-08-29T16:40:00",
  "source": "openmeteo",
  "days": 16,
  "exactDays": 16,
  "degradedSegments": ["extended"],
  "list": [ /* 共 16 条，字段与正常响应完全一致，此处省略 */ ]
}
```

**完全降级响应**（200，两段均不可用）：`source=default`、`days=0`、`exactDays=0`、`list=[]`，前端按空态展示。

### 3.3 字段说明

**外层字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| location | String | 站点名称 |
| updatedAt | String | 数据生成时间 `yyyy-MM-ddTHH:mm:ss`（北京时间），可用于「更新于 xx」展示 |
| source | String | 数据来源：`openmeteo`=正常；`default`=降级（两段均不可用），**前端以此判断异常态** |
| days | Number | **本次实际返回天数**（= `list.length`），缺段时相应缩小，**前端不可写死 40** |
| exactDays | Number | 本次 `list` 中 `accuracy=exact` 的实际条数，**前端不可写死 16** |
| degradedSegments | String[] | 缺失段列表，取值 `exact` / `extended`；空数组 `[]`=数据完整。**从未拉到、列表为空、或旧值已超上限（24 小时）均计入缺失**，此时该段数据不会返回（宁可缺也不展示过期数据） |
| list | Array | 逐日预报，按 `date` **升序**（从今天起） |

**list[] 逐日字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| date | String | 日期 `yyyy-MM-dd`（北京时间） |
| weekday | String | 星期（中文，如 `"周六"`） |
| weather | String | 天气描述（**后端已翻译为中文**，WMO 映射见第六节） |
| weatherIcon | String | WMO 天气代码（字符串），图标映射见第六节 |
| tempMax | Number | 最高温（°C，整数） |
| tempMin | Number | 最低温（°C，整数） |
| rainfall | Number | 日降水量（mm，2 位小数截断） |
| rainProbability | Number | 降水概率（%）：1~16 天为上游预计算值；17~40 天由 EC46 集合成员降水比例推导，**仅供参考** |
| humidity | Number | 平均相对湿度（%RH，展示加 "%"） |
| windDirection | String | 风向（中文，如 `"东南风"`） |
| windLevel | Number | 风力等级（蒲福风级 0~12，展示加 "级"） |
| windSpeed | Number | 风速（km/h，整数） |
| accuracy | String | 数据段：`exact`=1~16 天常规预报；`extended`=17~40 天延伸期趋势 |

> **缺失值口径（全接口统一）**：字段级缺失一律返回 `null`，**不折算为 0**——`null` 表示“上游未提供”，与真实的 `0`（0 °C / 0 mm）语义不同，前端需逐字段判空

### 3.4 前端要点

- **天数按响应渲染**：统一用 `days` / `exactDays` / `list.length` 决定渲染条数与图表 x 轴，**不要写死 40 或 16**
- **`accuracy` 必须参与渲染**：`extended` 段建议用虚线、浅色或「趋势」角标区分，避免与常规预报同等置信度展示
- **部分降级是预期行为**：EC46 为境外慢源，出现 `degradedSegments: ["extended"]`（只返回 16 天）时按已有天数正常渲染，可提示「延伸期暂不可用」，**不要弹错误提示**
- **`days ≤ 16` 只返回 A 段**：请求未来 7 天时响应不会混入 B 段（第 17 天起）数据；若此时 A 段缺失，返回空 `list` + `degradedSegments: ["exact"]`，展示空态即可
- **刷新频率**：日级按段缓存 3 小时（+0~30 分钟抖动），进入页面请求一次即可，无需轮询
- 完全降级（`source=default`、`list=[]`）时展示「暂无数据」空态

## 四、雨情趋势预判（GET /weather/rain-trend）

> 由 `/weather/daily` 的日级数据**实时计算**（不落独立缓存），因此与日级预报**永远一致**，降级状态完全继承。
> 注意：该接口只覆盖**预报段**；实测历史雨情请组合现有雨量监测接口绘制。

### 4.1 请求

```
GET /weather/rain-trend?lon={经度}&lat={纬度}&days={天数}&location={可选}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| lon | Number | **是** | 经度，范围 -180~180（WGS-84） |
| lat | Number | **是** | 纬度，范围 -90~90 |
| days | Number | 否 | 统计天数，与 `/weather/daily` 同口径（1~40，不传=40） |
| location | String | 否 | 站点名称，缺省取后端默认 |

**请求示例**：

```
GET /weather/rain-trend?lon=116.359678&lat=30.378607&days=40
```

### 4.2 响应

**正常响应**（200；`list` 实际返回 `days` 条，此处仅示例 1 条）：

```json
{
  "location": "南排",
  "updatedAt": "2026-08-29T16:40:00",
  "source": "openmeteo",
  "totalRainfall": 68.42,
  "maxDailyRainfall": 21.35,
  "maxDailyDate": "2026-09-02",
  "rainyDays": 8,
  "dryDays": 5,
  "dryDaysStart": "2026-09-12",
  "exactDays": 16,
  "degradedSegments": [],
  "list": [
    {
      "date": "2026-08-29",
      "rainfall": 2.35,
      "rainProbability": 55,
      "cumulative": 2.35,
      "rainLevel": "小雨",
      "accuracy": "exact"
    }
  ]
}
```

**降级响应**（200）：与 `/weather/daily` 完全一致——两段均不可用时 `source=default`、`list=[]`；仅扩展段缺失时 `degradedSegments=["extended"]`、`days` 与各项统计相应缩小。

### 4.3 字段说明

**外层统计字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| location | String | 站点名称 |
| updatedAt | String | 数据生成时间（继承日级数据） |
| source | String | 数据来源：`openmeteo`=正常；`default`=降级 |
| totalRainfall | Number | 全期累计雨量（mm，2 位截断） |
| maxDailyRainfall | Number | 最大单日雨量（mm）；**全期无雨时为 `null`** |
| maxDailyDate | String | 最大单日雨量对应日期；**全期无雨时为 `null`** |
| rainyDays | Number | 有雨天数（日雨量 ≥ 0.1 mm） |
| dryDays | Number | **最长连续无雨天数**（日雨量 < 0.1 mm 的连续段；数据缺失视为未知并打断连续段） |
| dryDaysStart | String | 最长连续无雨段的起始日期；**`dryDays=0` 时为 `null`** |
| exactDays | Number | `list` 中 `accuracy=exact` 的实际条数 |
| degradedSegments | String[] | 缺失段（继承日级数据） |
| list | Array | 逐日趋势，按 `date` **升序** |

**list[] 逐日字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| date | String | 日期 `yyyy-MM-dd` |
| rainfall | Number | 日降水量（mm，2 位截断） |
| rainProbability | Number | 降水概率（%） |
| cumulative | Number | **从今天起的累计雨量**（mm，2 位截断），前端无需自行累加 |
| rainLevel | String | 日雨量等级（GB/T 28592）；**< 0.1 mm 时为 `null`** |
| accuracy | String | 数据段标记：`exact` / `extended` |

**日雨量等级（GB/T 28592）**：

| 等级 | 日雨量范围（mm） |
|------|----------------|
| 小雨 | 0.1 ~ 9.9 |
| 中雨 | 10 ~ 24.9 |
| 大雨 | 25 ~ 49.9 |
| 暴雨 | 50 ~ 99.9 |
| 大暴雨 | 100 ~ 249.9 |
| 特大暴雨 | ≥ 250 |

### 4.4 前端要点

- **柱状图**用 `list[].rainfall`（柱高）+ `rainLevel`（颜色分级 / tooltip）
- **折线图**用 `list[].cumulative` 展示累计雨量走势
- **`rainLevel` 判空**：为 `null` 表示当日无雨，柱高 0 且 tooltip 显示「无雨」
- **统计卡片判空**：`maxDailyRainfall` / `maxDailyDate` / `dryDaysStart` 均可能为 `null`，需兜底显示 "--"
- 与 `/weather/daily` 同源，**同屏使用时建议用相同 `lon/lat/days` 一并请求**，避免天数口径不一致

## 五、台风监测（/weather/typhoon/active、/weather/typhoon/recent、/weather/typhoon/detail）

#### 5.1.3 字段说明

**外层字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| count | Number | 活跃台风数量（= `list.length`） |
| list | Array | 活跃台风列表，顺序与上游一致（后端不重排） |

**list[] 逐项字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| typhoonId | String | 台风 ID，**查详情时必须原值回传**（**不是** `code` 编号）；格式为上游内部数字 ID（7 位左右，如 `3319901`）；上游异常时该项可能为**非纯数字**（列表基础字段仍在，但此时**详情接口会返回 400**）——前端应先判数字再发详情请求 |

| windSpeed | Number | 中心风速（**m/s**，注意与天气接口的 km/h 不同） |
| moveDirection | String | 移向（16 方位中文，如 `"西北"`） |
| moveSpeed | Number | 移速（km/h） |
| latestTime | String | 最新实况时间 `yyyy-MM-ddTHH:mm:ss`（北京时间） |
| distanceKm | Number | 到灌区参考中心点的球面直线距离（km），**仅供排序/初筛参考，不作为影响判定依据** |

#### 5.1.4 前端要点

- 坐标为 WGS-84，直接用 `lon`/`lat` 打点（无需转换）
- 建议按 `distanceKm` 升序展示，便于快速识别最近的台风，但**不要用它做告警判据**
- `count=0` 时展示空态（「当前无活跃台风」），台风图层可整体隐藏，不弹错误
- 缓存 30 分钟：常规 30 分钟轮询；台风季可提高到 10 分钟或提供手动刷新
- **非台风季没有数据可看**：`count=0` 时若需核对字段或做「历史台风」展示，用 §5.3 的 `/typhoon/recent`（字段与本接口**完全一致**，可复用同一套渲染）

### 5.3 最近台风列表（GET /weather/typhoon/recent）

> **为什么有这个接口**：`/typhoon/active` 在非台风季必然返回空列表，前端**拿不到任何数据、也无法核对字段**。本接口按上游时间倒序返回**最近 N 个台风（不论是否活跃，含已停编）**，**任何季节都能取到数据**，用于联调取数与「历史台风回看」。

| limit | Number | 否 | 返回条数，默认 **5**，范围 **1~10**；<1 按 1、>10 按 10（越界钳制，**不报 400**） |

**请求示例**（2026-09-15 实测可复现）：

```
GET /weather/typhoon/recent?limit=5
```

#### 5.3.2 响应

**正常响应**（200，**2026-09-15 实测**：上游共 27 条历史台风，本接口返回最新 5 条、全部为 `stop`；下例列前 2 条）：

```json
{
  "count": 5,
```

- `limit` 参与缓存 key（不同 `limit` 各自缓存），建议前端固定一个值；首次请求需逐条补全详情（整体上限 5 秒），之后命中缓存为毫秒级

### 7.1 卡片交互建议

```javascript
// 状态机：加载中 → 正常态 / 异常态（source=default）
async function loadWeatherCard(lon, lat) {
  const res = await fetch(`/hltgq-site/weather/current?lon=${lon}&lat=${lat}`);
  const data = await res.json();
  if (data.source === 'default') {
    // 异常态：灰色占位卡片，显示"数据暂不可用"，保留点击弹窗入口或禁用
    return renderErrorCard(data);
  }
  return renderNormalCard(data); // 图标按 weatherIcon 映射，展示 temperature/weatherDesc/feelTemperature
}

// 刷新策略：10 分钟轮询 + 切回前台立即刷新
setInterval(loadWeatherCard, 10 * 60 * 1000);
document.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'visible') loadWeatherCard(lon, lat);
});
```

### 7.2 列表弹窗建议

- 打开弹窗时调用 `/weather/hourly`，默认传 `startDate=7天前`、`endDate=2天后`（与后端窗口匹配）
- 「查询」按钮：按用户选择的日期范围重新请求；「重置」按钮：恢复默认范围并重新请求
- 表格：后端已倒序 + id 连续，直接以 `id` 作 rowKey 渲染；分页建议客户端分页（如 50 条/页）
- 空数据：响应为 `[]` 时展示"暂无数据"空态（不弹错误提示）

### 7.3 常见问题

| 问题 | 原因与处理 |
|------|-----------|
| 卡片温度与实时温度有偏差 | 后端缓存 TTL 10~13 分钟，属正常滞后，无需处理 |
| 逐小时列表最早只能查到 7 天前 / 最远到 15 天后 | 窗口固定为 **过去 7 天 ~ 未来 15 天**（含今天共 23 天，与 §2.1 一致），超出范围返回空数组 |
| 偶发 429 | 触发 10 QPS 限流（如页面高频刷新/多个组件并发轮询），前端按 429 静默等待下次轮询即可 |
| `rainfall` 为 0.0 | 该小时无降雨，前端可显示 "--" |
| 卡片/列表返回 `source=default` / `[]` | 上游不可用**且缓存中连旧值都没有**（如服务刚重启又遇上上游故障），接口不会报 5xx；保持降级展示，下次轮询自动恢复 |
| 卡片温度像是几小时前的 | 上游抖动时后端返回旧值兜底（卡片最多 6 小时、逐小时最多 24 小时），用 `updateTime` 判断数据时间，属预期行为 |
| 日级预报只返回 16 天 | 扩展段（17~40 天）上游暂不可用或旧值超上限，`degradedSegments=["extended"]`，属预期降级，按实际天数渲染即可 |
| 第 17 天以后天气结果波动大 | 该段为 EC46 集合预报趋势（`accuracy=extended`），**仅供趋势参考**，建议以「趋势」标记弱化展示，不做精细预报 |
| 台风列表为空 | 非台风季或当前无活跃台风，属正常情况；上游不可达时同样返回空列表，不报 5xx。**需要随时可取的样例数据**用 `/weather/typhoon/recent`（§5.3，含已停编台风） |
| 台风详情没有预报路径 | 上游尚未发布机构预报（`forecast=[]`、`agency=null`），只画实况路径即可 |
| 台风详情 `track` 为空（连实况点都没有） | ① `typhoonId` 用错：传了 `code`（编号）或台风编号而非列表返回的内部数字 ID，上游查不到 → 200 + 空路径（**最常见**）；② 该台风上游确实无路径数据；③ 上游不可达且无可用缓存（降级） |
| 雨情趋势与日级预报对不上 | 两者同源（雨情实时读日级缓存计算），请确认两次请求使用了相同的 `lon/lat/days` |
| 雷达图层没有回波 | 见 §8.5 |

## 八、雷达图（RainViewer 回放）

> 「观测预判雷达图」由**两个接口**配合完成：`/weather/radar/frames` 给时间轴，`/weather/radar/tile/{z}/{x}/{y}` 给地图图层。

### 8.1 能力边界（接入前必读）

| 项 | 说明 |
|------|------|
| 时间范围 | **仅过去约 2 小时回放**（约 13 帧、10 分钟/帧）；**无未来外推**（上游 nowcast 已于 2026-01-01 全球停止） |
| 缩放级 | **最大 z=7**（上游免费层硬限制：约 1 km/px、单瓦片约 300 km 视野）；**z≥8 上游会返回统一占位图，后端已主动拦截为 400** |
| 色板 | 固定 `color=4`（Universal Blue）——上游仅保留该色板，前端无需也无法选择 |
| 定位精度 | 流域尺度：能看「雨带在灌区哪个方位、是否逼近」，**不能看渠系/闸站级细节** |
| 数据来源 | RainViewer（境外免费源）；**图注须标 `Radar by RainViewer`** |
| 降级 | 帧列表上游失败 → 返回旧值（上限 1 小时）或 `frames=[]`；瓦片失败 → 404（空白瓦片）；**均不返回 5xx** |

### 8.2 ① 帧列表（GET /weather/radar/frames）

**请求**：

```
GET /weather/radar/frames
```

无参数（瓦片本身就是全图数据，不需要 lon/lat）。**需登录态**（与其他天气接口一致）。

**正常响应**（200，**2026-09-15 实测**：`frames` 共 13 条、按时间**升序**，下例仅列 1 条示意）：

```json
{
  "generated": "2026-09-15T23:25:22",
  "frames": [
    {
      "time": "2026-09-15T23:20:00",
      "timestamp": 1789485600,
      "path": "/v2/radar/ed423efab9b4",
      "type": "past",
      "tileUrlTemplate": "weather/radar/tile/{z}/{x}/{y}?frame=/v2/radar/ed423efab9b4"
    }
  ],
  "maxZoom": 7,
  "color": 4
}
```

> **`path` 每 10 分钟滚动一帧**（上例为 2026-09-15 23:20 那一帧，现已失效）：**必须实时从本接口取**，不要写死在代码里，否则瓦片会 404。

| 字段 | 类型 | 说明 |
|------|------|------|
| generated | String | 帧列表生成时间（北京时间）；上游缺该字段时为 `null` |
| frames[].time | String | 帧时间（北京时间 `yyyy-MM-dd'T'HH:mm:ss`），**用作时间轴标签** |
| frames[].timestamp | Number | 帧时间戳（epoch 秒），用于排序/比对 |
| frames[].path | String | 帧标识，**仅用于回传瓦片接口的 `frame` 参数**（前端不需要理解其结构，也不要自己拼接） |
| frames[].type | String | 当前实测仅 `past`（历史回放）；上游若恢复外推会出现 `nowcast` |
| frames[].tileUrlTemplate | String | **该帧的完整瓦片模板**（`frame` 已替换好）——前端只需替换 `{z}/{x}/{y}` |
| maxZoom | Number | = 7，**图层 maxZoom 必须取该值** |
| color | Number | = 4（信息性字段） |

**降级响应**（200，上游不可达且无可用缓存）：`frames` 为空数组 `[]`，`maxZoom` / `color` 照常返回——前端**不叠加图层、仅展示底图**即可。

### 8.3 ② 瓦片代理（GET /weather/radar/tile/{z}/{x}/{y}?frame={path}）

**请求**：

```
GET /weather/radar/tile/{z}/{x}/{y}?frame={frames[].path}
```

| 参数 | 位置 | 必填 | 说明 |
|------|------|:--:|------|
| z | 路径 | 是 | 缩放级 **0~7**（越界 400） |
| x | 路径 | 是 | 列号 `0 ~ 2^z-1`（越界 400） |
| y | 路径 | 是 | 行号 `0 ~ 2^z-1`（越界 400） |
| frame | 查询参数 | 是 | 取 `frames[].path`（形如 `/v2/radar/4f4ae5d6985d`）；格式不符 400 |

**正常响应**（200）：PNG 字节流（`Content-Type: image/png`），并带 `Cache-Control: max-age=1800, public`（帧内容不可变，浏览器可缓存 30 分钟）。

**联调自证**（2026-09-15 实测；先取 `/weather/radar/frames` 的**最新一帧** `path`，再请求瓦片）：

```
GET /weather/radar/tile/7/105/52?frame=/v2/radar/{最新帧}   → 200 image/png（覆盖灌区中心；实测约 0.6 KB，该格当前无回波，透明图）
GET /weather/radar/tile/7/104/52?frame=/v2/radar/{最新帧}   → 200 image/png（紧邻西侧；实测约 6.8 KB，有回波）
```

- `z=7` 时 `x=105, y=52` 正好覆盖灌区中心（约 116.36°E / 30.38°N），联调地址可直接用；`{最新帧}` 必须接实时 `path`（含前导 `/`）
- 瓦片**已白名单免登录**，可直接用浏览器地址栏或 Postman 打开验证（无需会话头）
- 上面两个格子一张空、一张有回波是**正常现象**（回波按实际天气分布）：判断“接口是否可用”看 HTTP 200 + `image/png`，不要看图片内容

**错误与降级**：

| 状态 | 场景 | 前端处理 |
|------|------|------|
| 400 | z 越界（含 z≥8）、x/y 越界、`frame` 缺失或格式不符、z/x/y 非数字 | 属调用错误，修正参数即可。**z≥8 是后端主动拦截上游占位图**（不拦截会展示「永远无回波」的假图） |
| 404 | 上游限流/超时/失败，或上游确实无该瓦片 | 该瓦片空白，不影响底图与其他瓦片；拖动/缩放会自然重试，**不要做重试风暴** |
| 429 | 同一 IP 超过 **600 次/分钟**（瓦片专用终端限流） | 正常浏览一次拖动约 20~40 张，远达不到；出现即说明存在异常高频刷屏 |

**鉴权**：瓦片地址已列入后端白名单（可匿名拉取），原因是浏览器 `<img>` / XYZ 图层**无法携带自定义请求头**（登不登录都会带上页面 Cookie，但纯 Header 接入方式不行）；安全边界由 z≤7、上游配额 90/分钟、终端 IP 600/分钟共同收敛。**若需改为强制登录态拉瓦片，后端改一行配置即可（无需改代码），但要求页面与瓦片同源且登录 Cookie 覆盖 `/weather/radar/tile`。**

### 8.4 前端接入要点

1. **图层配置**：天地图之上叠加 XYZ 图层，URL 模板直接用 `frames[].tileUrlTemplate`，`maxZoom` 取接口返回的 `maxZoom`（= 7），**禁止请求 z≥8**；缩放超出时应隐藏图层或提示「已超出雷达数据精度」
2. **不要对 `frame` 做 URL 编码**：模板中查询参数里的原始 `/` 合法，直接拼接即可；`encodeURIComponent` 会把 `/` 变成 `%2F` 而触发 400
3. **不要给图层设置 `crossOrigin`**：瓦片由后端同源代理，设置后浏览器会切到 CORS 模式
4. **时间轴**：按 `frames` 数组顺序播放（后端已升序），间隔建议 500 ms，末帧停住；帧标签用 `frames[].time`（直接展示，不要再做时区换算）
5. **刷新节奏**：帧列表建议 5 分钟请求一次（上游 10 分钟滚动一帧，后端缓存 5 分钟）；瓦片已有浏览器 + 后端双层缓存，前端无需去重
6. **对外口径**：只回放**过去约 2 小时**，**没有未来预报**；雨带位置为流域尺度观感，不是渠系级预报
7. **署名（合规）**：图注标 `Radar by RainViewer`

### 8.5 雷达常见问题

| 问题 | 原因与处理 |
|------|-----------|
| 图层整体空白 | ① `frames` 是否为空数组（上游不可达，属降级）；② 是否在放大到 8 级后请求（后端 400，浏览器控制台可见）；③ 请求是否未带登录态且未走白名单（`/weather/radar/frames` 返回 401） |
| 单个瓦片空白 | 该瓦片本次返回 404（上游限流/超时，或该帧该区域无数据），拖动后自然恢复 |
| 放大后没有回波 | 上游 z≥8 无真实数据（返回占位图），故后端直接 400；前端务必把 `maxZoom` 限制为 7 |
| 时间轴长时间不更新 | 帧列表旧值兜底上限 1 小时；若超过 1 小时仍无新帧，请后端查日志「雷达帧列表更新」与上游可达性 |
| 瓦片大量 404 | 上游配额（90/分钟）被打满，属被动限流保护；避开高频刷新整屏瓦片、降低时间轴预加载帧数即可 |
| 雷达图与雨情趋势对不上 | 两者口径不同：雷达是**过去 2 小时回波观测**，雨情趋势是**未来 40 天预报降水**，不可相互校验 |
