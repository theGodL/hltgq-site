# 导入-导出对接接口

> 适用范围：巡查计划 Excel 导入（模板下载、上传解析入库）+ 业务数据导出数据源（前端自行生成文件）。
>
> 职责边界：**后端只负责** ①导入模板文件下发 ②上传文件解析入库 ③按查询条件返回 JSON 数据；
> 导出文件（Excel/CSV）由前端基于接口返回的数据自行生成，**后端不提供文件流导出接口**。
>
> 导入上传后同步解析入库并返回逐行结果（无异步任务、无轮询）；全部接口走现有登录会话鉴权；
> 文件缺失/格式错误/参数错误统一报 400（`{"message": "..."}`），逐行错误在响应体内按行返回。
>
> **实现状态**：本文件涉及接口已全部实现——模板下载与上传导入在 `patrol/controller/PatrolScheduleController`
> + `patrol/service/PatrolScheduleImportService`；5 个导出数据源在各业务模块 Controller。
> 2 项联调核对项（关系中间表表名 / field_id）见文末「附录：实现状态与联调核对项」。

---

## 通用约定

| 约定 | 说明 |
|------|------|
| 鉴权 | 全部接口需登录会话（与站内其他接口一致；页面同源请求自动携带，无需额外鉴权头） |
| 文件格式 | 导入仅支持 `.xlsx`（Apache POI 解析，首行为表头）；模板由接口下发 |
| 枚举字段 | 响应同时给中文翻译字段与 `*Code`/`*Codes` 编码原文（权威值，形如 `#1#`，多选以 `\|` 分隔存储） |
| 时间格式 | 请求参数日期 `yyyy-MM-dd`；响应时间戳为 ISO `yyyy-MM-dd'T'HH:mm:ss`（Jackson 默认序列化），纯日期回显字段为 `yyyy-MM-dd` |
| 列表接口 | 均为实时**全量**查询（无缓存、无分页参数）；页面列表展示与导出生成本地文件共用同一接口 |
| null 语义 | 无数据返回 `null`，**不返回 0**；空列表返回 `[]` |
| 错误响应 | 400 `{"message":"原因"}`；401 `{"code":401,"message":"未登录"}`；502/503 `{"code":...}` |

## 一、下载巡查计划导入模板

```
GET /patrol-schedule/import-template
```

无参数。成功响应为 xlsx 文件流：

| 响应头 | 值 |
|--------|-----|
| Content-Type | `application/octet-stream` |
| Content-Disposition | `attachment; filename="...xlsx"; filename*=UTF-8''...`（文件名「巡查计划导入模板.xlsx」，RFC 5987 编码，浏览器按 filename* 识别中文名） |

模板结构（首行表头，数据自第 2 行起，预留 300 行输入区；空行解析时自动跳过）：

| 列 | 必填 | 填写规则 |
|----|:--:|------|
| 计划编号 | 否 | 留空由后端自动生成（`XCJH` + 13 位毫秒时间戳）；填写须全局唯一 |
| 计划名称 | 是 | 文本 |
| 计划类型 | 是 | 下拉选择：年度计划 / 月度计划（单元格已内置下拉与提示批注） |
| 巡查范围 | 是 | 多个站点用「、」分隔（兼容 `,` `\|` `；`）；填站点名称或站点编号 |
| 巡查内容 | 是 | 文本（≤1000 字） |
| 计划开始时间 | 是 | 日期 `yyyy-MM-dd`（列已设日期格式，直接输入日期即可） |
| 计划结束时间 | 是 | 日期 `yyyy-MM-dd`，不得早于开始时间 |
| 创建人 | 否 | 用户姓名；留空 = 当前登录人 |
| 巡检人员 | 是 | 多个姓名用「、」分隔（兼容 `,` `\|` `；`） |
| 状态 | — | 只读提示列：填写无效，入库统一为 `#1#` 草稿 |

## 二、上传导入文件（解析并入库）

```
POST /patrol-schedule/import     （multipart/form-data）
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| file | File | 是 | 巡查计划 xlsx（按第一章模板填写） |

**处理流程（单接口内串行完成）**：① 文件校验（非空、可解析 .xlsx、数据行 ≤ 300）→ ② 表头校验（缺必需列直接 400）→ ③ 逐行解析（空行跳过；行号取 Excel 实际行号）→ ④ 名称 → ID 转换（站点/用户精确匹配）→ ⑤ 逐行入库（单行独立事务：主表 + 巡查范围/巡检人员多选关系）。
**逐行独立**：某行失败不影响其他行，已成功的行正常落库；单行入库为独立事务，关系写入失败整行回滚（不会出现主表已写、关系缺失的半成品行）。

逐行校验规则：

| 列 | 规则 | 违反时 |
|----|------|------|
| 计划编号 | 空 → 自动生成 `XCJH`+13 位毫秒时间戳（批内已用 + 库中已有双重防重，碰撞时毫秒递进）；非空 → 与批内已用编号及库中已有编号比对，须唯一 | 重复 → **该行失败**（`计划编号在本批次内重复：...` / `计划编号已存在：...`） |
| 计划名称 | 非空 | 空 → **该行失败** |
| 计划类型 | 接受「年度计划 / 月度计划」或编码 `#1#` / `#zjgg#` | 其他值 → **该行失败** |
| 巡查范围 | 逐项按**站点名称或站点编号**匹配站点档案；未匹配 / 重名的项忽略并在结果中提示；全部项均未匹配 | 全未匹配 → **该行失败**；部分未匹配 → 忽略该项，行仍入库 |
| 巡查内容 | 非空，≤1000 字 | 空或超长 → **该行失败** |
| 计划开始时间 | `yyyy-MM-dd`（兼容 `yyyy/M/d`、`yyyy.M.d`、`yyyy年M月d日` 及带时间串，取日期段） | 无法解析 → **该行失败** |
| 计划结束时间 | `yyyy-MM-dd`（兼容写法同开始时间），且不早于开始时间（等于允许） | 无法解析或早于开始 → **该行失败** |
| 创建人 | 空 → 当前登录人；填写 → 姓名精确匹配用户 | 匹配不到或重名（多个同名用户）→ **该行失败** |
| 巡检人员 | 逐项按**姓名**匹配用户；未匹配 / 重名的项忽略并提示；全部项均未匹配 | 全未匹配 → **该行失败**；部分未匹配 → 忽略该项，行仍入库 |
| 状态 | 忽略填写值（只读提示列） | 统一落 `#1#` 草稿 |

系统字段（记录 id、企业编码、创建/更新时间与人员、隐藏统计列）由后端生成，Excel 无需填写。巡查范围/巡检人员以多选关系落库，对接侧无需关心关系字段。计划编号 / 创建人 / 状态列整体缺失或留空时按「留空」处理（编号自动生成、创建人取当前登录人、状态统一草稿）；其余 7 列为必需列，缺失报 400。

成功响应（HTTP 200，逐行结果）：

```json
{
  "total": 3,
  "success": 2,
  "failed": 1,
  "rows": [
    { "row": 2, "ok": true, "id": "6Joa4knfy6Ko8SBQ0J9", "code": "XCJH1788233547834", "message": null },
    { "row": 3, "ok": false, "id": null, "code": null, "message": "计划名称为空" },
    { "row": 5, "ok": true, "id": "ish8UlZ9SOvMoqHU8G5", "code": "XCJH1788161861945", "message": "站点「测试站」未匹配，已忽略" }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| total / success / failed | Number | 数据行总数 / 成功行数 / 失败行数（空行不计入） |
| rows | Array | 逐行结果，按 Excel 实际行号升序 |
| rows[].row | Number | Excel 行号（表头为第 1 行，首条数据为第 2 行） |
| rows[].ok | Boolean | 该行是否成功入库 |
| rows[].id | String | 成功时的记录主键 id（失败为 null） |
| rows[].code | String | 成功时的最终计划编号（失败为 null） |
| rows[].message | String | 失败原因；成功但存在忽略项时为提示文案（无则 null） |

> 提示文案细则：多个忽略项在 message 中以「；」连接（如 `站点「测试站」未匹配，已忽略`）；失败行的 message 仅为失败原因（不含忽略提示）。

典型失败原因文案：`计划名称为空`、`计划类型无效（应为 年度计划/月度计划）`、`计划开始时间格式无效（应为 yyyy-MM-dd）`、`计划结束时间格式无效（应为 yyyy-MM-dd）`、`计划结束时间早于开始时间`、`巡查内容为空`、`巡查内容超长（≤1000 字）`、`计划编号在本批次内重复：XCJH...`、`计划编号已存在：XCJH...`、`创建人「张三」未匹配到用户`、`创建人「张三」存在多个匹配用户`、`巡查范围为空`、`巡查范围未匹配到任何站点`、`巡检人员为空`、`巡检人员未匹配到任何用户`、`入库失败：<原因>`（关系表写入异常等，含具体原因）。

整体性错误（HTTP 400）：

| 场景 | message 示例 |
|------|------|
| 文件为空 | 上传文件不能为空 |
| 非 xlsx / 解析失败 | 导入文件解析失败（仅支持 .xlsx 格式） |
| 无数据行 | 导入文件无数据行 |
| 缺少必需列（7 列：名称 / 类型 / 巡查范围 / 巡查内容 / 计划开始时间 / 计划结束时间 / 巡检人员） | 导入文件缺少以下列: 计划名称, 计划类型 |
| 数据行超过 300 | 导入文件数据行超出上限（300 行） |

## 三、导出数据源接口

> 后端不提供专用导出接口：前端用当前筛选条件调用对应业务列表接口，取全量 JSON 后自行生成 Excel/CSV。
> 各接口均为实时查询（无分页），响应为**数组**，筛选参数均可选（不传 = 全部）。
> 后续新增业务如需导出，按同样模式补充一个列表接口即可被前端复用。

### 3.1 设备库存

```
GET /inventory/list?departmentId=xxx&stockStatus=安全库存
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| departmentId | String | 否 | 所属部门 ID（部门表主键精确匹配） |
| stockStatus | String | 否 | 库存状态：`安全库存` / `库存预警`（或编码 `#1#`/`#2#`） |

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 记录主键 |
| departmentId / departmentName | String | 所属部门 ID / 部门名称（部门记录缺失时为 null） |

| stockQty / safetyStock | Number | 库存数量 / 安全库存（数值，空或非法为 null） |
| unit | String | 单位（如「个」） |
| stockStatus / stockStatusCode | String | 库存状态翻译 / 编码原文 |
| details | Array | 库存明细行：`code` 编号、`name` 物资名称、`brand` 品牌型号、`quantity` 数量、`unit` 单位、`inboundQty` 入库数量、`outboundQty` 出库数量、`outboundTotalQty` 累计出库数量（稀疏对象，无值字段为 null） |

## 附录：实现状态与联调核对项

**实现状态（本文件全部接口均已实现）**

| 接口 | 实现位置 |
|------|----------|
| GET `/patrol-schedule/import-template` | `patrol/controller/PatrolScheduleController`（下发 `classpath:static/templates/PatrolScheduleImport_Template.xlsx`） |
| POST `/patrol-schedule/import` | `PatrolScheduleController` → `patrol/service/PatrolScheduleImportService`（逐行校验 + 单行事务入库） |
| 5 个导出数据源接口 | `inventory` / `stationdata` / `workorder` / `watersaving` / `duty` 模块 Controller（全量实时查询） |

**主表写入口径**：`t_auto_hltgq_water_patrol_schedule` 仅写 13 列 = 审计 6 列（id / corp_code / created_at / created_by / updated_at / updated_by）+ 业务 7 列（code / title / content / start_time / end_time / xhonqv / status）；13 个隐藏统计列（pwtlmi、ftumeu～zxvbxm）不写入；start_time / end_time 存当日零点（`YYYY-MM-DD 00:00:00`）。

**联调核对项（2 项，按平台关系表命名约定推导，未读库确认，部署联调时核对）**

| 项 | 推导值 | 核对方式 |
|----|--------|----------|
| 关系中间表表名 | 巡查范围 → `t_auto_hltgq_water_patrol_schedule_inspection_scope_site_rel`；巡检人员 → `t_auto_hltgq_water_patrol_schedule_user_rel` | 导入成功后查看服务日志 `[巡查导入] 关系表写入：...`，并在平台表单页打开该计划确认巡查范围 / 巡检人员回显 |
| 关系表 field_id 取值 | `inspection_scope_site` / `user` | 同上（日志打印 field_id 与写入条数） |
