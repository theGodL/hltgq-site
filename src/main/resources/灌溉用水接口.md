# 灌溉用水接口（/irrigation-water）

> 页面：`static/irrigation-water.html`（需水方案多选 → 四县「灌区名称/需水时间/需水量/实际供水量/设计保证率/实际保证率/灌溉进度」列表）
> 鉴权：与其他接口一致（请求头 `X-Session-Id` 或 Cookie `sessionId`，完整前缀见平台登录态）

## 1. 接口一览

| 接口 | 方法 | 说明 |
|------|------|------|
| `/irrigation-water/schemes` | GET | 需水方案下拉选项（仅"已完成"方案，按创建时间倒序） |
| `/irrigation-water/summary` | GET | 选中方案 × 四县（宿松/怀宁/望江/太湖）汇总 |

---

## 2. GET /irrigation-water/schemes — 方案下拉选项

**请求参数**

| 参数 | 必填 | 类型 | 说明 |
|------|------|------|------|
| year | 否 | int | 计算年。缺省=方案创建年（方案在灌溉季内生成，与实际监测数据同季）；仅影响需水时间起止日期的年份 |

**响应**：数组，每项字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| schemeId | string | 方案ID（调 summary 时使用） |
| schemeName | string | 方案名称（如 `需水预测_90`） |
| guaranteeRate | string | 方案保证率（`50` / `75` / `90` / `多年平均`） |
| year | int | 计算年（缺省=方案创建年） |
| startTenday / endTenday | string | 需水旬范围（如 `5月上旬` ~ `10月下旬`） |
| periodStart / periodEnd | string | 需水日期范围（`yyyy-MM-dd`，可直接用于"需水时间"展示） |
| totalDemand | number | 方案总需水量(万m³) |
| districtCount | int | 灌区（县）数量（固定 4） |

**示例**

```json
[
  {
    "schemeId": "eJio2Ce6A3buqWRNBeMtVl",
    "schemeName": "需水预测_90",
    "guaranteeRate": "90",
    "year": 2026,
    "startTenday": "5月上旬",
    "endTenday": "10月上旬",
    "periodStart": "2026-05-01",
    "periodEnd": "2026-10-10",
    "totalDemand": 56833.0,
    "districtCount": 4
  }
]
```

> 方案下拉为**全量返回**（当前 56 条，随年份累积）。历史方案存在大量同名（如多个 `需水预测_90`），是否去重/过滤（按年、按保证率档、取最新等）由**前端/产品**决定，后端不做裁剪；同名方案可用 `year`、`guaranteeRate`、`startTenday ~ endTenday`、`totalDemand` 辅助区分，多方案对比行的归属可用行内 `schemeId`/`schemeName`。

---

## 3. GET /irrigation-water/summary — 灌溉用水汇总

**请求参数**

| 参数 | 必填 | 类型 | 说明 |
|------|------|------|------|
| schemeIds | 是 | string | 方案ID，逗号分隔（或重复参数），单次最多 10 个；不存在/已删除返回 400 |
| year | 否 | int | 计算年，缺省同 schemes |

**响应**：数组，每个方案一项；`rows` 固定 4 行（宿松县、怀宁县、望江县、太湖县）。

外层字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| schemeId / schemeName / guaranteeRate | string | 同 schemes |
| year | int | 计算年 |
| startTenday / endTenday / periodStart / periodEnd | string | 方案整体需水时间 |
| rows | array | 四县行，见下 |

行（rows[]）字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| district | string | 灌区（县）名称：宿松县/怀宁县/望江县/太湖县 |
| startTenday / endTenday | string | 该县需水旬范围 |
| periodStart / periodEnd | string | 该县需水时间（`yyyy-MM-dd`） |
| demandVolume | number\|null | 需水量(万m³)，该县对应片区 18 旬求和 |
| supplyVolume | number\|null | 实际供水量(万m³)，按县口径从流量监测计算；**部件数据缺失时为 null** |
| designGuaranteeRate | number | 设计保证率(%)，逐县配置值 |
| actualGuaranteeRate | number\|null | 实际保证率(%) = 供水量 ÷ 需水量 × 100（1 位小数截断） |
| irrigationProgress | number\|null | 灌溉进度(%)，暂同实际保证率（见「4.4」） |
| missingData | string[] | 缺失数据说明（如「章大计量闸（无流量数据）」），数据完整时为空数组 `[]` |

## 4. 计算口径

### 4.1 县 ↔ 需水片区（需水量来源）

| 县 | 对应片区（summary_type=片区） |
|----|------------------------------|
| 太湖县 | 总干渠 |
| 望江县 | 南干渠 + 北干渠 |
| 宿松县 | 太宿干渠 |
| 怀宁县 | 太怀灌区 |

需水量 = 对应片区 18 旬（5月上旬~10月下旬）需水量求和；四县合计 = 方案总需水量。

### 4.2 实际供水量（区间累计口径）

| 县 | 计算口径（业主定义） |
|----|----------------------|
| 宿松县 | 章大计量闸过闸流量 |
| 怀宁县 | 太怀干渠长喉槽流量 |
| 望江县 | 南干渠进水闸 + 北干渠进水闸 |
| 太湖县 | 渠首进水闸总流量 − 宿松/怀宁/望江各站取水 − 三电站（集岭/渠首/双庙湖）过流 − 损耗 |

- **时间窗**：该县需水时间（旬范围 → 起止日期，如 2026-05-01 00:00:00 ~ 2026-10-31 23:59:59）
- **区间累计** = 窗口内末行总累计 ttf − 起点前最近一条 ttf（起点前无基准按 0），与流量监测/闸门监测同口径；单站数值已在后端日志输出（`[灌溉用水]` 前缀），可逐站核对
- **计算年**：缺省取方案创建年（方案在灌溉季内生成，与实际监测数据同季），可 `year` 参数覆盖
- 单位：原始 m³ → 万m³（2 位截断）

### 4.3 站点映射与数据就绪状态

| 县 | 站点（系统内候选标识） | 当前状态 |
|----|------------------------|----------|
| 宿松 | 章大计量闸（章大测流站节点） | 设备未接入，暂无数据 |
| 怀宁 | 太怀干渠长喉槽（3408229002） | 站点已建、设备离线，暂无数据 |
| 望江 | 南干渠进水闸（9000000002）、北干渠进水闸（9000000001） | 有数据 |
| 太湖 | 渠首进水闸（总量站） | 窗口内暂无数据 |
| 太湖 | 集岭电站 / 渠首水电站 / 双庙湖水电站 | 设备未接入，暂无数据 |

- **设备接入后无需改接口**：流量数据一旦上报即自动纳入计算；若上报到新的站点标识，由后端调整站点配置即可
- **太湖县为严格口径**：任一扣减部件（各县取水/三电站）缺失时 `supplyVolume=null`，不做近似估算；全部接入后自动出数
- 缺失原因逐项列在 `missingData`（`（设备未接入）` / `（无流量数据）`），前端可悬浮展示

### 4.4 保证率与灌溉进度

- **设计保证率**：逐县配置值（业务定稿前使用产品稿默认：宿松 90 / 怀宁 85 / 望江 80 / 太湖 95）
- **实际保证率** = 实际供水量 ÷ 需水量 × 100（1 位小数截断，不封顶）
- **灌溉进度**：暂同实际保证率（产品稿口径）；如业务有独立定义，后端再调整
- 需水量 ≤ 0 或供水量缺失时，实际保证率/灌溉进度为 `null`

## 5. 数值精度

| 字段 | 精度 |
|------|------|
| 需水量、实际供水量（万m³） | 2 位小数，截断 |
| 设计/实际保证率、灌溉进度（%） | 1 位小数，截断 |
| null 显示 | 建议前端显示 `—`；`missingData` 非空时可提示「部分数据未接入」 |

## 7. 其他说明

- 单次 `schemeIds` 最多 10 个方案；方案不存在/已删除返回 `400 {"message": "..."}`
- 后端按「方案 × 县」输出计算明细日志（`[灌溉用水]` 前缀，含每个站点的区间累计值），联调核对以服务器日志为准
- 页面静态 Mock 与接口字段的对应：`district`↔灌区名称、`period`↔需水时间（periodStart ~ periodEnd）、`demand`↔demandVolume、`supply`↔supplyVolume、`designRate`↔designGuaranteeRate、`actualRate`↔actualGuaranteeRate、`progress`↔irrigationProgress
